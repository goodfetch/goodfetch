# Testing

How Goodfetch is tested: every surface, at every level. Each rule comes with its reason, and the hard-to-reverse ones are decided in ADRs. [`STYLE.md`](STYLE.md) shapes the code these tests drive. Here a *snapshot* is a stored expected value, never a Checkpoint, a Group backup or a Reference screenshot.

## Quality register

Decided in [ADR 0140](docs/adr/0140-every-shared-per-unit-path-has-one-owner-module-a-cost-contract-of-counted-work-and-a-benchmark.md), in the format of the `system-qualities` skill's register. It is the project's quality bar: the Floor every diff keeps, the limits that fail the merge gate, the figures that only ratchet down and the Exceptions that expire. The project has no `CONSTRAINTS.md`. Read it before writing code on a Shared path (ADR 0140's inventory: F1 to F6, C1 to C5, E1 to E6). Change a limit only by the rules below: tighten it in the pull request that earns it, loosen it with the owner.

Every row of counted work whose path exists has its counter and its first figure, and is Enforced, in the [Counted work](#counted-work) table; a row whose path is not built yet stays Measured, "not run yet". `code-review`'s Standards axis still checks the Shared paths' contracts as a judgement where no counter reaches. `just floor-guard` checks the Floor on every merge (`xtask floor-guard`, in `just merge`'s gate); it reads lines, not meaning, so `code-review` still checks the Floor too. `just stress`'s selection checks deleted tests by the IDs the runners collect.

**`just counts`** (`xtask counts`, ADR 0140) is the "Checked by" of every counted row: it runs each row's benchmark with its default features on and once per switchable feature off, divides each count by the units of the outcome that did the work, reads the row's limit (its Today figure, else its Contract) and fails over it, naming the row, its figure and its limit. ### Floor

Always enforced on the diff. A breach is a hard violation in `code-review`.

- **No new suppression comment,** except these forms, which never expire and always name what they suppress:
  - Rust: `#[expect(lint, reason = "…")]` ([`STYLE.md`](STYLE.md)), never `#[allow]`;
  - a test run as a child process by another test: `#[ignore = "run as a child by <test>"]`;
  - the SDKs' type tests: `@ts-expect-error` and `# type: ignore[code]` ([SDKs](docs/testing/sdk-and-cli-tests.md#sdks));
  - Python: `# pyright: ignore[rule]`;
  - TypeScript: `oxlint-disable-next-line <rule> -- <reason>`. [Oxlint's documentation](https://oxc.rs/docs/guide/usage/linter/ignore-comments) gives the comment and its rules and no reason syntax; its parser takes what follows ` -- ` as the description, so the guard asks for that form.
- **No unimplemented stub, or empty catch, standing in for the work.**
- **No skipped or deleted test without a `Quality-change` trailer.** A test replaced at a deepened module's interface names its replacement. The floor guard reads the diff's lines, where a test removed from one file and one of its name added in another cancel out, so `xtask stress select` also compares each runner's listing at the head with the base's: a test ID listed at the base and not at the head is deleted, a renamed or moved test too, and fails the selection unless a trailer names that ID. An rstest case, `case_<n>_<description>` with `<n>` its position zero-padded to the width of the case count, is matched on its description, so a case inserted or reordered deletes none of the cases it renumbers; a case with no description, `case_<n>`, is matched on its position.
- **No secret in source.**
- **No register row weakened outside the rules below.**
- **No edit to the gate's own files** (its benchmarks, the floor guard, the register check) without a `Quality-change` trailer. The guard reads them from this line, at the merge base; a new file of the gate adds to the bar and passes: `xtask/src/floor_guard.rs`, `xtask/src/floor_guard/`, `xtask/tests/it/floor_guard.rs`, `xtask/src/register.rs`, `xtask/src/register/`, `xtask/tests/it/register.rs`, `xtask/src/markdown.rs`, `xtask/src/git.rs`, `xtask/src/counts.rs`, `xtask/src/counts/`, `xtask/tests/it/counts.rs`, `xtask/src/stress/deleted.rs`, `crates/foxhound/goodfetch-foxhound/benches/`, `crates/goodfetch-page/benches/`, `crates/goodfetch-engine/benches/`.

_Why:_ the floor is diff-scoped, so the suppressions the code already holds (412 `#[expect]`, 28 `#[ignore]`, 51 `oxlint-disable` on 2026-11-01) fail nothing, while a new bare one does.

### Recorded changes

- **A change the Floor would flag but these rules allow carries a commit trailer:** `Quality-change: <file or row>: <reason>`. That covers a test removed with its replacement named, a row raised within its Cost contract, and an edit to the gate's own files.
- **The floor guard accepts a flagged change that a trailer names,** and `code-review` checks each trailer against the spec and ADR 0140. A file's trailer names its path, a row's its name (`F1.parses`, `X1`), a deleted test's its ID as its runner lists it at the base (`xtask::it stress::selects`, `tests/test_x.py::test_y`), an rstest case's with its number (`xtask::it pre_merge::forms::case_3_what_changed`), an ID that itself holds `: `, as a Vitest or Playwright title may, whole before its reason (`changed > kept: at one: <reason>`), and a change to a section of rules names that section (`Floor`, `Recorded changes`, `Rules`). The guard reads the trailers of every commit from the merge base to the head, and lists what each accepted as a `note[quality-change]` line.

### Rules

- **"Runs at" names one of two moments:** implementer done (`tdd`) or the merge gate. The rows of counted work run at implementer done, at most 60 seconds per benchmark family, once after the change and only for the families whose Shared paths it touched: `just counts --family <its Benchmark>`, or `--path` for one path. Their baseline is each row's Today figure, never a run before the change, and a change that touches no Shared path runs none. In a `/implement-spec` run they run at the spec's end instead, in the full gate of the pull request that finishes the spec, which runs every family (the owner's decision of 2026-11-23, [Checks by role](docs/testing/checks-by-role.md)). The merge gate's `perf` step runs every family. The rows read under Valgrind (instructions, allocations, bytes) run at the merge gate, through `xtask perf`.
- **Every enforced row has a number and a command.** A dimension with a number and no command stays in the Measured table until its command exists.
- **Counters only.** An enforced row counts counted work (ADR 0140), or instructions, allocations, bytes or system calls. Wall time and resident memory stay [Performance targets](docs/testing/performance-budgets.md#performance-targets), each figure with the setup it was measured on, and compared only with a figure from the same setup. Work is counted per unit of the outcome that does it, and each benchmark's input produces every outcome its path has.
- **A ceiling is the measured value, or the value an ADR sets,** never a round number above it. For work ADR 0140 plans and no code does yet, the row starts at the ADR's value. Raising a row up to its Cost contract, in the pull request whose spec names the added count, is not a loosening: the commit records it with a `Quality-change:` trailer. Above the contract, it is a loosening.
- **The ratchet.** A measured figure is compared with its recorded Today value. The pull request that improves a figure writes the new value in the same change. Counted work has zero tolerance. A figure that varies (coverage, instructions, bytes allocated) has a tolerance of 0.5 %. In parallel runs, only the merger writes a new Today value: the figure the merged ticket's implementer measured at done, since the merger runs no `just counts` of its own ([Checks by role](#checks-by-role)).
- **Coverage is a ratchet,** "must not fall", with no per-changed-line threshold; test quality, when measured, is ADR 0072's mutation score.
- **Tightening is silent; loosening is loud.** These need no approval:
  - lowering a number, adding a row or promoting a measured row to enforced;
  - extending a benchmark's input or counters to a new outcome or feature.

  These need the owner, and an amendment of ADR 0140 when they raise a Cost contract:
  - raising a number (outside the contract case above), or removing or demoting a row;
  - changing a row's command or Runs at;
  - narrowing a benchmark's input or what its counters see;
  - adding or extending an Exception.

  A loosening never rides in the pull request of the feature that failed the limit.
- **A temporary Exception is the coordinator's call** (owner, 2026-11-21, « Ok, alors fais comme tu recommandes et vas-y, enchaîne. », after X19 waited three days for an answer). Moving or extending an Exception needs no owner when all of these hold: an open ticket that has its place in the order of work removes it; its figures are measured on the head that needs it; its expiry is unchanged; and it raises no Cost contract. It still rides in a pull request of its own. The coordinator records the decision on that pull request and in `.claude/handoff/decisions.md`, and names it in the next hourly report, where the owner can reverse it. Anything else in the list above stays the owner's.
- **Exceptions expire.** Each has an owner and an expiry date, 90 days by default. From 21 days before a date, `xtask register check` lists the Exception in every gate's log, with its date and its "Removed by", as a note that fails nothing; the agent that runs the work brings that list to the owner as a decision to take. At the notice, each listed Exception is in one of two cases (the owner's decisions of 2026-11-10):
  - **the ticket it names is open and has its place in the order of work:** it is extended by 90 days, every such Exception in one pull request the owner approves;
  - **anything else,** an Exception that names no ticket or whose ticket is closed: the owner chooses, before the date, a ticket, which makes it the first case, or a Contract changed by an amendment of ADR 0140. It gets no new date without an open ticket. An Exception no ticket removes is also decided when the owner approves the ceilings ([#1932](https://github.com/goodfetch/goodfetch/issues/1932)), if that comes first.
- **No gate is informational without an owner and an expiry.** A waiver names its figures, its owner and a date or a named merge, and the gate blocks again by itself when it ends (ADR 0134, as ADR 0140 amends it).
- **Drift has a fixed baseline.** No counted figure passes 1.10 times its pinned reference build, #1577's tuned build and then each release tag, without an amendment the owner approves (ADR 0071, as ADR 0140 amends it).
- **The register is the source of the numbers.** The gate's code reads the register, or the register check compares the two and fails on a difference, as for `xtask perf`'s ceilings.
- **The register check, `xtask register check`, runs with the merge gate through `just lint`.** It fails when:
  - an enforced row's command does not exist: each code span of its "Checked by" must be a recipe of the justfile, a command of `xtask`, a file of the repository, or text a recipe runs;
  - an Exception has expired;
  - a path of ADR 0140 has no row, or a count in a Cost contract has no row: a row holds a count when its Metric names every word of the count, the words after the count's number up to the first word that says where or when it applies;
  - a row allows more than its contract's cap, or its Today figure is over its Contract with no Exception naming it;
  - a ceiling of `xtask perf` differs from the row whose Benchmark names it, or either has no counterpart;
  - a table it reads is missing or empty.
- **Each counter proves it can fail.** A benchmark's own tests plant one extra unit of each counted work it gates and expect a failure.
- **A row changes in the pull request that lowers its figure, raises it within its contract as its spec names, or amends ADR 0140.** Nothing waits for a separate maintenance task.
