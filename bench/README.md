# Benchmarks

The benchmark harness and its TypeScript targets (ADRs 0025 and 0071), moved from `rnd/lab`'s v2 campaign runner and cleaned up. Area 2 fills this folder.

- `hosts/`: the host classes above `local-dev`, each with the gates preflight checks before a run. `local-controlled` is a named machine whose figures are labelled with it and compared within one report (ADR 0025's note of 2026-11-10); `reference` is the bare-metal Linux host, declined while Goodfetch has no revenue (ADR 0076).
- `src/host.ts`: the host snapshot and the gates that grant a class, refuse it or, when the campaign allows, downgrade it. A gate it cannot measure fails, and uncommitted changes cap the host at `local-dev`.
- `src/provenance.ts`: the commit, whether the checkout is dirty, and a fingerprint of the harness's sources.
- `src/metrics.ts`: the metrics a run records and the probe each reads; a metric the host cannot measure is `null` with its reason, never 0.
- `src/resources.ts`: the adapter's process tree, sampled: CPU from `/proc/<pid>/stat` and proportional memory from `smaps_rollup` on Linux, RSS from `ps`.
- `src/campaign.ts`: a campaign file: its adapters, the Proving ground tasks they run, the blocks, warmup, iterations, concurrency, timeouts and restarts. Each adapter starts in the campaign file's folder. A competitor's adapter may name its tool's published `configuration`, a file beside the campaign whose `defaults` say whether the tool blocks by filter lists and handles Consent prompts. A Goodfetch adapter runs on the default row, every control on, or on a row `matched` against such a competitor (ADR 0025's equal guarantees): with the settings the campaign names, which switch off the controls the competitor lacks, and Filter-list blocking and Consent prompt handling set as its defaults declare (ADRs 0047 and 0048).
- `src/adapter.ts`: the competitor adapter protocol, one JSON line a message on the adapter's stdin and stdout: `hello` (the task kinds it claims, and a Goodfetch adapter's Product), `prepare` (the Proving ground's address and the adapter's row; a Goodfetch adapter answers the settings it set), `run` (one task) and `close`. A call past its time stops the adapter and fails alone; the calls beside it fail as `sibling_abort`. A slot restarts a stopped adapter with a new generation, up to the campaign's limit.
- `adapters/goodfetch/`: the Goodfetch adapter, `--product collie|foxhound`. It drives one Product through its own SDK, the smallest that carries the task's kind (ADR 0094): Collie reads the catalog's product page (`extract`), Foxhound crawls its listing (`crawl`); a task of another family is `unsupported`. Each `run` starts a Run, or a crawl, with its row's settings and the ones that reach the Proving ground. `tests/campaigns/goodfetch.json` is its smoke campaign, which `tests/goodfetch.test.ts` runs on each Product's executable of the commit.
- `src/proving-ground.ts`: the Proving ground's task list and oracle, on the address it answers on.
- `src/order.ts`: the seeded order of the adapters in each block, and the nearest-rank quantile.
- `src/cell.ts`: a cell's attempts and its metrics. The failure rate counts failed, falsely successful, incomplete, timed-out and crashed attempts against the verified ones; a timeout's aborted siblings count for neither.
- `src/runner.ts` and `src/cli.ts`: a run. Each block runs its adapters in a seeded order; each cell (an adapter on a task in a block) runs a conformance attempt, the warmup, then the measured attempts in a closed loop, and a cell that fails its gate is not measured. An attempt's status is the oracle's outcome, or what its error's code says. The run writes `run.json` (provenance, host, Proving ground seed and task digests, each cell's metrics) and `attempts.jsonl` in a new folder:

  ```sh
  node bench/src/cli.ts run <campaign.json> --proving-ground <address> --out <folder>
  ```

- `src/registry.ts`: decisions and claims (ADR 0025), declared before measuring, as JSON documents in a registry folder's `decisions/` and `claims/`. A decision names its options (each one adapter), its baseline, its primary metric, its contract gates, its minimum effect Δ and its fixed rule; a claim names its decision, metric, comparator, direction and Δ. A campaign's `registry` names the folder and the decisions it measures: the whole registry is checked, and nothing in it may be dated after now, before anything runs (`registry_refused`). The run record keeps what it declared with its dates, so evidence from a run that did not declare a claim, or started before it, is refused. Editorial text carries no measured figure.
- `src/stats.ts`, `src/verdict.ts` and `src/comparison.ts`: verdicts. Each option is paired with the baseline by block and task, and the per-pair log ratios give one of eight mechanical outcomes from the seeded block bootstrap, with at least five pairs and more when they scatter, Hodges–Lehmann and the exact signed-rank test beside it. A failed contract gate blocks the verdict whatever the effect.
- `src/statistics.ts`: an attempt set's counts and latencies, the verified rate with its 95% Wilson interval, pass^k, the bound a zero count can claim at its trial count, and Evaluations' regression statistic, in percentage points of verified rate against a baseline (ADR 0065).
- `src/ledger.ts`: the results ledger, each run beside a person's classification of it, as the lab's.
