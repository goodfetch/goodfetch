# Two-level fencing: work-item leases and a run epoch, with at-least-once delivery

A user handler runs out of process and may keep running after it has timed out, and a migrated run may leave a zombie copy alive on the old machine. So each work item is leased with a monotonic epoch, and the run itself carries an epoch that every resume increments. Handlers are delivered at least once, but their outputs are staged and become visible exactly once, when the current attempt commits under a valid lease and epoch. Decided in [Adopt runtime and state decisions](https://github.com/Jbmanllr/automan/issues/70).

## Considered Options

- **Expiring locks only**: rejected. Crawlee's locks expire but do not stop a late commit, and Scrapy and spider-rs hold no lease at all. Temporal, Hatchet, Restate and DBOS all reject a stale attempt's commit, and Restate also fences a superseded leader by epoch.
- **Checking each raw CDP message against the lease**: rejected. It parses every message and stops nothing more than cutting the attach does.

## Consequences

- The run epoch cannot be enforced inside the run's own file, since a zombie copy writes to its own copy and believes its epoch is current. Every write leaving the engine (checkpoint, export, sink write) carries the epoch, and the destination enforces it: the cloud either kills the old copy before resuming or rejects stale epochs with a compare-and-set. A conformance test runs two copies of one run against such a store.
- Inside the engine, every outgoing browser or network command is checked against the work item's lease, so a handler past its lease can send nothing more. This does not stop a zombie copy; only the measures above do. ADR 0033 narrows this to the engine's own commands: a Plugin's streams at `proxy_tcp` or `direct` are not checked per command, and their writes stay fenced at the destination. A raw CDP client (ADR 0017) reaches a browser only through an endpoint Goodfetch serves: the engine's relay, or the Browser host's beside a hosted browser (ADR 0022). When a handler opens raw CDP for a work item, the endpoint issues a token for that attach alone, scoped to the work item's Session and bound to its lease, which narrows ADR 0017's per-Session token; the Session serves no other work item until the attach ends, so one work item's cut never reaches another's connection, and a later attach gets a new token. When the lease ends, the endpoint first answers every command still in flight with the error `lease_ended` (reason `lost` or `released`, with the work item's ID), then closes that attach's connections with the same close reason and revokes its token; the Audit log records the cut beside the attach, and Goodfetch's helpers that attach Playwright or Puppeteer raise it as a typed error. A Browser host receives the lease's expiry with each renewal and cuts the attach by itself when the expiry passes unrenewed or its link to the engine drops, so a dead or cut-off engine leaves nothing driving the hosted browser. Commands a raw client sent before the cut are not fenced: they reach websites, outside the Effect journal. Raw CDP opened outside any work item, such as on a kept-alive Session (ADR 0001), holds no lease and stays governed by its token's lifetime and revocation (ADR 0017). Decided in [V1 scope sign-off: parity and pain coverage](https://github.com/Jbmanllr/automan/issues/81).
- A lease lasts the handler timeout plus a margin, a renewal only lengthens it, and expiry is judged on the engine's monotonic clock alone.
- Fencing cannot undo an effect a website has already received. The engine offers an effect journal to every run: an effect is checked rather than repeated on resume, and reported as uncertain when it has no check. When agents must use it is decided in [Adopt AI and agent decisions](https://github.com/Jbmanllr/automan/issues/72).
