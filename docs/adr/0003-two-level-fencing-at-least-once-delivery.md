# Two-level fencing: work-item leases and a run epoch, with at-least-once delivery

A user handler runs out of process and may keep running after it has timed out, and a migrated run may leave a zombie copy alive on the old machine. So each work item is leased with a monotonic epoch, and the run itself carries an epoch that every resume increments. Handlers are delivered at least once, but their outputs are staged and become visible exactly once, when the current attempt commits under a valid lease and epoch. Decided in [Adopt runtime and state decisions](https://github.com/Jbmanllr/automan/issues/70).

## Considered Options

- **Expiring locks only**: rejected. Crawlee's locks expire but do not stop a late commit, and Scrapy and spider-rs hold no lease at all. Temporal, Hatchet, Restate and DBOS all reject a stale attempt's commit, and Restate also fences a superseded leader by epoch.
- **Checking each raw CDP message against the lease**: rejected. It parses every message and stops nothing more than revoking the token and closing the connection does.

## Consequences

- The run epoch cannot be enforced inside the run's own file, since a zombie copy writes to its own copy and believes its epoch is current. Every write leaving the engine (checkpoint, export, sink write) carries the epoch, and the destination enforces it: the cloud either kills the old copy before resuming or rejects stale epochs with a compare-and-set. A conformance test runs two copies of one run against such a store.
- Inside the engine, every outgoing browser or network command is checked against the work item's lease, so a handler past its lease can send nothing more. This does not stop a zombie copy; only the measures above do. ADR 0033 narrows this to the engine's own commands: a Plugin's streams at `proxy_tcp` or `direct` are not checked per command, and their writes stay fenced at the destination. A raw CDP client (ADR 0017) reaches a browser only through an endpoint Goodfetch serves, the engine's relay or the Browser host's beside a hosted browser (ADR 0022), with a per-Session token. When a handler opens raw CDP for a work item, that token is also bound to the work item's lease: when the lease ends, lost or released when the handler finishes, the endpoint revokes the token, closes its connections with the WebSocket close reason `lease_lost` and the work item's ID, and answers every command still in flight with the same error, and the Audit log records the cut beside the attach. For a hosted browser, the user's engine, which holds the lease, revokes the token through the Browser host's protocol; a write that slips out before the revocation lands stays fenced at its destination. Goodfetch's helpers that attach Playwright or Puppeteer raise the close reason as a typed error. Raw CDP opened outside any work item (a kept-alive Session, an interactive Session from the Console) holds no lease and stays governed by the token's lifetime and revocation. Decided in [V1 scope sign-off: parity and pain coverage](https://github.com/Jbmanllr/automan/issues/81).
- A lease lasts the handler timeout plus a margin, a renewal only lengthens it, and expiry is judged on the engine's monotonic clock alone.
- Fencing cannot undo an effect a website has already received. The engine offers an effect journal to every run: an effect is checked rather than repeated on resume, and reported as uncertain when it has no check. When agents must use it is decided in [Adopt AI and agent decisions](https://github.com/Jbmanllr/automan/issues/72).
