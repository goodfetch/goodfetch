# Two-level fencing: work-item leases and a run epoch, with at-least-once delivery

A user handler runs out of process and may keep running after it has timed out, and a migrated run may leave a zombie copy alive on the old machine. So each work item is leased with a monotonic epoch, and the run itself carries an epoch that every resume increments. Handlers are delivered at least once, but their outputs are staged and become visible exactly once, when the current attempt commits under a valid lease and epoch. Decided in [Adopt runtime and state decisions](https://github.com/Jbmanllr/automan/issues/70).

> Amended by [ADR 0103](0103-a-handler-pushes-records-staged-with-its-attempt-into-datasets-its-crawl-declares-and-a-reader-never-slows-the-crawl.md): a handler's Records, enqueues and Key-value store writes through its context and its attempt-bound `ctx.run` are its staged outputs; a write a handler makes through the program's own Run value is the program's, committed at once and fenced by no lease.

## Considered Options

- **Expiring locks only**: rejected. Crawlee's locks expire but do not stop a late commit, and Scrapy and spider-rs hold no lease at all. Temporal, Hatchet, Restate and DBOS all reject a stale attempt's commit, and Restate also fences a superseded leader by epoch.
- **Checking each raw CDP message against the lease**: rejected. It parses every message and stops nothing more than cutting the attach does.
  > Amended by [ADR 0089](0089-a-page-is-lent-through-an-endpoint-that-shows-only-its-session-and-collie-joins-other-crawlers-by-borrowing.md): the endpoint of a Lent page does parse each message, to keep the attach inside the lent page's Session; that is scoping, which cutting the attach cannot do, and the lease is still enforced by the cut alone.

## Consequences

- The run epoch cannot be enforced inside the run's own file, since a zombie copy writes to its own copy and believes its epoch is current. Every write leaving the engine (checkpoint, export, sink write) carries the epoch, and the destination enforces it: the cloud either kills the old copy before resuming or rejects stale epochs with a compare-and-set. A conformance test runs two copies of one run against such a store.
- Inside the engine, every outgoing browser or network command is checked against the work item's lease, so a handler past its lease can send nothing more. This does not stop a zombie copy; only the measures above do. ADR 0033 narrows this to the engine's own commands: a Plugin's streams at `proxy_tcp` or `direct` are not checked per command, and their writes stay fenced at the destination. A raw CDP client (ADR 0017) reaches a browser only through an endpoint Goodfetch serves: the engine's relay, or the Browser host's beside a hosted browser (ADR 0022). The exception is a Borrowed browser that other code also drives (the person's own code, or, on their running browser, the person and their other tools; ADR 0056): that code holds its own CDP session, its commands are never fenced by a lease, the run's results are marked unguarded, and the run is marked as sharing its browser. When a handler opens raw CDP for a work item, the endpoint issues a token for that attach alone, scoped to the work item's Session and bound to its lease, which narrows ADR 0017's per-Session token. The request reserves the Session at once: the engine gives it no new work item, grants the attach when the other work items on it finish, and the wait counts against the requesting lease; if that lease ends before the grant, the request fails with `attach_ended` and the lease's reason, and the reservation is released; a second attach request on a reserved Session is refused with the typed error `session_reserved`, so two attaches never wait on each other. The Session stays reserved until the attach ends, and then stays out of any Session pool unless saved explicitly (ADR 0017); a later attach gets a new token. When the lease ends, the engine ends the attach: the endpoint answers every command still in flight with the error `attach_ended` (reason `lease_lost` or `lease_released`, with the work item's ID), then closes that attach's connections with the same reason and revokes its token. For a hosted browser, the engine sends the Browser host that end with its reason, and the Browser host reports the cut back. As a fail-safe that can only cut, the grant and each renewal give the Browser host the lease's remaining time, which it counts on its own monotonic clock; when that time runs out, possibly up to one message's transit after the engine's own expiry, or when its link to the engine drops, it ends the attach by itself the same way with the reason `unconfirmed`, since it cannot know whether the lease ended. The engine records each cut in the Audit log beside the attach: a Browser host's own cut when its report arrives or as `unconfirmed` when the link dropped, and, after a crash, every attach with no recorded cut as `unconfirmed` when an engine next takes the writer role on the run (by taking the lock file and the next run epoch locally, ADR 0031, or the next run epoch in Goodfetch Cloud), whatever it then writes, such as resuming the run, applying a person's answer to it or recording it `stopped`; until then, a reader that finds no live writer shows such an attach as `unconfirmed` without writing. A run resumed from a checkpoint after its machine was lost (ADR 0002) loses the attaches opened after that checkpoint together with their cuts, as it loses every later journal entry; an attach opened before that checkpoint whose cut came after it is recorded as `unconfirmed` by the rule above. Goodfetch's helpers that attach Playwright or Puppeteer raise `attach_ended` as a typed error. Commands a raw client sent before the cut are not fenced: they reach websites, outside the Effect journal. Raw CDP opened outside any work item, such as on a hosted Session kept alive ([Cloud readiness](https://github.com/Jbmanllr/automan/issues/69), ADR 0022), holds no lease and stays governed by its token's lifetime and revocation (ADR 0017). Decided in [V1 scope sign-off: parity and pain coverage](https://github.com/Jbmanllr/automan/issues/81).
- A lease lasts the handler timeout plus a margin, a renewal only lengthens it, and expiry is judged on the engine's monotonic clock alone.
- Fencing cannot undo an effect a website has already received. The engine offers an effect journal to every run: an effect is checked rather than repeated on resume, and reported as uncertain when it has no check. When agents must use it is decided in [Adopt AI and agent decisions](https://github.com/Jbmanllr/automan/issues/72).
