# Fair per-domain admission by default, with fairness before priority

The engine admits work through bounded per-domain queues served round-robin under a global cap, rather than through one global queue: with one heavy domain under overload, small domains got 2.6 times more work in the lab, and Scrapy made a similar change its default in 2.14 after one domain took every global slot. A domain is the registrable domain under the full Public Suffix List, private entries included, and a recipe can override the key. Decided in [Adopt runtime and state decisions](https://github.com/goodfetch/goodfetch/issues/70).

## Considered Options

- **Global FIFO queue** (Crawlee v3): rejected as the default. It is simpler, but one dominant domain starves the rest, and with a single site fair admission collapses to the same order anyway.
- **Priority first across domains** (Mercator): rejected. Round-robin picks the domain and priority orders requests within it, so a high priority on one domain never starves another, and cannot jump ahead of it either.
- **Hostname as the key** (Scrapy): rejected, because subdomains of one site usually share one server.

## Consequences

- A domain waiting out a politeness delay or a backoff is not ready and holds no global capacity; the cap counts only requests in flight.
- The global cap is now the ceiling of the engine's resource governor, which sizes concurrency from measured load and serves runs in turn before domains (ADR 0040).
- Per-domain queues are journaled and survive a resume; drained queues are released, so per-domain state stays bounded.
  > Note (agent decision, accepted by the owner on 2026-10-21), 2026-10-21, [#227](https://github.com/goodfetch/goodfetch/issues/227): the per-domain queues live in `goodfetch-frontier` under `crates/foxhound/` (the Frontier admits each Crawl request), which passes them to the engine as the gate in admission, `goodfetch_engine::admission::Gate`, a value of its contribution; the engine names no Foxhound type. Each domain's queue holds at most 64 requests, highest priority first and then in the crawl's own order (a retried work item keeps its place), and the rest wait in the run file, where each pending work item carries its domain key and priority, so its queue fills again from there when it drains and after a resume. Each domain's wait and backoff are journaled in the run file's `domains` table, and a domain with nothing waiting, in flight or to wait for is released, its row deleted. The key's override is the setting `crawl.domain_keys`, host names each mapped to the key they and the hosts under them share, the longest name winning, which a Recipe sets like any key. Until [#1541](https://github.com/goodfetch/goodfetch/issues/1541) adds jitter, a domain's backoff is 2 s doubling up to 60 s, a pure function of the reading it is given; a handler's `deadline_exceeded` whose `limit` is `timeout.first_byte` or `timeout.navigation` triggers it now, as a timed-out connection does under ADR 0086, and a 429, a 503 and a `Retry-After` join with the fetch tiers and #1541, and the per-domain cap and delay are [#239](https://github.com/goodfetch/goodfetch/issues/239)'s. The global cap is still `crawl.handler.concurrency` until the governor ([#234](https://github.com/goodfetch/goodfetch/issues/234)).
- The count in flight, the backoff and the halving per domain are shared by every run of the user that uses the same key, and across machines through a Politeness store; the queues and their order stay per run (ADR 0053).
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): so is the time of the domain's last request start, which the delay counts from.
- Each turn admits one request per domain: no weights or larger turns for some domains in V1. Politeness defaults (8 requests in flight per domain, backoff on 429, 503 and `Retry-After`) and the optional per-IP limit are set in ADR 0021.
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the defaults are 1 request in flight and at least 1 s between two request starts per domain. A 502, a 504, and a connection that is refused or times out back off too, and crawl requests obey robots.txt.
  > Note (spec [#2194](https://github.com/goodfetch/goodfetch/issues/2194), decided with the owner on 2026-11-07), 2026-11-16, [#2197](https://github.com/goodfetch/goodfetch/issues/2197): at `crawl.domain_order: fewest_in_flight`, the default, a free request slot goes to the ready domain key with the fewest of the Run's requests in flight, ties broken in the turn's order, so a slow site never holds every slot; `round_robin` keeps this turn. A ready key is one no Politeness `Wait` holds, not backing off and not at its 429 ceiling. The count is the queues' own: it rises when the gate admits a request and falls when that attempt's end comes back. The queues index the keys by when each is ready and, among the ready ones, by that count and turn, so a choice costs a logarithm of the keys with a request waiting, plus the keys whose wait ended since the last admission, and never a walk of every key. At one request in flight per key, as ADR 0086 sets, every ready key has none in flight, and both orders admit alike.
- The decision rests on the mechanism, head-of-line blocking by one domain, not on the size of the lab effect, whose verdict is still `insufficient-n` (5 of 22 blocks). The V1 benchmark measures the missing blocks; only a measurable slowdown on single-domain crawls would reopen it.
