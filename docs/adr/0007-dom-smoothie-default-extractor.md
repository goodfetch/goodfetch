# dom-smoothie is the default main-content extractor, not rs-trafilatura

The default chain is dom-smoothie for main content, htmd for Markdown, html5ever/scraper for selectors and fields, and lol-html for the fast streaming read of links, meta tags and title. rs-trafilatura, the R&D's choice, ships as a selectable alternative behind the same extractor interface. On the independent WebMainBench corpus (545 pages) dom-smoothie beats rs-trafilatura by 0.025 word F1 (CI above zero) and runs 5 to 6 times faster; rs-trafilatura's 0.06 lead on WCXB is not confirmed on an independent corpus. The reversal is consistent with a bias in WCXB, whose answer keys were drafted from rs-trafilatura's own output for 504 of 511 pages before review, but that cause was not tested. Decided in [Adopt collection decisions](https://github.com/goodfetch/goodfetch/issues/71), on the lab re-run of [PR 87](https://github.com/goodfetch/goodfetch/pull/87).

## Considered Options

- **rs-trafilatura as default**: rejected. One maintainer, no commit since April 2026, three bugs filed in October, and machine-learning layers that Python trafilatura does not have. It ships vendored in a fork Goodfetch can patch, pinned to a reviewed version.
- **lol-html for main content**: rejected. It is a streaming rewriter with no document tree and reached only all-body-text quality on WCXB; it reads fields at 0.27 of scraper's time with 99.6% or more agreement, which is what it is adopted for.
- **mdka or html2md for Markdown**: not adopted yet. mdka leads htmd by 0.045 on WebMainBench, short of a formal verdict. htmd (112 dependent crates) is kept and its two measured defects are fixed upstream: code in `<pre>` without `<code>`, and tables with row headers. If mdka still leads by more than 0.03 after those fixes, the converter switches.
  > Note (agent decision, accepted by the owner on 2026-10-22; [#783](https://github.com/goodfetch/goodfetch/issues/783)): until htmd takes them upstream, `goodfetch-extractor` carries both fixes as htmd element handlers of its own, each with a fixture that fails without it, and a third the 30 fixtures need, which every converter but html2md lacked: a heading with a `<br>` stays one heading. Offering the fixes upstream is a pull request to htmd's repository, a public action an agent does not take. The 30 fixtures are the Proving ground's `extraction/7` task, judged by Markdown structure as the lab's oracle judged them, with a heading's level, a code block's language and a link's relative or absolute form not counted, and case and paragraphs counted.

## Consequences

- The 30 hand-written Markdown fixtures become a V1 conformance suite.
- The Markdown converters were compared on rs-trafilatura's content HTML; the adopted dom-smoothie then htmd chain is measured again before the switch rule above is applied.
- No surveyed competitor uses a trafilatura-class extractor: Jina and Apify use Readability, Firecrawl a fixed list of selectors to remove, Crawl4AI its own pruning filters, and Crawlee, Scrapy and Stagehand none in their core.
- Before the extractor, the engine removes the elements matched by the cosmetic rules of the Clean-up rules, in every tier; raw HTML, WARC, Run traces, the lol-html link reading above and the user's own selectors see the page untouched (ADR 0047).
  > Note (agent decision, pending owner review; [#785](https://github.com/goodfetch/goodfetch/issues/785)): how much of the page a call reads. `markdown.content: "full"` is the cleaned, composed document's `<body>` as Markdown, read whether or not the page has main content. `"fit"` is the main content's HTML pruned from its outermost blocks inward before htmd writes it: a block (a paragraph, list, list item, table, quotation, figure, `div`, section or the like; never a heading or code) is left out when more than half its text, white space aside, is in `<a href>` links, when it holds an image and no text, or, for a list, when the page holds another list whose links go to the same paths in the same order. `html.raw` is the document as it stands: as served on a document tier, and on the browser tier the DOM's serialization with the `<template shadowrootmode>` of each shadow root taken out, byte for byte otherwise, which is what Playwright's `content()` returns; `html.cleaned` is the same after the cosmetic rules; `html.main` is dom-smoothie's content. `text` is the main content's text, a paragraph per block, one blank line apart. The Proving ground's `extraction/8` task holds two pages with every form written by hand; its oracle judges Markdown by structure, HTML by the text of its blocks and text white space aside.
  > Note (agent decision, pending owner review; [#786](https://github.com/goodfetch/goodfetch/issues/786)): links, images, media and tables as values. `links` lists each `<a href>` and `<area href>`, `images` each `<img src>`, `media` each `<video src>`, `<audio src>` and `<source src>` inside either (with `kind` and the `<source>`'s `type`), in document order, read by one lol-html pass over the document as it stands: its shadow roots' templates included, no Clean-up rule applied. lol-html passes attribute values and text through as written, so the pass decodes their character references as the HTML standard's tokenizer does, with html5ever's table of names (a property test compares it with html5ever's tree). `href` and `src` are kept as decoded; `url` is that value resolved against the document's base URL by the `url` crate's WHATWG parser, `null` when it does not parse; a link's text has its white space collapsed and its `rel` is split into tokens; `alt` is `null` when absent and `""` when empty. A query is encoded as UTF-8 whatever the document's encoding. `srcset`, `poster` and `<track>` are not read. `tables` reads scraper's html5ever tree of the cleaned, composed document: header rows are a `<thead>`'s, else the leading rows whose cells are all `<th>`; body rows follow, a `<tfoot>`'s last; each cell is one string, its text with white space collapsed, a `<br>` read as a space and a nested table left out (it is listed on its own); `colspan` and `rowspan` are not expanded. `page_formats_schema` derives from the serialize contract, so a nullable field such as `url` stays required in a Dataset's schema. The Proving ground's `extraction/9` task holds three hand-written pages (a `<base href>`, a redirect, tables) whose formats its oracle judges as JSON values.
  > Note (agent decision, pending owner review; [#788](https://github.com/goodfetch/goodfetch/issues/788)): the setting `content.extractor` takes `dom_smoothie` (the default) or `trafilatura`, at a Run, a Session's or a page's own `settings` (`run.new_page` and `session.new_page` take `settings`, holding only this key for now) and the configuration layers. rs-trafilatura is the crates.io release `=0.2.2` the lab reviewed, not yet a vendored fork: the fork is made the day a patch is needed, through Cargo's `[patch.crates-io]`, with no code change; its debug notes to stderr are switched off by turning debug assertions off for it in the `dev` profile. It runs with its fallback extraction and its least sizes off, with which it writes a short page's headings, lists and tables; with them on, it answered a short page as one run-together paragraph. Every step is held to one composition rule: a document with no text outside its navigation landmarks has no main content, and a step that finds no text in a document that holds some answers what is left of its body outside those landmarks (pitfall D02): rs-trafilatura finds none on a page holding only a list of links. The connection scope comes with the SDKs' `connect()` settings (#1245).
