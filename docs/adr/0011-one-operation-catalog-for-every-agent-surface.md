# One Operation catalog serves every agent surface

The engine exposes one typed Operation catalog, each operation classed read, idempotent write or Effect, and generates every agent surface from it: an MCP server (stdio and Streamable HTTP), the SDK methods, the CLI with `--json`, agent skills, and thin tool adapters for the Vercel AI SDK, LangChain/LangGraph (TypeScript and Python) and Mastra; the Claude Agent SDK uses the MCP server directly. Coding agents get the CLI plus skills, agent apps get MCP, and both can use code mode: a short model-written program that runs in the Script sandbox (ADR 0051) with no network or files, only catalog calls (journaled), and time and memory limits; it is opt-in in MCP profiles. The same sandbox runs Script Hooks (ADR 0033). Profiles trim the catalog so tool definitions stay short. Decided in [Adopt AI and agent decisions](https://github.com/goodfetch/goodfetch/issues/72).

> Amended by [ADR 0095](0095-both-products-speak-one-protocol-from-one-catalog-marked-by-product-and-their-sdks-share-collies-client-packages.md): the catalog stays one, and each operation names the smallest Product that carries it, Collie or Foxhound. Each Product's surfaces are generated from its own catalog, Foxhound's carrying every operation of Collie's under the same name. MCP profiles carry the same mark, so a Collie profile offers the same tools in both Products, and Framework adapters exist once per Product.

Evidence: lab [code-mode report](https://github.com/goodfetch/goodfetch/blob/main/rnd/lab/reports/code-mode-journal-2026-10-09.md) and [AI-in-the-loop browser frameworks](https://github.com/goodfetch/goodfetch/blob/research/ai-browser-frameworks/rnd/research/2026-10-10-ai-browser-frameworks.md) §6.

## Considered Options

- **Hand-written wrappers per agent framework**: rejected. MCP reaches all 15 frameworks surveyed and dedicated wrappers see little use (Firecrawl's MCP server has about 117k weekly downloads, framework wrappers tens to thousands); generated adapters cost a few dozen lines each.
- **The CLI for humans only**, the R&D's position: rejected. Playwright now steers coding agents to its CLI plus skills and Midscene dropped MCP; the lab's model-dependent CLI result (Haiku left 18 of 45 tasks unfinished, without skills) becomes a lab campaign and a documented warning.
- **Code mode without a sandbox or journal**: rejected. Raw code mode gave false successes in the lab, and an open LaVague report shows prompt injection reaching code execution through eval of model output.

## Consequences

- Other frameworks (OpenAI Agents SDK, Pydantic AI, CrewAI, Google ADK, LlamaIndex, Strands) connect through their MCP clients, each with a tested docs page.
- Observations carry stable element references, send diffs after the first one, and include a screenshot only when the page changed.
  > Amended by [ADR 0091](0091-collies-ai-verbs-live-on-the-page-replay-from-a-plan-file-the-run-names-and-expect-runs-a-success-check.md): in the SDKs an observation is `ariaSnapshot()` with no diffs, since a diff against the previous call is hidden state (ADR 0077's G2), and an element reference lasts as long as its element; the MCP server keeps diffs within its own session.
- One web search operation takes interchangeable providers: search APIs (Brave, Exa, Tavily, Perplexity, Mojeek, Kagi) and SearXNG with the user's key or URL, each flagged for whether its results may be kept in the run; a Model provider's built-in search, offered only as an option of AI operations and never as a source of links to crawl, as Google's grounding terms require; and opt-in browser search, DuckDuckGo by default, which stops at the first challenge and never masks itself. Evidence: [web search sources research](https://github.com/goodfetch/goodfetch/blob/research/web-search-sources/rnd/research/2026-10-10-web-search-sources.md).
- Sites' own WebMCP tools join the catalog as Effects unless marked read-only; a crawl configured from a prompt compiles into a configuration reviewed before it runs.
- Some writes are offered on no agent surface: `trusted_cas`, certificate pins and `any`, and the answers to `goodfetch certs accept` and `certs forget` (ADR 0042), and widening `pay_domains` or `max_price_per_page` and writing the rates and chain RPC endpoints of Paid fetches (ADR 0045), and widening `consent_domains` (ADR 0048), and widening `wall_domains` or `wall_refetch_domains` and changing `wall_denied_domains` (ADR 0052; `wall_refetch_domains` never through an answer, `wall_denied_domains` only in Operator policy) happen only in the Console, an interactive CLI prompt, configuration files or Operator policy. A run may still narrow `pay_domains`, `max_price_per_page`, `consent_domains`, `wall_domains` and `wall_refetch_domains` through any surface. A Filter list added through an agent surface contributes network and cosmetic rules only, never scriptlets (ADR 0047). The clear-text `storageState` export of a Saved identity (ADR 0056) is offered on no agent surface either, only in the Console or an interactive CLI prompt.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): reading and writing a Session's cookies (`cookies`, `addCookies`, `clearCookies`) and a page's storage (`localStorage`, `sessionStorage`) is offered in the SDKs only, to the program's own code: no CLI command, MCP tool, skill, Framework adapter or Code mode offers it, since a coding agent drives the CLI and a logged-in Session's cookies and storage never reach a model (ADR 0014).
  > Amended by [ADR 0137](0137-the-console-leaves-both-products-and-the-engine-and-the-owners-monitoring-tool-is-designed-apart.md): no Product carries a Console. The engine behaviour this ADR describes stands and the Console's part does not; a Client reaches it.
- ADR 0051 runs the Script sandbox in V8 without JIT, in a worker confined as a Plugin at network level `none`, one set per run; a program is JavaScript or type-stripped TypeScript, the body of an `async` function, calling catalog namespaces as async globals named as in the TypeScript SDK.
