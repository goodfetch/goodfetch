# AI safety is enforced by the engine, not by the model or the client

The engine enforces each run's domain policy on every request type (navigation, subresources, workers, WebSockets, WebRTC, `javascript:` URLs) through browser-protocol interception, and fails closed: a request the policy cannot judge is blocked. Page content is wrapped as untrusted in every observation. Effects an AI decides in the categories payment, account creation, accepting terms, sending messages and deletion ask for confirmation unless the run allows them, and vendor safety signals are journaled. Secrets are `%var%` placeholders the engine types at the moment of input, bound to the domains allowed to receive them, with the target field re-checked first; they never reach the model, Plans, caches, the journal, observations or logs, and are masked in screenshots, recordings and traces. The cookies and storage of a logged-in Session, including one seeded from an import, a Profile directory or a Borrowed browser (ADR 0056), never reach a model or an observation either. Decided in [Adopt AI and agent decisions](https://github.com/goodfetch/goodfetch/issues/72).

> Note (agent decision, on a guarantee, not read by the owner), 2026-10-22, [#620](https://github.com/goodfetch/goodfetch/issues/620): the domain policy is `egress.allowed_domains` and `egress.blocked_domains`, judged before any lookup by `goodfetch-engine`'s `egress::judge`, first on the engine's own HTTP client. Hosts and entries are both read as the WHATWG parser reads a host (punycode, any IPv4 spelling, an IPv6 entry with or without brackets), and one trailing dot is dropped from either, so `elsewhere.test.` cannot pass a block on `elsewhere.test`; an entry that is no host (a path, a port, a `*` label) is refused. `egress_refused`'s `setting` is omitted where no setting would allow the request (a URL that does not parse, a scheme no request may use, a request whose kind interception cannot see); a URL that does not parse and a kind interception cannot see are refused under `rule: "domain_policy"`. A refused request no call waits on is the catalog event `page.request_failed` (`url`, `method`, and `failure` as an error's `data`), recorded as a line of `trace/requests.jsonl` in the Run's folder; its publication on the event stream arrives with the browser's page events. Both keys keep the authority `every` until the narrowing rule for a Recipe and a Client acting for a model lands ([#624](https://github.com/goodfetch/goodfetch/issues/624)), since the list check would count a run's own `["scope.test"]` as widening the default `["*"]`.

> Note (agent decision, on a guarantee, not read by the owner), 2026-10-26, [#624](https://github.com/goodfetch/goodfetch/issues/624): both keys now take the authority `hosts_narrowed_by_recipe_or_model`. A Recipe's value, and a value a Client acting for a model gives at any layer, must narrow the value of the layers below as hosts, not as text: an `egress.allowed_domains` entry is taken when an entry below covers it (the same host, a subdomain of it, or `*`), and an `egress.blocked_domains` value is taken when it covers every entry below. Entries are read as the egress policy reads them, so `WWW.Scope.Test.` narrows `scope.test`; an entry that is no host covers nothing and is never taken from them. A widening value is `setting_locked` naming the key and the value below. The program's own code and configuration still set any value (spec #563's settings table).

> Note (agent decision, on a guarantee, not read by the owner), 2026-10-24, [#632](https://github.com/goodfetch/goodfetch/issues/632): on Chromium, each kind of request is held as follows. A page's own requests, a dedicated worker's (which pass its page's target) and an out-of-process frame's (each frame attached before it runs, its requests paused on its own target and passed through its page's pipeline) go through the page's interception; a service worker's and a shared worker's, attached before they run, go through their Session's; a frame or worker whose requests cannot be paused never runs. No browser-protocol interception sees a WebSocket's handshake or a WebRTC connection (the pinned Chromium pauses neither in `Fetch`, and `Network.setBlockedURLs` blocks no WebSocket), so the engine launches each browser whose Run's domain policy refuses any host with that policy as a proxy auto-config script (`egress::Policy::proxy_script`, `--proxy-pac-url` as a `data:` URL), which sends every connection the browser makes to a refused host to an unreachable `.invalid` proxy and every other one direct, and holds WebRTC to TCP (`--webrtc-ip-handling-policy=disable_non_proxied_udp`), so a refused host's WebSocket and TURN connection never leave and an allowed one's pass. A refused WebSocket of a page or an out-of-process frame is recorded as `page.request_failed` with `egress_refused` in the Run trace; a refused WebRTC connection, of which the browser reports nothing, is not recorded. The script holds only data and one fixed function, since Chromium connects directly when a script fails. It does not hold a Session with its own proxy, whose browser context's proxy replaces it, nor a Borrowed browser: their WebSockets and WebRTC are held once the egress relay (#634) carries every Session's traffic, which replaces the script.

> Note (accepted by the owner on 2026-10-28, the deep review's O13): within one Run, a Secret reference is resolved once for each placeholder it fills, and its value reused for the rest of the Run, as the Run already holds it until its end; the domain binding and the exception hosts are checked again at every use, and every use is recorded in the Audit log. Resolutions of one reference at once wait for the one in flight, so they make one call to its provider. A provider that answers it is briefly busy (`ProviderFailure::Busy`: a rate limit's 429, a 503, a token authority that is temporarily unavailable) is asked again within `timeout.secret`, after its `Retry-After` in seconds when it gave one, or after a wait drawn from the engine's `Entropy` with full jitter under a cap that doubles from 200 ms to 5 s; when the next ask would fall past `timeout.secret`, the resolution fails `provider_failed` with the provider's fix. An attempt that hangs still ends at `timeout.secret` as `timed_out`. A rotating secret's reference is listed in `secrets.resolve_each_use`, and resolved again at each use.

## Considered Options

- **Allowlists in the client library**: rejected. Domain allowlists were bypassed in Stagehand, Browser Use and Skyvern, and Playwright MCP calls its own filters "not a security boundary".
- **Relying on the model vendors' safety**: rejected as the only layer. OpenAI, Anthropic and Google ship classifiers and confirmations, but local and gateway models may not.

## Consequences

- An injection classifier on pages can be switched on (Firecrawl's precedent).
- Secrets are stored behind Secret references and Secret providers (ADR 0015). A run may switch redaction off, which lifts the guarantee above for logs, traces, HAR files, screenshots and recordings kept as outputs only (ADR 0016).
- A raw CDP client can switch off browser-protocol interception, so a Session with raw CDP attached is held to the domain policy at the network layer instead (ADR 0017), except on a Borrowed browser, where no network layer can be put under the browser: there the domain policy is enforced by interception, which a raw client can switch off, and the run is marked unguarded (ADR 0056).
- For payments, a run's allowance is `pay_domains`, which only Operator policy, user and project configuration or a person's answer can widen; no payment goes to a domain outside it (ADR 0045).
- For Consent prompts, the only allowance for accepting terms is `consent_domains`, never a run's general allowance, which only Operator policy, user and project configuration or a person's answer can widen (ADR 0048).
