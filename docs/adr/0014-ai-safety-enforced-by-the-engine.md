# AI safety is enforced by the engine, not by the model or the client

The engine enforces each run's domain policy on every request type (navigation, subresources, workers, WebSockets, WebRTC, `javascript:` URLs) through browser-protocol interception, and fails closed: a request the policy cannot judge is blocked. Page content is wrapped as untrusted in every observation. Effects an AI decides in the categories payment, account creation, accepting terms, sending messages and deletion ask for confirmation unless the run allows them, and vendor safety signals are journaled. Secrets are `%var%` placeholders the engine types at the moment of input, bound to the domains allowed to receive them, with the target field re-checked first; they never reach the model, Plans, caches, the journal, observations or logs, and are masked in screenshots, recordings and traces. The cookies and storage of a logged-in Session, including one seeded from an import, a Profile directory or a Borrowed browser (ADR 0056), never reach a model or an observation either. Decided in [Adopt AI and agent decisions](https://github.com/goodfetch/goodfetch/issues/72).
> Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): a Secret placeholder's domains are checked against the frame holding the target field, or against a request's URL at every redirect hop for a header or a JSON body a request sends; and the engine masks every value it resolved, by value and in the forms it builds from it (a Basic `Authorization` header), as `%name%`, in everything a call returns or an event carries (reads, page function results, extracted values, Records, response bodies, errors, page and network events) as well as in what it keeps, except a value too short to mask safely everywhere, such as a one-time code, which is masked where it was typed and in what it keeps.

> Amended by [ADR 0089](0089-a-page-is-lent-through-an-endpoint-that-shows-only-its-session-and-collie-joins-other-crawlers-by-borrowing.md): this enforcement covers the engine's own AI. A library attached to a Lent page, a model-driven one such as Browser Use included, acts outside it, except for the domain policy, enforced as ADRs 0017 and 0056 say: its model gets no Effect confirmation and no untrusted-content wrapping, and the library can read the Session's cookies. Only the SDKs lend, where the program's own code chooses the library (ADR 0056), and no generated surface offers lending (ADR 0070).
> Amended by [ADR 0091](0091-collies-ai-verbs-live-on-the-page-replay-from-a-plan-file-the-run-names-and-expect-runs-a-success-check.md): in the SDKs, the observation whose page text is wrapped as untrusted is an `ai` aria snapshot (`ariaSnapshot({ mode: 'ai' })`) and what the AI verbs send their model; a read such as `innerText()` or a default-mode `ariaSnapshot()` returns page text as it is, for the program's own use.
> Note (agent decision, pending owner review), 2026-10-22, [#620](https://github.com/goodfetch/goodfetch/issues/620): the domain policy is `egress.allowed_domains` and `egress.blocked_domains`, judged before any lookup by `goodfetch-engine`'s `egress::judge`, first on the engine's own HTTP client. Hosts and entries are both read as the WHATWG parser reads a host (punycode, any IPv4 spelling, an IPv6 entry with or without brackets), and one trailing dot is dropped from either, so `elsewhere.test.` cannot pass a block on `elsewhere.test`; an entry that is no host (a path, a port, a `*` label) is refused. `egress_refused`'s `setting` is omitted where no setting would allow the request (a URL that does not parse, a scheme no request may use, a request whose kind interception cannot see); a URL that does not parse and a kind interception cannot see are refused under `rule: "domain_policy"`. A refused request no call waits on is the catalog event `page.request_failed` (`url`, `method`, and `failure` as an error's `data`), recorded as a line of `trace/requests.jsonl` in the Run's folder; its publication on the event stream arrives with the browser's page events. Both keys keep the authority `every` until the narrowing rule for a Recipe and a Client acting for a model lands ([#624](https://github.com/goodfetch/goodfetch/issues/624)), since the list check would count a run's own `["scope.test"]` as widening the default `["*"]`.

## Considered Options

- **Allowlists in the client library**: rejected. Domain allowlists were bypassed in Stagehand, Browser Use and Skyvern, and Playwright MCP calls its own filters "not a security boundary".
- **Relying on the model vendors' safety**: rejected as the only layer. OpenAI, Anthropic and Google ship classifiers and confirmations, but local and gateway models may not.

## Consequences

- An injection classifier on pages can be switched on (Firecrawl's precedent).
- Secrets are stored behind Secret references and Secret providers (ADR 0015). A run may switch redaction off, which lifts the guarantee above for logs, traces, HAR files, screenshots and recordings kept as outputs only (ADR 0016).
- A raw CDP client can switch off browser-protocol interception, so a Session with raw CDP attached is held to the domain policy at the network layer instead (ADR 0017), except on a Borrowed browser, where no network layer can be put under the browser: there the domain policy is enforced by interception, which a raw client can switch off, and the run is marked unguarded (ADR 0056).
- For payments, a run's allowance is `pay_domains`, which only Operator policy, user and project configuration or a person's answer can widen; no payment goes to a domain outside it (ADR 0045).
- For Consent prompts, the only allowance for accepting terms is `consent_domains`, never a run's general allowance, which only Operator policy, user and project configuration or a person's answer can widen (ADR 0048).
