# The browser driver is direct CDP with the Goodfetch guard, and the guard is its own reference

The engine drives Chromium-family browsers through an in-house Rust CDP client over a pipe and checks every action with the Goodfetch guard: page scripts that require the target to be unique, visible, enabled, stable and not covered, then cancel any event that reaches another element and replay the gesture until the deadline. The guard never let a wrong action through: 390 of 390 cells on Chromium, WebKit and Firefox, under Linux and macOS for the first two and under Linux for Firefox, whose Playwright build does not start on macOS 27 ([cross-engine report](https://github.com/Jbmanllr/automan/blob/main/rnd/lab/reports/cross-engine-2026-10-09.md), [driver contracts](https://github.com/Jbmanllr/automan/blob/main/rnd/lab/reports/browser-driver-contracts-2026-10-08.md)). Its own conformance matrix, not another driver, is the reference the lab gate reads: native Playwright, the previous reference, let a click through on a still-moving target (cross-engine report) and timed out twice at 100 ms of latency, which left the verdict blocked ([quiet-host report](https://github.com/Jbmanllr/automan/blob/main/rnd/lab/reports/quiet-host-2026-10-10.md)). Decided in [Adopt site-access decisions](https://github.com/Jbmanllr/automan/issues/76).

## Considered Options

- **Playwright as the default driver or as the reference**: rejected. On the same machine guarded CDP takes 21 to 33% longer than Playwright on forms and clicks, but from 20 ms of driver-to-browser latency guarded CDP is 16 to 32% faster, and Playwright is not exact when remote.
- **Stagehand v4's model, a CDP runtime inside a Chrome extension**: rejected. It saves the round trips between a distant SDK and the browser, which the engine and the Browser host (ADR 0022) already avoid by running beside the browser. It needs `--enable-unsafe-extension-debugging`, reaches the browser through a debugging port, which ADR 0017 forbids, and enables `Runtime`. Its click checks nothing and acts on the first match ([Stagehand migration guide](https://github.com/browserbase/stagehand/blob/f261c38/packages/docs/v4/migrations/playwright.mdx)); in the lab, native Stagehand failed every actionability variant but the plain one. Its published "2x faster than Playwright" rests on one 50-action run on a remote browser (1.59x).
- **Chromey or Chromiumoxide**: rejected. Neither can send commands into cross-origin iframes, both trail Chrome by about ten versions, and the guard would bypass their APIs anyway ([Rust CDP client options](https://github.com/Jbmanllr/automan/issues/67)).

## Consequences

- The client never enables the CDP `Runtime` domain, a known automation signal ([stealth research](https://github.com/Jbmanllr/automan/issues/64)); the guard runs in an isolated world. The client still needs per-command timeouts, crash and detach handling, out-of-process iframe tracking and reconnect.
- Speed target: one round trip to check and arm, no stability wait for an element with no running animation or transition (the interception listener already cancels a click that lands elsewhere), and input sent as one burst. The guard must stay at 390 of 390 and be no slower than Playwright on the lab's click and form tasks on the same machine. The [V1 benchmark](https://github.com/Jbmanllr/automan/issues/79) measures it on the reference host; a miss reopens this decision with the numbers.
- The guard can be switched off per run or per call (ADR 0023); actions taken without it are marked unguarded in Provenance.
- Firefox and WebKit run through Playwright's driver process, with the same guard injected, and only when a run asks for that browser. Crawlee offers them through Playwright; Stagehand, Browserbase, Browser Use and agent-browser are Chromium-only. A native WebDriver BiDi path for Firefox can replace Playwright later without changing the API, for stock Firefox only: ADR 0035 keeps Camoufox on Playwright's driver and Juggler, which its isolation depends on.
- The TypeScript and Python SDKs ([SDK binding and distribution strategy](https://github.com/Jbmanllr/automan/issues/75)) offer Goodfetch's own page API, shaped like Playwright's (`goto`, `locator`, `getByRole`, `click`, `fill`, `evaluate`), which waits through the guard and refuses ambiguous targets. Each Playwright call in the parity list maps to it or is excluded with a reason. Existing Playwright or Puppeteer code attaches through the engine's raw CDP endpoint under ADR 0017's rules; that endpoint must be a WebSocket, because Playwright's `connectOverCDP` cannot attach over a pipe.
- The engine's only calls into a page's main world are single calls into a consent vendor's own API, made without enabling `Runtime` (ADR 0048); everything else, the guard included, stays in isolated worlds.
