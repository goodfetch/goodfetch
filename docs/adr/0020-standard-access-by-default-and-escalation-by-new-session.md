# Sessions open in standard access mode, and a block changes the Session, never its identity

Every Session opens in one Access mode, fixed for its life. `standard`, the default, presents a real browser's identity consistently and leaks no automation: no `HeadlessChrome` token, `Runtime` never enabled (ADR 0018), language and time zone matched to the proxy exit, and no generated fingerprints. `identified` declares the agent with a product user agent and a Web Bot Auth signature; it does not switch on Site preferences, which stay with `respect_site_preferences` (ADR 0016). `stealth` is opt-in and holds generated fingerprints and the rest of the catalog decided in [Stealth and challenge-solving catalog](https://github.com/Jbmanllr/automan/issues/78). Changing the Access mode, the Identity profile or the proxy opens a new Session, because a fingerprint or an IP that changes under the same cookies is itself a bot signal. Decided in [Adopt site-access decisions](https://github.com/Jbmanllr/automan/issues/76).

## Considered Options

- **`identified` by default** (the R&D's draft ADR-002): rejected. It applied Site preferences by default, which ADR 0016 rejected to stay competitive with Crawlee and Spider, and a declared bot is blocked more often.
- **Generated fingerprints by default** (Crawlee's browser crawlers): rejected as the default. Overriding browser properties from JavaScript leaves traces, and detection now judges identity consistency ([stealth research](https://github.com/Jbmanllr/automan/issues/64)). They stay available in `stealth`.
- **Escalating the proxy inside a Session** (Crawlee 3's `tieredProxyUrls`, per hostname): rejected. It changes the IP under the same cookies; Crawlee 4 removed it in favour of rotating whole sessions ([upgrade guide](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/docs/upgrading/upgrading_v4.md)).
- **Retrying each page through a stealth proxy after a 401, 403 or 429** (Firecrawl's `auto` mode): rejected. It learns nothing, so every page of a blocked site fails once, and it enters stealth without being asked.

## Consequences

- Proxy pools by kind: none, datacenter, ISP, residential, mobile, or the user's own list. Provider adapters build the sticky-session usernames and lifetimes, whose formats differ between providers (Bright Data, Oxylabs, Apify). Each Session binds one proxy (ADR 0006), and bytes per proxy kind count in Usage, so a Limit can cap them.
- Escalation is learned per domain, with ADR 0004's key, and the cause of the block picks the response: a 401, 403 or 429 without a challenge page moves one proxy tier up; a challenge page moves to the browser tier (ADR 0019), then to the challenge solver; a login page goes to the Page check's recovery (ADR 0006). The blocked Session is retired and its replacement opens at the new tier, and a periodic trial on the cheaper tier brings the domain back down. Rotation is on whenever more than one proxy is configured, as in Crawlee. Nothing escalates into `stealth` unless the run switches that on.
- Rules detect blocks. The Decision provider (ADR 0009) is asked only about pages the rules cannot classify, such as a possible soft block; it may abstain, its calls are journaled and counted, and it never declares a success (ADR 0013).
- The legal research rates IP rotation on block as a medium risk in the public framework ([legal exposure](https://github.com/Jbmanllr/automan/issues/65)); which parts are public is decided in [Open-core boundary and license](https://github.com/Jbmanllr/automan/issues/77).
- Politeness defaults: at most 8 requests in flight per domain (Scrapy's library default) and no fixed delay; 429 and 503 responses and `Retry-After` are honoured with a backoff that starts at 2 s, doubles and stops at 60 s; a 429 halves the domain's concurrency, which then grows back gradually. With no configuration, Crawlee has no per-domain limit, no delay and no `Retry-After` handling, and Spider has no delay. Crawl-delay applies only with `respect_site_preferences` (ADR 0016).
- `per_ip_concurrency` is `none` by default or a number, keyed by the IP the engine resolves (ADR 0017). Scrapy deprecated its per-IP limit in 2.14 and no other surveyed crawler has one.
- Every value above is a setting per run, and the backoff can be switched off (ADR 0022).
