# Sessions open in standard access mode, and escalation opens a new Session

Every Session opens in one Access mode, fixed for its life. `standard`, the default, presents a real browser's identity consistently and leaks no automation: no `HeadlessChrome` token, `Runtime` never enabled (ADR 0019), language and time zone matched to the proxy exit (an imported login or a Profile directory used in place keeps its source's, ADR 0056), and no generated fingerprints. `identified` declares the agent with a product user agent and a Web Bot Auth signature; it does not switch on Site preferences, which stay with `respect_site_preferences` (ADR 0016). `stealth` is opt-in and holds generated fingerprints and the rest of the catalog decided in ADR 0035. Changing the Access mode, the Identity profile or the proxy opens a new Session, because a fingerprint or an IP that changes under the same cookies is itself a bot signal; a Session on a Profile directory used in place or on a Borrowed browser is never replaced this way, and a failure that would replace it raises a Human pause (ADR 0056). Decided in [Adopt site-access decisions](https://github.com/goodfetch/goodfetch/issues/76).

> Amended by [ADR 0083](0083-a-program-sets-settings-in-one-typed-option-explicit-values-beat-the-environment-and-no-value-is-silently-ignored.md): an explicit `browser.locale` or `browser.timezone_id`, set where the Session opens, replaces the match with the proxy exit, and `config explain` and the Run trace show it; an identity fixed by the `stealth` Access mode, an imported login or a Profile directory used in place refuses a conflicting value set where the Session opens with `setting_locked`, an inherited one yields, and a Borrowed browser refuses any `browser.*` value set there.

> Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): `respect_site_preferences` is now `site_preferences.respect_use_signals`. Crawl requests obey robots.txt in every Access mode unless `site_preferences.respect_robots_txt` is off. The robots.txt groups for the token `Foxhound`, and for `site_preferences.robots_txt_user_agent` when set, apply merged, or else the `*` group. `standard` stays the default and needs no operator contact; `identified` remains the way to be identifiable.

> Amended by [ADR 0088](0088-collie-carries-every-capability-except-those-only-many-pages-need.md): the Human pause holds for a crawl's Session on a Profile directory or a Borrowed browser. A Session a program or an Agent opened, whatever its source, is never replaced: a Challenge on it goes on down ADR 0035's ladder without its new `stealth` Session, and any other Block cause on it is reported on the call that met it.

> Amended by [ADR 0089](0089-a-page-is-lent-through-an-endpoint-that-shows-only-its-session-and-collie-joins-other-crawlers-by-borrowing.md): while a library such as Playwright or Puppeteer is attached to a Lent page, `Runtime` may be enabled on the pages it wraps in any Access mode, `standard` included; Provenance records the attach, and a Saved identity saved from a Session that was lent records it.

> Note (agent decision, accepted by the owner on 2026-10-22; [#696](https://github.com/goodfetch/goodfetch/issues/696)): headless Chromium differs from the same build with a window only in its user agent's product token, `HeadlessChrome/` for `Chrome/`; its client hints are the window's. So a headless browser's pages get its window's user agent through `Emulation.setUserAgentOverride`, with every client hint read from the browser itself once per launch, since a user agent set alone clears the high-entropy hints. The hints are read with `Runtime.evaluate`, which enables no `Runtime`, on the build's own `chrome://version` in the browser's default context, which no Session and no site shares. `navigator.webdriver`, the same with a window or without, stays as Chromium sets it; hiding it is area 8's. A browser with a window gets no override.

> Amended by [ADR 0090](0090-products-are-named-goodfetch-collie-and-goodfetch-foxhound-and-share-one-product-version.md): in ADR 0086's note above, the robots.txt token is `goodfetch-foxhound`, not `Foxhound`.

> Amended by [ADR 0121](0121-service-workers-run-under-the-engines-interception-the-back-forward-cache-is-off-locators-reach-closed-shadow-roots-and-a-read-never-scrolls-a-list.md): on WebKit, `browser.service_workers: block`, its only value there, is Playwright's page-visible `register` stub, since Playwright's driver reaches no WebKit switch for service workers. A `standard` WebKit Session therefore departs from the no-injection identity, as a user init script does, and Provenance marks it. On Chromium and Firefox, `block` injects nothing.

## Considered Options

- **`identified` by default** (the R&D's draft ADR-002): rejected. It applied Site preferences by default, which ADR 0016 rejected to stay competitive with Crawlee and Spider, and a declared bot is blocked more often.
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): robots.txt is now obeyed by crawl requests whatever the Access mode, so only the second reason stands: a declared bot is blocked more often.
- **Generated fingerprints by default** (Crawlee's browser crawlers): rejected as the default. Overriding browser properties from JavaScript leaves traces, and detection now judges identity consistency ([stealth research](https://github.com/goodfetch/goodfetch/issues/64)). They stay available in `stealth`.
- **Escalating the proxy inside a Session** (Crawlee 3's `tieredProxyUrls`, per hostname): rejected. It changes the IP under the same cookies; Crawlee 4 removed it in favour of rotating whole sessions ([upgrade guide](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/docs/upgrading/upgrading_v4.md)).
- **Retrying each page through a stealth proxy after a 401, 403 or 429** (Firecrawl's `auto` mode): rejected. It learns nothing, so every page of a blocked site fails once, and it enters stealth without being asked.

## Consequences

- Proxy pools by kind: none, datacenter, ISP, residential, mobile, or the user's own list. Provider adapters build the sticky-session usernames and lifetimes, whose formats differ between providers (Bright Data, Oxylabs, Apify). Each Session binds one proxy (ADR 0006), and bytes per proxy kind count in Usage, so a Limit can cap them.
  > Note (agent decision, pending owner review), 2026-10-23, [#882](https://github.com/goodfetch/goodfetch/issues/882): the five `proxy.providers.<name>` keys are one setting, `proxy.providers`, a table by provider name whose entries take `username`, `password`, `endpoint`, `servers` and `price`, set only in an Operator policy and user and project configuration (its Feature is `setting:proxy.providers`). A `list` server is a table of `server` (`http://`, `socks5://` or `socks5h://`; `https://` is refused, since its bytes are counted on the Session's loopback relay, which its TLS does not pass), `kind` and an optional `country`; `list`'s default kind is its first server's, and the Sessions of a Run take the servers of their kind and country in turn, by their position. Every Session a Proxy provider serves relays its proxy connections through a loopback relay that charges each byte on them, handshakes included, before it passes, as `proxy_bytes` with its proxy kind as a part; `run.usage` keeps `proxy_bytes`, the total, and adds `proxy_bytes_by_kind` and `proxy_price` (run state's `usage_parts` table), and a `proxy.server` Session, which has no kind, is not counted yet. A price is per GB of 10^9 bytes, charged per Session rounded up to the millionth; under a currency Limit on `proxy_bytes`, a provider with no price in the Limit's currency refuses the Session with `setting_invalid` naming `proxy.providers`, and a refused charge closes the proxy connection and fails the call that met it with `limit_reached`. `proxy.username` or `proxy.password` beside `proxy.provider` is `setting_invalid` as `proxy.server` is; a `proxy.sticky_lifetime` above the provider's longest is held to it; and `proxy_exit_may_change` is checked when a page opens in the Session and when it closes, by `session.close`, its retirement or its Run's end (the deep review's D19, 599-2: a Session still open as its Run stops is checked before the Run report is written; a `session.close` that finds its Session ended already finds it checked; no navigation checks it).
  > Note (accepted by the owner on 2026-10-28, the deep review's O1, O11 and O12), 2026-10-30, [#882](https://github.com/goodfetch/goodfetch/issues/882): a `bright_data` entry of `proxy.providers` takes `zones`, a table from proxy kind to the zone its customer named for it (`[A-Za-z0-9_]+`), each kind left out going to the zone named after it; `zones` beside another provider is `setting_invalid`. A provider's `price` comes only from user configuration or an Operator policy, which a currency Limit trusts: a project configuration whose `proxy.providers` gives one is refused with `setting_locked`, and since a project's `proxy.providers` replaces the whole table, its entries are unpriced. A Client acting for a model never sets `proxy.kind` (`setting_locked`); a Recipe and the program still do. Agent decisions, pending owner review, from the same review: `proxy.country` takes only a code ISO 3166-1 assigns (599-3); Bright Data's failures are also read from its `Proxy-Status` member (599-9); `proxy_auth_failed` on a provider Session names the provider's `username` and `password` keys, and `bright_data`'s `zones` (599-6); and the relay charges ahead (599-7, 599-12): each direction of each connection reserves an allowance of `proxy_bytes`, and of its price at its worst, before its bytes pass, 16 KiB first and each next twice the last up to 1 MiB, or, when a Limit refuses that, the largest of its halves down to what is needed now that the Limits allow, in one ledger transaction. An allowance is settled at what passed when the next is taken or the connection closes, its Run's end included, so no byte passes uncharged, a refusal closes the connection before the bytes it refused pass, and the price stays rounded up once per Session. A Run reads its Limits on one ledger connection it keeps, which a Limit set meanwhile still reaches.
- Escalation is learned per domain, with ADR 0004's key, and the cause of the block picks the response: a 401, 403 or 429 without a challenge page moves one proxy tier up; a challenge page moves to the browser tier (ADR 0020), and the Challenge solver's place after it, including whether it needs `stealth`, is decided in ADR 0035; a login page goes to the Page check's recovery (ADR 0006). The blocked Session is retired and its replacement opens at the new tier, and a periodic trial on the cheaper tier brings the domain back down. Rotation is on whenever more than one proxy is configured, as in Crawlee. Nothing escalates into `stealth` unless the run switches that on.
  > Amended by [ADR 0088](0088-collie-carries-every-capability-except-those-only-many-pages-need.md): only a Session that a crawl's Session pool opened is retired and replaced. A Session a program or an Agent opened itself stays in place, and opening another one is its choice.
  > Note (agent decision, accepted by the owner on 2026-10-22), 2026-10-21, [#920](https://github.com/goodfetch/goodfetch/issues/920): the proxy tiers are the proxy kinds in the order above, `none`, `datacenter`, `isp`, `residential`, `mobile`, the top staying where it is; a domain's tier is held by its Session pool, per domain key. `rate_limit` and `ip_block` retire their Session and move the domain one tier up, where the replacement opens; `challenge` and `captcha` retire their Session and leave the proxy tier, their escalation being the fetch tier's and the Challenge solver's ladder (areas 5 and 8); `payment_required`, `consent_required` and `decoy` never rotate. Until Collie's proxy pools exist (area 5), a tier names the kind a Session's proxy is drawn from, and the periodic trial on the cheaper tier is not built.
  > Note (agent decision, pending owner review), 2026-10-25, [#773](https://github.com/goodfetch/goodfetch/issues/773): `challenge` and `captcha` on a pool's Session now also move its domain to the browser tier, kept in run state with the proxy tiers: under `fetch.tier: auto` the domain's later requests start on `browser`, in a new Session; a forced tier stays forced, and a request the built-in default hands its handler alone fetches nothing the engine could move. A retired Session's browser context closes once no attempt holds it, through Collie's `Retire` (spec #594), so the replacement is a new Session with its own context.
- Rules detect blocks. The Decision provider (ADR 0009) is asked only about pages the rules cannot classify, such as a possible soft block; it may abstain, its calls are journaled and counted, and it never declares a success (ADR 0013).
- The legal research rates IP rotation on block as a medium risk in the public framework ([legal exposure](https://github.com/goodfetch/goodfetch/issues/65)); whether any part of it leaves the public framework follows ADR 0018's rule and is decided in ADR 0035.
- Politeness defaults: at most 8 requests in flight per domain, keyed as in ADR 0004, and no fixed delay. Scrapy's library default is also 8, but per hostname, so Goodfetch's limit is stricter on sites spread over subdomains. 429 and 503 responses and `Retry-After` are honoured with a backoff that starts at 2 s, doubles and stops at 60 s; a 429 halves the domain's concurrency, which then grows back gradually. With no configuration, Crawlee has no per-domain limit, no delay and no `Retry-After` handling, and Spider has no delay. Crawl-delay applies only with `respect_site_preferences` (ADR 0016).
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the defaults are 1 request in flight and a delay of at least 1 s between two request starts per domain. A 502, a 504, and a connection that is refused or times out back off like a 503. Crawl-delay applies with `site_preferences.respect_robots_txt`, on by default, up to `site_preferences.max_crawl_delay` (30 s); a host that asks for more has its crawl requests skipped with `crawl_delay`. These limits govern crawl requests, not a program's own navigation.
  > Amended by [ADR 0118](0118-every-fetch-tier-follows-redirects-as-the-browser-does-fails-a-cut-body-and-resends-only-what-a-site-never-processed.md): each wait of the backoff is drawn with decorrelated jitter from the `Entropy` handle (ADR 0059), between `politeness.backoff.initial` and three times the previous wait, at most `politeness.backoff.max`. A `Retry-After`, in seconds or as an HTTP-date, is honoured past `politeness.backoff.max`, up to `politeness.retry_after.max` (15 minutes). Past that, nothing is sent to the domain before the site's time, and the requests it holds end `failed` with `response_unavailable`.
- `per_ip_concurrency` is `none` by default or a number, keyed by the IP the engine resolves. When `per_ip_concurrency` is set, the engine resolves the name for it even when ADR 0017's resolved-IP check is switched off; behind a proxy that resolves names differently, the limit is approximate. Scrapy deprecated its per-IP limit in 2.14 and no other surveyed crawler has one.
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the setting is `politeness.ip.concurrency`.
- Every value above is a setting per run, and the backoff can be switched off (ADR 0023). The per-domain state they act on is shared by every run of the user, and across machines through a Politeness store; per-proxy limits are added there (ADR 0053).
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the keys are `politeness.domain.concurrency`, `politeness.domain.delay`, `politeness.backoff.enabled`, `politeness.backoff.initial` and `politeness.backoff.max`. A value that presses a site harder than its built-in default is recorded in the Audit log and listed in the run's result.
- A local address is a Session egress option beside proxy pools, and a change of address opens a new Session (ADR 0044). A `challenge` or `captcha` page on which Filter-list blocking blocked a request from the challenge is first retried once with blocking off (ADR 0047). The Block causes `payment_required` and `consent_required` (ADR 0048) never escalate or rotate, nor does a refused Wall allowance refetch (ADR 0052), and `goodfetch signing-key` manages the Web Bot Auth keys of `identified` Sessions (ADR 0045).
