# Sessions open in standard access mode, and escalation opens a new Session

Every Session opens in one Access mode, fixed for its life. `standard`, the default, presents a real browser's identity consistently and leaks no automation: no `HeadlessChrome` token, `Runtime` never enabled (ADR 0019), language and time zone matched to the proxy exit (an imported login or a Profile directory used in place keeps its source's, ADR 0056), and no generated fingerprints. `identified` declares the agent with a product user agent and a Web Bot Auth signature; it does not switch on Site preferences, which stay with `respect_site_preferences` (ADR 0016). `stealth` is opt-in and holds generated fingerprints and the rest of the catalog decided in ADR 0035. Changing the Access mode, the Identity profile or the proxy opens a new Session, because a fingerprint or an IP that changes under the same cookies is itself a bot signal; a Session on a Profile directory used in place or on a Borrowed browser is never replaced this way, and a failure that would replace it raises a Human pause (ADR 0056). Decided in [Adopt site-access decisions](https://github.com/Jbmanllr/automan/issues/76).

> Amended by [ADR 0083](0083-a-program-sets-settings-in-one-typed-option-explicit-values-beat-the-environment-and-no-value-is-silently-ignored.md): an explicit `browser.locale` or `browser.timezone_id`, set where the Session opens, replaces the match with the proxy exit, and `config explain` and the Run trace show it; an identity fixed by the `stealth` Access mode, an imported login or a Profile directory used in place refuses a conflicting value set where the Session opens with `setting_locked`, an inherited one yields, and a Borrowed browser refuses any `browser.*` value set there.

> Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): `respect_site_preferences` is now `site_preferences.respect_use_signals`. Crawl requests obey robots.txt in every Access mode unless `site_preferences.respect_robots_txt` is off. The robots.txt groups for the token `Foxhound`, and for `site_preferences.robots_txt_user_agent` when set, apply merged, or else the `*` group. `standard` stays the default and needs no operator contact; `identified` remains the way to be identifiable.

## Considered Options

- **`identified` by default** (the R&D's draft ADR-002): rejected. It applied Site preferences by default, which ADR 0016 rejected to stay competitive with Crawlee and Spider, and a declared bot is blocked more often.
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): robots.txt is now obeyed by crawl requests whatever the Access mode, so only the second reason stands: a declared bot is blocked more often.
- **Generated fingerprints by default** (Crawlee's browser crawlers): rejected as the default. Overriding browser properties from JavaScript leaves traces, and detection now judges identity consistency ([stealth research](https://github.com/Jbmanllr/automan/issues/64)). They stay available in `stealth`.
- **Escalating the proxy inside a Session** (Crawlee 3's `tieredProxyUrls`, per hostname): rejected. It changes the IP under the same cookies; Crawlee 4 removed it in favour of rotating whole sessions ([upgrade guide](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/docs/upgrading/upgrading_v4.md)).
- **Retrying each page through a stealth proxy after a 401, 403 or 429** (Firecrawl's `auto` mode): rejected. It learns nothing, so every page of a blocked site fails once, and it enters stealth without being asked.

## Consequences

- Proxy pools by kind: none, datacenter, ISP, residential, mobile, or the user's own list. Provider adapters build the sticky-session usernames and lifetimes, whose formats differ between providers (Bright Data, Oxylabs, Apify). Each Session binds one proxy (ADR 0006), and bytes per proxy kind count in Usage, so a Limit can cap them.
- Escalation is learned per domain, with ADR 0004's key, and the cause of the block picks the response: a 401, 403 or 429 without a challenge page moves one proxy tier up; a challenge page moves to the browser tier (ADR 0020), and the Challenge solver's place after it, including whether it needs `stealth`, is decided in ADR 0035; a login page goes to the Page check's recovery (ADR 0006). The blocked Session is retired and its replacement opens at the new tier, and a periodic trial on the cheaper tier brings the domain back down. Rotation is on whenever more than one proxy is configured, as in Crawlee. Nothing escalates into `stealth` unless the run switches that on.
  > Amended by [ADR 0088](0088-collie-carries-every-capability-except-those-only-many-pages-need.md): only a Session that a crawl's Session pool opened is retired and replaced. A Session a program or an Agent opened itself stays in place, and opening another one is its choice.
- Rules detect blocks. The Decision provider (ADR 0009) is asked only about pages the rules cannot classify, such as a possible soft block; it may abstain, its calls are journaled and counted, and it never declares a success (ADR 0013).
- The legal research rates IP rotation on block as a medium risk in the public framework ([legal exposure](https://github.com/Jbmanllr/automan/issues/65)); whether any part of it leaves the public framework follows ADR 0018's rule and is decided in ADR 0035.
- Politeness defaults: at most 8 requests in flight per domain, keyed as in ADR 0004, and no fixed delay. Scrapy's library default is also 8, but per hostname, so Goodfetch's limit is stricter on sites spread over subdomains. 429 and 503 responses and `Retry-After` are honoured with a backoff that starts at 2 s, doubles and stops at 60 s; a 429 halves the domain's concurrency, which then grows back gradually. With no configuration, Crawlee has no per-domain limit, no delay and no `Retry-After` handling, and Spider has no delay. Crawl-delay applies only with `respect_site_preferences` (ADR 0016).
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the defaults are 1 request in flight and a delay of at least 1 s between two request starts per domain. A 502, a 504, and a connection that is refused or times out back off like a 503. Crawl-delay applies with `site_preferences.respect_robots_txt`, on by default, up to `site_preferences.max_crawl_delay` (30 s); a host that asks for more has its crawl requests skipped with `crawl_delay`. These limits govern crawl requests, not a program's own navigation.
- `per_ip_concurrency` is `none` by default or a number, keyed by the IP the engine resolves. When `per_ip_concurrency` is set, the engine resolves the name for it even when ADR 0017's resolved-IP check is switched off; behind a proxy that resolves names differently, the limit is approximate. Scrapy deprecated its per-IP limit in 2.14 and no other surveyed crawler has one.
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the setting is `politeness.ip.concurrency`.
- Every value above is a setting per run, and the backoff can be switched off (ADR 0023). The per-domain state they act on is shared by every run of the user, and across machines through a Politeness store; per-proxy limits are added there (ADR 0053).
  > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): the keys are `politeness.domain.concurrency`, `politeness.domain.delay`, `politeness.backoff.enabled`, `politeness.backoff.initial` and `politeness.backoff.max`. A value that presses a site harder than its built-in default is recorded in the Audit log and listed in the run's result.
- A local address is a Session egress option beside proxy pools, and a change of address opens a new Session (ADR 0044). A `challenge` or `captcha` page on which Filter-list blocking blocked a request from the challenge is first retried once with blocking off (ADR 0047). The Block causes `payment_required` and `consent_required` (ADR 0048) never escalate or rotate, nor does a refused Wall allowance refetch (ADR 0052), and `goodfetch signing-key` manages the Web Bot Auth keys of `identified` Sessions (ADR 0045).
