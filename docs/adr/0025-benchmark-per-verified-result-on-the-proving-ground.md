# The V1 benchmark measures per verified result, on the Proving ground, at equal guarantees

Every figure Goodfetch publishes about its performance comes in three views: raw throughput or latency, the same work per verified result (time, CPU, memory), and dollars per 1,000 verified results. A raw figure never appears without its verified count and its false-success count beside it. A result is verified when an oracle independent of the tool confirms it correct and complete; the oracle decides, whatever status the tool gave the result. A false success is a result the tool reports as a success that the oracle refutes. A result Goodfetch reports as `needs-review` (ADR 0013) is verified when the oracle confirms it, is never a false success, and its count is shown beside the others. Every failed attempt and retry counts in the cost. Figures come only from the Proving ground, a website Goodfetch owns and generates, mostly from a seed, so that every page has a known expected result. None of the public benchmarks surveyed can rank Crawlee, Spider and Stagehand for all of Goodfetch's tasks: Spider's harness never checks that each competitor fetched the same pages, and an agent benchmark counts cost on successful attempts only ([benchmark audit](https://github.com/goodfetch/goodfetch/blob/main/rnd/research/2026-10-07-benchmark-audit-followup.md)). Decided in [V1 benchmark protocol](https://github.com/goodfetch/goodfetch/issues/79).

## Considered Options

- **Raw speed alone** (pages per second), as Spider and Lightpanda publish for crawls: rejected as a standalone figure. A tool that does less work, or reports success without delivering, looks faster. Raw speed is kept as one of the three views.
- **Cost alone**: rejected as the only view. It hides latency, which decides interactive automation.
- **Live third-party sites**: rejected for published figures. They change between runs and rate-limit, and scraping them for marketing carries the legal exposure found in [Legal exposure of stealth and challenge-solving tooling](https://github.com/goodfetch/goodfetch/issues/65). Challenges are measured on the Proving ground's online copy instead, behind real vendors on a domain Goodfetch owns.
- **Laptops or shared cloud instances**, as competitors measure (Spider on an M1 Max, Lightpanda on AWS m5, per the [benchmark research](https://github.com/goodfetch/goodfetch/blob/main/rnd/research/2026-10-07-benchmark-and-runtime.md)): rejected. Only the lab's `reference` host class, dedicated bare-metal Linux, is published.

## Consequences

- **Families.** HTTP crawl; rendered crawl; extraction, speed and quality; scripted actions; remote browser; AI; repeated runs with Drift; incident and recovery; startup and binding overhead, on the Linux reference host (ADR 0024); the cost of each switchable control (ADRs 0016 and 0023); and Access, whose content comes from ADR 0035.
  > Amended by [ADR 0094](0094-both-products-are-released-and-signed-together-and-each-test-runs-on-collie-unless-it-needs-foxhound.md): each family runs on the smallest Product that carries it, Collie for one page and Foxhound for crawls, and startup and binding overhead on each Product's executable; each result names its Product.
- **AI use cases.** First run that compiles a Plan; replay with Drift and Repair; autonomous agent; Goodfetch driven by an outside agent through MCP, CLI and skills, or code mode; AI extraction to a schema; AI-guided crawl; search then crawl; vision against DOM actions; the Decision provider's fast path; AI safety against prompt injection, fake success messages and allowlist escapes; Human pause; an agent woken by a change on a watched page; a fleet of agents running at once; an agent resumed from a Checkpoint after the engine is killed; an authenticated agent with MFA and account rotation; extraction rules written once by AI and then run on every page without a model; and documents and visuals. Each runs, where it applies, in all four combinations of a cloud or local model (ADR 0012) with a local or hosted browser (ADR 0022).
- **Measurements handed on by earlier decisions.**
  - The guard stays at 390 of 390 and is no slower than Playwright on the lab's click and form tasks on the same machine; a miss reopens ADR 0019.
  - A third-party remote browser driven over raw CDP with the guard is measured against Stagehand v4 with equal guarantees; if Goodfetch is clearly slower, an in-browser runtime for such browsers becomes a ticket, as ADR 0022 states.
  - The cost of every switchable control is published (ADR 0023).
  - Power-cut-safe and fast run state are both measured on the reference host; a large gap may reopen the separate-log option (ADR 0002).
  - The missing blocks of the fair per-domain admission verdict are measured; only a measurable slowdown on single-domain crawls reopens ADR 0004.
- **Proving ground.**
  - **Pages.** Millions of pages generated from a seed, plus hand-made pages. It covers, among others:
    - CSS class churn, honeypot links and every kind of CAPTCHA and protection
    - flagged IPs and per-IP rate limits with `Retry-After`
    - every HTTP error, soft 404s, redirect loops, crawler traps and duplicate URLs
    - schema.org data and hidden APIs
    - the same entity under small structure changes
    - AJAX loading, infinite scroll, shadow DOM and iframes
    > Amended by [ADR 0121](0121-service-workers-run-under-the-engines-interception-the-back-forward-cache-is-off-locators-reach-closed-shadow-roots-and-a-read-never-scrolls-a-list.md): hand-made pages add a service worker that answers one JSON call from its cache and passes another to the network, a page reached by Back, a virtualized list of 1,000 rows declaring its count, and targets inside closed shadow roots, attached by script and declared in HTML.
    - logins with MFA and logins that expire
    - geo and language variants, odd encodings, huge pages, PDFs and downloads, sitemaps
      > Amended by [ADR 0119](0119-every-fetch-tier-decodes-a-crawls-document-as-the-browser-does-a-label-names-the-content-types-its-handler-takes-and-exports-are-utf-8.md): the list gains content-coding pages (a body labelled gzip that is plain, an invalid gzip header, `gzip, br`, raw deflate, an unknown coding, and a body compressed twice but labelled once), whose decoding failures are `navigation_failed` with `net::ERR_CONTENT_DECODING_FAILED`; the odd-encodings pages read the same on every fetch tier, by ADR 0119's order, and a PDF or download a crawl reaches is `skipped` with `content_type` by default, or reaches its handler with its bytes and no `Download` when the Label's `crawl.content_types` lists it.
    - content that changes on a known schedule, for change tracking
    - prompt-injection pages, fake success messages, and TLS and HTTP/2 fingerprint checks
  - **Ground truth.** Expected results come from the seed data that generates each page, or are written by hand for hand-made pages, never from any tool's output, extractors included.
  - **Two copies.** A local copy serves every published speed figure, with declared network profiles: 0, 20, 100 and 300 ms of added round-trip time, and loss through `tc netem`. An online copy on a domain Goodfetch owns adds real networks and real challenge vendors: a subdomain of `goodfetch.dev` behind Cloudflare, plus a hostname served by Vercel for Vercel BotID (ADR 0032).
  - **Where network profiles apply.** `tc netem` exists only on Linux, so published figures always come from it on the reference host. Unpublished runs on any OS use the lab's user-space latency proxy. Either way, the added delay is measured before the run and recorded with it, and a run outside tolerance keeps its correctness results but loses its time metrics (settled on the gaps the [Proving ground and conformance spec](https://github.com/goodfetch/goodfetch/issues/152) listed, as the [owner settled them](https://github.com/goodfetch/goodfetch/issues/152#issuecomment-6115242029)).
  - **Open source.** The Proving ground is published, so anyone, competitors included, can rerun the benchmark.
  - **Conformance.** The conformance suites run against its pages too. How the lab's fixtures and oracles move into it is left to the repository layout item of the [V1 map](https://github.com/goodfetch/goodfetch/issues/61).
- **Competitors.**
  - **Tools.** Crawlee (JavaScript and Python), Spider, Scrapy, Colly in async mode, Stagehand v4, Playwright, Crawl4AI, Browser Use, Vercel's `agent-browser`, Firecrawl self-hosted (its cloud-only anti-bot engine noted as absent) and Scrapling; ScrapeGraphAI, Skyvern and changedetection.io where their use case applies.
  - **Configuration.** Each runs in its best documented configuration for the family, pinned at its latest stable release when the benchmark freezes. Configurations are published, and maintainers get 14 days to review theirs before publication. The owner opens an issue or discussion on each competitor's repository, linking the configuration and the date the window closes (settled on the gaps the [Proving ground and conformance spec](https://github.com/goodfetch/goodfetch/issues/152) listed, as the [owner settled them](https://github.com/goodfetch/goodfetch/issues/152#issuecomment-6115242029)).
    > Note (owner's decision, 2026-11-10, [#2252](https://github.com/goodfetch/goodfetch/issues/2252), Q1): one pinned side per competitor (its pin, lock, configuration and crawl program) serves both this benchmark and `just compare`. [#180](https://github.com/goodfetch/goodfetch/issues/180) and [#181](https://github.com/goodfetch/goodfetch/issues/181) wrap the sides `xtask/compare-*` holds, so no competitor is measured two ways.
  - **Equal guarantees.** Where a competitor lacks a guarantee, Goodfetch appears twice: by default, with every control on, and matched, with the controls the competitor lacks switched off and marked as ADR 0023 requires.
- **Reference host.** One rented bare-metal x86_64 server with 16 cores and 32 threads, 128 GB of RAM and NVMe, running Ubuntu 24.04 LTS. Turbo is off and SMT is on, fixed for a series, under the lab's `reference` gates. The Proving ground is served from a second machine on the same switch, so the reference host measures only the tool. arm64 runs stay unpublished `local-controlled` checks. The owner approves both machines when they are provisioned.

  > Amended by [ADR 0076](0076-tests-and-ci-run-on-free-tiers-and-ai-calls-go-through-the-vercel-ai-gateway.md): while there is no revenue, this rented host, its second machine and the benchmark's paid services (proxies, CAPTCHA solving, model spend) are declined; the owner's machine (Apple M3 Max) runs the benchmark as an unpublished `local-controlled` stand-in labelled with that machine, and published reference-class runs wait for revenue.
- **Cost.** Dollars per 1,000 verified results sum:
  - the reference host's public hourly price multiplied by wall time
  - model, proxy and CAPTCHA-service spend at list price, failed attempts included
  - hosted browsers at the vendor's list price per browser-minute

  A Plan's one-time cost (compilation and Repairs) is shown spread over 1, 10, 100 and 1,000 runs, counts declared before measuring. Human time is reported apart, never folded in.
- **Statistics and load.**
  - **Statistics.** The lab's rules: each claim is declared before measuring with its metric, comparator and direction, and the decision it serves fixes its minimum effect Δ (`rnd/lab/claims/` and `rnd/lab/decisions/` today); verdicts computed by fixed rules from block-bootstrap intervals; at least five blocks, more when results scatter widely; the page or the task as the pairing unit.
  - **Load.** Concurrency runs at 1, 8, 64 and 256, plus a search for the highest concurrency where verified throughput still rises and false success stays at zero.
- **Publication.** Every result is published, losses and inconclusive verdicts included, with raw data, harness, configurations and redacted traces. Results go on a Benchmarks page in the documentation and in a versioned folder of the repository. A figure used in marketing must quote a published claim and link to it.
- **Releases.** The benchmark reruns at every minor release against the then-current competitor versions, and earlier results stay published with their dates. A correctness failure always blocks a release. A primary metric worse than the previous release by more than its Δ blocks it unless the release notes explain it. Each family has one release-gate claim, declared in `bench/` before the first frozen series, naming its primary metric, with Δ set from the reference host's measured run-to-run spread and approved by the owner (settled on the gaps the [Proving ground and conformance spec](https://github.com/goodfetch/goodfetch/issues/152) listed, as the [owner settled them](https://github.com/goodfetch/goodfetch/issues/152#issuecomment-6115242029)). ADR 0030 adopts this rule and runs it on the release candidate.
- **Clean-up.** The matched Goodfetch rows set Filter-list blocking and Consent prompt handling as each competitor's default does, and the benchmark publishes what the clean-up costs and saves in time and bytes (ADRs 0047 and 0048). The online copy also carries real consent vendors' prompts, through their free tiers where their terms allow (ADR 0048).
