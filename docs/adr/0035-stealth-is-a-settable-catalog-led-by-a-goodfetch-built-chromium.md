# Stealth is a settable catalog led by a Goodfetch-built Chromium, and only the solver's own logic is a Private component

The `stealth` Access mode turns on a catalog of items, each of which a run can set on or off: a Fingerprint method, generated Identity profiles, headful browsing, human-like input and HTTP fingerprints matched to the browser. Its default Fingerprint method, `engine`, runs a Chromium that Goodfetch builds itself: fingerprint-chromium's open patches compiled on every Chrome Stable major for Linux, Windows and macOS on x64 and arm64, reproducible from its published patches and signed. ADR 0030 already ships every Chrome major; reproducibility is this decision's own requirement. Saved identities, block detection and trap-link avoidance serve every Access mode. The Challenge solver has its own switch and escalates deterministic steps first, then AI, then a person. Everything is public except Goodfetch's own solving logic, which becomes a Private component behind the public Challenge solver Plugin kind (ADR 0033), because publishing it is the one item rated High legal exposure. Decided in [Stealth and challenge-solving catalog](https://github.com/goodfetch/goodfetch/issues/78), on the evidence of [State of the art in stealth and challenge solving](https://github.com/goodfetch/goodfetch/issues/64) and [Legal exposure of stealth and challenge-solving tooling](https://github.com/goodfetch/goodfetch/issues/65).

## Considered Options

- **Injecting fingerprints from page JavaScript as the default** (Crawlee with fingerprint-suite, Crawlee Python with browserforge, Spider with `spider_fingerprint`, Steel's open-source image): rejected as the default. Overridden properties are detectable, and detectors now judge consistency across layers ([stealth research](https://github.com/goodfetch/goodfetch/blob/research/stealth-state-of-the-art/rnd/research/2026-10-10-stealth-state-of-the-art.md)). It stays selectable as the `js-injection` method, with its warning.
- **Shipping fingerprint-chromium or Clearcote binaries as the default** (both BSD-3, at Chromium 150 on 2026-10-11, when Stable was 155 on Linux and 156 had reached early Stable on Windows and macOS, per [chromiumdash](https://chromiumdash.appspot.com/schedule)): rejected as the default. Version 150, Stable since 2026-06-30, misses every Chrome security fix released since, including CVE-2026-85046, exploited in the wild and fixed in 152.0.7977.82 on 2026-09-03 ([report](https://esecurityplanet.com/threats/news-google-chrome-cve-2026-85046-zero-day)), and their builds cannot be reproduced from public sources. Research found no anti-bot vendor that flags an old version by itself, only versions that contradict the engine ([Akamai](https://techdocs.akamai.com/cloud-security/docs/detection-methods), [Castle](https://blog.castle.io/how-dare-you-trust-the-user-agent-for-detection/)), so staleness costs security and a thinner crowd. They stay selectable through an Operator policy allowance (below).
- **Closed Chromium builds** (CloakBrowser, BotBrowser) or closed antidetect cores (Multilogin Mimic, GoLogin Orbita, AdsPower SunBrowser, Kameleo Chroma, Dolphin Anty, Octo): rejected as shipped defaults. Their licences forbid redistribution or hosting, they live inside their vendors' apps, and BotBrowser's terms forbid scraping use. A user with a licence runs one through a Browser backend Plugin (ADR 0033).
- **A Goodfetch build on Chrome's Extended Stable channel**, which ships a major every eight weeks with security fixes back-ported ([Chrome blog](https://developer.chrome.com/blog/chrome-two-week-release)): rejected. ADR 0030 already carries every Chrome major in a patch release so that the shipped browser and the stealth material stay current, and the only gain was fewer builds.
- **A Goodfetch build for Linux only**: rejected. On a Windows or macOS desktop the real fingerprint is human, but account rotation runs many identities from one machine, and only an engine-level build gives each its own graphics, canvas, audio and fonts.
- **No Goodfetch build, only Chrome's debugging protocol on a stock Chrome** (close to Kernel, Patchright and nodriver): kept as the `basic` method. The [Emulation domain](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/) sets user agent, client hints, time zone, locale, geolocation, screen and core count, but not graphics, canvas, audio or fonts, so Sessions on one machine stay linkable.
- **Camoufox as the main stealth browser** (Crawlee's template; [Scrapling 0.3.13](https://github.com/D4Vinci/Scrapling/releases) replaced it with patchright): rejected as the main engine. Firefox is about 2.8% of traffic against about 78% for the Chromium family ([StatCounter](https://gs.statcounter.com/browser-market-share), September 2026), Firefox no longer speaks CDP ([Mozilla](https://fxdx.dev/cdp-retirement-in-firefox/)), and some vendors test the JavaScript engine itself ([Camoufox](https://github.com/daijro/camoufox)), so a Firefox can only claim to be Firefox. It stays the Firefox stealth engine.
- **Stealth WebKit or Safari identities**: rejected. No stealth WebKit build exists, Playwright's Linux WebKit is not Safari, and vendors that offer Safari profiles fake them with Chromium.
- **Each stealth option switched on one by one** (the R&D's draft ADR-002): rejected. Opting into `stealth` turns the whole catalog on; each item can then be switched off.
- **Moving every Medium-risk item out of the public framework**: rejected. Only High-risk items leave. Rotate-on-block and the token-service adapters are rated Medium, and Crawlee and Spider publish them; Spider (MIT) even publishes an autonomous solver for Turnstile, reCAPTCHA, GeeTest, Imperva and hCaptcha (`src/features/solvers.rs`, 2.53.9).
- **Renaming `stealth` to a neutral word**: rejected. Spider, Browserbase and Browser Use use the same word; the wording policy below carries the legal weight.

## Consequences

### Fingerprint methods

| Method | Browser | How the fingerprint changes | Warning |
| --- | --- | --- | --- |
| `none` (default outside `stealth`) | Chrome for Testing (ADR 0024) | no change beyond the language and time zone every Access mode matches to the proxy (ADR 0021; an imported login or a Profile directory used in place keeps its source's, ADR 0056) | the machine's real fingerprint shows, and Sessions on one machine are linkable |
| `js-injection` | Chrome for Testing | page JavaScript | detectors can see the injected values |
| `basic` | Chrome for Testing | the CDP Emulation domain and launch flags | graphics, canvas, audio and fonts stay the machine's own |
| `engine` (default in `stealth`) | the Goodfetch build | inside the engine | none while the build matches the current Chrome Stable major |
| `engine` with fingerprint-chromium or Clearcote binaries | theirs | inside the engine | behind on security fixes and not reproducible; allowed only by Operator policy (below) |
| `engine` with Camoufox | Camoufox, a separate download (ADR 0018) | inside the engine, Firefox identities only | a smaller crowd |
| `engine` with the user's own browser (a licensed CloakBrowser, another Chromium build) | through a Browser backend Plugin: a declared download with a digest per platform, allowed per digest by Operator policy and off by default, or a CDP endpoint (ADR 0033) | whatever it does | Goodfetch cannot vouch for the build or its licence |

- The warning appears in the CLI, the SDK results, the Console and the run's report, and the choice is recorded in Provenance and the Audit log (ADRs 0016 and 0023).
- Choosing any method other than `none` makes the Session a `stealth` Session; the items the run set keep their values, and `stealth`'s defaults fill the rest. `identified` refuses every masking item and the Challenge solver: a signed agent that masks spends its key's reputation (ADR 0021).
- **Third-party patched binaries.** The fingerprint-chromium and Clearcote binaries are listed in the browser cache by name and digest but are not reproducible by Goodfetch and trail Chrome's security fixes, so the engine refuses them unless Operator policy allows them, per digest, as ADR 0033 does for browsers a Plugin declares. The allowance is off by default, recorded in the Audit log, and marks the results. It is not one of ADR 0016's run switches: like other no-cost security rules, a run cannot turn it off. Camoufox is exempt, since it is built in public and tracks Firefox within one major; browsers a Plugin declares already follow ADR 0033, and an installed Chrome follows ADR 0030's support rule.

### The Goodfetch build

- It reuses ungoogled-chromium's build pipeline, applies fingerprint-chromium's patch set and sends fixes upstream.
- **Platforms.** Linux, Windows and macOS on x64 and arm64. Chromium has no musl build, so on a musl host `engine` falls back to `basic` on the distribution's Chromium (ADR 0024), with that method's warning.
  > Note (owner's decisions, 2026-11-11, grilling of decision G-15 of the consolidated review: Q5 answered "yes to all" and Q12, put after an independent check of the grilling's drafts, answered "Yes, confirmed", each on the grilling's recommended option as put; the wording is the grilling session's, and the owner did not read it): one rule everywhere. On a musl host, as anywhere no Goodfetch Chromium exists for the machine, `stealth` with no Fingerprint method set falls back to `basic` with `fingerprint_basic_fallback`, and an explicit `engine` is refused with the reason (Q12). This replaces the sentence above: an explicit `engine` is refused, and the fallback's warning is `fingerprint_basic_fallback`. Not built yet: the re-cut of line 5 of Features writes it into the tickets.
- **Cadence.** It is rebuilt for every Chrome Stable major and Google's security updates, and ships in the patch release that carries that major (ADR 0030). One measured first build on a paid runner, approved by the owner, sets the cost before the cadence starts.
- **Source and distribution.** The repository holds only the patch files and the build scripts (ADR 0032); the pipeline fetches Chromium's source at the tagged version, so Chromium's code is never copied in. The build runs as its own release job on paid large runners. Each build is a Platform-signed (ADR 0039), attested release asset (ADR 0030), never part of the npm, PyPI or crates.io packages, and reaches users through the digest-checked browser cache (ADR 0024). A patch that no longer applies blocks the release that carries that Chrome major, as a red Private component build blocks promotion and patches (ADR 0032).
  > Amended by [ADR 0074](0074-the-goodfetch-chromium-is-gated-where-it-is-built-against-a-control-build-of-the-same-revision.md): the build runs on the pull request that changes its inputs, as the Chromium build gate, and the release pipeline signs the bytes that pull request published; a patch that no longer applies blocks that pull request.
- It always claims its true version, in the user agent, client hints and features; claiming a newer version than the engine is the contradiction detectors look for.
- **Version check.** Before a Session uses a Chromium or Firefox-based build, Camoufox included, the engine compares it with a table of Chrome and Firefox releases shipped in every Goodfetch release, which includes the scheduled dates of upcoming majors, so it knows from the date alone which major is Stable today (for Firefox builds, Firefox's current release). It makes no network call, as ADR 0030 requires of update checks; an online lookup of Google's release data is opt-in, recorded in the Audit log. Levels, with the exact gap in versions and weeks: current shows nothing; 1 version behind Stable is info; 2 or 3 behind is a notice; 4 or more behind, or a version its vendor no longer patches, is a warning that calls the build outdated. An installed Chrome that ADR 0030 supports (the current stable, beta or dev channel, the current Extended Stable, or a stable major of the last eight weeks) is graded against its own channel and never gets more than a notice. Playwright's WebKit is pinned with each release (ADR 0030) and not graded. Nothing blocks the run. The check matters for users who do not update and for every browser Goodfetch does not build.
- HTTP-only `stealth` Sessions send through wreq the TLS ClientHello, HTTP/2 settings, header order and client hints captured from the Goodfetch build by the lab's relay, so HTTP and the browser claim the same version (ADR 0020). The version check grades those profiles too.
- The Goodfetch Chromium build turns browser background traffic off at build time and ships the variations seed captured at build, so Google sites receive Chrome's `X-Client-Data` header with no call at run time (ADR 0043).

### Engines

- Chromium is the main stealth engine, driven over Goodfetch's CDP driver (ADR 0019), with Chrome, Edge and Android Chrome identities.
- Firefox stealth is Camoufox, reached through Playwright's driver and its Juggler protocol, with Firefox identities only. A native WebDriver BiDi path would not replace Juggler for Camoufox, whose isolation depends on it.
  > Amended by [ADR 0121](0121-service-workers-run-under-the-engines-interception-the-back-forward-cache-is-off-locators-reach-closed-shadow-roots-and-a-read-never-scrolls-a-list.md): a Camoufox Session never registers a service worker, since Playwright's driver intercepts none of a service worker's requests and ADR 0014 fails closed; Firefox's own `dom.serviceWorkers.enabled` preference, set through the driver's Firefox preferences, refuses it, never a page-visible stub; a site can see the difference from real Firefox, and area 8's spec measures its cost.
- WebKit runs without a stealth mode and never claims to be Safari.

### The rest of the catalog

- **Headful.** `stealth` Sessions show a window by default, on a virtual display on Linux; Browser Use measured 2% of protected sites passed headless and 50% headful on the same IP ([its own benchmark](https://browser-use.com/posts/stealth-benchmark)).
- **Generated identities.** Drawn from a population model per engine (the open data of fpgen, fingerprint-suite and BrowserForge, Apache-2.0), matched to the proxy exit for language, time zone, geolocation and WebRTC address (an imported login or a Profile directory used in place keeps its source's language and time zone, ADR 0056), with the OS following real traffic shares rather than the host's, and applied only inside the engine.
- **Human-like input.** Cursory's recorded mouse movements (LGPL-3.0-or-later) are downloaded at runtime into the browser cache, never compiled in, kept replaceable and listed in the notice inventory; Goodfetch writes the reshaping step from Cursory's published description, not from its code. The Boğaziçi mouse recordings may widen the set once their CC BY 4.0 licence is confirmed. A Rust port of ghost-cursor (MIT) is the fallback when the recordings are absent. Typing with neighbouring-key slips, scrolling and press-and-hold use Goodfetch's own model. Input goes through native CDP events, inside the guard's deadlines (ADR 0019).

### What serves every Access mode

- **Saved identities.** A Session's identity can be saved under a name and reused by later runs: a seed that regenerates the Identity profile exactly, the Session's proxy binding (the same sticky exit where the provider supports it, else the same country and proxy kind), and its cookies and storage. Saved identities live in a store per install, outside any run's state, because a run's key is destroyed with the run (ADR 0015); like ADR 0002's per-install layout, the store is kept per product major (ADR 0030). This is a deliberate exception to ADR 0001's reset rule: resetting or discarding a run leaves nothing of the run behind, but a saved identity is a named object that outlives runs by design, and only its own delete operation removes it, leaving no recoverable secrets. The store's secret fields are encrypted under a key reached through a Secret reference, and one run at a time may write a saved identity, under an install-wide lock (in a Daemon group, the Lead Daemon keeps the store and the lock is a lease it holds, ADR 0055); other runs read it or copy it. When a saved identity is reused after the browser moved to a new major, its version fields (user agent, client hints and the HTTP profile) follow the current build, as after a real browser update, and the rest stays fixed. A saved identity expires after 30 days unused by default, as Steel's saved profiles do, and the limit is settable; within a run, the Session pool still retires Sessions by age and use count, by default Crawlee's 3,000 s and 50 uses (a Session on a Profile directory used in place or on a Borrowed browser is never retired, ADR 0056). An optional warm-up browses declared pages before work. A saved identity keeps the Access mode it was saved under, and reusing it under another Access mode or an inconsistent proxy is refused, since either change is a new Session (ADR 0021). Saving, reusing, copying and deleting a saved identity are recorded in the Audit log (ADR 0016), and moving one to another machine uses ADR 0015's session export (an import bound to its machine cannot move, ADR 0056). A login the person already has becomes a Saved identity by import, which records its source and is bound to it (ADR 0056). In Goodfetch Cloud, where each run has its own engine and the engine knows no Tenants (ADR 0001), the cloud keeps saved identities per Tenant and hands one to a run's engine through the protocol; that store is designed in Goodfetch Cloud's map.
  > Amended by [ADR 0088](0088-collie-carries-every-capability-except-those-only-many-pages-need.md): only a crawl's Session pool retires Sessions by age and use count. A Session a program or an Agent opened itself is never retired.
  > Amended by [ADR 0098](0098-both-products-share-one-goodfetch-home-and-one-daemon-per-major-run-by-the-fullest-product-installed.md): the Saved identity store of a major serves both Products and records the lowest minor of its major that can use it, so an older engine opens it unless that minor is newer than itself.
- **Block detection.** Rules seeded from Spider-rs (MIT), wafw00f (BSD-3), identYwaf and Nuclei's `waf-detect` (MIT) record their source and licence per rule. webappanalyzer (GPL-3.0) and Scrapfly's Antibot-Detector (NPOSL-3.0) are watchlists only: a scheduled job opens an issue when they list a vendor Goodfetch lacks, and the rule is written from vendor documentation and Goodfetch's own captures. A rule fires on evidence of a challenge, never on a vendor's mere presence, and is tested against captured pages and the Proving ground. Causes are `challenge`, `captcha`, `rate_limit`, `ip_block` and `decoy`.
- The Block cause `payment_required` joins these causes; it never escalates, rotates or retries (ADR 0045).
- The Block cause `consent_required` joins them too; it never escalates, rotates, retries or hides (ADR 0048).
- A Block cause met by a Wall allowance refetch never escalates or rotates, and none of the escalation ladder below runs for it (ADR 0052).
- **Trap links.** In the browser tier, the Frontier skips links a person cannot see and invisible `nofollow` links, and a page reached through one, or marked `noindex` and failing its Page check, is classed `decoy`; Cloudflare documents both signals for [AI Labyrinth](https://developers.cloudflare.com/bots/additional-configurations/ai-labyrinth/). HTTP-tier crawls flag such links instead. This avoids traps rather than honouring Site preferences, so ADR 0016 is unaffected. It can be switched off; that is recorded and the results say so (ADR 0023).
- Links inside an element a cosmetic rule of the Clean-up rules matched are left out of the trap-link judgement, so a link inside a hidden ad is not taken for a trap (ADR 0047).

  > Note (agent decision, accepted by the owner on 2026-10-28 as narrowed by owner decision O26 in the note of 2026-10-30 below), 2026-10-26, [#1148](https://github.com/goodfetch/goodfetch/issues/1148): a person cannot see a link with no box (`hidden`, `display: none`, no area), whose box lies wholly outside the page, whose computed `visibility` is not `visible`, that it or an element holding it makes transparent (`opacity: 0`), that sits in an `aria-hidden="true"` subtree, or that a `clip`, `clip-path` or cut overflow of an element holding it clips to nothing. The browser tier reads these facts in the guard's isolated world when a handler's `enqueueLinks` reads a browser page's links (that page now answers `crawl_request.links` and `crawl_request.enqueue_links` itself), and the Frontier's `trap_links` judges them; an element a cosmetic rule the page's live hiding applies matched, or one holding it, is left out. An invisible `nofollow` link is answered as any invisible link, `trap_link`; a visible `nofollow` link is followed.

  > Note (agent decision, on a guarantee, not read by the owner), 2026-10-27, [#1153](https://github.com/goodfetch/goodfetch/issues/1153): a served document has no layout, so the HTTP tier judges only what its markup states of a link and each element holding it: a `hidden` attribute, an inline `display: none`, an inline `visibility` other than `visible`, an inline `opacity` of 0, `aria-hidden="true"`; a link only layout or a style sheet hides goes unflagged. Such a link is added, its work item marked as a suspected trap and a `trap_link_suspected` entry written in the Run trace's Provenance, naming the request added, its URL and the request whose page held it. A request so marked that reaches a browser tier (a Label on `browser`, or an escalation) ends `blocked` with `decoy` before anything is sent, since the browser tier never follows a link a person cannot see; on the HTTP tier it is fetched as any other. "Marked `noindex`" is a `noindex` or `none` directive in the document's `X-Robots-Tag` header or a robots `meta` element; `page_check_failed`'s details carry it as `noindex`, which Collie reports and Foxhound reads: a crawl request whose page fails its Page check so marked ends `blocked` with `decoy`, never `page_check_failed`, on any tier. Under `fetch.tier: auto` a page failing its expected page over HTTP still moves to the browser first, whose Page check decides.

  > Note (agent decision, on a guarantee, not read by the owner), 2026-10-29, deep review findings 600-1, 600-6 and 600-12 and decision D20 ([#1153](https://github.com/goodfetch/goodfetch/issues/1153)): a work item stays marked only while every link that reached it was suspected. A link a person sees, or one whose markup hides nothing, that the Frontier answers `duplicate` clears the mark of the request it names, or of the one a learned rule merged it into, in the same staged admission, so the clear commits or is discarded with its attempt. A request still marked that reaches a browser tier ends `blocked` with `decoy` as the #1153 note says, except a sample's browser run: its `http` run was already sent, so the browser's run is weighed like any other and the request counts toward its Label's choice. The `trap_link_suspected` Provenance entries are written once the attempt commits, for the marks still standing in the run file then, so a discarded or rolled-back attempt writes none. A decoy's details are the `blocked` details, `status` `null` for a page never fetched.

  > Note (owner decision O26 (a), 2026-10-28; its reading below an agent decision, on a guarantee, not read by the owner), 2026-10-30, deep review findings 600-2, 600-7, 600-8 and 600-9 ([#1148](https://github.com/goodfetch/goodfetch/issues/1148), [#1153](https://github.com/goodfetch/goodfetch/issues/1153)): what "cannot see" covers is narrowed, alike on both tiers. An invisible `nofollow` link, the signal Cloudflare documents for AI Labyrinth, is still a trap wherever it sits. Any other invisible link that a menu, a tab or a disclosure holds is one a person reveals by opening it, since a menu's links are a site's main navigation: it is added on either tier, its work item marked `revealable`, and its `trap_link_suspected` Provenance entry says `revealable: true`; every tier follows it, so it never ends `decoy`, and a revealable link that reaches a request marked through markup alone again leaves it marked `revealable`. A menu, a tab or a disclosure is a `nav`, `menu` or `details` element, an element with a `navigation`, `menu`, `menubar`, `menuitem`, `menuitemcheckbox`, `menuitemradio`, `tablist`, `tab` or `tabpanel` role, a `popover`, a `hidden="until-found"`, or an element another names in `aria-controls`, on the link or any element holding it; the Frontier's `trap_links` holds the lists and hands them to the page's reading. Other invisible links stay traps. A cut overflow is `hidden` or `clip` only, on an axis, of an element on the link's chain of containing blocks: a scroll container (`auto`, `scroll`) cuts nothing, since a person scrolls its content into view, a fixed or absolutely positioned link escapes every holder short of its containing block, and the overflow of `<html>`, and of `<body>` while `<html>`'s is visible, goes to the viewport and cuts nothing. A `display: contents` link is seen through what it holds. `aria-hidden` hides when its value is `true` past ASCII whitespace, in any ASCII case, on both tiers. A selector holding one of the HTML parser's own extensions (`:contains()`, `:has-text()`, `:only-text`), which a browser refuses, is refused with `invalid_params` on both tiers. An `X-Robots-Tag` value that names a user agent first (`googlebot: nofollow, noindex`) speaks to that crawler in full, so none of it marks the page `noindex`; the valued directives (`unavailable_after`, `max-snippet`, `max-image-preview`, `max-video-preview`) name no user agent.

### Challenge solver and escalation

`solve_challenges` is off by default. The solver runs in `standard` and `stealth` Sessions, never in `identified` ones, and does not itself require `stealth`. The ladder below completes ADR 0021's escalation and is learned per domain, so later pages start at the step that worked:
1. A challenge page on HTTP moves to the browser tier, in the same Access mode (ADR 0020).
2. The Session waits, with a timeout, for an invisible challenge to clear in the genuine browser.
3. If the run allows `stealth`, a new `stealth` Session opens.
   > Amended by [ADR 0088](0088-collie-carries-every-capability-except-those-only-many-pages-need.md): only for a Session that a crawl's Session pool opened. A Session a program or an Agent opened itself skips this step and is never replaced.
4. If `solve_challenges` is on, deterministic solving: scripted interactive steps (checkbox, slider, press-and-hold), then the configured token services (CapSolver, 2Captcha, CapMonster) and the services that compute the anti-bot sensor data a site expects (such as Hyper Solutions), whose accounts the user brings. Goodfetch never reverse-engineers vendor scripts itself.
5. If `solve_challenges` is on and the run allows AI escalation, vision models solve puzzles.
6. A Human pause, if a human channel is configured (ADR 0006).
   > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): a Session whose `session.recovery.human_pause` is `false` skips this step, as it skips the login recovery's Human pause.
7. Otherwise a typed stop, `challenge_unsolved` with the block cause (Error code style of ADR 0038).

- When Filter-list blocking blocked a request from a challenge's document or frames, the page is retried once with blocking off before step 2's wait, and blocking is learned off for the domain only if that clears the challenge (ADR 0047).
- At any step, the Decision provider classifies pages the rules cannot, as ADR 0021 already provides, whatever `solve_challenges` says.
- Paid solves and model calls are entries in the Effect journal (ADR 0010) and count in Usage, so money Limits cap them; every step, including the moves between tiers and Sessions and the Human pause, is recorded in the run's trace. Only the Page check declares a challenge passed (ADR 0013).
- Every solver in steps 4 and 5, the Private component, a token-service or sensor-data adapter, or a Plugin, follows ADR 0033's Challenge solver contract: it acts only through engine operations or returns a token the engine injects, and its `needs_human` outcome leads to step 6.
- A solver that needs a vision model asks the engine through an operation of the Operation catalog (ADR 0011). The engine makes the call with the run's Model provider and Limits (ADR 0012), so a solver Plugin never holds model credentials. The call needs no extra permission: it acts within the engine's call to the solver and counts against the run (ADR 0033).

### Placement

| Item | Legal level if public | Lives in |
| --- | --- | --- |
| Fingerprint methods, the Goodfetch build, identities, input, headful, saved identities | Low with neutral wording | public framework |
| Block detection, trap links, typed stop, the timed wait for invisible challenges | Low | public framework |
| Proxy pools, provider adapters, retiring a blocked Session and opening a new one at the next tier | Medium | public framework, worded as Session health |
| Token-service and sensor-data adapters | Medium | public framework |
| Human pause on a challenge, and the Challenge solver Plugin kind | Low | public framework |
| Goodfetch's own solving logic: scripted interactive steps and vision-model puzzle solving | High (US §1201 trafficking; posting code counts) | Private component |
| Managed solving, managed proxies, hosted stealth browsers | operations | Goodfetch Cloud, designed in its own map |

- **Who loads the Private component.** It ships only as a process Plugin (ADR 0033). As ADR 0033 says, it is not first-party: it loads only when Operator policy allows it, runs fully confined or not at all, and resumes under ADR 0033's rule for Plugins that are not first-party, including its audited override. It is built against every release (ADR 0032), so a current version always exists. Its artifact carries a provenance attestation from the private repository's release workflow, which the engine checks with `sigstore-verify` against that signer identity. The signed Plugin index lists that identity, so the Private component falls under the index's expiry and revocation like any third-party Plugin (ADR 0033), and a compromised build is revoked by digest there. Goodfetch Cloud loads it in its own fleet; a self-hoster loads it only under a licence granted to a vetted customer (ADR 0018) and an Operator policy that allows it.
- A self-hoster without it keeps the whole ladder except Goodfetch's own solving logic: steps 4 and 5 run through their token-service account, their own Challenge solver Plugin, or a licensed copy of the Private component.
- On this one row Goodfetch publishes less than Spider. Parity holds, because the capability ships in V1 through the Private component and Goodfetch Cloud.
- **Wording policy.** Docs, READMEs, the CLI, the Console, error messages and the agent skills never say "bypass", "undetectable" or "solve any CAPTCHA"; they describe consistency, privacy, testing and authorized automation. Marketing is its own legal prong in the US (§1201(a)(2)(C)), the EU (InfoSoc 6(2)(a)) and France (L.335-3-1 II 4°).
  > Amended by [ADR 0097](0097-one-docs-site-renders-each-products-section-from-one-source-and-neither-product-leads-with-access.md): the policy covers every text published about either Product, registry descriptions and keywords, release notes, the repository's description and topics and the marketing site included; `xtask wording`, run in the Quick suite, fails on "bypass" in any form, "undetectable", "undetected" or "solve any CAPTCHA" in the repository's published prose, from a list counsel's review may extend; and no opening of either Product leads with stealth or access.
- **Counsel review.** Before V1 is released, counsel reviews the public stealth documentation, the Private component's licence terms and the Platform signature it carries (ADR 0039), starting from questions 1, 2, 4, 17 and 19 of the legal note. The licence terms and the signature are reviewed before the first licensee receives the component. Counsel shapes the wording and the terms; it does not remove the solver.
  > Amended by [ADR 0097](0097-one-docs-site-renders-each-products-section-from-one-source-and-neither-product-leads-with-access.md): the review covers both Products' stealth pages, since Collie carries stealth too, and also the registry metadata and the marketing site.
- **Recheck triggers.** A ruling on SerpApi's renewed motion to dismiss in *Google v. SerpApi* (N.D. Cal. 4:25-cv-10826, undecided on 2026-10-11 after the October 13 hearing was vacated, ECF 60), or on Oxylabs' motion in *Reddit v. SerpApi* (S.D.N.Y. 1:25-cv-08736), reopens the placement table. At the pleading stage, *Reddit* (ECF 104) held masking (proxies, IP shifting, fake user agents, human mimicry) to be circumvention and cited an automatic CAPTCHA bypass as circumvention, and *Google*'s July 20 order found masking and passing on a solved challenge's authorization close to circumvention; neither has ruled on the merits.

### Measurement

Stealth quality is the content of the benchmark's Access family (ADR 0025), on two rungs:
1. Hermetic fixtures in CI, on the Proving ground's local copy: JA4, HTTP/2, header order and client hints kept consistent from HTTP to the browser; self-hosted probes such as CreepJS and BotD; CDP side-effect probes; the version check; and the block-detection corpus.
2. Real vendor protections in front of the Proving ground's online copy, on a domain Goodfetch owns, read back through the vendor's own verdict: Turnstile with Siteverify, the Cloudflare bot score, AWS WAF Bot Control labels, reCAPTCHA scores, Vercel BotID, hCaptcha, and proof-of-work challenges (Anubis, ALTCHA, Cap). DataDome, Akamai, HUMAN and Kasada need trials the owner approves one by one.

Every result is reported per Fingerprint method, engine, Access mode and build age, against stock headless and stock headful Chrome as controls. Outside the benchmark, dated live campaigns on targets that authorized them may tune the rules; they are never published or merged with the benchmark, which ADR 0025 limits to the Proving ground.
