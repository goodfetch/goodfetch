# One resource governor per engine, sized from measured load, and redundant requests only on request

Each engine process has one resource governor that admits work for all its runs. It sizes concurrency from measured memory, CPU and Tokio saturation, within the ceilings the user sets. ADR 0004's fixed global cap becomes a ceiling, and setting the floor equal to it brings the fixed cap back. Memory decides how many browser pages may be open, and recycling keeps browsers from growing without bound. A run under memory pressure sheds load before the operating system's OOM killer can act. Goodfetch never sends a redundant request to a site unless the run asks for it. Decided in [Engine resource governance](https://github.com/goodfetch/goodfetch/issues/115).

Crawlee scales on memory, CPU, event-loop delay and API 429s ([system_status.ts](https://github.com/apify/crawlee/blob/v3.18.2/packages/core/src/autoscaling/system_status.ts)). It reads cgroup limits only when it detects a container, and then from the root of `/sys/fs/cgroup` rather than its own cgroup ([general.ts](https://github.com/apify/crawlee/blob/v3.18.2/packages/utils/src/internals/general.ts), [memory-info.ts](https://github.com/apify/crawlee/blob/v3.18.2/packages/utils/src/internals/systemInfoV2/memory-info.ts)). Its users report:

- OOM kills under limits it missed ([crawlee#4057](https://github.com/apify/crawlee/issues/4057), [crawlee-python#1535](https://github.com/apify/crawlee-python/issues/1535)).
- A limit captured once ([crawlee-python#1704](https://github.com/apify/crawlee-python/issues/1704)).
- Concurrency collapsing to 1 or 0 ([crawlee#1721](https://github.com/apify/crawlee/issues/1721), [crawlee#4129](https://github.com/apify/crawlee/issues/4129)).

Spider and Crawl4AI read only the host's memory ([detect_system.rs](https://github.com/spider-rs/spider/blob/main/spider/src/utils/detect_system.rs), [async_dispatcher.py](https://github.com/unclecode/crawl4ai/blob/main/crawl4ai/async_dispatcher.py)). No surveyed tool recycles a browser because its memory grew; Crawlee retires one after 100 pages ([browser-pool.ts](https://github.com/apify/crawlee/blob/v3.18.2/packages/browser-pool/src/browser-pool.ts)). Together these answer pain #22 (`perf-memory-concurrency`) and parity rows RT-01, RT-03, SA-09, RT-20 and CO-16.

## Considered Options

- **A fixed cap only** (ADR 0004 as it stood, Spider without `balance`): rejected. A run that moves to the browser tier (ADRs 0020 and 0021) takes about a hundred times the memory at the same concurrency, and users tune by hand on every machine.
- **A governor per run**: rejected. Runs on a Daemon share one machine, and the first to grow would starve the rest. Crawlee 4 moves the same way, to a `ConcurrencySystem` that several crawlers share ([upgrade guide](https://github.com/apify/crawlee/blob/master/docs/upgrading/upgrading-v4/autoscaling.md)).
- **One count of work in flight for every kind of work** (Crawlee's AutoscaledPool): rejected. A browser page and an HTTP fetch differ by orders of magnitude in memory, so one count either wastes the machine on HTTP or exhausts it on browsers.
- **The host's total memory as the allowance** (Spider, Crawl4AI): rejected. Inside a container it overshoots the limit, and the process is OOM-killed.
- **Crawlee's default of about 22 % of memory** (0.9 × `availableMemoryRatio` 0.25): rejected. It leaves a dedicated container mostly idle.
- **Recycling browsers on page count alone** (Crawlee): rejected. A browser on a heavy single-page app can grow faster than 100 pages allow.
- **Hedged requests by default** (Spider's `hedge`, which never checks the request method; [hedge.rs](https://github.com/spider-rs/spider/blob/main/spider/src/utils/hedge.rs)): rejected. They add load to sites and proxy cost, and a hedged Effect would run twice. gRPC allows hedging only for methods that are safe to repeat ([A6](https://github.com/grpc/proposal/blob/master/A6-client-retries.md)).
- **Racing every fetch tier on every page by default, scored on its HTML** (Spider's `parallel_backends`, [parallel_backends.rs](https://github.com/spider-rs/spider/blob/main/spider/src/utils/parallel_backends.rs)): rejected. Every page then costs a browser, and a score on how the HTML looks is the kind of success ADR 0013 refuses. Firecrawl staggers its engines rather than racing them ([scrapeURL](https://github.com/firecrawl/firecrawl/blob/main/apps/api/src/scraper/scrapeURL/index.ts)).
- **Coalescing by URL alone** (Spider's `request_coalesce`): rejected. Two Sessions fetching one URL with different cookies would receive one Session's response.

## Consequences

**The governor.**
- **Ownership.** It belongs to the engine process (an Attached engine, the Daemon, or an engine embedded through the Rust crate), sits under ADR 0038's cancellation tree, and serves every run of that process.
- **Fairness.** Capacity goes round-robin to the live runs, then, within a run, to its domains as in ADR 0004. Each run keeps its own ceilings, and Operator policy can cap any run's share.
- **Kinds of work.** It admits three kinds separately, each with its own floor and ceiling: HTTP and discovered-API fetches, open browser pages, and model calls. All three share the engine's memory and CPU allowance:
  - Browser pages are held mainly by memory, from a running average of what a page costs on its route.
  - HTTP fetches are held by CPU and file descriptors.
  - Model calls are held by the provider's rate limits.
- **Control.** It works by additive increase and multiplicative decrease. Concurrency rises step by step while memory, CPU and Tokio saturation all have headroom, and drops quickly when one is under pressure. Tokio saturation is the share of time its workers are busy (`worker_total_busy_duration`, a stable Tokio metric), the Rust counterpart of Crawlee's event-loop delay.
- **Limits of the controller.** It never goes below a floor. ADR 0021's halving on 429 still acts per domain, below the governor.
- **Defaults.** The default ceilings are set from ADR 0025's search for the highest concurrency where verified throughput still rises.
- **Settings.** Every value is a setting (ADR 0028). Setting floor equal to ceiling gives the fixed behaviour of ADR 0004. Autoscaling costs nothing at run time, so it is not one of ADR 0023's marked controls.
  > Note (agent decision, accepted by the owner on 2026-10-28, deep review of M1 (213-O1); [#234](https://github.com/goodfetch/goodfetch/issues/234)): how the governor is built.
  > - **Keys**, all under `governor.` (ADR 0083): `governor.<kind>.floor` and `.ceiling` for `http`, `browser_page` and `model_call`, `governor.memory_allowance` (bytes), `governor.pressure` and `governor.critical` (percent), `governor.sample_interval` (1 s) and `governor.last_resort_after` (60 s) are the machine's own (Operator policy and user configuration), read again at every sample, since one governor serves every run of the engine; `governor.run_share` (percent of each kind's target, at least one admission, 100 by default) is a run's, so Operator policy caps a run's share through it.
  > - **Control.** A target starts at its ceiling, ADR 0004's fixed cap, halves at each sample under pressure, never below its floor, and with headroom rises by a twentieth of its ceiling, at least one, only while the kind's admissions fill it. Memory past `governor.pressure` of the allowance, host pressure, or CPU time (against `available_parallelism`) or Tokio workers' busy time past the same share put the engine under pressure, CPU and Tokio busy time only halving each target (#236's note); memory past `governor.critical`, or the host's critical pressure, is critical. The last resort is memory critical with every kind at its floor for `governor.last_resort_after`; a Daemon's `/readyz` then fails with `governor_last_resort`, and #236 stops the largest run there.
  > - **Host pressure** on Linux: memory in use (all but `MemAvailable`) past the thresholds, or PSI's `some avg10` past 10 % (pressure) and `full avg10` past 10 % (critical); on Windows, the low-memory notification is critical and the memory load counts as on Linux.
  > - **Fairness.** Each live Run joins the governor; while Runs wait for a kind, what is given back goes round-robin to the waiting Runs, never back to the one that gave it. Foxhound's crawl takes one `http` admission per attempt, beside `crawl.handler.concurrency` and the per-domain queues; browser pages and model calls take theirs once areas 5 and 10 open them.
  > - **`engine.system_info`** carries each sample; a subscription takes it only when it asks (`events.subscribe`'s `system_info`), and it takes no position otherwise, so a stream of what changes sees no periodic event. Metrics: `goodfetch.governor.target{kind}`, `goodfetch.governor.pressure_source{source}` and `goodfetch.governor.saturation`, the highest share of a kind's target in use.
  > - **Who samples.** Each Product's executable gives its engine the OS to read; an engine given none, such as one embedded through the Rust crate today, holds each kind at its default ceiling. A Browser host's reports set the targets its Session's work is admitted by (`HostGovernor`).
  > Note (agent decision, pending owner review), 2026-10-31, [#1792](https://github.com/goodfetch/goodfetch/issues/1792): the ceiling a target starts at is the one the machine's settings give, which the governor reads at its first sample, taken as it starts. Until that sample it admits nothing, so a Run that asks first waits for it, a few milliseconds, rather than taking admissions up to the built-in ceiling: a crawl started before the first sample once took three of a fixed cap of two.

**The allowance.**
- **Memory.** The engine's memory allowance is the tightest of:
  - the process's own cgroup memory limit, v1 or v2, read from its own cgroup path rather than the root;
  - a Windows Job object limit;
  - the `governor.memory_allowance` setting;
  - 50 % of physical memory when none of these applies, so a workstation stays usable.

  Limits are read again at every sample, so a limit raised by Kubernetes' in-place Pod resize, or by hand, is seen.
- **The host's own pressure.** Several engines on one machine, such as three scripts with Attached engines, would each claim 50 %. So the governor also reads the host's own memory pressure (PSI and `MemAvailable` on Linux, the memory-pressure level on macOS, the low-memory notification on Windows) and treats host pressure as its own. The Daemon remains the way to share one allowance between many scripts.
  > Amended 2026-11-06 (#2115, #2116; agent decision, pending owner review): `governor.host_memory` (on by default, the machine's own) turns the host's judgement off, so the engine's memory against its allowance alone sets the level, as on a host whose other workloads are not the engine's to answer for. Every test's user configuration turns it off: the host's pressure came from the suites running beside a test and, once critical, shed its Run's browsers. The host's rules are tested on a `/proc` the test writes.
- **CPU.** The CPU allowance comes from the cgroup CPU quota through `std::thread::available_parallelism`, which honours `cpu.max`.
- **What counts as used.** The engine and all its child processes: browsers, process Plugins and a local Browser host. On Linux this is PSS, which splits Chrome's shared pages fairly between its processes; on other platforms it is the platform's own measure of a process's footprint.
- **Thresholds.** Pressure starts at 85 % of the allowance and critical at 95 %. Both are settings.

**Browsers and Sessions.**
- **Sharing a process.** Sessions of the same run, in any Access mode, share a browser process, each in its own browser context with its own proxy. CDP `Target.createBrowserContext` takes `proxyServer`, a parameter still marked experimental, so the conformance suite covers it on every Chrome major the release supports (ADR 0030). A Session whose Fingerprint method is fixed per process gets a process of its own. That covers the Goodfetch-built Chromium of ADR 0035, whose fingerprint seed is a launch flag. The number of contexts per process is a setting.
- **Never across runs.** Sessions of different runs never share a browser process, because the run is the unit of isolation and an Attached engine's browsers stop with it (ADR 0024). A Borrowed browser serves one run and one Session; the governor neither recycles it nor counts it in the memory allowance (ADR 0056). A browser on a Profile directory used in place is recycled by relaunching it on the same directory.
  > Amended by [ADR 0089](0089-a-page-is-lent-through-an-endpoint-that-shows-only-its-session-and-collie-joins-other-crawlers-by-borrowing.md): through `run.borrow()`, a Borrowed browser still serves one run but can serve several of its Sessions, one per browser context a borrowed page belongs to; the governor still neither recycles it nor counts it.
- **Recycling.** A browser is recycled after 100 pages, when its memory passes a per-browser cap (by default twice its size measured after warm-up, or an absolute value), or after it has been idle for a set time. All are settings.
  - To recycle, it stops taking new pages, lets its pages finish, closes, and is replaced.
  - A Session is not its browser: its cookies, storage and, for a per-process fingerprint, its seed carry over to the new process. Recycling therefore never changes an identity, which ADR 0021 treats as a bot signal.
  - **Held browsers.** A browser holding a page in a Human pause, under a person's control in the Live view (ADR 0031) or under a raw CDP attach bound to its work item's lease (ADR 0003) is recycled only once that page is released.
  > Note (agent decision, pending owner review; [#235](https://github.com/goodfetch/goodfetch/issues/235)): how the browser pool is built.
  > - **Keys**, under `governor.browser.` and settable by every layer, since they bound one Run's browsers: `contexts_per_process` (8), `recycle_pages` (100), `recycle_idle` (5 minutes) and `memory_cap` (bytes, unset: twice the warm-up size).
  > - **Placement.** A Session takes its browser context in the first browser of its Run with room that is not being recycled, else in a new one; each browser has a Browser data folder of its own in the Run's folder, `browser-data/<n>` (renamed from `browser-profiles/<n>` on 2026-10-24, review of spec #577).
  > - **When.** Pages count when they open. Memory, the browser process and its descendants as the governor counts the engine's (PSS on Linux), is read when a page opens, once the browser has opened one: a browser that opened none has not grown, and its replacement would be past the same absolute cap. The warm-up size is the reading taken when the browser opens its second page. Idle means no open page for `recycle_idle`; the replacement is launched only when a Session needs it.
  > - **Letting pages finish.** A page finishes when it closes, which today is with its Session or its Run (no `page.close` yet). A Session whose browser is recycled moves at its next page: its cookies (every cookie of its context) and the `localStorage` of each origin its pages' documents came from are copied into a context in another browser, while the pages it already had stay open in the recycled browser, in their old context, until they finish; the recycled browser closes once none is left, and a Session that had not moved yet takes its cookies and storage along. `sessionStorage`, IndexedDB and caches are not carried. Each origin's storage is read and written in a page of the context that commits an empty document of that origin, answered through `Fetch`, so nothing reaches the site.
  > - **Held, Borrowed, Profile directory.** A page's place in its browser can hold it, which defers recycling until released; the Human pause, the Live view and raw CDP attach take that hold when their tickets land (#978). A Borrowed browser never enters the pool, so it is neither recycled nor counted. Relaunching a Profile directory used in place on the same directory is left to the ticket that serves that source (#737), since a Session cannot open from one yet.
  > - **Seed.** Each Session draws its identity seed from its Run's `Entropy` when it opens and keeps it in run state (`page_sessions.identity_seed`), which recycling never touches; the per-process Fingerprint method passes it to its browser (#977), whose Sessions get a process of their own.
  > Amended by [ADR 0143](0143-a-crawls-browsers-grow-with-its-concurrency-a-browser-is-recycled-for-growth-after-its-warm-up-and-a-sessions-page-serves-its-next-request.md): a browser is recycled for memory only once a governor sample reads its footprint past `governor.browser.memory_growth` (200 percent) of its warm-up size, the highest footprint read until it has served `governor.browser.warm_up_pages` (32) requests since it last held more open pages than ever; `memory_cap` is an absolute cap only, judged at every sample, and `recycle_pages` is unset by default and counts requests served when set. At most `governor.browser.recycle_at_once` (1) browsers of a Run are recycled for growth or pages at once; `memory_cap`, idleness and the critical shedding never wait. The pool reads the sampler's last measure instead of walking a browser when a page opens. A crawl's page goes back to its Session after a healthy attempt as a Spare page and serves the Session's next request (`crawl.browser.page_reuse`), closing off the request's path otherwise, and the Session pool opens Sessions on demand, so a Run's browser contexts, still one per Session, and its browsers follow its requests in flight.
- **Session retirement.** ADR 0006 still retires Sessions that fail, except a Session on a Profile directory used in place or on a Borrowed browser, which raises a Human pause instead (ADR 0056). Recycling is about the process, retirement about the identity.
  > Amended by [ADR 0088](0088-collie-carries-every-capability-except-those-only-many-pages-need.md): only a crawl's Session pool retires a failing Session. A Session a program or an Agent opened itself is never retired: a Challenge on it goes on down ADR 0035's ladder without its new `stealth` Session, and any other Block cause on it is reported on the call that met it.

**Under memory pressure.**
1. **Pressure.** Nothing new is admitted.
2. **Critical.** The governor:
   - closes idle browsers, then recycles the largest ones first, skipping held browsers;
   - puts back in the queue the work item whose page passes a per-page cap, with the Error code `page_memory_exceeded`, which is retryable (ADR 0038), retried under the run's retry policy. It does so at the item's next safe point: an Effect in flight finishes or is reported uncertain first (ADR 0029);
   - treats a browser killed by the operating system as a page crash: its work items go back in the queue and the crash counts in Usage.
     > Note (agent decision, pending owner review), 2026-10-23, [#731](https://github.com/goodfetch/goodfetch/issues/731): the Usage kind is `page_crashes`, one per page that crashes, its renderer or its browser's process; a crash racing the page's close does not count (spec #594's decision 14).
     > Note (agent decision, accepted by the owner on 2026-10-28), deep review of M1 (594-O2), [#731](https://github.com/goodfetch/goodfetch/issues/731): `page_crashes` counts one per crash, not one per page, replacing the note above's count: a renderer's crash counts once, for its page, and a browser's once, for the browser, however many pages and Sessions it held, so a Limit on crashes measures how often the Run crashes. A crash racing the page's close still does not count (decision 14).
3. **Last resort.** If memory stays critical at the floor for a set time, one run checkpoints and stops with the Error code `resources_exhausted`, which is not retryable. The run can be resumed once memory frees up, on an engine with a larger allowance, or with lower ceilings for the run. Scrapy's `MEMUSAGE_LIMIT_MB` closes the spider instead, and Crawlee only lowers concurrency.
   > Amended by [ADR 0122](0122-a-run-stops-resumably-before-its-disk-fills-and-a-daemons-logs-rotate-at-a-bounded-size.md): the governor also samples free storage. At its `critical` storage level, every Run with an essential write on that filesystem stops together, a Run holding a page under a person's control last, as below, since stopping one frees no disk, with `resource: "storage"` and no Checkpoint copy written there. `resources_exhausted` is an `UnavailableError`, not retryable, whose details carry `resource` (`memory` or `storage`).
   - **Which run.** The run with the largest measured footprint, which can be measured because runs never share a browser process. The governor stops one run at a time and measures again before stopping another.
   - **Held pages.** A page under a person's control in the Live view is never ended by the governor: a run holding one is stopped last, and only after that person hands back or leaves. A page waiting in a Human pause with nobody on it ends with its run, as a pending pause does when its run stops (ADR 0031).
   - **Changes ADR 0029.** `stopped` also covers this stop for exhausted resources. Its Completeness is `incomplete`, never `complete`. It is reported with the other `stopped` causes, and like them it neither counts toward a Schedule's auto-pause nor resets that count (ADR 0036).

> Note (agent decision, accepted by the owner on 2026-10-28, deep review of M1 (213-O1); [#236](https://github.com/goodfetch/goodfetch/issues/236)): how the shedding ladder is built.
> - **Pressure.** Under memory pressure, the allowance's or the host's, and at critical, a kind admits nothing past its floor, whatever its halved target, since the controller never goes below a floor; a floor of `0` admits nothing. CPU time or Tokio workers' busy time past `governor.pressure` is pressure too, with its own `pressure_source`, but it only halves each target, never below its floor, and a kind admits up to that target: a machine at full CPU is working, not in danger as it is when memory runs out, and holding every kind at its floor would saw each one between its floor and its target and leave the machine under-used.
> - **Critical.** Each browser a Run's pool launched joins the governor with its process and reports its open pages (a Session being seated or opening a page counts as one) and whether it holds a held page. At each critical sample the governor measures every one, then closes every idle one and recycles the largest with open pages, one a sample so the next is measured again, never a held one nor one already shed; a recycled browser closes once its pages finish, as #235's recycling does.
> - **Per-page cap.** `governor.browser.page_memory_cap` (1 GiB, settable by every layer like the other `governor.browser.` keys) bounds a page's JavaScript heap, its embedder's heap and the buffers it holds, as `Runtime.getHeapUsage` reports them, measured at each critical sample. A page past it ends at its safe point, once no call on it is in flight: it closes, emits `close`, and its later calls raise `page_memory_exceeded` (retryable, `UnavailableError`, details: the page, what it held and the setting with its layer). A crawl's browser pages, which go back in the queue, wait for the crawl to open them (area 6).
> - **OS-killed browser.** #731's `page_crashed` and its `page_crashes` Usage count are the page crash; a crawl's work items requeue once its browser pages exist.
> - **Last resort.** A Run's footprint is its browsers' memory at the last sample. The Runs' registry stops the largest, the first by Run ID among equals, with `resource: "memory"` and a Checkpoint, then waits until a sample read wholly after that Run ended (the second after it) before it stops another. A Run whose page a person controls in the Live view (`PageHold::Person`) is never picked while the person holds it, so it is stopped last, once handed back; the Live view takes that hold with #978.

**Remote browsers** (adds to ADR 0022).
- A Browser host serves one Session (ADR 0022). It runs the same governor for its own browser, with the allowance, recycling and per-page cap above measured where it runs, and reports its pressure to the engine. The engine then admits that Session's pages by the host's pressure, not its own. Where Browser hosts are placed across machines is Goodfetch Cloud's concern.
- For a vendor's cloud browsers, the engine sees only the vendor's refusals. It learns a ceiling per provider from them, the way ADR 0021 halves on 429, and the ceiling can be set by hand. The ceiling is shared by every run of the user and across machines, like Politeness (ADR 0053). Browserbase limits concurrent browsers by plan and answers with 429 when a limit is reached ([concurrency](https://docs.browserbase.com/optimizations/concurrency/overview.md)).

**Redundant requests.**
- **Hedged requests** are off by default and switched on per run.
  - **What they cover:** only requests whose method is GET or HEAD, from a work item that declares no Effect (ADR 0010).
  - **When and where:** the hedge is sent after the route's 95th-percentile latency, on a new connection through the Session's own sticky proxy binding (ADRs 0006 and 0021), or directly when the Session has no proxy. It therefore leaves through the same exit, and the Session keeps its identity: a hedge helps against a slow connection or a slow server, never by changing IP. Only the reqwest and wreq transports hedge. Browser-fetch pools its connections inside Chrome, so it cannot open a new one on demand.
  - **How they count:** both copies hold per-domain slots under ADR 0021's politeness limit and count in Usage. The losing copy is cancelled.
    > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): in a crawl, each copy also waits for the domain's delay. A crawl's Run that switches hedges on while `politeness.domain.concurrency` is 1, where a second copy could never start, is refused with `setting_not_applicable` when it opens. Outside a crawl neither copy counts in Politeness, which is Foxhound's (ADR 0084).
  - **Rate:** hedges are capped at 5 % of a run's requests by default, settable. Envoy's retry budget ([`budget_percent`](https://www.envoyproxy.io/docs/envoy/latest/api-v3/config/cluster/v3/circuit_breaker.proto)) and Finagle's `RetryBudget` ([clients](https://twitter.github.io/finagle/guide/Clients.html)) cap extra attempts the same way, as a share of requests. "The Tail at Scale" cut p99.9 latency from 1,800 ms to 74 ms with 2 % more requests ([Dean and Barroso, 2013](https://www.barroso.org/publications/TheTailAtScale.pdf)).
- **`tier_race`** is off by default and switched on per run, for one-off fetches or wherever latency matters more than cost.
  > Amended by [ADR 0093](0093-a-crawl-declares-its-labels-and-one-handler-each-and-a-handler-reads-collies-page-on-every-fetch-tier.md): its key is `fetch.tier_race`, in the `fetch.*` family.
  - **How it runs:** within one Session, browser-fetch starts first and a full browser navigation after a delay. Browser-fetch is the HTTP tier ADR 0020 requires in any Session that may move to the browser, so the race never changes the Session's TLS fingerprint.
  - **The winner:** the first result that passes the Page check and agrees with the route's comparison (ADR 0020).
  - **How it counts:** the loser is cancelled, both count in politeness and in Usage, and Provenance records the race. The loser shares the Session's browser context, so cookies its response already set stay, as they would after any request of that Session.
    > Amended by [ADR 0086](0086-a-crawl-obeys-robots-txt-and-sends-one-request-at-a-time-per-domain-by-default-and-pressing-harder-is-recorded.md): as with hedges, a crawl's Run that switches `tier_race` on while `politeness.domain.concurrency` is 1 is refused with `setting_not_applicable`, and outside a crawl neither fetch counts in Politeness.
  > Note (agent decision, accepted by the owner on 2026-10-28), 2026-10-25, [#945](https://github.com/goodfetch/goodfetch/issues/945): how a crawl races.
  > - **Which requests:** with `fetch.tier_race` on, every attempt whose tier is not forced races, unless a Challenge moved its domain to the browser; the race does not feed the sample comparison, so until its weighing ([#768](https://github.com/goodfetch/goodfetch/issues/768)) an attempt whose Label on its domain is due a sample takes that sample in place of a race (owner, 2026-10-28, deep review item 582-O1), and a racing Run learns its Labels' choices as any other. A request a hidden link reached (ADR 0035's #1153 note) races with no navigation, which loses as `not_sent` with the `decoy` a browser run of it ends with.
  > - **The delay:** the median by nearest rank of the latest 128 browser-fetch latencies of the request's Label on its domain key, 500 ms before any; a latency runs from the race's start, robots.txt read included, to its document's arrival, and is kept in memory for the Run, so a resumed Run starts again at 500 ms.
  > - **The comparison:** until the sample comparison's weighing ([#768](https://github.com/goodfetch/goodfetch/issues/768)), browser-fetch's page agrees with its Label's comparison unless the Label, or the request's path segment of it, was learned onto `browser`.
  > - **The winner:** browser-fetch wins with a page that passes the Page check and agrees; the navigation wins with a page that passed it. A refusal (robots.txt, a hop out of scope, an AI-use signal) or the lease's end on browser-fetch ends the attempt for both. When neither wins, the attempt fails with the navigation's failure, else browser-fetch's. A handler that escalates browser-fetch's page runs again in the browser, as on `http`.
  > - **Room:** the navigation takes room beside the attempt's own as a hedge does, waits its key's delay through the navigation gate, and charges one `requests` in Usage; while its domain is full it asks again every 250 ms, as the navigation gate does, until the race ends, and Usage with none left never sends it.
  > - **Cancelling:** a browser-fetch in flight is dropped, closing its connection, and a page it served closes as it drops; a navigation not yet sent is never sent, and one sent has its page closed, its load with it, and gives its room back; Collie's `BrowserPages::open` now closes its page when dropped after it opened.
  > - **Provenance:** `tier_race` (the delay, how each run ended: `won`, `failed`, `cancelled` or `not_sent`, and the winner, `browser_fetch` or `browser`), and the winner's `fetch_tier` entry with `chosen: race`, whose `tier` names the winner as `tier_race` does (owner, 2026-10-28, deep review item 582-O1); the handler is still given browser-fetch's page on `http`, the tier it serves as.
  - **Otherwise:** ADR 0020's sample comparison stays the default.
- **Coalescing** is on by default. Identical GET or HEAD requests in flight at the same time from the same Session, from work items that declare no Effect, wait for one response. Identical means the same method, URL and the headers that change the response. Typical cases are robots.txt, sitemaps, discovered-API calls and shared subresources.
  - **Never across Sessions or runs:** cookies differ between Sessions, and the run is the unit of isolation.
  - **Recorded:** Provenance records that a response was shared, and coalescing is a setting.
  > Note (agent decision, pending owner review), 2026-10-24, [#238](https://github.com/goodfetch/goodfetch/issues/238): how the HTTP tier builds both.
  > - **Keys:** `fetch.hedge.enabled` (off), `fetch.hedge.max_percent` (5, whole percent of the requests the Run's HTTP tier sent, hedges not counted) and `fetch.coalesce` (on), Foxhound's beside `fetch.tier`.
  > - **Threshold:** a route is a Label on a domain key. Its latency is a whole fetch's, from the first copy's send to the answer used, of successful fetches only; its threshold is the 95th percentile by nearest rank of its latest 128, and a route hedges nothing before 20.
  > - **Room:** the copy takes a Permit of its domain key from the Politeness the Run shares, beside its first's and without waiting in turn, a share of the rate cap, an HTTP admission of the governor and one `requests` in Usage. A key whose delay has not passed holds the copy until it has; one with no free slot, or one a `Retry-After` holds past the Run's wait, never sends it. The refusal at a concurrency of 1 is the Frontier's one rule for every second copy, so `fetch.tier_race` takes it too; since `politeness.domain.concurrency` is unset until the fetch tiers set ADR 0086's default, it refuses only a value of 1 set.
  > - **The winner:** the first copy that answers; a copy that fails waits for the other, and when both fail the first's failure is the request's.
  > - **Identical:** the same Session, method, URL, every header the request carries and body, a conservative reading of "the headers that change the response". An answer shared includes a failure; a first request cancelled before it answered leaves the next to send its own.
  > - **Provenance:** `hedged` (the URL, the threshold, which copy answered) and `response_shared` (the request whose response it shared), in the Run trace's Provenance log.
  > - **Effects and Paid fetches:** the rule takes whether the work item declared an Effect and whether the fetch is paid; the crawl passes neither until area 9's Effect journal and ADR 0045's Paid fetches exist.
