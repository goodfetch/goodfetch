# Nothing leaves the machine unless configured

Goodfetch sends nothing about its user, their runs or their machine anywhere except to destinations a run, Recipe, user or operator configured. There is no product telemetry, not even opt-in, and no setting can turn it on. The only connections nobody configured are downloads of artifacts pinned by digest, which carry nothing about the user, and an `offline` setting turns them off. The rule covers the binary, the SDKs, the CLI, the MCP server, the Console, Plugins and the browsers Goodfetch launches, and CI enforces it. Before this decision only the Console (ADR 0031) and version checks (ADR 0030) promised it (parity row SC-10). Decided in [Network defaults](https://github.com/goodfetch/goodfetch/issues/118).

> Amended by [ADR 0137](0137-the-console-leaves-both-products-and-the-engine-and-the-owners-monitoring-tool-is-designed-apart.md): no Product carries a Console. The engine behaviour this ADR describes stands and the Console's part does not; a Client reaches it.

Goodfetch's users send it the URLs, accounts and tasks they care most about, so telemetry costs more trust here than elsewhere. Browser Use sends PostHog events by default, tied to a device ID persisted on disk or derived from the MAC address and host name, and its docs now say they may include tasks, visited URLs and results ([service.py](https://github.com/browser-use/browser-use/blob/main/browser_use/telemetry/service.py), [telemetry docs](https://docs.browser-use.com/open-source/development/monitoring/telemetry)). Its users report the gap between "anonymous usage data" and what is sent ([browser-use#5216](https://github.com/browser-use/browser-use/issues/5216)) and an empty `ANONYMIZED_TELEMETRY=` turning it on ([browser-use#5837](https://github.com/browser-use/browser-use/issues/5837)). Stagehand's CLI sends events unless `DO_NOT_TRACK`, `BROWSERBASE_TELEMETRY_DISABLED` or `CI` is set, and its SDKs send none ([telemetry.ts](https://github.com/browserbase/stagehand/blob/main/packages/cli/src/lib/telemetry.ts)). Crawlee, Playwright, Scrapy and Spider have no telemetry; self-hosted Firecrawl sends events only with a configured PostHog key.

## Considered Options

- **Opt-out telemetry** (the Next.js and Homebrew model): rejected. It contradicts what Goodfetch's users expect, and Browser Use shows what it does to trust.
- **Opt-in telemetry**: rejected. Few users enable it, so it gives little data, and it is still code that must be maintained and audited on every release.
- **Honouring `DO_NOT_TRACK`** (Stagehand's CLI): unnecessary, since nothing is sent to switch off.
- **Leaving browsers' background traffic on**: rejected. Chrome's component updates, Safe Browsing and field-trial fetches are calls to Google from the user's machine that nobody configured.

## Consequences

**The rule.**
- **Changes ADR 0016:** this rule joins the controls that cannot be switched off.
- Configured destinations are those set in a run, a Recipe, user or project configuration, or Operator policy: targets and the pages they lead to, proxies, Sinks, webhooks and Notifications, Model providers, Secret providers, OTLP export, the Plugin index and registries, and payment endpoints (ADR 0045).
- **Changes ADRs 0024 and 0033:** unconfigured connections are limited to downloads of artifacts pinned by digest: browsers on first use (ADR 0024), Lightpanda when its tier is chosen (ADR 0020), browsers a Plugin declares and Plugin language runtimes (ADR 0033), Cursory's recordings (ADR 0035), the Clean-up rules on first use by any run (ADR 0047), the `goodfetch` binary of its exact version when the Rust crate first needs it (ADR 0051), and the Proving ground binary and seed when `goodfetch plugins test` first needs them (ADRs 0025 and 0033; settled on the gaps the [Proving ground and conformance spec](https://github.com/goodfetch/goodfetch/issues/152) listed, as the [owner settled them](https://github.com/goodfetch/goodfetch/issues/152#issuecomment-6115242029)). They are plain HTTPS GETs to the pinned URL with no cookie, no identifier, no query beyond the pinned path and no user agent naming the install.
- The `offline` setting, which Operator policy can lock, turns each of those downloads into the Error code `artifact_unavailable_offline`, which is not retryable (ADR 0038). They can be supplied beforehand: `goodfetch browsers install` fetches browsers, Lightpanda, Cursory's recordings, the Clean-up rules and the Proving ground, `goodfetch rules update` fetches the Clean-up rules alone, `GOODFETCH_BROWSERS_PATH` points at a copy, `GOODFETCH_ENGINE_PATH` points at the `goodfetch` binary, and `goodfetch plugins add` fetches a Plugin's runtime along with its artifact. For the Clean-up rules, only an explicit `goodfetch rules update` raises it; a run uses the version it has (ADR 0047).
  > Amended by [ADR 0115](0115-a-cdp-url-the-engine-cannot-use-and-a-missing-browser-build-fail-with-one-error-code-per-remedy.md): `artifact_unavailable_offline` is a `RefusedError` whose `limit` names `offline` and the layer that set it, and whose details name the artifact and what pins it (a Product version, or the Plugins that use a runtime), raised by the call or command that first needs it; a pinned download that fails is `artifact_download_failed`, an `UnavailableError`, retryable.
- The rule binds Goodfetch's own code. A third-party Plugin's manifest domains and network level are approved by a person when it is installed or updated (ADR 0033), which makes them configured. At the `direct` level the engine does not see the Plugin's connections, and approving `direct` is what grants that.
- Any future call that is neither configured nor a pinned download needs a decision that changes this ADR.

**Diagnostics.**
- Crash reports and panics are written to a local file and never sent.
- `goodfetch doctor` builds a redacted bug-report file (versions, settings with secrets removed, recent errors) that the user chooses to attach to an issue.

**Browsers.**
- Every browser Goodfetch launches has its background traffic turned off, starting from Playwright's switches ([chromiumSwitches.ts](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/chromium/chromiumSwitches.ts)): `--disable-background-networking`, `--disable-component-update`, `--disable-breakpad`, `--disable-sync`, `--disable-client-side-phishing-detection`, `--metrics-recording-only`, `--disable-field-trial-config`, and the features `OptimizationHints`, `NetworkTimeServiceQuerying`, `Translate` and `MediaRouter`. Firefox and Camoufox get the matching preferences.

  > Note (agent decision, accepted by the owner on 2026-10-22), 2026-10-21, [#639](https://github.com/goodfetch/goodfetch/issues/639): the list is the table `CHROMIUM_BACKGROUND_TRAFFIC_OFF` in `goodfetch-engine`'s `pinned_download` module, which the launcher applies to every launch. Chrome for Testing 156 launched with only the switches above, and with all of Playwright's, still asked `accounts.google.com` (`ListAccounts`, at every startup, signed in or not), `www.google.com` (AI Mode's eligibility, and a preconnect to the default search engine) and `update.googleapis.com` (a component installed on demand, which `--disable-component-update` leaves on), as its traffic through the Proving ground's forward proxy showed. The table adds the features `AimEnabled` and `PreconnectToSearch`, and points the two endpoints no switch turns off at names that never resolve: `--gaia-url=https://gaia.invalid` and `--component-updater=url-source=https://components.invalid`, which the launcher's `MAP *.invalid ~NOTFOUND` rule fails without a DNS query. Chrome for Testing has no OAuth client, so it runs without Desktop Identity Consistency and a site sees no change; for an installed Chrome, where Chrome adds its account headers to requests to Google's sign-in host, the redirect is area 8's to weigh.
- **Changes ADR 0035:** the Goodfetch Chromium build turns this traffic off at build time rather than by switches. It also ships the variations seed and its Google signature, captured when each Stable major is built and loaded through `--variations-test-seed-path` with `--disable-variations-seed-fetch`, so Google sites receive the `X-Client-Data` header a real Chrome sends ([variations_http_headers.cc](https://chromium.googlesource.com/chromium/src/+/main/components/variations/net/variations_http_headers.cc)) with no call at run time. The seed is Google's signed data, so its redistribution gets a licence check before the first public preview and an entry in ADR 0018's notice inventory, like every third-party input of the build. Chrome for Testing is unbranded and never sends the header, as in every Playwright and Puppeteer setup; the docs say so.

**Enforcement.**
- **Changes ADR 0032:** every step that runs Goodfetch's product (the surfaces of this ADR's opening paragraph), in every CI tier and on every operating system it covers, denies outbound traffic except to the fixtures and the pinned artifact mirror, and fails on any other connection. The conformance suite therefore proves the rule wherever it runs, including the nightly installed-Chrome matrix. Settled in [Tighten ADR 0043's CI rule scope](https://github.com/goodfetch/goodfetch/issues/129) and [Release promotion, release branches, vendor conformance and docs hosting](https://github.com/goodfetch/goodfetch/pull/131), on the gaps the [Repository, CI and release spec](https://github.com/goodfetch/goodfetch/issues/130) listed, as the [owner settled them](https://github.com/goodfetch/goodfetch/issues/130#issuecomment-6114909646):
  - **Before the deny:** checkout, toolchain and dependency installs, pinned container images and cache restores.
  - **Outside the rule:** jobs that run none of the product, such as publishing, signing, the Plugin index signature, deploying the docs, deploying the online Proving ground and the watchlist job (ADR 0035).
  - **The pinned artifact mirror** is the set of digest-pinned downloads this ADR's rule lists, or a CI cache of them.

    > Amended on 2026-10-19 (owner decision of 2026-10-19): the mirror is fetched before the deny and is not reachable under it. A job under the deny reaches only the fixtures, and its named endpoints when this ADR names it; every pinned download, the test V8 build (ADR 0067) and Goodfetch's own releases from `compat/releases.toml` (ADR 0066) included, comes before the deny, so a denied step that reaches GitHub fails the job ([#135](https://github.com/goodfetch/goodfetch/issues/135)).
  - **A canary** in every job under the deny tries a forbidden connection after the deny starts and must be refused.
- Only these jobs may also reach named endpoints, and only those:

  > Amended by [ADR 0065](0065-ai-features-are-tested-without-live-models-and-measured-by-oracle-graded-evaluations.md): adds the provider check, the recorder and the Evaluations, which reach only the Model providers, gateways and hosted Decision providers they name.

  - the nightly real SaaS sink accounts (ADR 0026);
  - the release-candidate benchmark's online Proving ground behind real vendor protections and the model, proxy, CAPTCHA and hosted-browser services it pays for (ADRs 0025 and 0035);
  - the nightly public testnets that check Paid fetch proofs (ADR 0045);
  - the online conformance of fetch backends, browser backends and Challenge solvers against real vendors (ADR 0033). It runs on every release candidate, on every patch that carries a new Chrome major or new stealth material, and on manual dispatch. It reaches only the online Proving ground, the hosts from which the challenges of the vendors protecting it load, and, for a Challenge solver that uses one, its solving service; the online Proving ground reads the vendors' verdicts server-side. It reports in the release notes and never blocks a release, because a vendor's own scoring change is outside Goodfetch's control and must not hold back a same-day security patch;
  - the nightly build of the Clean-up rules' daily channel (ADR 0047), which reaches the upstream Filter-list URLs, autoconsent's package, the online Proving ground for its gate, and the hosts from which the challenges of the vendors protecting it, and the consent vendors it uses, load;
  - the release-candidate Cloud Run deploy (ADR 0049), which reaches only Google Cloud's APIs, Artifact Registry and the deployed Cloud Run service's own URL, authenticates through Workload Identity Federation with no stored key, and runs in a Google Cloud project the owner approves as a paid test resource (settled on the gaps the [Repository, CI and release spec](https://github.com/goodfetch/goodfetch/issues/130) listed, as the [owner settled them](https://github.com/goodfetch/goodfetch/issues/130#issuecomment-6132949033));
  - a fixture's licence endpoint where the fixture needs one, named in its job.
- The Console's Content Security Policy (ADR 0031) and the offline version checks (ADRs 0030 and 0035) are instances of this rule.
  > Amended by [ADR 0137](0137-the-console-leaves-both-products-and-the-engine-and-the-owners-monitoring-tool-is-designed-apart.md): no Product carries a Console, so what this says of the Console ends; the rest stands.
- The daily channel of the Clean-up rules is a configured destination once `clean_up.update = daily` is set or `clean_up.version` names a daily set, the Filter lists' own URLs once `clean_up.update = upstream` is set, and a Filter list URL once `filter_lists.extra` names it (ADR 0047).
- ADR 0051 adds the `goodfetch` binary, which the Rust crate downloads on first use for the Script sandbox and `plugin-shim`, to the pinned downloads.
