# An ops listener serves token-free probes and token-protected metrics, from one OpenTelemetry instrumentation

A Daemon can open an **ops listener**, off by default, on its own port. Its `/livez` and `/readyz` answer without a token and return an HTTP status only; its Prometheus `/metrics` requires a scoped read-only token. Metrics are instrumented once with the OpenTelemetry metrics API and exported through OTLP (decided opt-in in [Adopt runtime and state decisions](https://github.com/goodfetch/goodfetch/issues/70)), the Prometheus endpoint, or both, each off until configured. Metric labels hold bounded values only, and metric names are a versioned contract. Decided in [Self-hosted deployment and operations](https://github.com/goodfetch/goodfetch/issues/120).

Browserless users asked for a health check that needs no token, for Kubernetes probes ([browserless#4168](https://github.com/browserless/browserless/issues/4168)), and its `/pressure` once failed to return 503 under load ([browserless#4820](https://github.com/browserless/browserless/pull/4820)); its v2 `/metrics` is JSON, not Prometheus. Firecrawl's production probes are an open request ([firecrawl#4291](https://github.com/firecrawl/firecrawl/issues/4291)) and its prom-client metrics sit behind an admin key. Crawlee has OpenTelemetry tracing (`@crawlee/otel`, `crawlee[otel]`) and no metrics endpoint. Kubernetes deprecated `/healthz` in 1.16 for `/livez` and `/readyz` ([docs](https://kubernetes.io/docs/reference/using-api/health-checks/)). Prometheus can receive OTLP, but only with `--web.enable-otlp-receiver`, which most installs do not set.

## Considered Options

- **Probes behind the endpoint token** (ADR 0017): rejected for the two probe paths only. The token would sit in every pod spec, and `exec` probes do not exist on every platform. The probes reveal nothing beyond up or down.
- **Unauthenticated metrics**: rejected. Even bounded metrics reveal a deployment's activity.
- **OTLP only**: rejected. Kubernetes users scrape Prometheus endpoints through `ServiceMonitor`s.
- **Two instrumentations** (the `metrics` crate for Prometheus beside OpenTelemetry): rejected. Names and units would drift between exporters. `opentelemetry-prometheus` is maintained (0.33.1).
- **URLs, domains or run IDs as labels**: rejected. They blow up cardinality and leak targets into monitoring stacks; that detail stays in each run's own state and traces.

## Consequences

**Ops listener** (changes ADRs 0016 and 0017: the probe paths are the only endpoints without a token).
- `/livez` succeeds while the Tokio runtime and the run-state writer respond.
- `/readyz` succeeds while the Daemon can accept a new run: run state is writable, the browsers its configuration uses are available, it is not draining, and the governor has not reached its last-resort stage, where runs stop as `resources_exhausted` (ADR 0040). In a Daemon group, readiness ignores the Lead Daemon's reachability; new runs that need a slice, and `partitions` above 1, are then refused with `lead_unreachable` (ADR 0055).
  > Amended by [ADR 0122](0122-a-run-stops-resumably-before-its-disk-fills-and-a-daemons-logs-rotate-at-a-bounded-size.md): `/readyz` also fails while the filesystem holding run state is at the `critical` storage level, and the metrics gain each sampled filesystem's free space and storage level, labelled by what it holds.
  > Note (agent decision, on a guarantee, not read by the owner), 2026-10-24, [#1255](https://github.com/goodfetch/goodfetch/issues/1255): `/readyz` reads the Resource governor's last storage sample, so it fails from the first sample that finds the run folders' filesystem at `critical` and succeeds again from the first that does not; `daemon health` names the reason `storage_critical`. The three metrics `goodfetch.storage.available` (`By`, rendered `goodfetch_storage_available_bytes`), `goodfetch.storage.inodes.available` (`{inode}`) and `goodfetch.storage.level` (`{level}`: 0, 1, 2) give one series per value of `holds` whose folder was sampled, so a filesystem holding run state and the home gives both series, equal, and an alert on `holds="run_state"` never depends on which folders share a filesystem. A filesystem that reports no inodes gives no inode series. `trace` is declared but has no series until a Run trace folder is sampled (ADR 0122's note of #1566).
  > Note (agent decision, accepted by the owner on 2026-10-28, deep review of M1 (583-2, 583-7, O30 (a1) and (b1))), 2026-10-29, [#1255](https://github.com/goodfetch/goodfetch/issues/1255): `/readyz` reads the filesystems of the Daemon's essential writes afresh on each probe, one `statvfs` each on the blocking pool, as a start reads them, rather than the governor's last sample, so readiness and the start's `resources_exhausted` agree, at a Daemon's start too. Those filesystems are run state's (the per-major folder, which holds the install database, in the per-install layout; the run folders' folder otherwise) and the Goodfetch home's, which holds the Usage ledger and the Politeness file: `storage_critical` names either at `critical`. The `holds="run_state"` series follows run state in the same way, so in the per-install layout it reads the install database's filesystem wherever the run folders are.
- Neither returns a body, a version or run information.
- `/metrics` takes a scoped read-only token as a bearer token.
- `goodfetch daemon health` answers the same questions for `exec` probes and systemd.
  > Note (agent decision, accepted by the owner on 2026-10-22; [#230](https://github.com/goodfetch/goodfetch/issues/230)): how the ops listener is built until area 4 and area 12 bring scoped tokens and TLS.
  > - **Where.** Only `daemon run` opens one, at `ops.address` (unset by default, so none), which `GOODFETCH_OPS_ADDRESS` overrides unless the Operator policy locks it. Any address is taken, unlike `daemon.address`, so a cluster's kubelet and Prometheus reach it. A request whose `Host` is a name other than `localhost` (an IP address passes, as kubelet's and Prometheus' pod-IP requests carry), or that carries an `Origin`, is refused with 403 before anything else, so a DNS-rebinding page reads nothing; each refusal is logged under the listeners' refusal target with its reason.
  > - **Token.** The scoped read-only token is the ops token, the `ops.token` file (`0600`) of the major's folder, which the Daemon makes when it finds none and an operator may write beforehand, as a mounted Kubernetes Secret does; no other listener takes it, and `/metrics` refuses the Daemon's own token, a token in the query string and none at all with 401.
  > - **Checks.** Live: the Daemon's Runs registry, which writes their run state, answers. Ready: live, a file can be written in the folder of the run folders, the browser a Run launches by default is installed (the pinned build in the Browser cache, or the distribution's Chromium where no build is made), and it does not drain. The governor's last resort joins with #234, and ADR 0122's `critical` storage level with #1566.
  > - **`daemon health`.** It asks the major's running Daemon, found through its runtime file, or else the foreground Daemon at `daemon.address` with the persistent token, over the new operation `daemon.health`, which answers `live`, `ready` and the reasons it is not ready; `--live` answers `/livez`'s question instead of `/readyz`'s; it exits 0 when the answer is yes and 1 otherwise, no Daemon answering included.
  > - **Export.** Prometheus is on whenever the ops listener is, its text holding the metrics alone (no `target_info`, no scope labels). OTLP is on once `otlp.metrics_endpoint` names a collector: OTLP/HTTP in protobuf every 60 seconds, and once more as the Daemon exits.
  > - **Initial set.** Emitted now, all Stable: `goodfetch.run.active` (by `run_kind`), `goodfetch.run.ended` (by `run_kind`, `lifecycle`, `verdict`, `completeness`), `goodfetch.browser.running` (by `browser`: `chrome_for_testing` or `chromium`), `goodfetch.client.connected` (by `surface`), `goodfetch.daemon.draining`, and Foxhound's `goodfetch.work_item.leased` and `goodfetch.work_item.retried`, which the crawl makes on the meter each Run hands out. Declared now and emitted by #234: `goodfetch.governor.saturation`, Experimental. The rest of the set joins with the tickets that build what it measures: work items queued (the Frontier's depth), browsers recycled and their memory, the governor's target and pressure source, Politeness degraded periods and the Lead Daemon's reachability.

  > Note (agent decision, on a guarantee, not read by the owner), 2026-10-28, step 7 review finding 213-misc-1 ([#230](https://github.com/goodfetch/goodfetch/issues/230)): three Experimental metrics join the runtime's initial set: `goodfetch.work_item.queued`, an up-down counter of the work items Foxhound's per-domain queues hold, each queue at most 64, so those still in the Frontier past that bound are not counted; `goodfetch.browser.recycled`, a counter by `reason` (`pages`, `memory`, `idle`, `shed`) of the browsers the Runs' pools recycled; and `goodfetch.browser.memory`, a gauge in bytes of what the browsers the Resource governor counts used at its last sample, summed, which `engine.system_info` also gives as `memory.browsers`. A metric per browser would need a label per browser, which ADR 0050's bounded labels forbid.

**Metrics** (adds to ADR 0030).
- Names follow OpenTelemetry conventions under `goodfetch.*`, rendered `goodfetch_*` for Prometheus, and are generated from `goodfetch-protocol` into the reference, as the Operation catalog is (ADR 0038).
- Each metric is Stable or Experimental under ADR 0030's semver scope.
  > Amended by [ADR 0132](0132-each-request-may-carry-its-callers-trace-context-across-goodfetchs-own-links-and-the-engines-spans-stay-experimental.md): metric names stay a versioned contract; span names and span fields do not, and are Experimental.
- The initial set: runs active by Lifecycle and finished by Verdict and Completeness (ADR 0029); work items queued, leased and retried; requests by tier and outcome, Block causes, and latency histograms by tier; browsers running, recycled and their memory; the governor's concurrency target and pressure source; Sink delivery lag and failures by Guarantee class (ADR 0026); model calls, tokens and latency by provider under the GenAI conventions; connected Clients and drain state.
- Labels take values from bounded sets only, such as tier, Block cause, Error code, browser kind and Guarantee class.
- Usage stays journaled and is never derived from metrics or traces.
