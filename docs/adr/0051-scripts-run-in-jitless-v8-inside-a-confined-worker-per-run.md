# Scripts run in V8 without JIT, inside a confined worker per run

Code mode programs and Script Hooks run in the **Script sandbox**: V8, built from source with its own sandbox on and always without JIT, inside a worker process confined as ADR 0033 confines a Plugin at network level `none`, one set of workers per run. Both kinds of script are untrusted: a page can steer the model that writes a program through prompt injection, and a Recipe that carries a Script Hook may come from a stranger. A JavaScript engine is a large C or C++ program, so a bug in it hands the script whatever process it runs in; in the engine's own process that is every run, the resolved Secrets, Session cookies and the run key. The worker holds none of them, and the OS caps it where the engine's own limits fall short. Decided in [Code-mode JavaScript sandbox engine](https://github.com/Jbmanllr/automan/issues/125).

Evidence: [JavaScript engines for the code-mode sandbox and Script Hooks](https://github.com/Jbmanllr/automan/blob/research/js-sandbox-engines/rnd/research/2026-10-12-js-sandbox-engines.md) (measured on macOS arm64 and in aarch64 and x86_64 musl containers) and [Code-mode sandboxes in practice: engines, confinement and author contracts](https://github.com/Jbmanllr/automan/blob/research/code-mode-sandboxes/rnd/research/2026-10-12-code-mode-sandboxes-in-practice.md).

|---|---|---|---|
| Size added to the binary | +1.1 MB | +42.8 MB | +10.3 MB |

| test262 ([test262.fyi](https://test262.fyi)) | 83.5%, no `Intl` or `Temporal` | 97.7% (measured on V8 15.7) | 95.6% |

## Considered Options

- **Scripts in the engine's own process**: rejected. Fastest (one hook call in 1 to 5 µs instead of a pipe round trip), but one engine bug reaches every run and Secret. Both remaining engines also need a backstop the process cannot give itself: V8 aborts the whole process when it runs out of memory unless a callback catches it, and QuickJS's interrupt runs only every 10,000 bytecode steps. In-process JavaScript sandboxes keep being escaped: vm2 had about 60 advisories in 2026, n8n's `node:vm` runner was escaped twice in 2026, and Figma left its Realms shim for QuickJS inside WebAssembly.
- **QuickJS-NG through `rquickjs`**: rejected. It is 40 times smaller, but it had ten security advisories in 2026, several of them memory corruption on the out-of-memory path that a memory limit triggers, and on 2026-10-11 it stopped taking private security reports and issuing CVEs; it is not on OSS-Fuzz. It lacks `Intl` and `Temporal`, which the owner expects models to reach for when parsing prices and dates. `rquickjs` also prints failed jobs to stdout, which only the transport may write.
- **Boa**: rejected. It has no memory limit and nothing can stop a running script from outside; its interrupt pull request closed unmerged in August 2026.
- **`deno_core`**: rejected. 47 breaking releases in twelve months, it pins an older V8 than the `v8` crate, and it brings a runtime the sandbox does not need.
- **V8 with JIT**: rejected. On macOS the hardened runtime then needs the `allow-jit` entitlement, and a TurboFan-optimised loop can escape `terminate_execution` ([rusty_v8#2088](https://github.com/denoland/rusty_v8/issues/2088), reproduced on 152.2.0). Without JIT it runs with no entitlement, every loop the research probed stopped, and WebAssembly is gone, which narrows the attack surface.
- **The `v8` crate's prebuilt libraries**: rejected. They ship with V8's own sandbox off, their musl builds exist only since July 2026 and are not tested in the crate's CI, and the crate had not released since 2026-08-20, while Chrome fixed two V8 bugs exploited in the wild after the crate's V8 pin of 2026-07-29 (whether that V8 is affected was not verified).
- **Type-checking programs before they run** (pctx, used by goose): rejected for performance. The TypeScript 6 compiler inside the sandbox adds about 9 MB and seconds per program without JIT; TypeScript 7's Go compiler would be a second binary per platform and has no stable programmatic API until 7.1. The engine already checks every catalog call's arguments against the schema of ADR 0038 before it acts, and the replay rule below makes a corrected program safe after earlier Effects.
- **TypeScript refused** (Cloudflare's prompt forbids it): rejected. Models given TypeScript declarations write annotations, and each refusal costs a turn.
- **State kept by a Script Hook between calls**: rejected. Results would depend on when a worker was last replaced, after a crash, a limit or a resume elsewhere (ADRs 0002 and 0003).
- **The Rust crate starting the user's program again in a worker mode**: rejected. It puts V8, its 43 MB and its musl link flag into every crate user's build, and a forgotten call in `main` fails only at run time.

## Consequences

**The engine.**
- `goodfetch` links V8 through the `v8` crate, built from source (`V8_FROM_SOURCE`) in release CI with V8's sandbox on, for every V1 target of ADR 0024. On aarch64 musl the link needs `-lgcc` for `__clear_cache`; x86_64 musl links with default flags. V8 always runs with `--jitless`.
- The engine's V8 is never more than one Chrome Stable major behind. When the `v8` crate lags, Goodfetch carries the update in a fork and sends it upstream; a release check fails when the rule is broken (adds to ADR 0030).
- The spec measures, on the reference host and with the bundled mimalloc, V8's cost with its sandbox on and the 3 to 5 times slowdown seen in a musl container, whose cause the research did not isolate.

**Confinement.**
- The worker is the `goodfetch` binary started in a worker mode, as `plugin-shim` is, confined as a Plugin at network level `none` with no file access, under ADR 0033's per-OS mechanisms. It reaches the engine only over its pipe and never holds a Secret: the engine inserts Secrets into the catalog calls it carries out, as it does for Plugins.
- Workers start lazily, at a run's first script, and are never shared between runs. The governor of ADR 0040 sizes each run's pool between one worker and the run's concurrency, since a worker runs one script at a time while it computes.
- Limits apply at two levels. V8's heap limit, its near-heap-limit callback and `terminate_execution` enforce them first; ADR 0033's resource limits are the backstop (cgroup v2 where delegated, else rlimits, on Linux; footprint sampling on macOS; a Job object on Windows), and the engine kills a worker past its hard deadline. The Linux rlimit fallback is `RLIMIT_DATA`, never `RLIMIT_AS`, since V8 reserves a 4 GB pointer-compression region ([V8](https://v8.dev/blog/pointer-compression)) and, with its sandbox on, a far larger address-space reservation ([V8](https://v8.dev/blog/sandbox)) than any memory limit.
- **Failures** (changes ADR 0033). A worker killed for time or memory, or crashed, fails only the script call it was running, with `script_time_exceeded`, `script_memory_exceeded` or `script_crashed`, which replace `plugin_limit_exceeded` and `plugin_crashed` for the Script sandbox; a limit V8 itself enforces raises the same codes, and no script can catch them. The two limit codes are not retryable and `script_crashed` is (ADR 0038). The engine tells a limit from a crash by the OS limit's own event: a cgroup's `memory.events`, a Job object's memory or end-of-time notification, its own footprint sampling on macOS, and `SIGXCPU` under `RLIMIT_CPU`; under `RLIMIT_DATA`, by the cause the worker's V8 out-of-memory handler sends over the pipe before the process exits. A death with none of these is `script_crashed`.
  - A failed Script Hook is a `hook_failed` naming that code (ADR 0033); it carries the `retryable` flag of the code it names (ADR 0038), and the work item's policy retries it only when that flag is set.
  - A failed code-mode program returns the code and its captured `console` to the model, which decides what to run next; the engine does not retry it.
  - The worker restarts with backoff, as a Plugin does. A catalog call the engine was carrying out for the script when the worker died completes and is journaled as usual, since the engine, not the worker, carries out every Effect.
  - Only repeated `script_crashed` counts toward ADR 0033's quarantine; time and memory limits fail only their call. A quarantined Script Hook fails its stage with `hook_failed` naming `script_quarantined` for every later work item, never skipped silently, and a quarantined code mode answers every program with `script_quarantined`, which is not retryable. Both last for the rest of the run, and the quarantine sends a Notification.

**What a script is.**
- A program is JavaScript, or TypeScript whose types are stripped by `oxc` and never checked. A code-mode program is the body of an `async` function, with `await` at the top level, and returns a JSON value. A Script Hook is a single function expression (an arrow or a `function`), `async` or not, receiving its stage's context. There are no modules and no `import`.
- A script gets standard JavaScript including `Intl` and `Temporal`, and only the web APIs that touch nothing outside it: `URL`, `URLSearchParams`, `TextEncoder`, `TextDecoder`, `atob`, `btoa`, `structuredClone`, `crypto.getRandomValues` and `crypto.randomUUID`. `console` is captured into the Run trace and returned to the model. There is no `fetch`, no timers, no WebAssembly, no `require` or `process`, and no file or socket; waiting and fetching are catalog calls.
- Each catalog namespace is an async global (`await page.click(…)`, `await net.fetch(…)`), with the names and shapes of the TypeScript SDK (ADR 0038), from the same generator. Code mode's declarations are generated from the Operation catalog and trimmed to the MCP profile; a Script Hook's are those of its stage.
- A Script Hook has nowhere to keep state: its source must parse as one function expression; each worker's context is locked down at setup with Endo's SES `lockdown()` ([ses](https://github.com/endojs/endo/tree/master/packages/ses), Apache-2.0, used by MetaMask), which deep-freezes every built-in object and prototype reachable from `globalThis` and removes legacy statics such as `RegExp.$1`, keeping `Date.now` and `Math.random` live; and the hook's function object is `harden`ed, so it cannot carry properties either. Each worker then keeps one warm context per Script Hook for the whole run. Lasting state goes in the run's Key-value store, whose operations Script Hooks gain (changes ADR 0033). Each code-mode program starts in a fresh context; what carries over travels through its return value or the Key-value store.

**Replay** (adds to ADR 0010).
- A corrected or resumed program is replayed against the Effect journal by position, the rule the lab measured at zero false successes in 135 runs: the same Effect at the same position is skipped and reported "already applied"; a different Effect while an Effect that cannot be repeated still lies ahead in the journal stops the program with `effect_diverged`, which it cannot catch; an Effect that only sets a value (`fill`, `select`) resumes live when nothing unrepeatable lies ahead.
- The engine carries out one program's Effects one at a time, so `Promise.all` cannot reorder them, as it can in Cloudflare's position-keyed runtime. Reads stay concurrent and are not journaled; model calls are, as ADR 0010 already says. `Date.now` and `Math.random` stay live, since only the order of Effects is compared.

**The Rust crate** (changes ADRs 0024, 0033 and 0043).
- The crate never links V8. For the Script sandbox and for `plugin-shim` it runs the `goodfetch` binary of its exact version, found through `GOODFETCH_ENGINE_PATH` or downloaded on first use into the shared cache, pinned and checked by digest, as browsers are. This download joins ADR 0043's list of pinned downloads: under `offline` a missing binary is `artifact_unavailable_offline`, and setting `GOODFETCH_ENGINE_PATH` supplies it beforehand.

**Other changes.**
- **Changes ADRs 0011 and 0033:** the sandbox that runs code mode and Script Hooks is the Script sandbox, a confined worker rather than part of the engine's process.
- **Changes ADR 0039:** the `goodfetch` binary carries no `allow-jit` entitlement.
- Default limits (CPU time, wall time, memory, result and log sizes, number of catalog calls) are spec values, set through the layers of ADR 0028.
