# The SDK API follows eight guarantees and four ranked shape rules

Every decision about the SDK API of Goodfetch Collie and Goodfetch Foxhound follows numbered principles, so the tickets that design it cite a principle instead of arguing taste again: eight guarantees that no shape may break, four shape rules ranked for when they conflict, and a tie-breaker. They bind the TypeScript, Python and Rust SDKs, and the naming rules by which the Operation catalog names what every surface shows. They come from two research notes: what users of Playwright, Stagehand, Browser Use, Crawlee, Scrapy and their peers praise and complain about ([research on their APIs](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md)), and what the leaders of multi-language SDK design prescribe (Azure, Stainless, AWS, the Rust API Guidelines) together with what is known about the code coding agents write ([SDK design guidelines research](https://github.com/goodfetch/goodfetch/blob/research/sdk-design-guidelines/rnd/research/2026-10-14-sdk-design-guidelines.md)). Both notes agree: users praise and complain about the same qualities the guidelines prescribe. Decided in [SDK API principles](https://github.com/goodfetch/goodfetch/issues/462), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461).

## Decision

### Guarantees

A guarantee is never traded for a shorter, faster or more familiar shape: a shape that breaks one is rejected.

- **G1. Honest results.** A failure never looks like a result, an expected outcome (not found, nothing to do, blocked by policy) is never thrown as a failure, and a call that did nothing says why. Browser Use reports failed tasks as successes, Skyvern's `extract` returns `None` when its own server fails, and Firecrawl returned failed jobs exactly like successful ones; Azure forbids raising on a normal outcome such as a 404 from `exists()`; Crawlee users meet a second run that does nothing and does not say why. Whether failures are values or exceptions is decided in [Results, outcomes and errors](https://github.com/goodfetch/goodfetch/issues/466) (ADR 0079).
- **G2. No hidden state.** Every call acts on a value the caller holds (an engine connection, a page, a frame, a run, a Session): no current-page or current-frame pointer, no implicit queue, no implicit purge and no process-wide default instance. A one-call helper may start its own engine and stop it before it returns, since nothing survives the call. Selenium's frame pointer, Cypress's command queue, Stagehand's implicit active page, Crawlee v3's implicit purge and Scrapy's process-global reactor were each removed or became the top complaint.
- **G3. Strict inputs, tolerant results.** An unknown, misspelled or ineffective option is an error, never ignored: the type checker rejects it where the language can, and the engine rejects the rest with an Error code whose message names the closest valid name. Results keep the fields and enum values an SDK does not know, and nothing new raises, because a Daemon or Goodfetch Cloud can run a newer minor than the SDK (ADR 0024). Browser Use swallows unknown keyword arguments; openai-python's `parse()` and its streaming helpers raised `ValidationError` when results drifted from the SDK's models.
- **G4. A guest in the user's program.** An SDK never owns the process, the host's event loop, signal handlers or stdout. Its logs go through the host's logging (`logging` in Python, `tracing` in Rust, a logger option in TypeScript) and are never printed. It never closes or kills what it did not start, as with the Borrowed browser (ADR 0056). Many instances run in one process, can be started again after closing, and work in a notebook. Scrapy's `ReactorNotRestartable`, Browser Use killing a browser it was handed, and stdout writes that broke MCP servers (Crawl4AI, Scrapling, Browser Use) are the counter-examples. The CLI owns its own process; the SDKs do not.
- **G5. Safe defaults for the user and for the sites reached.** With nothing set, Goodfetch protects the user (ADRs 0015, 0016, 0043, 0045) and is never a burden on the sites it reaches. Anything less safe is an explicit opt-in, visible and recorded, as ADR 0016 records a switched-off security control. Site owners call Scrapy "a malicious denial-of-service tool in its default configuration". [Crawl politeness defaults](https://github.com/goodfetch/goodfetch/issues/480) (ADR 0086) applies this to ADRs 0016 and 0021 and decides robots.txt.
- **G6. Diagnosable.** Every failure says what was attempted, what was observed, where the limit came from and which setting or action would change the outcome; every call made in a run is visible in its Run trace. Users of Playwright for Python are told to match on message text, Stagehand's own docs branch on `message.includes(...)`, and Crawlee's silent hangs took years to fix. Error fields are decided in [Results, outcomes and errors](https://github.com/goodfetch/goodfetch/issues/466) (ADR 0079), deadlines in [Time, waits, deadlines, cancellation and budgets](https://github.com/goodfetch/goodfetch/issues/467) (ADR 0080).
- **G7. Goodfetch's own types are enough.** No third-party type is the only way to use an operation, after the Rust API Guidelines' C-STABLE. Ecosystem types come in through standard interfaces (Standard Schema in TypeScript). Where one is the language's idiom, as Pydantic v2 models are in Python (ADR 0038), its supported major range is pinned and stated in the release notes (ADR 0030). A third-party trait such as Rust's `Stream` is implemented in addition to Goodfetch's own methods, never instead. Zod 4 broke openai-node, and httpx 0.28 broke openai-python.
- **G8. A way down at each layer.** Each layer offers a documented way down (a raw catalog call, a raw CDP session, `evaluate`, lending the page to another driver) with the main path's protections (ADRs 0016, 0017), and no golden scenario needs one. The golden scenarios are the complete programs for real tasks, each set against its leader's version, that [Golden scenarios and the pain coverage matrix](https://github.com/goodfetch/goodfetch/issues/463) chooses. Browser Use left Playwright for raw CDP because Playwright's way down was too narrow.

### Shape rules

When two shape rules point to different shapes, the higher one wins.

- **S1. Idiomatic and consistent within each language, identical in meaning across them.** Concepts, verbs, defaults and behaviour are the same in every SDK, from the Operation catalog. Each language expresses them its own way (an options object, keyword-only arguments, a builder), and one concept has one form throughout that language's SDK. This is Azure's order, which Stainless, AWS and Playwright's ports also follow, and ADR 0038's split between the generated layer and each language's hand-written runtime. Crawlee for Python was criticized for looking like JavaScript, and Selenium's bindings disagreed until it wrote a behavioural contract.
- **S2. One obvious way per task.** Every parameter can be set (ADR 0028), but not every setting is an argument: a call shows the arguments its task needs, and the rest goes through settings. Shortcuts are built on the same objects, never as a second API; a method has one return type whatever its options; no alias is kept for familiarity alone. The SDK API stays small enough to freeze at 1.0 (ADR 0030). Stagehand's three verbs and Firecrawl's single call are praised; Browser Use's `Agent`, with about 60 keyword arguments, and Crawl4AI's `arun()`, whose return type depends on its configuration, are not.
- **S3. Familiar where the meaning is the same.** Goodfetch takes the leader's name and shape when its behaviour matches exactly: Playwright for the page (ADR 0019), the `act`, `observe` and `extract` verbs the AI browser tools converged on, and Crawlee and Scrapy where they agree for crawls. Where leaders disagree, the deciding ticket picks with evidence. A different meaning gets a different name or type. GPT-4o made valid calls to little-known APIs far less often than to well-known ones (39% against 94%, CloudAPIBench), and a behaviour changed under an unchanged name is the hardest case (38% success, RustEvo²).
- **S4. The same form across languages.** Ranked last: two SDKs differ in form wherever S1 to S3 call for it.

Three conflicts show the order:

- **Durations.** Playwright for Python takes `timeout=30000` in milliseconds, while Python, Scrapy and Crawlee for Python count seconds or use a `timedelta`. S1 above S3 gives each SDK one duration form throughout, chosen in [Time, waits, deadlines, cancellation and budgets](https://github.com/goodfetch/goodfetch/issues/467) (ADR 0080), and S3 makes a Playwright-style `timeout=30000` a type error rather than an eight-hour wait.
- **Two ways from the leader.** Playwright keeps `page.click(selector)` and discourages it in favour of locators: S2 above S3 keeps only locators.
- **Waiting for an event.** Playwright for Python waits with `with page.expect_response(...)` and Playwright for TypeScript with a promise: S3 above S4 keeps each language's form.

### Tie-breaker

- **T. Written for coding agents too.** When shapes still tie, the one that scores better in the [Agent-writability check](https://github.com/goodfetch/goodfetch/issues/484) and the golden scenarios (concepts introduced, lines, failure points) wins. Every deprecated name, generated or hand-written, carries the language's type-level marker (PEP 702's `@deprecated`, TSDoc's `@deprecated`, Rust's `#[deprecated]`) besides ADR 0030's runtime warning: models write deprecated calls 70–90% of the time when nearby code is outdated, and a type-level marker is what lets the type checker flag them.
  > Amended by [ADR 0099](0099-every-surface-spells-each-catalog-name-by-its-own-rule-shapes-come-from-declared-kinds-and-call-is-the-way-down.md): a deprecated name carries its language's type-level marker wherever the language has one; a Python plain-data field or settings `TypedDict` key, which PEP 702 cannot mark, keeps ADR 0030's runtime warning and is listed in the release notes' deprecations.

### Rules already adopted

These act as SDK principles and are decided in their own ADRs: one Operation catalog generates every surface (ADR 0011); thin SDKs speak JSON-RPC to one engine (ADR 0024); contracts come from Rust types, failures carry typed Error codes and a call is cancelled with `$/cancel` (ADR 0038); capabilities are settings, never Cargo features (ADR 0038); the page API is Playwright-shaped and guarded (ADR 0019); every parameter is a setting (ADR 0028); semver, Experimental status and deprecation follow ADR 0030; a local engine and Goodfetch Cloud serve the same contract (ADR 0001); nothing leaves the machine unless configured (ADR 0043).

### Scope and use

- **Scope.** The principles bind the SDK API of the TypeScript, Python and Rust SDKs, and the naming rules by which the Operation catalog names operations, parameters and Error codes on every surface, so every principle that bears on a name, an input or an error binds CLI flags and MCP tool names as well (among them G3, G6, S1, S2, S3 and T). The CLI's, the Console's, Goodfetch Cloud's HTTP API's and the Framework adapters' own designs are not bound by this ADR.
  > Amended by [ADR 0137](0137-the-console-leaves-both-products-and-the-engine-and-the-owners-monitoring-tool-is-designed-apart.md): no Product carries a Console. The engine behaviour this ADR describes stands and the Console's part does not; a Client reaches it.
- **Use.** A ticket that decides part of the SDK API names, in its resolution, the principles that decided a choice and any departure with its reason, and the decision pull request's fresh review checks the chosen shapes against them. A departure meant to last amends this ADR.
  > Amended by [ADR 0133](0133-agent-work-follows-the-matt-pocock-skills-as-written-and-the-fresh-review-is-retired.md): no fresh review exists; this check is a review standard the `code-review` skill applies, and the owner sees its result before merging.

## Considered Options

- **The principles in `STYLE.md`**: rejected. ADR 0038 keeps `STYLE.md` for conventions that are easy to reverse and concern code inside the repository, while these shape what users write and fall under semver from 1.0.
- **"Familiar over novel" ranked first**: rejected. One Python SDK would count milliseconds for pages and seconds for crawls, and familiar names whose behaviour differs are what models get wrong most often.
- **The same shape in every language**, as in Stagehand v4's generated SDKs: rejected. It draws the criticism Crawlee for Python drew, and the Rust SDK would read like TypeScript.
- **Free form and behaviour per language**: rejected. Bindings drift, as Selenium's did and as Spider's Python binding did, about 25 minor versions behind its crate.
- **Lenient inputs with warnings**: rejected. A warning is easy to miss in a log or a notebook, and leniency is where silently ignored options start: Browser Use swallows unknown keyword arguments without a word.
- **No third-party type in the SDK API at all**: rejected. It contradicts ADR 0038's Pydantic models and Python's idiom.
- **A module-level default instance for one-liners**: rejected by G2. A one-call helper gives the same brevity without state that survives the call.
- **Obeying robots.txt by default, decided here** (as Firecrawl does): rejected for this ADR. It would decide [Crawl politeness defaults](https://github.com/goodfetch/goodfetch/issues/480) (ADR 0086) in advance and reverse ADR 0016's compliance stance from a principles ticket.
- **A total order of all the principles**: rejected. Guarantees are not tradeable at any rank.
- **Leaving every conflict to each ticket**, as Azure does outside its consistency order: rejected. The map's later tickets would argue the same conflicts again.
- **Writing for coding agents as a docs task only** (llms.txt, skills): rejected. In Vercel's own evaluation an on-demand docs skill scored no better than no docs (53%) and was never invoked in 56% of cases, while typed, familiar shapes are what models get right.

## Consequences

- **Adds to ADR 0038.** The shapes its contracts show users follow these principles, so under ADR 0037's reading rule every area's `/to-spec` reads this ADR. Area 11 (Client surfaces) builds its main decisions and lists it.
- **Adds to ADR 0030.** A deprecated name also carries its type-level marker (T), and an ecosystem type in the SDK API has its supported major range pinned and stated in the release notes (G7).
- **How G2 reads ADR 0056.** ADR 0056's SDK relay, first written `goodfetch.borrow(browserOrPage)`, carries CDP over "the JSON-RPC connection the SDK already holds". Under G2 that connection is a value the caller holds, so `borrow` is called on it, never on a process-wide instance; [Entry points and lifecycle](https://github.com/goodfetch/goodfetch/issues/465) names that object and the call's spelling. ADR 0056's decision is unchanged.

  > Amended by [ADR 0078](0078-an-sdk-program-opens-an-explicit-engine-connection-and-closes-only-what-it-started.md): `borrow` is called on the Run whose Session it serves, `run.borrow(pageOrBrowser)`, itself a value the caller holds under the connection, and its CDP still travels over that connection.

- **Areas 1 to 3 already have specs.** A shape in them that breaks a principle is raised as a new ticket on the map, never patched silently.
- **ADR 0028's settings reach code through S2.** [Settings in code](https://github.com/goodfetch/goodfetch/issues/470) decides where the settings that are not arguments go.
  > Amended by [ADR 0083](0083-a-program-sets-settings-in-one-typed-option-explicit-values-beat-the-environment-and-no-value-is-silently-ignored.md): they go in one `settings` option on each value that opens a scope, typed from the settings schema in each language's form.
- **ADRs 0016 and 0021 are unchanged here.** G5 gives [Crawl politeness defaults](https://github.com/goodfetch/goodfetch/issues/480) (ADR 0086) its direction, and that ticket amends them if it must.
- **The `prototype/sdk-api` branch** holds the API sketch, checked by `tsc`, pyright, mypy and `cargo check`; its README lists these principles by ID as the review list for every ticket on the map.
