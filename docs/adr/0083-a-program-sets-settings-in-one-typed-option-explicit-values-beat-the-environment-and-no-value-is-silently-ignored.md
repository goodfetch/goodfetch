# A program sets settings in one typed option, explicit values beat the environment, and no value is silently ignored

ADR 0028 makes every parameter a setting and resolves it through five layers; this decides how a program reaches them. Each value that opens a scope takes one `settings` option, typed from the settings schema in each language's own form, while a call takes only its task's inputs and `timeout`. A value written in code beats the environment, which carries only a closed list of deployment variables. A value that cannot take effect where it is set is refused when the scope opens, never ignored, clamped or dropped. Configuration is the research's fifth crawl pattern and the AI tools' sixteenth pain: Browser Use swallows unknown keyword arguments, reads the environment at import and lets an empty variable switch telemetry on; Playwright ignored `isVisible({ timeout })`; Crawlee v3 let environment variables override its constructor until v4 reversed it ([consumer API research](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md), its [AI](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md), [browser drivers](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/browser-drivers.md) and [crawl](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/crawl-frameworks.md) notes; [SDK design guidelines research](https://github.com/goodfetch/goodfetch/blob/research/sdk-design-guidelines/rnd/research/2026-10-14-sdk-design-guidelines.md), items 26 to 29). Decided in [Settings in code](https://github.com/goodfetch/goodfetch/issues/470), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461).

## Decision

### Precedence

- **Explicit beats the environment.** The environment carries no setting: it fills only connection inputs the code left unset, so an explicit `engine` beats `GOODFETCH_URL` (below). Every setting comes from code, a flag, a form or configuration, and within ADR 0028's run layer an explicit value (a call's argument, a `settings` option, a CLI flag, an Integration's form) beats configuration files. Stainless SDKs read `OPENAI_API_KEY` only as a default an argument replaces, Azure requires per-client configuration to override every global source, and Crawlee v4 reversed v3's order for the same reason. What a reader sees in the code is what runs (G2, G6).
- **Among explicit values, the nearest scope wins**, and a call's argument is nearer than any scope's `settings`. This decides no order between a program's values and a CLI flag or a form: a run takes its explicit values from one surface.
- **A plain program's values are the run layer.** ADR 0028's layer 4, "a Recipe or the developer's code", means a Recipe's code, whose declared settings are locked for the Recipe's users unless exposed. A program that is not a Recipe has no separate users, so its values sit in the run layer, above configuration.
- **The layer is named.** An error's `limit` (ADR 0079) and `explainSettings()` name the layer, and for the run layer its origin: a call's argument, `settings`, a flag or a form.
  > Amended by [ADR 0104](0104-a-crawl-declares-its-hooks-per-stage-in-code-a-hook-returns-its-change-and-a-program-registers-its-own-plugins-by-name.md): a fifth run-layer origin, `registered`, the lowest: a program's only SDK handler of a kind that one setting chooses, registered on `connect()`, becomes that setting's value at the connection scope, which every other run-layer value replaces and configuration does not; a lock on the key wins over it with no refusal.

### The environment

- **A closed list of deployment variables**, the values that differ by machine rather than by program: `GOODFETCH_HOME` (ADR 0059), `GOODFETCH_ENGINE_PATH` and `GOODFETCH_BROWSERS_PATH` (ADR 0024), `GOODFETCH_URL` (ADR 0049) and `GOODFETCH_TOKEN`, the scoped token it needs, and `GOODFETCH_TEST_SEED` (ADR 0059), which test support reads and the SDK only recognizes. No setting has an environment variable: a variable per setting would let any shell or CI job reshape a crawl unseen (G2, G5), and the research's lesson reads "Env only for secrets and deployment knobs." Secrets keep their own route, the Secret reference `env:NAME`, which names any variable the user chooses (ADR 0015). Whether the variables and their prefix keep these names is [Product names, packages, executables and version line](https://github.com/goodfetch/goodfetch/issues/457)'s (ADR 0084); the rules here hold whatever the names.
  > Amended by [ADR 0090](0090-products-are-named-goodfetch-collie-and-goodfetch-foxhound-and-share-one-product-version.md): the prefix and these variables keep their names, except `GOODFETCH_ENGINE_PATH`, which becomes `GOODFETCH_COLLIE_ENGINE_PATH` and `GOODFETCH_FOXHOUND_ENGINE_PATH`. Both are on the list in both Products' SDKs, so neither is unknown to either. Each SDK reads only its own Product's; the other Product's is recognized and not read, as `GOODFETCH_TEST_SEED` is, because it names an executable that SDK never starts.
  > Note (agent decision, accepted by the owner on 2026-10-21), [#353](https://github.com/goodfetch/goodfetch/issues/353): the list also holds `GOODFETCH_LOG_OUTPUT`, a stop-gap the executable reads in place of the `log.output` setting until the engine reads its configuration and the `log.*` settings ([#1566](https://github.com/goodfetch/goodfetch/issues/1566)), as ADR 0122's note on it says; it leaves the list when #1566 lands.
  > Note (agent decision, pending owner review), 2026-10-23, [#1566](https://github.com/goodfetch/goodfetch/issues/1566): `GOODFETCH_LOG_OUTPUT` and `GOODFETCH_LOG`, which stood in for `log.level`, left the list with #1566: the `log.*` settings replace them, and a program or a test that set them gets `setting_unknown`.
  > Note (agent decision, pending owner review), 2026-10-26, [#1199](https://github.com/goodfetch/goodfetch/issues/1199): the list also holds `GOODFETCH_CHANNEL`, the channel the executable came from, which its channel's launcher, wrapper or image sets so that `not_in_product`'s `fix` names that channel's install command (ADR 0087).
- **Connection inputs, not settings.** A deployment variable is read only from the environment map; it is no key in `settings` or a configuration file, which `GOODFETCH_HOME` itself locates, and `explainSettings()` does not list it. Its explicit counterparts are `engine` (ADR 0078), which beats `GOODFETCH_URL` and `GOODFETCH_TOKEN`, and the environment map itself (S2). `gf.engine` reports the Goodfetch home, the engine binary and the address it used (G6). `GOODFETCH_URL` fills `engine` only when the code leaves it at `auto`; there is no `GOODFETCH_ENGINE`. `GOODFETCH_TOKEN`'s value never appears in a log, an error or `gf.engine`; whether it also takes a Secret reference is [Sessions, logins, Human pause and secrets in code](https://github.com/goodfetch/goodfetch/issues/476)'s.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): `GOODFETCH_TOKEN` takes no Secret reference: references resolve in the engine, which the token is needed to reach.
- **Read once, strictly.** `connect()` reads the environment once, from the environment map of ADRs 0062 and 0069, which an option replaces and which defaults to the process's own, in all three SDKs (S1): the Rust crate reads the process environment there and nowhere else, unlike Azure's Rust rule, because a deployment variable must mean the same in every SDK and neither Product targets a WASM platform. Nothing is read at import (G4). The `GOODFETCH_` prefix is reserved (ADR 0034): an unknown name fails `connect()` with `setting_unknown`, naming the closest listed variable, and an empty or unparsable value with `setting_invalid` (G3). A newer tool's variable in an older SDK's environment fails too; versions released together (ADR 0030, with the Products' version line #457's) make that rare, and failing beats Browser Use's empty variable that switched telemetry on.
  > Amended by [ADR 0090](0090-products-are-named-goodfetch-collie-and-goodfetch-foxhound-and-share-one-product-version.md): both Products carry one Product version, so Collie's and Foxhound's SDKs of one release know the same list.
- **Whose environment.** The list governs an SDK program, the environment an Attached engine is given, and the CLI, whose flags beat it, so a variable means the same on every surface (S1). A Daemon's own process configuration (ADR 0049) is the operator's, outside this decision.

### Settings in code

- **One `settings` option on each value that opens a scope**: `connect()`, starting a Run, opening a Session and opening a page. It holds any setting that applies within that scope; the nearest scope wins, and values are inherited by everything opened beneath it. A call takes only its task's inputs and `timeout` (ADR 0080). The leaders split the other way and are criticized for it: Browser Use's `Agent` has about 60 keyword arguments, Crawlee spreads constructor options beside a global `Configuration` (S2).
  > Amended by [ADR 0093](0093-a-crawl-declares-its-labels-and-one-handler-each-and-a-handler-reads-collies-page-on-every-fetch-tier.md): a crawl's Label is a scope between the Run and its requests. It takes every setting a page takes, `timeout.handler`, `fetch.tier`, `crawl.retry.*`, `crawl.handle_statuses`, `crawl.handler.concurrency`, every `session.*` key and `secrets.*`, and refuses the Session's identity, Politeness, Site preferences, scope and Run-wide keys with `setting_not_applicable`. `fetch.*`, like `crawl.*`, answers `not_in_product` on a Collie engine (ADR 0087) and `setting_not_applicable` on a Collie Run on a Foxhound engine.
  > Amended by [ADR 0110](0110-a-crawl-handler-reads-the-responses-its-labels-settings-kept-from-its-own-navigation.md): a crawl's Label also takes `fetch.kept_responses.urls` and `fetch.kept_responses.max_size`.
- **A per-call argument** may exist for a setting that is part of one call's task, as `timeout` is (ADR 0080), such as a model chosen for one extraction; the verb's own ticket decides it. The argument applies to that call alone and is that setting at the run layer. Where a call opens a scope, its argument is the one spelling there (S2): a connection's own connect timeout is `connect()`'s `timeout`, and a Run's own timeout is starting the Run's `timeout`. `timeout.connect` in `settings` is refused at every scope, and `timeout.run` is accepted only at the connection, as a default for its Runs; elsewhere both fail with `setting_not_applicable`. `timeout.connect` is set only in the project file, which `connect()` and the CLI read before they connect and apply themselves; in user configuration or an Operator policy, which only the engine reads once reached, it is refused with `setting_not_applicable` (G3).
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): opening a Session takes `session.source` as such an argument, `source`; set in that Session's own `settings`, which only Rust's single `Settings` type allows, it is refused with `setting_not_applicable`, as `timeout.run` is on a Run.
- **No setters.** Nothing changes a setting of a scope already open, as Playwright's `page.setDefaultTimeout` does (G2).
- **The options of `connect()` that are not settings stay its own:** `engine` and `logger` (ADR 0078), `timeout` and `limits` (ADR 0080), the environment map, `project` (below) and `settings` (S2).
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): `resolveSecret`, which answers `caller:` Secret references, joins them.
- **Three states.** A setting left out inherits; `null` (`None` in Python and Rust) clears it where its type allows, such as no timeout; a value sets it. The SDK sends only what the program set and validates nothing the engine owns, so an Operator policy is never bypassed by an SDK-side default (G3; guidelines items 26 and 27).

### Each language's form

Generated from the settings schema (ADR 0028), one form throughout each SDK (S1):

- **TypeScript: a nested object literal**, each segment of the key camelCased: `settings: { crawl: { payload: { maxSize: 65_536 } }, timeout: { navigation: 60_000 } }`. Excess-property checks reject an unknown key in a literal, and `exactOptionalPropertyTypes` keeps a left-out key apart from `undefined`, as the three states need. It is Playwright's option style (S3); flat dotted strings would match configuration files but complete worse and read unlike TypeScript.
- **Python: a nested `TypedDict` literal**, every key `NotRequired`, which pyright and mypy check key by key: `settings={"crawl": {"payload": {"max_size": 65_536}}, "timeout": {"navigation": timedelta(seconds=60)}}`. openai-python and anthropic-python type their nested request parameters the same way (S3); generated dataclasses would need a class import per level and a `not_given` default on every field, and double-underscore keywords, as pydantic-settings spells nested environment variables, would be a second spelling of every key.
- **Rust: typed key constants on a `Settings` value**: `Settings::new().set(crawl::payload::MAX_SIZE, 65_536_u64).set(timeout::NAVIGATION, Duration::from_secs(60))`. Each key is a generated `Setting<T>` constant in a module path mirroring its dotted name, so the value's type is checked; `set` takes `impl Into<T>`, so a setting that can be cleared, with `T = Option<…>`, takes a value as it is and `None` to clear it. It scales to hundreds of keys without as many builder methods, as `http::header::CONTENT_TYPE` does; nested closure builders read poorly, and nested structs could not be `#[non_exhaustive]` and would need `Option<Option<T>>` (S1, S3).

The same nesting reads the same in TypeScript, Python, TOML and YAML configuration, which helps a coding agent move between them (T).

### Names

[Mapping the catalog to each language and surface](https://github.com/goodfetch/goodfetch/issues/471) applies the same casing to operations; the CLI's flag syntax is the CLI's own design. One rule a reader or a coding agent applies without exceptions (S1, S3, T).

### Refusals

Checked when the scope opens, or when a call with a per-call argument starts, so the error points at the line that set the value (G6). Nothing is clamped, dropped or ignored (G3), unlike Playwright's `isVisible({ timeout })` and Skyvern's `webhook_url`:

| Case | Error code | Group |
|---|---|---|
| An unknown key, or an unknown `GOODFETCH_` variable; the message names the closest valid one | `setting_unknown` | `ProgramError` |
| A value of the wrong type or out of the setting's own range, or an empty or unparsable deployment variable | `setting_invalid` | `ProgramError` |
| A setting no scope beneath can use, such as a `crawl.*` setting on a Collie Run, `browser.viewport` on a page, or `browser.*` set where a Borrowed browser's Session opens | `setting_not_applicable` | `ProgramError` |
| A value a lower layer locked or capped, or outside a Recipe's exposed bounds; or a `browser.*` value that conflicts with an identity fixed elsewhere (below). `limit` names the layer, or the setting that fixed the identity and its layer | `setting_locked` | `RefusedError` |
| A capability the platform cannot provide; its fix names the setting that turns it off | `capability_unavailable` | `UnavailableError` |

> Amended by [ADR 0087](0087-each-product-is-an-executable-crate-that-links-only-its-crates-and-has-its-own-size-budget.md): on a Collie engine, a key only Foxhound honours is refused with `not_in_product` (`UnavailableError`), naming Foxhound, before the scope check, so a `crawl.*` setting there is not `setting_not_applicable`. User and project configuration and Operator policy may hold the other Product's keys, since one project or one Goodfetch home can serve both: a Product applies its own and `config explain` lists the others as Foxhound's.

> Amended by [ADR 0102](0102-a-program-names-its-run-by-an-id-that-a-start-resumes-ends-it-with-a-run-report-and-reads-what-waits-and-why.md): `setting_not_applicable` also refuses, on a resume, a value changed since the Run began for a key fixed for a Run's life, such as `crawl.scope.*`; its `fix` names a new Run.

> Amended by [ADR 0104](0104-a-crawl-declares-its-hooks-per-stage-in-code-a-hook-returns-its-change-and-a-program-registers-its-own-plugins-by-name.md): a lock over a value with the origin `registered` is no `setting_locked`. The lock wins with no refusal, since the program never wrote the key.

A capability is a setting, never a Cargo feature (ADR 0038), and one binary carries every capability (ADR 0057), so the types are the same in every build: Spider's 132 Cargo features change field types, and its default `io_uring` panicked in Docker. ADR 0033's `confinement_unavailable`, a security refusal for a Plugin's network level, stays its own code.

> Amended by [ADR 0087](0087-each-product-is-an-executable-crate-that-links-only-its-crates-and-has-its-own-size-budget.md): there are two executables, one per Product, and every build of a Product has the same types; what separates the Products is the crates each links, never a Cargo feature.

### Reading settings

Each scope value has one read-only call, `explainSettings(keys?)` (`explain_settings` in Python and Rust), returning what `goodfetch config explain` shows for that scope: per key, the effective value, the layer and origin that set it, the layer that locked it, and the setting that fixed a Session's identity when an inherited `browser.*` value yielded to one. A program or a test can assert what it actually runs with, as Scrapy spiders read `self.settings` and Crawlee calls `Configuration.get`, without a setter (G6, G2).

> Note (owner's decision of 2026-11-08 to keep it and record it), 2026-11-08: "read-only" is what the call does: `config.explain` is a read, and it changes no setting. It does not promise that the process around it writes nothing. `goodfetch config explain` runs the call on an Attached engine in the command's own process, or under `--daemon` on the Daemon, so one resolution answers both and a program. That Attached engine starts whole and stops with the command, and each engine's start writes before it answers its first Run call: the managed Operator policy's install Limits go into the Usage ledger, created when a policy names any, and the Slices of dead runs are reclaimed there (ADR 0041). So the command may create or change the Usage ledger, its stop waits on those writes, and a ledger it cannot open gives a `warn` line on stderr while the answer and the exit code hold. On machine settings it cannot read, it fails with their Error code and starts no engine.

### Configuration files

- **Project configuration.** `connect()` reads it as the CLI does, searching upward from the working directory, as git and Scrapy's `scrapy.cfg` do, so `goodfetch config explain` run in the same folder shows what the program gets. A `project` option names another file, or `null` reads none, for a service whose working directory means nothing (Azure's per-client opt-out). `gf.engine` reports the file used, also logged at info (G6).
- **Layer 3's rank everywhere, run-layer authority from afar.** The SDK sends the file's values as ADR 0028's layer 3, reported as `configuration` with the file, below a Recipe and the run, wherever the engine runs. On an Attached or linked engine, or a Daemon on the same machine, they also have layer 3's authority. On an Exposed Daemon or Goodfetch Cloud, they have only the run layer's: a value that would widen what ADR 0028 reserves to configuration, such as `trusted_cas`, certificate pins, `pay_domains` or `consent_domains` (the full list is ADR 0028's), is refused with `setting_locked`, so no Client widens a shared engine's allowances by sending a file (G5), while a Recipe's lock wins quietly, as on a local engine, so the same program behaves the same wherever its engine runs.
- **User configuration is the engine's.** The engine reads it from its Goodfetch home; a program isolates it by giving `GOODFETCH_HOME` in the environment map, as tests do (ADR 0069), and over a Daemon it is the Daemon's (G2).

- **Locale and time zone** default to ADR 0021's match with the proxy exit; an explicit value replaces the match, and `config explain` and the Run trace show it (G6).
- **An identity fixed elsewhere wins, and says so.** Under the `stealth` Access mode the Identity profile fixes locale, time zone and geolocation (ADR 0035); an imported login or a Profile directory used in place keeps its source's locale and time zone (ADRs 0021, 0056). A conflicting `browser.*` value set where that Session opens is refused with `setting_locked`, whose `limit` names the setting that fixed it (the Access mode or `session.source`) and its layer; a Borrowed browser, the user's own, refuses one set there with `setting_not_applicable` (G3, G5). An inherited value, from the Run, the connection or configuration, yields to the fixed identity, and `explainSettings()` shows what fixed it, so a default stays usable above such Sessions.
- Where Sessions and pages are opened is [Collie's page API](https://github.com/goodfetch/goodfetch/issues/472)'s (ADR 0085) and [Sessions, logins, Human pause and secrets in code](https://github.com/goodfetch/goodfetch/issues/476)'s (ADR 0092).

## Considered Options

- **Environment variables above code**, ADR 0028's literal reading and Crawlee v3's order: rejected. A variable set in a shell or a CI job silently overrides what the program says, which Crawlee v4 reversed.
- **An environment variable per setting**, as crawlee-python's pydantic-settings `Configuration`: rejected. Every setting gets a second name, and any shell can reshape a crawl unseen (G2, G5).
- **Deployment variables as keys in `settings`** (`home`, `engine.url`, …): rejected. Configuration files cannot hold the value that locates them, and `engine` and the environment map already spell them in code (S2).
- **No environment at all**, as Azure's Rust rule: rejected. It breaks ADR 0049's `GOODFETCH_URL` and the test fixtures of ADR 0069.
- **Ignoring unknown `GOODFETCH_` variables, or failing only on near misses**: rejected. One strict rule is easier to state and to trust (G3), and ADR 0077 rejected lenient inputs with warnings.
- **Rust reading the environment only on request**: rejected. `GOODFETCH_URL` would work in two SDKs and do nothing in the third (S1).
- **Every setting as a top-level option of each opener**, as Browser Use's `Agent` and Crawlee's constructors: rejected by S2; signatures would grow to hundreds of fields.
- **A separately built `Settings` value in TypeScript and Python**: rejected. An extra type to learn, and a pull toward one shared global instance (G2).
- **Flat dotted string keys in TypeScript and Python**: rejected. They read unlike either language (S1) and complete worse; the canonical key stays what configuration files and errors show.
- **Generated dataclasses, or double-underscore keywords, in Python**: rejected above, under Each language's form.
- **Nested builders or nested structs in Rust**: rejected above, under Each language's form.
- **Exempting keys already named without an area**: rejected. Two naming styles a reader must tell apart (S1, T).
- **Timeouts named under their subjects** (`page.navigation.timeout`, `crawl.handler.timeout`): rejected. They scatter one concept of ADR 0080 across areas.
- **Product-dependent defaults** (Crawlee's 60 s navigation for crawls, Playwright's 30 s for scripts): rejected. Nesting already bounds a crawl's actions by its handler's timeout.
- **Project configuration read only when named, or never**: rejected. A program and the CLI in the same folder would disagree about what runs.
- **A project file with layer-3 authority on an Exposed Daemon or Goodfetch Cloud**: rejected. Any Client could widen a shared engine's reserved allowances (G5). **Ranking it as the run layer there**: rejected. A Recipe's lock would fail the program there and win quietly on a local engine. **Ignoring it there**: rejected. The same program would behave differently by where its engine runs.
- **Clamping a value above a cap, or applying it where it has no effect**: rejected by G3; a silent no-op is how Playwright's ignored `timeout` and Skyvern's ignored `webhook_url` hurt.
- **Viewport per page**, as Playwright's `newPage({ viewport })` and `setViewportSize`: rejected. A Session's identity is fixed for its life (ADR 0021).

## Consequences

- **Amends ADR 0028.** Environment variables carry no setting, only the deployment variables above, which fill connection inputs; layer 4's "developer's code" is a Recipe's code; a project file sent to an Exposed Daemon or Goodfetch Cloud keeps layer 3's rank with the run layer's authority.
- **Amends ADR 0080.** `.no_timeout()` is the one spelling of no timeout for a call and the option builders, while a scope's timeout setting is cleared with `Settings::set(timeout::…, None)` in Rust. The setting names are those above, and Foxhound's defaults are Collie's.
- **Amends ADR 0059.** `GOODFETCH_HOME`, `GOODFETCH_ENGINE_PATH` and `GOODFETCH_BROWSERS_PATH` are deployment variables, read from the environment map, not keys in `settings`; and the Rust SDK's `connect()`, given no map, reads the process environment, the one reader besides `main`, under an `#[expect]` of the `disallowed-methods` lint.
- **Amends ADR 0021.** An explicit `browser.locale` or `browser.timezone_id` replaces the `standard` Access mode's match with the proxy exit, and is shown; an identity fixed by `stealth`, an imported login or a Profile directory used in place refuses a conflicting one.
- **Amends ADR 0079.** `limit` names the run layer's origin: a call's argument, `settings`, a flag or a form.
- **Answers ADR 0077's and ADR 0078's open points.** The settings that are not arguments go in each scope's `settings` option; the environment sets the engine only through `GOODFETCH_URL`, and the connection's other settings go in its `settings` option.
- **Answers ADR 0081's naming point in part.** The Run's handler concurrency setting follows the naming rule above, under `crawl.*`; its exact key and its per-route form are [Crawl definition and handler context](https://github.com/goodfetch/goodfetch/issues/477)'s.
  > Amended by [ADR 0093](0093-a-crawl-declares-its-labels-and-one-handler-each-and-a-handler-reads-collies-page-on-every-fetch-tier.md): the key is `crawl.handler.concurrency`, and its per-Label form is the same key set on a Label.
- **Error codes.** `setting_unknown`, `setting_invalid` and `setting_not_applicable` join `goodfetch-protocol` in the `program` group, `setting_locked` in the `refused` group and `capability_unavailable` in the `unavailable` group, through `xtask codegen`'s naming checks (ADR 0079).
- **The settings schema** (ADR 0028) gains, per setting, its canonical key, the scopes where it applies and whether it can be cleared; `xtask codegen` emits from it the TypeScript object types, the Python `TypedDict`s and the Rust key constants.
  > Amended by [ADR 0102](0102-a-program-names-its-run-by-an-id-that-a-start-resumes-ends-it-with-a-run-report-and-reads-what-waits-and-why.md): it also marks whether a resume may change the setting. A key that decides a Run's scope or what its committed results mean, such as `crawl.scope.*`, is fixed for the Run's life. `crawl.keep_alive` and `checkpoint.interval` join it.
- **Area 3 (Engine runtime)** builds the resolver's run-layer order, the strict environment, the refusals, `explainSettings`, a project file's authority by the engine's place, and the areas of existing keys. **Area 5 (Site access)** builds the `browser.*` settings and `network.throttle`. **Area 8 (Stealth and Challenge solving)** builds the refusals under an Identity profile. **Area 11 (Client surfaces)** builds the three forms, the environment map's reading and project discovery.
- **ADR 0037's matrix**: typed configuration and environment variables (RT-22), the timeouts' names (RT-06) and device emulation (SA-23) cite this ADR.
- **The `prototype/sdk-api` sketch** holds these signatures in its `settings` files for each language; the pain coverage matrix closes P27 as Elsewhere (ADRs 0038, 0057), P38 as API and P54's Settings part as API.
