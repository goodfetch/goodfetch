# Collie's page API keeps Playwright's names, strictness waits, values cross as JSON, and unanswered requests fall through

Collie's page API is Playwright's (ADR 0019) wherever the meaning is the same, with the guard's promises kept everywhere and Playwright's traps closed where its behaviour hurts users. Pages, Sessions and frames are values, and a locator is resolved again at each use. Uniqueness is one more condition the guard waits for. A page's gestures run one at a time. A page function takes one explicit argument, and values cross as JSON. Routes and dialog handlers answer requests under written rules, so a handler that answers nothing never stalls the page. A raw CDP session is the way down. Leaving Playwright is where AI tools lose users: "partial shape plus missing guarantees is worse than a different shape" (the research's lesson from AI pain 12, after Stagehand's migration guide). Playwright's own traps are documented: strictness fails at once while every other condition is waited out ([#36045](https://github.com/microsoft/playwright/issues/36045), open). A non-serializable `evaluate` result silently becomes `undefined`. A route that settles nothing stalls its request. A `dialog` listener that does not answer stalls the action. Decided in [Collie's page API](https://github.com/goodfetch/goodfetch/issues/472), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461), every answer by the agent on the owner's delegation, on the evidence of the [research on competitors' APIs](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md) ([browser drivers](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/browser-drivers.md) §2.1, §4 and P1, P4, P5, P6, P9, P12, P13; [AI browser automation](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md) §6 rows 9 and 12), of Selenium's [ADR 17685](https://github.com/SeleniumHQ/selenium/blob/trunk/docs/decisions/17685-network-handler-behavior.md), and of Playwright 1.64.1's own documentation. Principles are cited by their IDs in [ADR 0077](0077-the-sdk-api-follows-eight-guarantees-and-four-ranked-shape-rules.md).

## Decision

### Pages, Sessions and frames

- **The Session is Playwright's context.** Playwright's `BrowserContext` holds cookies, storage, proxy and routes; the glossary's Session already is that unit, so there is no second type (S2). Pages open with `session.newPage()` or arrive as popups. How a Session is opened, and whether `run.newPage()` uses a default Session, are [Sessions, logins, Human pause and secrets in code](https://github.com/goodfetch/goodfetch/issues/476)'s.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): a Session opens with `run.newSession({ source, login, settings })`, `run.newPage()` uses the Run's default Session, and the Session's own API (cookies, `saveIdentity`) is ADR 0092's.
- **Tabs are values; there is no active page** (G2). A popup is a Page of its opener's Session (`popup` event); `session.pages()` lists open pages and the Session's `page` event announces new ones. `close()` closes a popup as any page the engine opened, and on a Borrowed browser only releases it (ADR 0078); `page.session()` is the Session a page belongs to, Playwright's `page.context()`. There is no `bringToFront()`: the Live view follows popups (ADR 0031), and area 5's spec keeps a driven page from being throttled as a background tab. There is no `opener()`: the page that emitted `popup` is the opener.
- **Frames are reached through frame locators only.** `frameLocator(selector?)` on a page, a locator or a frame locator, with Playwright's selector-less form that searches every frame, plus `locator.contentFrame()` and `frameLocator.owner()`. They cross same-origin and out-of-process frames alike (ADR 0019 tracks OOPIFs). There is no eager `Frame` handle and no frame pointer (S2, G2). Code that must run in a frame's own window goes through a locator inside it.
- **Shadow DOM:** CSS and `getBy*` pierce open shadow roots and XPath does not, as in Playwright (S3). Whether closed shadow roots are reached on Chromium is area 5's spec; when one hides a target, the deadline error's `observed` says so (G6).
  > Amended by [ADR 0121](0121-service-workers-run-under-the-engines-interception-the-back-forward-cache-is-off-locators-reach-closed-shadow-roots-and-a-read-never-scrolls-a-list.md): on Chromium, locators, the guard's checks and `ariaSnapshot` reach closed author shadow roots too, resolved in the engine's isolated world without changing the page; user-agent roots are never reached. On Firefox and WebKit closed roots are not reached, and `observed` says that Chromium reaches them.

### Locators

- **Playwright's constructors and matching rules** (S3): `locator(selector)`, `getByRole`, `getByText`, `getByLabel`, `getByPlaceholder`, `getByAltText`, `getByTitle`, `getByTestId`. Text matches as a case-insensitive substring after whitespace is normalized, or exactly with `exact`, because a different default under the same name is what models get wrong most (ADR 0077's RustEvo² figure). Regexes run in the engine under ADR 0081's rules.
  > Amended by [ADR 0091](0091-collies-ai-verbs-live-on-the-page-replay-from-a-plan-file-the-run-names-and-expect-runs-a-success-check.md): `page.getByRef(ref)` is a further constructor, for an element reference from an `ai` aria snapshot. A reference whose element is gone fails with `target_not_found` at once rather than waiting out the deadline, since the element cannot come back.
- **`locator()` takes CSS, or XPath** when the string starts with `//`, `..` or `xpath=`, as Playwright detects it. Playwright's other selector engines (`text=`, `role=`, `internal:`), `>>` chains and its CSS extensions (`:has-text()`, `:text()`, `:visible`, `:nth-match()`) fail with `selector_invalid`, whose fix names the method that replaces them (`getByText`, `filter({ hasText, visible })`, `nth()`): each has a method, and a string mini-language would be a second way (S2, G3). Standard CSS, `:has()` and `:is()` included, is accepted. There is no `getById` (Playwright declined it, +81).
- **The test-id attribute is the setting `locator.test_id_attribute`**, `data-testid` by default, set at any scope (ADRs 0028, 0083), never Playwright's process-wide `selectors.setTestIdAttribute` (G2).
- **Composition is declarative and resolved by the engine:** `filter({ hasText, hasNotText, has, hasNot, visible })`, `and`, `or`, `first()`, `last()`, `nth()`, `all()`, and constructors on a locator. No host callback ever runs in the page (ADR 0081).
- **No handles.** A locator is a lazy value, built without I/O and resolved again at each use. No `ElementHandle` or `JSHandle` exists; `locator.evaluate` hands its element to a page function, and raw CDP is below that (G8). Selenium's stale references and Puppeteer's destroyed contexts are the handle model's pains (browser drivers P5).

### Strictness

- **Uniqueness is one of the conditions the guard waits for.** Every action, and every read of one element, waits until exactly one element matches and the guard's other conditions hold, until its deadline (ADR 0080). If the last observation was ambiguous, it raises `target_not_unique` (a `PageError`, ADR 0079's case) listing every match rendered in the caller's language, its `limit` naming the timeout's setting; otherwise a missing target raises `DeadlineExceededError`. This is the one timeout that is not `deadline_exceeded`: its remedy is the locator, not the timeout, and ADR 0079 groups errors by remedy (amends ADR 0080). Playwright too reports a strict-mode violation, not a timeout.
  > Note (agent decision, accepted by the owner on 2026-10-22), 2026-10-21, [#700](https://github.com/goodfetch/goodfetch/issues/700): on the wire a locator is `{ page_id, selector }`, a CSS selector matched in the document and its open shadow roots, and the locator actions are `locator.click`, `locator.fill` (`value`) and `locator.press` (`key`), which answer an empty object. `target_not_unique` details `target` (the locator), `matches` (each element as its opening tag and the start of its text, with a locator that reaches it alone, `.nth(i)`), `limit` and `elapsed`; the locators are rendered in the language of the `hello`'s surface: TypeScript with single quotes, Python and Rust with double quotes, and every other surface in the catalog's form, with double quotes. A target never actionable raises `deadline_exceeded` whose `waited_for` names the step, `target_attached`, `target_visible`, `target_enabled`, `target_editable`, `target_stable` or `target_receives_events`. Until `selector_invalid` is declared, a selector the page does not parse and a key no keyboard has fail with `invalid_params`.
  > Amended by [ADR 0091](0091-collies-ai-verbs-live-on-the-page-replay-from-a-plan-file-the-run-names-and-expect-runs-a-success-check.md): `expect`'s `success_check_failed` is a second failure at a timeout that is not `deadline_exceeded`: its remedy is the page or the program, and the failure is the Success check's answer.
- **A question that never waits** (`isVisible()`) raises `target_not_unique` at once. `first()`, `last()` and `nth()` are the visible opt-outs.
- Playwright fails at once on ambiguity while it waits out every other condition, so two copies during a re-render fail where a moving element would be waited for. A persistent ambiguity now costs the timeout a missing target already costs, and `timeout` shortens both. The promise of an action is unchanged; only when an unkept promise is reported changes, as the guard's replay already changes it (ADR 0019).

### Actions

- **Playwright's locator actions under their names** (S3): `click`, `dblclick`, `tap`, `hover`, `check`, `uncheck`, `setChecked`, `dragTo`, `fill`, `clear`, `press`, `pressSequentially`, `selectOption`, `selectText`, `setInputFiles`, `focus`, `blur`, `scrollIntoViewIfNeeded`.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): `fill` and `pressSequentially` also take a Secret placeholder, typed by the engine and checked against the domain of the field's frame.
- **Every action goes through the guard** (ADR 0019) and needs a unique target. Pointer actions also need it visible, stable, enabled and receiving the event, and a gesture that lands elsewhere is cancelled and replayed. Text actions need it visible and enabled, and `fill` and `clear` need it editable, so a read-only field is waited for. Input is trusted browser input, so controlled inputs see real events (P52).
- **A target of the wrong kind fails at once** with `target_unsupported` (a `PageError`), naming the action, what it accepts and what it found, after a `<label>` is followed where the action follows it (below): `fill` on an element that cannot hold text, `selectOption` on anything but a `<select>`, `setInputFiles` on anything but a file input. An element's kind does not change while waiting, where its read-only or disabled state may.
- **`force` is ADR 0023's per-call switch:** it skips the actionability checks and the replay, keeps uniqueness, and marks the action unguarded in Provenance. It is the setting `action.force` given for one call, a per-call argument as ADR 0083 allows; a run can set it for all its actions. Playwright's `force` has that meaning (S3).
- An action that starts a navigation waits for it to commit, and `selectOption` waits for the options it names, as Playwright's do.
- **A `<label>`, or an element inside one, is followed to its control** as Playwright 1.64.1 follows it: by `fill`, `clear`, `selectOption`, `selectText`, `setInputFiles` and `inputValue`, and for every element state but visibility, in the state reads and the guard's checks alike, so a click on a label waits for its checkbox to be enabled. Visibility (the guard's check included), stability, the hit target and the pointer input stay on the label.
- **Input with no target** keeps Playwright's `page.keyboard`, `page.mouse` and `page.touchscreen` (a canvas, a map, a key for whatever has focus). Nothing can be guarded, so each call is marked unguarded.

### Gestures on one page

- **The engine runs a page's gestures one at a time, in arrival order.** A gesture is a call that sends input or navigates: every locator action, `keyboard`, `mouse` and `touchscreen` calls, `goto`, `reload`, `goBack`, `goForward`, `setContent` and `fileChooser.setFiles`. `evaluate` is not one, even when its code changes the page. The next starts when the previous one has returned.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): while a Human pause from `page.pause()` holds a page, its Gestures wait; reads and waits run.
  > Amended by [ADR 0114](0114-a-program-and-collie-take-turns-on-a-page-other-code-drives-and-an-ai-verb-fails-when-a-navigation-it-did-not-start-replaces-its-document.md): the order covers only the calls that reach the engine. On a page other code also drives (a shared Borrowed browser, a Lent page while a library is attached, a page with an open CDP session), that code's commands are outside it; the program awaits each Collie call before its own driver acts, and an AI verb whose document a navigation it did not start replaces fails with `page_navigated_during_call`.
  > Note (agent decision, pending owner review), 2026-10-24, review of spec #577 (M10), [#698](https://github.com/goodfetch/goodfetch/issues/698) and [#700](https://github.com/goodfetch/goodfetch/issues/700): a navigation holds no place in this order yet, and the page stays `Open` while one runs, not spec #594's `Navigating`. A later `goto`, `reload`, `goBack` or `goForward` supersedes a pending one, which raises `navigation_interrupted` (#698's criterion, as in Playwright), and a locator action sent while one is pending acts on the document the page holds then. A click or a key press that starts a navigation answers once its document committed, but gives up its turn while it waits, so a route or dialog handler's gesture and the Consent prompt runner's clicks run meanwhile without a deadlock. A program that needs the order awaits each call before it sends the next. Holding the order through a navigation needs the navigation to give up its turn while its document's request waits on a route handler, and #698's superseding `goto` to wait instead; the owner decides between the two.
  > Note (agent decision, accepted by the owner on 2026-10-28), deep review of M1 (594-O1), [#731](https://github.com/goodfetch/goodfetch/issues/731): a navigation holds its place in this order, as spec #594's P14 says, replacing the note above's first sentence and its open choice. A `goto`, `reload`, `goBack` or `goForward` leaves the page `Navigating` until its document commits or fails, and a gesture sent meanwhile waits behind it, except while one of the page's requests, a frame's included, waits on a route handler: the navigation then gives up its turn, so the handler's gestures run without a deadlock. A later navigation still interrupts the pending one, which raises `navigation_interrupted` (P37, decision 15), and a read such as `evaluate` never waits. A click or a key press that starts a navigation keeps the note above's rule.
- **A gesture that waits on the program gives up its turn** while it waits: during a locator handler's turn, before an attempt, or while a request it waits on waits for a route handler's answer, after its input. Gestures queued meanwhile run, the handler's own among them, so a handler that clicks never deadlocks the action it interrupts; when the answer comes, the gesture takes its turn again and the guard checks its target afresh before acting. It gives up its turn only between its own inputs, so two gestures' keystrokes and pointer moves never interleave. An open dialog blocks the page's input, so a dialog handler answers before it acts on the page.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): it also gives up its turn while the scripted login step it waits on runs.
- **Reads, waits, `evaluate` and answers to routes and dialogs run concurrently**, so ADR 0080's waiters stay armed during a gesture and `Promise.all` over reads costs one round trip's latency. Pages of one Session do not wait for each other.
- A gesture's timeout counts from its call (ADR 0080), so time spent behind another counts. This is the engine's per-page input order, as a browser has one input stream, not a queue in the SDK (ADR 0081, K04). Overlapping gestures interleave keystrokes and pointer moves silently, as concurrent Playwright `fill`s race for focus (G1).

### Reads

- **Playwright's getters, each one round trip whatever the number of matches** (P28; headless_chrome's per-element round trips made `find_elements` 150 times slower than JavaScript): `textContent`, `innerText`, `innerHTML`, `inputValue`, `getAttribute`, `boundingBox`, `isEnabled`, `isDisabled`, `isChecked`, `isEditable`, `isVisible`, `isHidden`, `count`, `all`, `allTextContents`, `allInnerTexts`.
- Reads of one element's content, and states that need one element, wait for a unique match under the action timeout, as Playwright's do. `isVisible`, `isHidden`, `count`, `all` and the `all*` reads answer at once, take no timeout and return values (ADR 0079); Playwright's `isVisible({ timeout })` ignored its timeout (#12224, #33017). An absent attribute is `null`: an answer (G1).
- No row-wise structured read is added (S2): reads run concurrently, `evaluateAll` reads rows in one call, and a crawl's selector reads and `extract` belong to [Crawl definition and handler context](https://github.com/goodfetch/goodfetch/issues/477) (ADR 0093) and [Collie's AI verbs and Plans](https://github.com/goodfetch/goodfetch/issues/473) (ADR 0091).

### Page functions

- **A page function is JavaScript source run in the page with one explicit argument** (ADR 0081). TypeScript takes a function, whose source is sent, or a string; Python and Rust take a string, as Playwright for Python does. A string is a function if it parses as one, otherwise an expression; an argument given with an expression is a `ProgramError`.
- **Values cross as JSON both ways,** ADR 0082's `JsonValue` (S1, S2). The argument is `JsonValue` in TypeScript and Python and `impl Serialize` in Rust, and TypeScript constrains the result to JSON, so returning a `Date` or an element is a type error (G3).
- A value outside JSON (a non-finite number, a DOM node, a function, a `Map`, a cycle, a `BigInt`) raises `page_value_invalid` (a `ProgramError`) naming its path, its kind and the fix, in either direction; an argument is refused before it is sent. Playwright resolves such a result to `undefined`, silently (G1).
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): it also refuses, before sending, a Secret placeholder outside the positions that take one.
- `undefined` follows `JSON.stringify`: dropped from objects, `null` in arrays. A function that returns nothing gives `undefined` in TypeScript, `None` in Python and JSON `null` in Rust, and `-0` arrives as `0`.
- **An exception thrown in the page** raises `page_function_failed` (a `ProgramError`, the program's own code, as `handler_failed` is) with the page's error name, message and stack. A `ReferenceError`'s fix names the argument: a page function sees only its argument ("pass variable into evaluate" is Puppeteer's second most-voted question).
- **The calls:** `page.evaluate(fn, arg)`, `locator.evaluate(fn, arg)` with the element first, `locator.evaluateAll(fn, arg)`, `page.waitForFunction(fn, arg, { polling })` with Playwright's `raf` or an interval in the language's duration type (ADR 0080), `locator.waitForFunction(fn, arg)` with the element first, resolved again at each check (Playwright 1.62), and `addInitScript(fn, arg)`, which returns a `Subscription` and is registered when called.
- **Its trust level is fixed, so the name stays** (S3, ADR 0019; AI pain 9 asks for a trust level in the name of code-execution verbs). It runs only in the page, with the page's privileges, never in the program's or the engine's process; code a model writes runs in the Script sandbox (ADR 0051).
- **A `world` option** takes `main` (the default, as Playwright and Puppeteer, so page globals are visible) or `isolated` (the page can neither see nor hook it). Main-world calls and init scripts are marked in Provenance (ADR 0019).
- The argument is plain JSON, so a Secret reference cannot be passed in (G5); where Secret references go is Sessions, logins, Human pause and secrets in code's.
  > Note (agent decision, pending owner review), 2026-10-23, [#704](https://github.com/goodfetch/goodfetch/issues/704): on the wire `page.evaluate {page_id, function, arg?, world?}` (`sdk_only`, cancellable) answers `{value?}`, `value` absent for `undefined`; `page.add_init_script {page_id, function, arg?}` (`sdk_only`) is a subscription, as a route is: counted when its request arrives, so a navigation sent after it waits until the script is registered (`Page.addScriptToEvaluateOnNewDocument`, main world), removed by its `$/cancel`, after which a navigation waits until it is removed, and answered `{}` when its page ends. Both are the page's main frame's; `locator.evaluate` and `evaluateAll` are the frames ticket's (#726). The engine runs `page.evaluate` as one `Runtime.evaluate`, in the main world with no context or in an isolated world `goodfetch-page-functions` apart from the guard's, so a page function never touches the guard's state; the program's source sits in a thunk outside the engine's walker, which calls it with the argument when it evaluates to a function and otherwise refuses an argument after evaluating the expression. For an init script, whose source may be statements, the engine calls the source only when the whole of it is one function (`function …` or an arrow function, maybe `async`, comments and one closing `;` around it), so a declaration followed by its call runs as the script it is, and refuses a script given an argument before sending it (corrected 2026-10-24 after the spec #577 review, M18: the start alone wrapped `function patch(){…} patch();` and ran a commented arrow uncalled). An expression or script given an argument raises `page_function_failed` with no `name`. `page_value_invalid` details `{direction, path, kind, constructor?, fix}`, `path` from `$` (`$.rows[0].cell`), `kind` one of `node`, `window`, `not_a_number`, `infinity`, `bigint`, `symbol`, `function`, `cycle`, `map`, `set`, `date`, `regexp`, `error` and `object` (any other non-plain object); the engine raises only `direction: "result"`, the SDKs `argument` (#1296). `page_function_failed` details `{name?, message, stack?, fix?}`, a `ReferenceError`'s fix naming the missing variable and the argument in the caller's language. Provenance marks a Session `{action: "main_world_injection", session_id, page_id, by}` once per operation, the first main-world `page.evaluate` and the first init script. A page function still waits at most the CDP command timeout, 30 s.

  > Note (agent decision, pending owner review), 2026-10-26, [#1597](https://github.com/goodfetch/goodfetch/issues/1597): on the wire `locator.evaluate_all {locator, function, arg?, world?}` (`sdk_only`, cancellable) answers `{value?}` as `page.evaluate` does, its function called with the array of every match, none included, then the argument; `locator.wait_for_function {locator, function, arg?, world?, polling_interval?, timeout?}` (`sdk_only`, a waiter under `timeout.wait`, `waited_for: "function"`) is `page.wait_for_function` called with the one element its locator matches, then the argument. Both find their matches in the world the function runs in, with the guard's CSS, open shadow roots included, so no handle crosses worlds; the wait resolves its locator again at each check, and a check while none or several elements match counts as falsy rather than raising `target_not_unique`, as a function wait waits out what is not there yet. A selector the page does not parse raises `invalid_params`, as the guard's does. Each is marked in Provenance by its own operation. `locator.evaluate`, on one element and closed roots (ADR 0121), stays #726's.

### Routes and responses

Selenium's ADR 17685 under Playwright's names, the same in every SDK because the engine applies it (S1; Selenium's bindings had drifted until it was written: Java ran one handler "chosen in no defined order", Ruby raced threads):

- **`page.route(url, handler)` and `session.route(url, handler)`,** the Session's catching a popup's first request, return a `Subscription`. `url` is ADR 0081's matcher: a glob or a regex matched in the engine, or a predicate run in the program, which, like a `**/*` route, has every request wait for the program.
- **Page routes run before Session routes,** as Playwright's page routes come before its context's.
- **Later routes run first. The first to settle wins:** `continue(overrides)`, `fulfill(response)`, `abort(reason)`, or `fetch(overrides)` followed by `fulfill`. `fallback(overrides)` passes the request, with its overrides, to the route registered before, and from the page's first route to the Session's last.
  > Amended by [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md): a header value in `continue`, `fallback` and `fetch` overrides may be a Secret placeholder, added at the engine's interception and checked against the request's URL at every hop.
- **A handler that ends without settling falls back too,** and past the last route the request goes to the network. Playwright stalls such a request (G1, G6). A handler that never returns, or a Rust stream kept but never read, still holds its requests: whatever waits on them ends by its own deadline (ADR 0080), and the Run trace shows the held request. Settling twice, or after the handler ended, raises `route_already_handled`; in Rust each answer takes the route, so it cannot happen. Return values are ignored, and handlers read the original request.
  > Amended by [ADR 0104](0104-a-crawl-declares-its-hooks-per-stage-in-code-a-hook-returns-its-change-and-a-program-registers-its-own-plugins-by-name.md): on a crawl request's own document fetch, the original request is the one its last before-request Hook left; a route may not change its method or body (`page_value_invalid`), and a new URL is checked as a Hook's rewrite.
- **A handler that throws:** its request is aborted, never sent half-changed (ADR 17685 decision 7). The route is removed, and the exception reaches the program as `page_handler_failed`, under ADR 0081's listener rule: from a call in flight that waited on that request, such as the `goto` whose document it was, or else from the next call or close of the value the route was registered on.
- **Routes run before the network.** What a route sends on still passes the run's domain policy (ADR 0014) and Filter lists (ADR 0047); `fulfill` and `abort` reach no network. A route sees what the engine's own interception sees, so adding one changes neither caching nor Service Worker coverage, which Playwright's routing does ("Enabling routing disables http cache"); area 5's spec states both.
  > Amended by [ADR 0121](0121-service-workers-run-under-the-engines-interception-the-back-forward-cache-is-off-locators-reach-closed-shadow-roots-and-a-read-never-scrolls-a-list.md): on Chromium a site's service workers run, and the engine attaches to each before it runs. A service worker's own requests pass the domain policy, Filter lists, the Response cache and the Session's routes, never a page's. A page request a service worker's fetch handler answers never passes the page's interception, so no route answers it; events, waits and kept responses see it, marked by `fromServiceWorker()`. On Firefox and WebKit no service worker registers. `browser.service_workers: block` turns them off without a page-visible stub on Chromium and, through Firefox's own preference, on Firefox; on WebKit it is Playwright's `register` stub, marked in Provenance.
- **Bodies.** `body()`, `text()` and `json()` read on demand. They never fail for a response obtained through `waitForRequestFinished` (ADR 0080), `route.fetch()` or `page.request`, whose bodies the engine keeps. Elsewhere, a body the browser has dropped raises `body_unavailable` (an `UnavailableError`) whose fix names `waitForRequestFinished`, where Playwright and Puppeteer report "Request content was evicted from inspector cache". `json()` returns `JsonValue`, and a body that is not JSON raises `response_not_json` (a `PageError`). No streaming body: large files are downloads.
  > Amended by [ADR 0118](0118-every-fetch-tier-follows-redirects-as-the-browser-does-fails-a-cut-body-and-resends-only-what-a-site-never-processed.md): a body that was cut raises `response_truncated`, a `PageError`, including a `page.request`'s and one obtained through `waitForRequestFinished` or `route.fetch()`; a cut body is never returned as a whole one.

- **`ok` is offered** with Playwright's spelling per language (`ok()` in TypeScript and Rust, the `ok` property in Python): true for a status from 200 to 299. A route's `RouteRequest` takes the same values.

### Dialogs and overlays

- **A dialog with no handler gets Playwright's default:** an `alert`, `confirm` or `prompt` is dismissed, since accepting a `confirm()` may confirm an Effect (ADR 0014, ADR 0037's SA-26), and a `beforeunload` dialog is accepted, so the navigation the program started goes on instead of waiting out its deadline.
- **`page.on('dialog', handler)` keeps Playwright's spelling,** but the handler answers a request (ADR 0081) under the routes' rules: later handlers first, the first `accept(promptText?)` or `dismiss()` wins, and a handler that does neither falls through. Past the last one the dialog gets that default. Playwright's docs warn that an unanswered `dialog` listener stalls the action (G1).
- A handler that throws: the dialog gets its default, and `page_handler_failed` follows the routes' rule, raised from the gesture the dialog blocked or else from the next call. In Rust a dialog is an `EventStream` item, and dropping one unanswered passes it on.
- `close()` runs no `beforeunload` handler unless `close({ runBeforeUnload: true })`, as in Playwright; a navigation can still raise one.
- While a person has the page in the Live view, native dialogs become Console dialogs that the person answers (ADR 0031).
  > Note (agent decision, pending owner review), 2026-10-23, [#719](https://github.com/goodfetch/goodfetch/issues/719): on the wire a dialog handler is a subscription, `page.on_dialog {page_id}` (`sdk_only`), armed when its request arrives and removed by its `$/cancel`, as a route is (#702). For each dialog the engine sends the handler request `dialog.handle {id, dialog_id, page_id, dialog: {type, message, default_value}}` to the latest handler first; the handler answers with `dialog.accept {dialog_id, prompt_text?}` (a prompt's default value when `prompt_text` is absent) or `dialog.dismiss {dialog_id}`, each answering once the page closed the dialog, and replies to `dialog.handle` once it ends: a reply without an answer falls through, and a failure reply is the handler's throw, which gives the dialog its default, removes the handler, ends its subscription with `page_handler_failed` (`handler: "dialog"`, `url` the dialog's document) and leaves the code for the call the dialog blocked, else the page's next call. A second answer, or one after the dialog closed, raises `dialog_already_handled` (`ProgramError`, details `{dialog_id}`), the dialog's counterpart of `route_already_handled`, which no spec listed. `page.close {page_id, run_before_unload?}` closes a page, a popup as any other, as `session.close` closes a Session's: calls in flight raise `call_cancelled` naming the program and the page, it emits `close`, and a second close changes nothing; with `run_before_unload` the engine sends `Page.close`, the `beforeunload` dialog goes to the dialog handlers, and the call answers without waiting, as Playwright's does. Live view dialogs are area 12's: no Live view takes them yet.
- **`addLocatorHandler(locator, handler, { times, noWaitAfter })`,** Playwright's handler for overlays that interrupt an action (P01, Midscene #1551), returns a `Subscription`. Before each attempt of a guarded action, when its locator is visible, the guard calls the handler in the program, then waits for the locator to be hidden unless `noWaitAfter`. Handlers run one at a time, their own actions trigger none, and their time counts toward the action's timeout. One that throws fails the action it interrupted with `page_handler_failed`, its exception as the cause, and stays registered, since that action already reports it. In Rust a turn is an `EventStream` item, and a stream kept unread holds the action until its deadline, as an unread route stream holds requests. It sits beside ADR 0048's Consent prompt refusal and ADR 0047's hiding, which already clear known overlays.

### Navigation

- `goto`, `reload`, `goBack` and `goForward` return `Response | null`, with a 404 or a 500 as a value when no Page check is declared (ADR 0079). `url` is read without a round trip, kept current by the engine's navigation events. `title()` and `content()` are reads, and `setContent(html)` is a gesture.

A failing proxy of the run's own is something the engine depends on, not the site, and stays an `UnavailableError`.

One waiting for `domcontentloaded` or `load` whose main document was cut raises `response_truncated` (a `PageError`, retryable), and so do `body()`, `text()` and `json()` of a cut response and a cut `page.request`. `page.request`'s `maxRedirects` takes at most 19, its default, and raises `too_many_redirects` past its count.

### The raw CDP way down

- **`page.newCdpSession()` returns a `CdpSession`:** `send(method, params?)` returning `JsonValue`, events through `on` (an `EventStream` in Rust), and `close()` (G8). Puppeteer's `createCDPSession()` and Playwright's `context.newCDPSession(page)` are the leaders' forms. browser-use left Playwright because its way down was too narrow (browser drivers P12).
  > Amended by [ADR 0099](0099-every-surface-spells-each-catalog-name-by-its-own-rule-shapes-come-from-declared-kinds-and-call-is-the-way-down.md): by ADR 0099's initialism rule, it is spelled `page.newCDPSession()` returning a `CDPSession` in TypeScript, `page.new_cdp_session()` returning a `CDPSession` in Python, and `page.new_cdp_session()` returning a `CdpSession` in Rust.
- **It travels over the program's own connection,** so no port or token is opened. It is a raw CDP attach under ADR 0017: the Session's traffic goes through the egress proxy (on a Borrowed browser, ADR 0056's interception instead), no Secret is typed, results are marked unguarded, the attach is in the Audit log, and an attach from a handler is bound to its work item's lease (ADR 0003) and ends with ADR 0087's `attach_ended` when the lease ends.

- **Semver covers its shape, never the protocol:** methods, parameters and events are Chromium's and typed `JsonValue`. No generated CDP types enter the SDK API (G7), as Selenium's ADR 17670 keeps raw BiDi out of its public API.

### What ADR 0019's mapping leaves out

ADR 0019 asks each Playwright call in the parity list to map or be excluded with a reason. Mapped calls keep their names, `page.context()` becoming `page.session()`; these are excluded:

- **Selector-taking page shortcuts** (`page.click(selector)`, `page.fill`, `$`, `$$`, `$eval`, `waitForSelector`) and `dragAndDrop`: S2, ADR 0077's own example. `locator.type` and `waitForNavigation`, which Playwright itself replaced. No tombstones are added: each has its replacement one dot away, the type checker flags the call at its line, and tombstoning thirty discouraged names would freeze them per language at 1.0 (ADR 0030). ADR 0080's sleep tombstone stays the only one.
- **`ElementHandle`, `JSHandle` and `Frame`:** the handle model.
- **`trial`**, which runs the checks without acting: rare, and `waitFor` and the state reads cover it. **`noWaitAfter`**, deprecated by Playwright: an action waits for the navigation it starts. **`dispatchEvent`**: synthetic, untrusted events are `evaluate`'s.

### Error codes

Each code has one class under ADR 0079's naming rule, and none shadows a built-in:

| Group | Codes |
|---|---|
| `ProgramError` | `selector_invalid`, `page_function_failed`, `page_value_invalid`, `page_handler_failed`, `route_already_handled` |
| `PageError` | `target_not_unique`, `target_unsupported`, `navigation_failed`, `navigation_interrupted`, `response_not_json` |
| `UnavailableError` | `page_crashed`, `body_unavailable`, `download_failed` |
| `RefusedError` | `cdp_command_refused` |

> Amended by [ADR 0116](0116-a-saved-file-is-written-whole-or-not-at-all-and-a-failed-write-says-whether-its-path-or-its-storage-failed.md): a file a page call saves to the program's path adds `path_not_writable` (`ProgramError`) and `file_write_failed` (`UnavailableError`), Collie codes shared with every saved file.

> Amended by [ADR 0118](0118-every-fetch-tier-follows-redirects-as-the-browser-does-fails-a-cut-body-and-resends-only-what-a-site-never-processed.md): `too_many_redirects` and `response_truncated` join the `PageError` row.

`page_handler_failed` and `route_already_handled` are raised by the TypeScript and Python SDKs only: Rust answers those requests in the program's own code, and its answers take the route.

> Note (agent decision, pending owner review), 2026-10-22, [#702](https://github.com/goodfetch/goodfetch/issues/702): on the wire a route is a subscription, `page.route` or `session.route`, a call that stays in flight, armed when its request arrives, so a later call's requests reach it (the engine calls each operation's handler in the Connection's arrival order), and removed by its `$/cancel`. For each request it matches, the engine sends the Connection the handler request `route.handle`, naming the request by a `route_id`; the handler answers with `route.continue`, `route.fulfill`, `route.abort`, `route.fallback` or `route.fetch`, each a call of its own, and replies to `route.handle` once it ends: a reply without an answer falls back, and a failure reply is the handler's throw. The engine therefore raises both codes, so every SDK, and a Client on the bare protocol, gets the same rule: a failure reply aborts the request unless it was answered, removes the route, ends its subscription with `page_handler_failed`, and leaves the code for the navigation waiting on the request or else the next call on the page; an answer after the first, or after the handler ended, raises `route_already_handled`. The Rust SDK's answers still take the route, so it cannot answer twice. The route operations are kept to the SDKs (`sdk_only`), since only program code answers `route.handle`. `route.fetch` sends the request on through the browser and pauses its response, so what it fetches passes the same steps as `continue`. On Chromium the paused request already carries the Session's cookies; the engine leaves them out of what a route sees, and the browser keeps them on what it sends, whatever headers a route set.

> Amended by [ADR 0111](0111-a-rust-crawl-hands-what-it-subscribes-on-its-page-to-serve-which-reads-it-for-the-rest-of-the-attempt.md): the Rust SDK raises `page_handler_failed` for a route, dialog or locator handler that a crawl reads through `ctx.for_each`, under the rules above; `route_already_handled` still cannot happen in Rust.

### Forms per language

TypeScript and Python keep Playwright's spellings, including Python's properties (`response.ok`, `locator.first`, `frame_locator.owner`), `continue_` and `abort(error_code=)`. Rust's calls are builders implementing `IntoFuture` (ADR 0080), a question that never waits returns a `Query` with no timeout, the selector-less frame locator is `any_frame()`, an init script returns a `Registration` removed on drop, and answering a route or a dialog takes it, so dropping one unanswered gives its default.

> Amended by [ADR 0099](0099-every-surface-spells-each-catalog-name-by-its-own-rule-shapes-come-from-declared-kinds-and-call-is-the-way-down.md): Rust's route answer is `r#continue()`, by ADR 0099's rule for reserved words.

> Amended by [ADR 0111](0111-a-rust-crawl-hands-what-it-subscribes-on-its-page-to-serve-which-reads-it-for-the-rest-of-the-attempt.md): `Registration::keep()` keeps an init script until its page or Session closes, so a crawl's Hook can add one for the rest of its attempt.

> Amended by [ADR 0099](0099-every-surface-spells-each-catalog-name-by-its-own-rule-shapes-come-from-declared-kinds-and-call-is-the-way-down.md): Rust's selector-less frame locator is `frame_locator(None)`: one `frame_locator` takes `impl Into<Option<&str>>`, as TypeScript's `frameLocator(selector?)` is one member, and there is no `any_frame()`.

## Considered Options

- **A `BrowserContext` beside the Session:** rejected by S2 and the glossary, whose Session avoids "context".
- **Playwright's `Frame` handles beside frame locators:** rejected. An eager handle detaches on navigation, and two ways reach a frame. **A frame pointer**, as Selenium and WebdriverIO before v10: rejected by G2.
- **Playwright's whole selector language** (`text=`, `>>`, `internal:`): rejected by S2. Every engine has a method, and the mini-language would be frozen at 1.0.
- **Exact text matching by default,** as Testing Library and Playwright's open request #19235: rejected by S3. The same name with a different default is the case models get wrong most.
- **Failing at once on an ambiguous target,** as Playwright: rejected. It is the only condition not waited out, and transient duplicates during a re-render fail. **Failing once the same matches have held for a settle window:** rejected. It is a heuristic and, under ADR 0028, one more setting.
- **Overlapping gestures,** as Playwright allows: rejected; keystrokes and pointer moves interleave silently. **Every call on a page one at a time:** rejected; it deadlocks ADR 0080's waiters, which must be armed while their gesture runs.
- **A structured row-wise read** beside the getters: rejected by S2. Concurrent reads, `evaluateAll`, the crawl's selector reads and `extract` already cover it.
- **Playwright's serializer for page functions** (JSON plus `NaN`, `±Infinity`, `-0`, and `undefined` for anything else): rejected. Python's and Rust's JSON idioms cannot hold the extras, and the silent `undefined` breaks G1.
- **Renaming `evaluate` to carry a trust level,** as AI pain 9 suggests for code-execution verbs: rejected. Its trust level is fixed by where it runs, the page, and a new name breaks S3 and ADR 0019.
- **Routes that stall when no handler settles,** as Playwright: rejected by G1 and G6. **Routes without predicates,** as Selenium's ADR 17685: rejected, since ADR 0081 keeps Playwright's predicates for waits and routes alike (S3).
- **A route that throws staying registered,** as a crawl handler stays: rejected. ADR 0081's listener rule is one rule for the functions a value calls in the background, and the program hears of it at once. A locator handler is different: the action it interrupted reports its exception.
- **Gestures that keep their turn while they wait on the program:** rejected. A locator handler's click would wait for the action that waits for the handler.
- **Failing at the deadline with `deadline_exceeded` when the target is still ambiguous,** as ADR 0080 had every timeout: rejected. Raising the timeout never fixes an ambiguous locator, and ADR 0079 groups errors by remedy.
- **Refusing a Collie program's own navigation for an AI-use signal**, with a code of its own (an earlier draft of this ADR): rejected. ADR 0086 says these signals tell "how results may be used, not how hard a site may be pressed", and a Collie page's own navigation is outside Politeness; it would also add a second Site-preferences refusal code. **A value on `Response` reporting the signals:** rejected; Provenance and the Run trace already record them, and no page call acts on them.
- **`navigation_failed` as an `UnavailableError`:** rejected. ADR 0079 lists there what the engine itself depends on; a site that never answered is the page never reaching the state the call needed.
- **No `ok()`:** rejected. It would not stop `status === 200`, and agents and users write `ok` everywhere (S3, T).
- **A `dialog` listener that must answer,** as Playwright: rejected; it stalls the action. **A declarative overlay dismissal** (click this when that appears): rejected; it cannot express a close that takes two steps.
- **Generated CDP types in the SDK API,** as chromiumoxide's: rejected by G7. They break on Chrome updates (browser drivers P11) and would put a third party's protocol under the SDKs' semver.
- **Tombstones for every discouraged Playwright call:** rejected by S2 and ADR 0030.

## Consequences

- **Adds to ADR 0019.** This ADR is the mapping its Consequences ask for, in all three SDKs; each Playwright call in the parity list maps here or is excluded with a reason.
- **Amends ADR 0080.** A target still ambiguous when its deadline passes raises `target_not_unique`, not `deadline_exceeded`; a note sits under its timeout errors.
- **Answers ADR 0083's hand-over.** Contexts are Sessions, and pages open with `session.newPage()` or arrive as popups.
- **Answers ADR 0087's hand-over.** Pages open with `session.newPage()` or as popups; a page a Collie program opens leaves ADR 0087's handler value empty, and pages opened from a handler's page inherit it.
- **Answers ADR 0086's hand-over.** A use signal that refuses a Collie Run's Purpose refuses no call of the program's own page; the AI verbs that send a page's content to a model refuse it, under a code Collie's AI verbs and Plans chooses. One code for every Site-preferences refusal, with its reason, as Crawl definition and handler context proposes for a handler's navigation, would serve both.
- **Adds to ADR 0023.** The guard's per-call switch is `force`, the setting `action.force` given for one call; it keeps uniqueness.
- **Adds to ADR 0017.** A CDP session opened from an SDK is a raw CDP attach under its rules, relayed over the program's connection, so it needs no endpoint or token of its own.
- **Adds to ADR 0047.** User routes run before Filter lists, and what a route sends on is blocked or allowed by them like any request.
- **Adds to ADR 0081.** Route and dialog handlers follow its listener rule for exceptions, under `page_handler_failed`, raised first from a call in flight they blocked; a locator handler's exception fails the action it interrupted.
