# Sessions open from their source, `page.pause()` waits for a person, and a secret is a placeholder bound to domains

A program brings a login in, keeps it, waits for a person and uses a secret through four things: a Session opened from its Session source, a Saved identity, `page.pause()`, and Secret placeholders that a setting binds to a Secret reference and the domains allowed to receive it. The engine resolves a secret's value at the moment of use, so the value never reaches the program's code, its Plans, logs or results, except a value the program itself answers for a `caller:` reference. The leaders leave each of these to the user. Browser Use's login and human-in-the-loop issues are among its most reacted (#221, 18 reactions; #404, 11 reactions; #4798, "Support agent.pause() within tool calls", still open), and an HN thread reads "no way to login without giving the LLM your credentials". Stagehand's server cache received `%var%` values by default, and Playwright MCP put password values in snapshots (#1566). Scrapy has had no cookie API since 2016 ("Expose cookiejars", #1878). Playwright writes logins to clear-text `storageState` files, and its `httpCredentials` without an origin "are sent to any servers upon unauthorized responses". Decided in [Sessions, logins, Human pause and secrets in code](https://github.com/goodfetch/automan/issues/476), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/automan/issues/461), every answer by the agent on the owner's delegation, on the evidence of the [research on competitors' APIs](https://github.com/goodfetch/automan/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md) ([AI browser automation](https://github.com/goodfetch/automan/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md) §6 rows 9 and 11; [crawl frameworks](https://github.com/goodfetch/automan/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/crawl-frameworks.md) §6.17), of Playwright 1.64.1's API documentation, of Browser Use's [Secrets](https://docs.browser-use.com/cloud/guides/secrets.md) and [Human in the loop](https://docs.browser-use.com/cloud/agent/human-in-the-loop.md) guides, and of Crawlee 3.18.2's `Session`. Principles are cited by their IDs in [ADR 0077](0077-the-sdk-api-follows-eight-guarantees-and-four-ranked-shape-rules.md).

## Decision

### Sessions

- **A Session opens from its source.** `run.newSession({ source?, login?, settings?, timeout? })` (Python `new_session(source=..., login=...)`, Rust `run.new_session().source(..)`). `source` is ADR 0056's `session.source`, a tagged union typed per language (`{ kind: "saved_identity", name }` in TypeScript and Python, `SessionSource::SavedIdentity { … }` in Rust), given as the call's own argument as ADR 0083 lets a call take the setting that is its task. A Session's `settings` type leaves `session.source` out, as a Collie Run's leaves out `timeout.run`, so one Session has one spelling (S2); set in the `settings` of a Session being opened, which only Rust's single `Settings` type allows, it is refused with `setting_not_applicable`. At a Run or connection scope, `settings.session.source` is the default for the Sessions opened beneath: the default Session and a crawl's Session pool. `client_browser` stays `run.borrow()`'s (ADR 0078), and the Rust crate reaches a browser through `cdp_url`. One union replaces Playwright's `newContext({ storageState })`, `launchPersistentContext` and `connectOverCDP`, as ADR 0056 decided (S1, G3).
- **The Run's default Session.** `run.newPage()` opens pages in the Run's default Session, which its first call opens with the Run's settings and every later call shares. `page.session()` reaches it, as Playwright's `page.context()` (a property in Python, as Playwright's). Closing it ends it, and a later `run.newPage()` raises `closed`, since a value never reopens (ADR 0078). It is a shortcut built on the same objects (S2), held where the program can reach it (G2). Playwright's `browser.newPage()` "creates a new page in a new browser context", "a convenience API that should only be used for the single-page scenarios and short snippets". Two such pages would silently lose a login between them, and the Run is not a Browser, so no Playwright name changes meaning (S3).
- **A login is kept as a Saved identity.** `session.saveIdentity(name)` keeps the Session's identity, cookies and storage as a Saved identity (ADR 0035), replacing one of that name under the install-wide lock, and the Audit log records it. A later Session reuses it with `source: { kind: "saved_identity", name }`. A Session whose cookies live outside run state (a Borrowed browser, a Profile directory used in place) raises `session_not_savable`, whose fix names importing that source. `gf.identities` lists Saved identities (each with its source, when it was saved, the earliest cookie expiry per domain and whether it is bound to its machine, ADR 0056), imports one from a source, deletes one, and exports one as ADR 0015's `age`-encrypted bundle for a CI job on another machine. No SDK writes a clear-text `storageState`, which only a person exports (ADR 0056) (G5).
- **Cookies.** Playwright's `session.cookies(urls?)`, `addCookies(cookies)` and `clearCookies(filter?)`, with its `Cookie` fields (S3). Only the program's own code calls them: the SDKs offer them, and no CLI command, MCP tool, skill, Framework adapter or Code mode does, since a coding agent drives the CLI (ADR 0011) and a logged-in Session's cookies never reach a model (ADR 0014). On a Session whose navigation is bound to its source's `domains` (a borrowed running browser, a `cdp_url` naming them, a Profile directory used in place, ADR 0056), a cookie outside them is neither read nor written, with ADR 0056's `domain_not_allowed`.
- **A point in time is the language's own type.** A cookie's `expires`, a Saved identity's save time and its cookie expiries are a `Date` in TypeScript, a time-zone-aware `datetime` in UTC in Python and a `SystemTime` in Rust, and a session cookie's `expires` is `null`. No earlier ADR fixed a type for a point in time; Playwright's seconds since the epoch, with `-1` for a session cookie, would bring back the bare numbers ADR 0080 removed for durations, and a magic value (S1, G3). A cookie the program adds is session state, encrypted in run state and never logged (ADR 0015); one written to a Borrowed browser or a Profile directory stays there (ADR 0056). Crawlee's `Session` reads and writes cookies per URL; Scrapy has no way (G2).
- **Proxies.** `proxy.server`, `proxy.bypass`, `proxy.username` and `proxy.password` are Session settings with Playwright's fields, one proxy per Session (ADR 0021), `proxy.password` a Secret reference. Pools by kind and provider adapters (ADR 0021) belong to the same family, and area 8's spec names their keys. A proxy per page or per request is declined: it changes the IP under the same cookies (ADR 0021, SA-22; Puppeteer declined it too, #678, +118). In a crawl, the Session pool retires a blocked Session with its proxy (ADR 0021); in Collie, the blocked call raises its Block cause (ADR 0079) and the program opens a new Session.
- **HTTP authentication.** `session.http_credentials` is a list of `{ username, password, domains }`, `password` a Secret reference, `domains` required: credentials answer a challenge only from a listed registrable domain. Playwright's default without an origin is not kept (G5).
- **Permissions and a visible window.** `browser.permissions` grants Playwright's permission names (`clipboard-read`, `clipboard-write`, `geolocation`, …) to every page of the Session, none by default and no `grantPermissions` setter (ADR 0083, G2); it answers ADR 0085's clipboard question. `browser.headless`, `true` by default and `false` under `stealth` (ADR 0035), shows a window for a person at the keyboard (ADR 0031's first Live view tier). Both follow ADR 0083's `browser.*` rules, refused where a Borrowed browser's Session opens with `setting_not_applicable`, since they would change the person's browser.

### A lost login

- **The Page check is a Session setting.** `session.page_check` is `{ login_page, expected_page }` (camelCased in TypeScript, as ADR 0083 has it), each optional and each a page match: a URL glob or regular expression, a CSS or XPath selector, a text, matched in the engine (ADR 0081). Every page of the Session is judged against it (ADR 0006); without one, ADR 0006's built-in detector applies and pages are weakly checked.
- **The scripted login step is the program's own function.** `login` on `newSession` is called with a page of the Session on its login page, where the program's code runs (ADR 0081). The Page check judges the page it leaves, and it counts toward ADR 0006's two recoveries per page. In Rust it is `session.logins()`, an `EventStream` of requests, as ADR 0081 shapes requests that need an answer, and dropping one hands the page back.
- **An unattended program turns the pause off.** `session.recovery.human_pause`, `true` by default, lets the ladder end in a Human pause; `false` skips that step.
- **A login that does not come back raises `logged_out`** (a `PageError`), listing each step of the ladder and why it did not recover, with an exception from `login` chained as the cause. A program learns "the saved login expired" from one typed error, never from a missing element (G1, G6). No leader detects a lost login from page content (ADR 0006).

### The Human pause

- **`page.pause()` is the Human pause.** Playwright's `page.pause()` "pauses script execution… User can inspect selectors or perform manual steps while paused", and needs a headed browser. The Human pause has that meaning, extended to headless browsers through the Live view, so the name stays (S3, T); ADR 0085 left it here. Browser Use Cloud has no such call: a run stops, a person uses its live view URL, and a new run continues the session, losing the program's place and its clocks.
- **What it takes.** `page.pause({ reason?, until?, timeout? })` (Rust: `page.pause().reason(..).until(&locator)` or `.until_url(..)`, an `IntoFuture` builder as ADR 0080 has it). `reason` is shown in the Console's "Needs you", the Notification (ADR 0027) and the Live view, and logged at info through the host's logging (ADR 0078). `until` is a Locator becoming visible or a `UrlMatcher` as `waitForURL` takes it (ADR 0080). It ends the pause by itself when it holds, and a person's "Done" is accepted only while it holds. Without `until`, a person's "Done" ends it.
- **What it returns.** `HumanPauseResult { resolvedBy: "condition" | "person", person, waited }`. A person's "Decline" raises `human_pause_declined` (a `RefusedError`, "a person refused", ADR 0079) with their note, because the call promises that the step was done (G1). The program ends its own pause by cancelling the call (ADR 0080). A Live view grant holder ends a pause only through `until`, since a grant holder is not a Goodfetch person (ADR 0031). A person's "Hand back" ends a program's pause as "Done" does.
- **Where the person acts.** In the page's own window when the browser is headful on their desktop, otherwise in the Live view from any device; an Attached engine starts the Daemon for its link when needed (ADR 0031).
- **A pause is a gesture.** Under ADR 0085's per-page order, the page's later gestures wait for it, while reads and waits run, so a program cannot type under a person's hands.
- **How long.** `timeout.human_pause`, 24 hours by default (ADR 0036's value for an after-a-run Schedule), with ADR 0080's three states: `null` waits without limit and `0` is refused. Past it, `page.pause()` raises `deadline_exceeded` naming the setting, while a pause the engine raised inside a call ends that call with its own code (such as `logged_out`) carrying the expired pause. A Schedule's pause timeout (ADR 0036) still governs its runs: both apply, and the first to expire acts. Time in a pause counts toward no enclosing timeout, the Run's included (ADR 0080).
- **Limits keep counting.** Usage consumed during a pause counts toward Limits as anywhere else: a paused browser holds browser time, and a person browsing in the Live view spends proxy bytes, both Usage under ADR 0041. Suspending Limits, as the research's lesson for AI pain 11 words it, would leave a day-long pause uncapped (G5). What that lesson needs is met by clocks and steps: no timeout counts the pause, and a pause is no Agent step ([The Agent in Collie's SDK API](https://github.com/goodfetch/automan/issues/474)). A Limit reached during a pause stops the run (ADR 0041), ending the pause, and its Notification says why.

### Secrets

- **A Secret placeholder, bound at a scope.** The setting `secrets.<name>` binds the **Secret placeholder** `name` to `{ reference, domains, totp }` (`totp` optional) or `{ code_source, domains }`, camelCased in TypeScript, at the connection, a Run or a Session, nearest winning, so each Session of a pool can log in to its own account. Code uses `secret("name")`, a typed `SecretPlaceholder`, in deterministic calls, and `%name%` in an AI instruction (ADR 0014). This is ADR 0015's "the run binds each placeholder to a Secret reference and to the domains allowed to receive it", as one setting; Browser Use Cloud's `secretBindings` give each credential an alias and allowed domains the same way. `totp: true` types the current code from a seed, and a vault that makes codes itself needs no flag (ADR 0015). `code_source` names one of ADR 0006's email or SMS code sources, whose keys area 5's spec names; a Human pause takes over when no code arrives.
- **Domains are required.** They are registrable domains (ADR 0004), `*` only when written, as `consent_domains` and `wall_domains` are (ADRs 0048, 0052). They are checked against the frame holding the target field, as Browser Use checks the focused field's frame so that a payment frame on an allowed page needs its own domain, or against a request's URL.
- **Who binds.** The program's own code at the run layer, configuration, and an Operator policy, which may lock a binding. A Recipe declares the names it needs and may expose them, but never binds them, as with `session.source` (ADR 0056): a third-party Recipe could otherwise bind `keychain:` to a domain of its author's. A Client acting for a model never sets one (`setting_locked`), so model-written code (Code mode) cannot bind `env:AWS_SECRET_ACCESS_KEY` to its own domain (G5).
- **A Secret reference** is `provider:rest` (`env:`, `keychain:`, `op://`, `caller:`, ADR 0015). A value that is not a reference is refused with `setting_invalid`, so a raw password is never sent. TypeScript types it as `` `${string}:${string}` ``, so a literal without a provider fails `tsc`.
- **Where a placeholder goes.** Into text typed into a target, `locator.fill` and `locator.pressSequentially`, where the guard re-checks the field (ADR 0014). Into a header value in `page.request` and in a route's `continue`, `fallback` and `fetch` overrides, and a string of a JSON body `page.request` sends, checked against the request's URL, for logins made through an API. A request carrying a secret is sent where no page script or Service Worker can read it: the engine adds the value at its own interception, after the page's scripts and Service Workers, never in the page's JavaScript. And `%name%` into an AI instruction, whose verbs are [Collie's AI verbs and Plans](https://github.com/goodfetch/automan/issues/473)' and The Agent in Collie's SDK API's: a Secret placeholder there is bound by `secrets.*`, never by a per-call map, which may carry only plain values. Not into `keyboard.*`, which has no field to re-check, nor page functions (ADR 0085), nor `addCookies`. `extract` reads and takes none. The types enforce the list: `keyboard.type(secret("x"))` fails the type checker (G3).
- **Credentials the engine uses itself** take a Secret reference directly: `proxy.password`, `session.http_credentials`, model keys, Sink and webhook secrets, an export bundle's passphrase, a `cdp_url`'s headers.
- **What comes back.** The program never receives a value. The engine masks every value it resolved, by value, as `%name%`, in everything a call returns (reads such as `inputValue`, page function results, extracted values, Records, response bodies, an error's `observed`) and in everything it keeps (logs, the Run trace, Plans, the Effect journal). Screenshots and recordings are masked (ADR 0014). A value too short to mask safely wherever it appears, such as a one-time code, is masked where it was typed and in what the engine keeps; area 4's spec sets the length. ADR 0016's redaction switch lifts masking only for logs, traces, HAR files, screenshots and recordings kept as outputs (ADR 0014), never for what a call returns or a model receives. Once a raw CDP session is attached to the page, no secret is typed (ADRs 0017, 0085) (G5, G1).
- **The caller as Secret provider.** `connect({ resolveSecret })` (Python `resolve_secret`; Rust `gf.secret_requests()`, an `EventStream` of requests it answers) resolves `caller:<name>` references at the moment of use, where the program's code runs (ADR 0081). The value goes straight to the engine; the SDK keeps no copy and logs nothing. `env:` resolves in the engine's environment, which for an Attached engine is the program's environment map (ADR 0083) and for a Daemon its own (ADR 0036), so a program whose per-customer credentials live in its own store has this route. Without it, a `caller:` reference raises `secret_unavailable` whose fix names the option, and a Schedule on a Daemon still refuses `caller:` (ADR 0036).
- **`GOODFETCH_TOKEN` holds a value, not a reference.** References resolve in the engine, which the token is needed to reach, and a thin SDK carries no Secret providers (ADR 0024). The environment already is ADR 0015's `env:` store, and a program keeping its token in a vault passes `engine: { url, token }` from its own code. Its value never appears anywhere (ADR 0083).

### Error codes

Each code has one class under ADR 0079's naming rule, and each names the placeholder and the reference, never a value:

| Group | Code | When |
|---|---|---|
| `ProgramError` | `secret_unbound` | No scope binds the placeholder; lists the names bound |
| `ProgramError` | `session_not_savable` | `saveIdentity` on a Session whose cookies live outside run state |
| `UnavailableError` | `secret_unavailable` | The provider gave no value: a missing variable, a locked keychain, an unreachable vault, `resolveSecret` missing or throwing; retryable by cause |
| `RefusedError` | `secret_domain_not_allowed` | The field's frame or the request is outside the binding's `domains` |
| `RefusedError` | `secret_input_refused` | A browser other code also drives (ADR 0056), or a raw CDP attach (ADR 0017) |
| `RefusedError` | `human_pause_declined` | A person declined the step `page.pause()` asked for |
| `PageError` | `logged_out` | The Page check found a login page and recovery did not bring the login back, or was off |

A field of the wrong kind stays ADR 0085's `target_unsupported`.

## Considered Options

- **One option per login mechanism** (`storageState`, `userDataDir`, `cdpUrl`), as Playwright and Browser Use: rejected by ADR 0056. **The source only in `settings`**: rejected; it buries the call's main input three levels deep.
- **No `run.newPage()`**, a Session always opened first: rejected; two lines in nearly every golden scenario for no safety. **A new Session per page**, as Playwright's `browser.newPage()`: rejected; a login silently does not carry to the second page.
- **A clear-text `storageState` file** from code, as Playwright: rejected by ADR 0056. **A mutable cookie-jar object**: rejected by S3; Playwright's three methods are what users know. **Cookies only through Hooks**, as ADR 0037's SA-21 noted: rejected; reading a cookie is a one-line need (crawl frameworks §6.17).
- **A new name for the pause** (`waitForHuman`, `humanPause`): rejected by S3; the meaning is Playwright's. **Only pauses the engine raises**, as Browser Use Cloud's stop-and-continue: rejected; the program loses its place and its clocks.
- **A declined pause as a value**: rejected by G1; a program that forgets to check it saves a logged-out identity. **No limit on a pause by default**, as Playwright: rejected; every other phase has a finite default (ADR 0080), and ADR 0036 already bounds a scheduled run's pause by 24 hours. **Suspending Limits during a pause**: rejected by G5 (above).
- **Secret values in code**, as Browser Use's open-source `sensitive_data` and Stagehand's `variables`: rejected by ADR 0015. **A reference written inline at each call**: rejected; model-written code could bind any reference to any domain, and every call would repeat it.
- **Placeholders in `keyboard.*`**: rejected; no field can be re-checked. **A Secret reference in `GOODFETCH_TOKEN`**: rejected (above).

## Consequences

- **Amends ADR 0011.** Reading and writing a Session's cookies is offered in the SDKs only, on no CLI command, MCP tool, skill, Framework adapter or Code mode.
- **Amends ADR 0006.** The Page check is the setting `session.page_check`; the scripted login step is the Session's `login` function, or the Rust `logins()` stream; `session.recovery.human_pause` switches the ladder's Human pause off; a login recovery does not bring back raises `logged_out`.
- **Amends ADR 0014.** A secret's domains are checked against the frame holding the target field, or a request's URL; the engine masks every value it resolved, as `%name%`, in everything it returns to a Client.
- **Amends ADR 0015.** The run's bindings are the setting `secrets.<name>`, which a Recipe never binds and a Client acting for a model never sets; a program answers `caller:` references with `resolveSecret`; `GOODFETCH_TOKEN` holds a value.
- **Amends ADR 0028.** A Recipe declares and may expose `secrets.*`, never binds or locks it, as `session.source`.
- **Amends ADR 0031.** A Live view grant holder ends a pause a program raised only through its `until` condition, and a person's "Hand back" ends it as "Done" does.
- **Amends ADR 0078.** `run.newPage()` uses the Run's default Session.
- **Amends ADR 0080.** A Human pause lasts at most `timeout.human_pause`, 24 hours by default.
- **Amends ADR 0083.** The keys `timeout.human_pause`, `browser.headless`, `browser.permissions`, `session.page_check`, `session.recovery.human_pause`, `session.http_credentials`, `proxy.*` and `secrets.<name>` join the schema; a Session's `settings` type leaves out `session.source`, which opening it spells `source`, and refuses it where a type cannot; `GOODFETCH_TOKEN` takes no Secret reference.
- **Error codes.** The table's codes join `goodfetch-protocol`'s list through `xtask codegen`'s naming checks (ADR 0079).
- **Area 4 (Security and egress)** builds the bindings, the frame-domain check, masking by value and the caller resolver. **Area 5 (Site access)** builds Session sources in code, the default Session, cookies, `proxy.*`, `session.http_credentials`, `browser.permissions`, `browser.headless`, `session.page_check` and the code sources' keys. **Area 8 (Stealth and Challenge solving)** names the proxy pool keys. **Area 9 (AI and agent)** builds `%name%` in instructions. **Area 11 (Client surfaces)** builds the shapes per language, `gf.identities` and `resolveSecret`. **Area 12 (Console)** shows program pauses in "Needs you" with their reason and `until`. Each lists this ADR.
- **ADR 0037's matrix:** SA-21 (cookies) and SA-27 (HTTP authentication) are decided here; SA-22, CO-13, SC-08 and the pains `access-auth-session` and `agent-human-in-loop` cite it.
- **Other tickets of the map.** [The Run in code](https://github.com/goodfetch/automan/issues/478) gives the Run's live states and events for pending Human pauses. Collie's AI verbs and Plans and The Agent in Collie's SDK API use `%name%`; a pause is no Agent step, and the Agent ticket decides how a program switches off the ladder's AI agent login step. [Crawl definition and handler context](https://github.com/goodfetch/automan/issues/477) gives a crawl's Session pool `session.source`, `session.page_check`, `secrets.*` and a login function from the Run or per Label, and a handler reaches its Session's cookies through `page.session()`. [Mapping the catalog to each language and surface](https://github.com/goodfetch/automan/issues/471) names `gf.identities`' per-language forms (Python's `import_`) and offers cookie operations to no Client acting for a model.
- **`GLOSSARY.md`** gains **Secret placeholder**, and **Human pause** covers a step a program asks for.
- **TESTING.md** gains Sessions, Human pause and secrets cases in every SDK and against the engine, and its Secret canaries cover the new kinds of secret and what a call returns.
- **The `prototype/sdk-api` sketch** holds these signatures in its `sessions` files for each language; the pain coverage matrix closes P14 and P40 as API and P50 as API, its proxy per page Declined.
