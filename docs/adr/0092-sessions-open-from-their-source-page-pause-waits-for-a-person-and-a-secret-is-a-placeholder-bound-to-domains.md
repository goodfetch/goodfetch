# Sessions open from their source, `page.pause()` waits for a person, and a secret is a placeholder bound to domains

A program brings a login in, keeps it, waits for a person and uses a secret through four things: a Session opened from its Session source, a Saved identity, `page.pause()`, and Secret placeholders that a setting binds to a Secret reference and the domains allowed to receive it. The engine resolves a secret's value at the moment of use, so the value never reaches the program's code, its Plans, logs or results, except a value the program itself answers for a `caller:` reference or reads back through a raw CDP session it attached. The leaders leave each of these to the user. Browser Use's login and human-in-the-loop issues are among its most reacted (#221, 18 reactions; #404, 11 reactions; #4798, "Support agent.pause() within tool calls", still open), and an HN thread reads "no way to login without giving the LLM your credentials". Stagehand's server cache received `%var%` values by default, and Playwright MCP put password values in snapshots (#1566). Scrapy has had no cookie API since 2016 ("Expose cookiejars", #1878). Playwright writes logins to clear-text `storageState` files, and its `httpCredentials` without an origin "are sent to any servers upon unauthorized responses". Decided in [Sessions, logins, Human pause and secrets in code](https://github.com/goodfetch/goodfetch/issues/476), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461), by the agent on the owner's delegation; the owner then confirmed every decision of the grilling record and its first four addenda ([confirmation](https://github.com/goodfetch/goodfetch/issues/476#issuecomment-6188988230)), and the [fifth addendum](https://github.com/goodfetch/goodfetch/issues/476#issuecomment-6189068147), answering ADR 0088, is the agent's on the owner's delegation; on the evidence of the [research on competitors' APIs](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md) ([AI browser automation](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md) §6 rows 9 and 11; [crawl frameworks](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/crawl-frameworks.md) §6.17), of Playwright 1.64.1's API documentation, of Browser Use's [Secrets](https://docs.browser-use.com/cloud/guides/secrets.md) and [Human in the loop](https://docs.browser-use.com/cloud/agent/human-in-the-loop.md) guides, and of Crawlee 3.18.2's `Session`. Principles are cited by their IDs in [ADR 0077](0077-the-sdk-api-follows-eight-guarantees-and-four-ranked-shape-rules.md).

## Decision

### Sessions

- **A Session opens from its source.** `run.newSession({ source?, login?, settings?, timeout? })` (Python `new_session(source=..., login=...)`, Rust `run.new_session().source(..).login(..)`). `source` is ADR 0056's `session.source`, a tagged union typed per language (`{ kind: "saved_identity", name }` in TypeScript and Python, `SessionSource::SavedIdentity { … }` in Rust), given as the call's own argument as ADR 0083 lets a call take the setting that is its task. A Session's `settings` type leaves `session.source` out, as a Collie Run's leaves out `timeout.run`, so one Session has one spelling (S2); set in the `settings` of a Session being opened, which only Rust's single `Settings` type allows, it is refused with `setting_not_applicable`. At a Run or connection scope, `settings.session.source` is the default for the Sessions opened beneath: the default Session and a crawl's Session pool. `client_browser` stays `run.borrow()`'s (ADR 0078), and the Rust crate reaches a browser through `cdp_url`. One union replaces Playwright's `newContext({ storageState })`, `launchPersistentContext` and `connectOverCDP`, as ADR 0056 decided (S1, G3).
- **The Run's default Session.** `run.newPage()` opens pages in the Run's default Session, which its first call opens with the Run's settings and every later call shares. `page.session()` reaches it, as Playwright's `page.context()` (a property in Python, as Playwright's). Closing it ends it, and a later `run.newPage()` raises `closed`, since a value never reopens (ADR 0078). It takes no `login`: a program that needs the scripted login step opens a Session of its own. It is a shortcut built on the same objects (S2), held where the program can reach it (G2). Playwright's `browser.newPage()` "creates a new page in a new browser context", "a convenience API that should only be used for the single-page scenarios and short snippets". Two such pages would silently lose a login between them, and the Run is not a Browser, so no Playwright name changes meaning (S3).
  > Note (agent decision, pending owner review), 2026-10-23, [#697](https://github.com/goodfetch/goodfetch/issues/697): the operations are `run.new_session` (`run_id`, `source`, `settings`) answering the `session_id`, `session.new_page` and `session.close`; a Session's ID names its Run and its position among the Run's Sessions (`<run_id>.session-<n>`). `session.source`'s tagged union is defined once in `goodfetch-protocol` with ADR 0056's seven kinds and their fields as the SDK sketch has them, `source: null` opening a fresh Session beneath a Run's `session.source`; until the ticket of each kind builds its reader, a Session opening from that kind raises ADR 0083's `capability_unavailable` naming `session.source`, the layer and the kind. Every key of a Session's own `settings` is refused with `setting_not_applicable`, `session.source` first: no setting yet takes effect on one Session apart from its Run's, so none is ignored; the Session settings ticket lifts the refusal for its keys. Each open page holds one `browser_page` admission of the Resource governor (ADR 0040), which `session.close` gives back. The run state keeps each Session's position, whether it is the default one and whether it is closed, never its source; a Run resumed under its ID reopens its Sessions from it on the first call that reaches it, each making its browser context again on its next page, and its cookies and storage are not carried over until the Sessions' run-state encryption (area 4) keeps them.
- **A login is kept as a Saved identity.** `session.saveIdentity(name)` keeps the Session's identity, cookies and storage as a Saved identity (ADR 0035), replacing one of that name under the install-wide lock, and the Audit log records it. A later Session reuses it with `source: { kind: "saved_identity", name }`. It keeps the binding of the import its Session came from (ADR 0056): a login bound to its machine stays bound, and its export bundle keeps the binding, so using it on another machine is refused with `session_bound_to_machine` (ADR 0056). A Session whose cookies live outside run state (a Borrowed browser, a Profile directory used in place) raises `session_not_savable`, whose fix names importing that source. `gf.identities` lists Saved identities (each with its source, when it was saved, the earliest cookie expiry per domain and whether it is bound to its machine, ADR 0056), imports one from a source, deletes one, and exports one as ADR 0015's `age`-encrypted bundle for a CI job on another machine. No SDK writes a clear-text `storageState`, which only a person exports (ADR 0056). A Client acting for a model, or a Recipe run, that saves, imports, deletes or exports a Saved identity waits for a person's approval in a Human pause, as its imports do (ADR 0056), so a prompt-injected agent cannot replace a person's login with an attacker's (G5).
- **Cookies.** Playwright's `session.cookies(urls?)`, `addCookies(cookies)` and `clearCookies(filter?)`, with its `Cookie` fields (S3). Only the program's own code calls them: the SDKs offer them, and no CLI command, MCP tool, skill, Framework adapter or Code mode does, since a coding agent drives the CLI (ADR 0011) and a logged-in Session's cookies never reach a model (ADR 0014). On a Session whose navigation is bound to its source's `domains` (a borrowed running browser, a `cdp_url` naming them, a Profile directory used in place, ADR 0056), a cookie outside them is neither read nor written, with ADR 0056's `domain_not_allowed`. A cookie the program adds is session state, encrypted in run state and never logged (ADR 0015); one written to a Borrowed browser or a Profile directory stays there (ADR 0056). Crawlee's `Session` reads and writes cookies per URL; Scrapy has no way (G2).
- **Storage.** Playwright's `page.localStorage` and `page.sessionStorage` (since 1.61), each a `WebStorage` with `items()`, `getItem`, `setItem`, `removeItem` and `clear` on the page's current origin, answer what ADR 0085 left here (S3). They follow the cookies' rules: offered in the SDKs only, since a logged-in Session's storage never reaches a model either (ADR 0014); refused outside a bound source's `domains`; a value set is session state. `localStorage` travels between runs in a Saved identity; `sessionStorage`, kept per tab, travels only in a session export bundle (ADR 0056); neither in a clear-text file.
- **A point in time is the language's own type.** Every point in time the SDK API takes or returns, a cookie's `expires` and a Saved identity's times first, is a `Date` in TypeScript, a time-zone-aware `datetime` in UTC in Python and a `SystemTime` in Rust; a session cookie's `expires` is `null`. No earlier ADR fixed a type for a point in time; Playwright's seconds since the epoch, with `-1` for a session cookie, would bring back the bare numbers ADR 0080 removed for durations, and a magic value (S1, G3).
- **Proxies.** `proxy.server`, `proxy.bypass`, `proxy.username` and `proxy.password` are Session settings with Playwright's fields, one proxy per Session (ADR 0021), `proxy.password` a Secret reference. Pools by kind and provider adapters (ADR 0021) belong to the same family, and area 8's spec names their keys. A proxy per page or per request is declined: it changes the IP under the same cookies (ADR 0021, SA-22; Puppeteer declined it too, #678, +118). A crawl's Session pool retires a blocked Session with its proxy (ADR 0021); a Session a program or an Agent opened, in either Product, is never replaced (ADR 0088), so the program opens a new Session when it wants another IP.
- **A Block cause on a program's Session raises `blocked`.** On a Session a program or an Agent opened, a Block cause the engine cannot get past is reported on the call that met it (ADR 0088) as `blocked`, a `PageError` whose details carry the Block cause, kept as received when the SDK does not know it (ADR 0079), with the URL and the response status. It is raised by the call that waits for the navigation that met it, `goto()`, `reload()`, `goBack()`, `goForward()`, `waitForURL()` or a Gesture that waits for the navigation it started, or else by the next call on the page, as ADR 0085 raises a dialog handler's failure. A Challenge first goes down ADR 0035's ladder without its new-Session step (ADR 0088) and, when the ladder ends, raises ADR 0035's `challenge_unsolved` with its Block cause. One code with the cause as a field lets a program catch every block in one place and branch on the cause (G1, G6), as a crawl request's `blocked` outcome carries it (ADR 0079, S2). `page.request` judges no Block cause and returns its response, as Playwright's `APIRequestContext` does (S3). The Session stays open and keeps its cookies; the program decides whether to wait, open another Session or ask for a Human pause with `page.pause()` (ADR 0077's G1 and G2).
  > Amended by [ADR 0118](0118-every-fetch-tier-follows-redirects-as-the-browser-does-fails-a-cut-body-and-resends-only-what-a-site-never-processed.md): the details of `blocked` also carry `retryAfter`, the time a `rate_limit`'s `Retry-After` asks for, read in either form, or `null`. The engine never waits on it for a program's own navigation.
  > Note (agent decision, pending owner review), 2026-10-24, [#711](https://github.com/goodfetch/goodfetch/issues/711): the document a `goto()`, `reload()`, `goBack()` or `goForward()` reached is judged for its Block cause before its Page check (a Challenge or a captcha whose navigation the Filter lists touched is first loaded once more with blocking off, ADR 0047, and that load judged), and so is the one a `waitForURL()` waited for; a Gesture waits for the navigation it started only until its document commits (ADR 0085; fix-queue 45, 2026-10-24), never for its load, so any other navigation's document (a click's, a script's redirect) is judged by the next call that reads or acts on the page, once: a navigation, a locator action or wait, `evaluate()`, `addInitScript()`, `waitForFunction()`, `request` or a format read. Block detection reads only the markers its rules name for the response's status, found in the page's own serialization, and none for a status no rule reads. The wire spells the detail `retry_after` (ADR 0038), RFC 3339, read from any blocked response that carries a `Retry-After`; `0`, a past date or an unparsable value give `null`. Until area 8's Challenge ladder exists, a `challenge` or a `captcha` raises `blocked` with its cause too.
- **HTTP authentication.** `session.http_credentials` is a list of `{ username, password, domains }`, `password` a Secret reference, `domains` required: credentials answer a challenge only from a listed registrable domain. Playwright's default without an origin is not kept (G5). A challenge on a browser other code may read (a Borrowed browser other code drives, a page with a raw CDP session, a Lent page, ADR 0089) is not answered: the call fails with `secret_input_refused`, since that code could read the header.
- **Permissions and a visible window.** `browser.permissions` grants Playwright's permission names (`clipboard-read`, `clipboard-write`, `geolocation`, …) to every page of the Session, none by default and no `grantPermissions` setter (ADR 0083, G2); it answers ADR 0085's clipboard question. In a headful window on the person's desktop the page's clipboard is the person's own, so `clipboard-read` and `clipboard-write` are refused there with `setting_not_applicable` (ADR 0085 keeps the host's clipboard out); a program's own copy and paste shortcuts in that window reach the person's clipboard, as the person's would. `browser.headless`, `true` by default and `false` under `stealth` (ADR 0035), shows a window for a person at the keyboard (ADR 0031's first Live view tier). Both follow ADR 0083's `browser.*` rules, refused where a Borrowed browser's Session opens with `setting_not_applicable`, since they would change the person's browser.

### A lost login

- **The Page check is a Session setting.** `session.page_check` is `{ login_page, expected_page }` (camelCased in TypeScript, as ADR 0083 has it), each optional and each a page match: a URL glob or regular expression, a CSS or XPath selector, a text, matched in the engine (ADR 0081). Every page of the Session is judged against it (ADR 0006); without one, ADR 0006's built-in detector applies and pages are weakly checked.
- **The scripted login step is the program's own function.** `login`, given where a Session opens (in Rust a closure, as [Crawl definition and handler context](https://github.com/goodfetch/goodfetch/issues/477) (ADR 0093) takes a crawl's login step), is called with the page whose call met the login page, where the program's code runs (ADR 0081). The call waiting on recovery gives up the page's turn while `login` runs, so its Gestures run, as ADR 0085's locator handlers do. In Rust this is a step inside a call the program awaits, so it is a closure run in that call's future rather than ADR 0081's `EventStream`, which stays the shape of a request that may come while no call is in flight. The Page check judges the page `login` leaves, and it counts toward ADR 0006's two recoveries per page.
  > Amended by [ADR 0109](0109-a-rust-programs-own-code-returns-any-error-as-a-box-error-read-as-the-other-sdks-read-an-exception.md): a Rust login step returns `Result<(), BoxError>`, so any error of the program, or its panic, is chained to `logged_out` as `login`'s exception.
- **An unattended program turns the pause off.** `session.recovery.human_pause`, `true` by default, lets the ladder end in a Human pause; `false` skips that step, and step 6 of ADR 0035's Challenge ladder on the same Session too, so a Challenge the earlier steps cannot pass raises `challenge_unsolved` at once instead of waiting up to `timeout.human_pause` for no one. One switch says that no person is there, for a lost login and a Challenge alike (S2, G5).
  > Amended by [ADR 0100](0100-collies-agent-is-one-bounded-call-on-a-page-judged-by-the-programs-success-check-and-replayed-whole-from-the-plan.md): `session.recovery.agent`, `true` by default, switches ADR 0006's AI agent login step as `session.recovery.human_pause` switches the Human pause step. The step runs the built-in Agent with the Session's Secret placeholders, bound by their own domains and the run's domain policy, not by `agent.domains`; with the step off, or with no model and no login Plan (or under `plan.frozen` without one), it is skipped, and `logged_out` names why.
- **A login that does not come back raises `logged_out`** (a `PageError`), listing each step of the ladder and why it did not recover, with an exception from `login` chained as the cause. A program learns "the saved login expired" from one typed error, never from a missing element (G1, G6). No leader detects a lost login from page content (ADR 0006).

### The Human pause

- **`page.pause()` is the Human pause.** Playwright's `page.pause()` "pauses script execution… User can inspect selectors or perform manual steps while paused", and needs a headed browser. The Human pause has that meaning, extended to headless browsers through the Live view, so the name stays (S3, T); ADR 0085 left it here. Browser Use Cloud has no such call: a run stops, a person uses its live view URL, and a new run continues the session, losing the program's place and its clocks.
- **What it takes.** `page.pause({ reason?, until?, timeout? })` (Rust: `page.pause().reason(..).until(&locator)` or `.until_url(..)`, an `IntoFuture` builder as ADR 0080 has it). `reason` is shown in the Console's "Needs you", the Notification (ADR 0027) and the Live view, and logged at info through the host's logging (ADR 0078). `until` is a Locator becoming visible or a `UrlMatcher` as `waitForURL` takes it (ADR 0080). It ends the pause by itself when it holds, and a person's "Done" is accepted only while it holds. Without `until`, a person's "Done" ends it.
  > Amended by [ADR 0099](0099-every-surface-spells-each-catalog-name-by-its-own-rule-shapes-come-from-declared-kinds-and-call-is-the-way-down.md): Rust's is one `.until(..)`, taking `impl Into<PauseUntil>` from a `&Locator`, a `UrlMatcher` or a URL glob, as TypeScript's one `until` option; there is no `.until_url(..)`.
- **What it returns.** `HumanPauseResult { resolvedBy: "condition" | "person", person, waited }`. A person's "Decline" raises `human_pause_declined` (a `RefusedError`, "a person refused", ADR 0079) with their note, because the call promises that the step was done (G1). The program ends its own pause by cancelling the call (ADR 0080). A Live view grant holder ends a pause only through `until`, since a grant holder is not a Goodfetch person (ADR 0031). A person's "Hand back" ends a program's pause as "Done" does.
  > Amended by [ADR 0113](0113-a-human-pause-whose-page-closes-raises-call-cancelled-naming-what-closed-and-a-lost-live-view-ends-no-pause.md): a pause whose page is closed in the browser, outside every Client (a person on the desktop, the page's own `window.close()`), raises `call_cancelled` with `by: "browser"` and `closed: "page"`, or `closed: "browser"` when the browser quits, never `human_pause_declined`; later calls on the page raise `closed`, and its Session stays open when only the page closed.
- **Where the person acts.** In the page's own window when the browser is headful on their desktop, otherwise in the Live view from any device; an Attached engine starts the Daemon for its link when needed (ADR 0031).
  > Amended by [ADR 0113](0113-a-human-pause-whose-page-closes-raises-call-cancelled-naming-what-closed-and-a-lost-live-view-ends-no-pause.md): a lost Live view ends no pause, which keeps waiting under `timeout.human_pause` until the person comes back through "Needs you" or the Notification's link; the Live view and the Console close no page a Human pause holds, offering "Done" and "Decline" instead.
- **A paused page takes no Gesture.** While the pause holds a page, its later Gestures wait (ADR 0085's per-page order), while reads and waits run, so a program cannot type under a person's hands.
- **How long.** `timeout.human_pause`, 24 hours by default (ADR 0036's value for an after-a-run Schedule), with ADR 0080's three states: `null` waits without limit and `0` is refused. Past it, `page.pause()` raises `deadline_exceeded` naming the setting, while a pause the engine raised inside a call ends that call with its own code (such as `logged_out`) carrying the expired pause. In a scheduled run the built-in default does not apply: ADR 0036's pause timeout governs, by its own rules, and a value set at any layer, the built-in default aside, also applies, the first to expire acting. Time in a pause counts toward no enclosing timeout, the Run's included (ADR 0080).
  > Amended by [ADR 0100](0100-collies-agent-is-one-bounded-call-on-a-page-judged-by-the-programs-success-check-and-replayed-whole-from-the-plan.md): the Agent's own Human pause (`agent.human_pause`, off by default) is a question the model asked: the person's answer, a decline with its note, or the pause running out goes back to the model as that action's outcome instead of ending the call. A declined confirmation of an Effect still ends the task with `effect_not_confirmed`.
- **Limits keep counting.** Usage consumed during a pause counts toward Limits as anywhere else: a paused browser holds browser time, and a person browsing in the Live view spends proxy bytes, both Usage under ADR 0041. Suspending Limits, as the research's lesson for AI pain 11 words it, would leave a day-long pause uncapped (G5). What that lesson needs is met by clocks and steps: no timeout counts the pause, and a pause is no Agent step ([The Agent in Collie's SDK API](https://github.com/goodfetch/goodfetch/issues/474) (ADR 0100)). A Limit reached during a pause stops the run (ADR 0041), ending the pause, and its Notification says why.

### Secrets

- **A Secret placeholder, bound at a scope.** The setting `secrets.<name>` binds the **Secret placeholder** `name` to `{ reference, domains, totp }` (`totp` optional) or `{ code_source, domains }`, camelCased in TypeScript, at the connection, a Run or a Session, nearest winning, so each Session of a pool can log in to its own account. Code uses `secret("name")`, a typed `SecretPlaceholder`, in deterministic calls, and `%name%` in an AI instruction (ADR 0014). This is ADR 0015's "the run binds each placeholder to a Secret reference and to the domains allowed to receive it", as one setting; Browser Use Cloud's `secretBindings` give each credential an alias and allowed domains the same way. `totp: true` types the current code from a seed, and a vault that makes codes itself needs no flag (ADR 0015). `code_source` names one of ADR 0006's email or SMS code sources, whose keys area 5's spec names; a Human pause takes over when no code arrives, and with `session.recovery.human_pause` off the call fails with `secret_unavailable`.
- **Domains are required.** They are registrable domains (ADR 0004), `*` only when written, as `consent_domains` and `wall_domains` are (ADRs 0048, 0052). They are checked against the frame holding the target field, as Browser Use checks the focused field's frame so that a payment frame on an allowed page needs its own domain, or against a request's URL.
- **Who binds.** The program's own code at the run layer, configuration, and an Operator policy, which may lock a binding. A Recipe declares the names it needs and may expose them, but never binds them, as with `session.source` (ADR 0056): a third-party Recipe could otherwise bind `keychain:` to a domain of its author's. A Client acting for a model never sets one (`setting_locked`), so model-written code (Code mode) cannot bind `env:AWS_SECRET_ACCESS_KEY` to its own domain (G5). The same holds for `session.http_credentials` and for `proxy.server` and the proxy's credentials, which send a Secret reference's value to a destination they also name: whoever sets `proxy.server` receives `proxy.password`. A Recipe exposes them and never sets them, and a Client acting for a model never sets them; a Recipe may still set the pool kinds it needs.
  > Note (agent decision, pending owner review), 2026-10-23, [#708](https://github.com/goodfetch/goodfetch/issues/708): a Client acting for a model is one whose `hello` names the surface `mcp` or `worker` (Code mode in the Script sandbox); the engine keeps no `form`, so a Framework adapter on an SDK's surface is not yet told apart. `proxy.*` take the catalog authority `not_by_recipe_or_model`, checked by the resolver at the run layer of a Run and of a Session's own `settings` (`Resolved::beneath`), whose `proxy.*` keys are the only ones a Session's own settings take so far. A Session records its own settings in run state, Secret references and never values, so a resumed Session keeps its proxy. `proxy_auth_failed` is declared here as a `RefusedError`, not retryable, beside `proxy_unavailable`. As Playwright does, `proxy.bypass`'s entries become Chromium's bypass rules with a leading dot made `*.`, and `<-loopback>` is added so loopback goes through the proxy too; `socks5h` reaches Chromium as `socks5`, whose SOCKS5 proxies resolve the names they are given.
  > Note (agent decision, accepted by the owner on 2026-10-28), 2026-10-29, [#1370](https://github.com/goodfetch/goodfetch/issues/1370) (owner item O7): behind a gateway, the surface that tells a model's Client is the Client's own, which the gateway's `hello` names in `client_surface` (ADR 0095), never the gateway's `cloud`.
- **A Secret reference** is `provider:rest` (`env:`, `keychain:`, `op://`, `caller:`, ADR 0015). A value that is not a reference is refused with `setting_invalid`, so a raw password is never sent. TypeScript types it as `` `${string}:${string}` ``, so a literal without a provider fails `tsc`.
- **Where a placeholder goes.** Into text typed into a target, `locator.fill` and `locator.pressSequentially`, where the guard re-checks the field (ADR 0014). Into a header value in `page.request` and in a route's `continue`, `fallback` and `fetch` overrides, and a string of a JSON body `page.request` sends, checked against the request's URL at every hop, for logins made through an API: a redirect to a domain outside the binding drops the value and fails with `secret_domain_not_allowed`, so neither the header nor a resent body follows it. A request carrying a secret is sent where no page script or Service Worker can read it: the engine adds the value at its own interception, after the page's scripts and Service Workers, never in the page's JavaScript. No secret is typed into or sent from a browser other code may read, a Borrowed browser other code drives (ADR 0056), a page with a raw CDP session attached (ADR 0017) or a Lent page (ADR 0089): there `fill` and a request with a placeholder fail with `secret_input_refused`. And `%name%` into an AI instruction, whose verbs are [Collie's AI verbs and Plans](https://github.com/goodfetch/goodfetch/issues/473)' and The Agent in Collie's SDK API's: a Secret placeholder there is bound by `secrets.*`, never by a per-call map, which may carry only plain values. Not into `keyboard.*`, which has no field to re-check, nor page functions (ADR 0085), nor `addCookies` or storage. `extract` reads and takes none. The types enforce the list: `keyboard.type(secret("x"))` fails the type checker (G3). In Rust, whose JSON goes through serde, a placeholder is not serializable and enters a JSON body through `json_secret(pointer, placeholder)`, so no serializer carries one into a page function or a fulfilled body; at runtime every SDK refuses a placeholder anywhere else before sending it (`page_value_invalid`).

  > Amended by [ADR 0104](0104-a-crawl-declares-its-hooks-per-stage-in-code-a-hook-returns-its-change-and-a-program-registers-its-own-plugins-by-name.md): a before-request Hook's header value takes a Secret placeholder too, checked against the request's URL at every hop as in `page.request`; the engine adds the value after the last Hook.

- **Credentials the engine uses itself** take a Secret reference directly: `proxy.password`, `session.http_credentials`, model keys, Sink and webhook secrets, an export bundle's passphrase, a `cdp_url`'s headers.
- **What comes back.** The program never receives a value. The engine masks every value it resolved, by value, as `%name%`, in everything a call returns or an event carries (reads such as `inputValue`, page function results, extracted values, Records, response bodies, an error's `observed`; `request`, `response`, `console`, `pageerror`, `dialog` and WebSocket events) and in everything it keeps (logs, the Run trace, Plans, the Effect journal). It masks the forms it builds itself from a value too, such as the base64 of a Basic `Authorization` header from `session.http_credentials` or a `Proxy-Authorization` header, as the setting's key (`%session.http_credentials%`, `%proxy.password%`) where no placeholder names it. Screenshots and recordings are masked (ADR 0014). A value too short to mask safely wherever it appears, such as a one-time code, is masked where it was typed and in what the engine keeps; area 4's spec sets the length. ADR 0016's redaction switch lifts masking only for logs, traces, HAR files, screenshots and recordings kept as outputs (ADR 0014), never for what a call returns or a model receives. Once a raw CDP session or another program is attached to the page, no secret is typed or sent (ADRs 0017, 0085), and what that client reads from the page, a field typed earlier included, is beyond masking; such results are already marked unguarded (ADRs 0017, 0056) (G5, G1).
- **The caller as Secret provider.** `connect({ resolveSecret })` (Python `resolve_secret`; Rust `gf.secret_requests()`, an `EventStream` of requests it answers, since a request may come while no call of the program is in flight and the Rust SDK spawns nothing, ADR 0081) resolves `caller:<name>` references at the moment of use, where the program's code runs (ADR 0081). It answers only references of Runs its own connection opened. The value goes straight to the engine; the SDK keeps no copy and logs nothing. `env:` resolves in the engine's environment, which for an Attached engine is the program's environment map (ADR 0083) and for a Daemon its own (ADR 0036), so a program whose per-customer credentials live in its own store answers them through `caller:`. Without `resolveSecret`, a `caller:` reference raises `secret_unavailable` whose fix names the option, and a Schedule on a Daemon still refuses `caller:` (ADR 0036). On Goodfetch Cloud, whose gateway answers `caller:` references from a tenant's store (ADRs 0015, 0036), how a program's own answers join the gateway's is Goodfetch Cloud's map's.

  > Amended by [ADR 0104](0104-a-crawl-declares-its-hooks-per-stage-in-code-a-hook-returns-its-change-and-a-program-registers-its-own-plugins-by-name.md): Rust declares the program's Secret provider when connecting, `ConnectOptions::resolve_secret()`, as it declares its other SDK handlers, and `gf.secret_requests()` reads only what it declared. Without the declaration a `caller:` reference raises `secret_unavailable` as in TypeScript and Python, whether or not a stream is open.

- **`GOODFETCH_TOKEN` holds a value, not a reference.** References resolve in the engine, which the token is needed to reach, and a thin SDK carries no Secret providers (ADR 0024). The environment already is ADR 0015's `env:` store, and a program keeping its token in a vault passes `engine: { url, token }` from its own code. Its value never appears anywhere (ADR 0083).

### Error codes

Each code has one class under ADR 0079's naming rule, and each names the placeholder and the reference, never a value:

| Group | Code | When |
|---|---|---|
| `ProgramError` | `secret_unbound` | No scope binds the placeholder; lists the names bound |
| `ProgramError` | `session_not_savable` | `saveIdentity` on a Session whose cookies live outside run state |
| `UnavailableError` | `secret_unavailable` | The provider gave no value: a missing variable, a locked keychain, an unreachable vault, `resolveSecret` missing or throwing, no one-time code; not retryable, and its `failure` says which |
| `RefusedError` | `secret_domain_not_allowed` | The field's frame or the request is outside the binding's `domains` |
| `RefusedError` | `secret_input_refused` | A secret typed into or sent from a browser other code also drives (ADR 0056), a page with a raw CDP attach (ADR 0017) or a Lent page (ADR 0089), or an HTTP authentication challenge left unanswered there |
| `RefusedError` | `human_pause_declined` | A person declined the step `page.pause()` asked for |
| `PageError` | `blocked` | A Block cause the engine cannot get past on a Session a program or an Agent opened (ADR 0088); names the cause, the URL and the status |
| `PageError` | `logged_out` | The Page check found a login page and recovery did not bring the login back, or was off |

A field of the wrong kind stays ADR 0085's `target_unsupported`.

## Considered Options

- **One option per login mechanism** (`storageState`, `userDataDir`, `cdpUrl`), as Playwright and Browser Use: rejected by ADR 0056. **The source only in `settings`**: rejected; it buries the call's main input three levels deep.
- **No `run.newPage()`**, a Session always opened first: rejected; two lines in nearly every golden scenario for no safety. **A new Session per page**, as Playwright's `browser.newPage()`: rejected; a login silently does not carry to the second page.
- **A clear-text `storageState` file** from code, as Playwright: rejected by ADR 0056. **A mutable cookie-jar object**: rejected by S3; Playwright's three methods are what users know. **Cookies only through Hooks**, as ADR 0037's SA-21 noted: rejected; reading a cookie is a one-line need (crawl frameworks §6.17).
- **A new name for the pause** (`waitForHuman`, `humanPause`): rejected by S3; the meaning is Playwright's. **Only pauses the engine raises**, as Browser Use Cloud's stop-and-continue: rejected; the program loses its place and its clocks.
- **A declined pause as a value**: rejected by G1; a program that forgets to check it saves a logged-out identity. **No limit on a pause by default**, as Playwright: rejected; every other phase has a finite default (ADR 0080), and ADR 0036 already bounds a scheduled run's pause, by its next occurrence or 24 hours. **Suspending Limits during a pause**: rejected by G5 (above).
- **Secret values in code**, as Browser Use's open-source `sensitive_data` and Stagehand's `variables`: rejected by ADR 0015. **A reference written inline at each call**: rejected; model-written code could bind any reference to any domain, and every call would repeat it.
- **Placeholders in `keyboard.*`**: rejected; no field can be re-checked. **A Secret reference in `GOODFETCH_TOKEN`**: rejected (above).

## Consequences

- **Amends ADR 0006.** The Page check is the setting `session.page_check`; the scripted login step is the `login` function given where the Session opens; `session.recovery.human_pause` switches the ladder's Human pause off; a login recovery does not bring back raises `logged_out`.
- **Amends ADR 0011.** Reading and writing a Session's cookies and a page's storage is offered in the SDKs only, on no CLI command, MCP tool, skill, Framework adapter or Code mode.
- **Amends ADR 0014.** A secret's domains are checked against the frame holding the target field, or a request's URL; the engine masks every value it resolved, as `%name%`, in everything a call returns or an event carries, except a value too short to mask safely everywhere.
  > Note (agent decision, pending owner review), 2026-10-24, [#619](https://github.com/goodfetch/goodfetch/issues/619): a setting's key takes the place of `name` where no placeholder names a value, so `run_state.key_reference`'s value is masked as `%run_state.key_reference%`. The engine's masks sort outputs into three scopes, each one Aho-Corasick automaton rebuilt when a value joins or a Run ends: what a call returns or an event carries, `$/log` lines included (values of 8 characters or more; a shorter one or a one-time code only in a read of the field it was typed in); what the engine keeps beside its outputs, run state's warnings, progress message and Run report, a crawl's attempt errors and crash reports (every value); and kept outputs, logs and the Run trace (every value but those of a Run whose `security.redaction` is off). The RPC layer masks each line a Connection sends; where a value's raw form spans a message's own JSON syntax, it masks the message string by string so it stays one message. The Basic `Authorization` and `Proxy-Authorization` headers are covered by the base64 forms at each alignment. The automata hold the values' forms in their own tables, freed but not zeroized when rebuilt.
- **Amends ADR 0015.** The run's bindings are the setting `secrets.<name>`, which a Recipe never binds and a Client acting for a model never sets, as `session.http_credentials`, `proxy.server` and the proxy's credentials; a program answers `caller:` references with `resolveSecret`; `GOODFETCH_TOKEN` holds a value.
- **Amends ADR 0028.** A Recipe declares and may expose `secrets.*`, `session.http_credentials`, `proxy.server` and the proxy's credentials, never sets or locks them, as `session.source`; it may still set the proxy pool kinds it needs.
- **Amends ADR 0031.** A Live view grant holder ends a pause a program raised only through its `until` condition, and a person's "Hand back" ends it as "Done" does.
- **Amends ADR 0035.** `session.recovery.human_pause: false` also skips the Challenge ladder's Human pause (step 6) on that Session.
- **Amends ADR 0056.** A Client acting for a model or a Recipe run that saves, imports, deletes or exports a Saved identity waits for a person's approval.
- **Amends ADR 0078.** `run.newPage()` uses the Run's default Session.
- **Amends ADR 0079.** The code naming a Block cause a `goto()` cannot get past is `blocked`, with the cause in its details, and every call that waits for that navigation raises it, or else the page's next call; a Challenge raises `challenge_unsolved`.
- **Amends ADR 0080.** A Human pause lasts at most `timeout.human_pause`, 24 hours by default; in a scheduled run ADR 0036's pause timeout governs, a value set at any layer also applies, and the first to expire acts.
- **Amends ADR 0081.** In Rust, a step inside a call the program awaits, the scripted login step, is a closure run in that call's future; a request that may come while no call is in flight stays an `EventStream`.
- **Amends ADR 0083.** `resolveSecret` joins `connect()`'s own options. The keys `timeout.human_pause`, `browser.headless`, `browser.permissions`, `session.page_check`, `session.recovery.human_pause`, `session.http_credentials`, `proxy.*` and `secrets.<name>` join the schema; a Session's `settings` type leaves out `session.source`, which opening it spells `source`, and refuses it where a type cannot; `GOODFETCH_TOKEN` takes no Secret reference; the clipboard permissions are refused in a headful window on the person's desktop.
  > Amended by [ADR 0093](0093-a-crawl-declares-its-labels-and-one-handler-each-and-a-handler-reads-collies-page-on-every-fetch-tier.md): `session.source`, `session.http_credentials`, `session.recovery.human_pause`, `session.page_check` and `secrets.*` are also set on a crawl's Label; a Label that sets what a Session holds gets a Session pool of its own.
