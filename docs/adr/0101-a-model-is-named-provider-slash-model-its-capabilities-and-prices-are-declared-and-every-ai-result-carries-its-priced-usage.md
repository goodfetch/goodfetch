# A model is named `provider/model`, its capabilities and prices are declared, and every AI result carries its priced Usage

A program chooses a model with one string, a **Model reference** such as `anthropic/claude-sonnet-4-5` or `ollama/qwen3:8b`, set for a scope as `ai.model` or given to one AI call as `model`. It reaches ADR 0012's formats, gateways and local servers through built-in or declared Model providers, a Model provider Plugin (ADR 0033), or answers model calls with its own code. What a model can do is declared, never guessed from its name, and its price comes from the price table, which only configuration changes. Every AI result, and every error from a call that made model calls, carries the Usage of those calls with its price, and a Run reports its totals and what remains of its Limits. Model choice is the AI tools' fourth pain and the synthesis's twelfth: Stagehand's model option changed shape in every major and has no base URL, Browser Use sniffs model names and dropped providers in 0.3.3, Midscene makes a model family mandatory, and structured output breaks on every provider's own JSON Schema subset. Seeing what AI work spends is the thirteenth: Stagehand reports tokens but never money and loses the usage of calls that throw, Browser Use prices only when asked, from prices fetched at run time, and Pydantic AI's totals silently leave unpriced models out ([consumer API research](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md) pain 12 and like 8; [AI browser automation](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md) §4.1 items 7 and 8, pains 4, 8 and 13; [model choice, capabilities, structured output, usage and cost in comparable tools](https://github.com/goodfetch/goodfetch/blob/research/sdk-models/rnd/research/2026-10-15-sdk-models-usage-cost.md), checked 2026-10-15). Decided in [Models, usage and cost in the SDK API](https://github.com/goodfetch/goodfetch/issues/475), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461), under the principles of [ADR 0077](0077-the-sdk-api-follows-eight-guarantees-and-four-ranked-shape-rules.md), building on [ADR 0091](0091-collies-ai-verbs-live-on-the-page-replay-from-a-plan-file-the-run-names-and-expect-runs-a-success-check.md) and [ADR 0092](0092-sessions-open-from-their-source-page-pause-waits-for-a-person-and-a-secret-is-a-placeholder-bound-to-domains.md).

## Decision

### Naming a model

- **A Model reference is `"<provider>/<model id>"`:** a Model provider's name, a slash, and that provider's own model ID verbatim, so a gateway's ID keeps its own slash (`vercel/anthropic/claude-sonnet-4.5`, `openrouter/meta-llama/llama-4-scout`). The Vercel AI Gateway and OpenRouter name models `creator/model`, and LiteLLM and Stagehand put the provider first, so this is the form models and people meet most (S3, T); it fits a configuration file, a CLI flag and an MCP argument as well as code (S1, ADR 0011).
- **Where it goes.** The setting `ai.model` gives a scope its model; the `model` argument of `act`, `observe` and `extract` (ADR 0091) is that setting at the run layer for one call (ADR 0083). It has no default: no model is called unless one is configured (ADR 0043), and a call that needs one fails with ADR 0091's `model_not_configured`, whose fix names `ai.model`.
- **Checked as far as Goodfetch can know.** The provider must be built in, declared, a Model provider Plugin the operator allowed, or the program's own, where the scope opens or the call starts, or the value fails with `setting_invalid`, naming the closest provider (G3). The model ID passes verbatim, since providers add models every month; a wrong one fails with `model_not_found` at its first call. TypeScript types a reference as `` `${string}/${string}` ``, so a bare `gpt-5-mini` fails `tsc`.
- **One model per call.** No fallback list, as OpenRouter's `models` or LiteLLM's fallbacks: a Plan records which model compiled each step (ADR 0091), and a silent switch would hide it (G1, G2). A gateway's own routing still works through its ID.

### Model providers

- **Built in:** `openai`, `anthropic`, `google` (Gemini's native format), `vercel` (the Vercel AI Gateway, through Anthropic Messages for `anthropic/…` models and its OpenAI-compatible endpoint for the rest, ADRs 0012 and 0076) and `openrouter`, and the local `ollama`, `llamacpp`, `lmstudio` and `vllm`, each at its server's default loopback address.
- **Declared** under `ai.providers.<name>`: `format` (`openai`, `anthropic` or `gemini`, ADR 0012's three), `base_url`, `api_key`, `headers` (whose values are Secret references, as ADR 0056's `cdp_url` headers), and `models` (below). Declaring a built-in's name changes that built-in, such as a proxy in front of OpenAI. Azure, Bedrock and Vertex endpoints are declared providers or are reached through a gateway (ADR 0012). Providers are declared at the connection, a Run or a Session; a page's settings take only `ai.model` and `ai.structured_output`. A model ID that holds a dot or a slash is quoted as one segment of a key, as TOML quotes it: `ai.providers.lab.models."gpt-5.1".image_input`.
- **Keys are Secret references** (ADR 0015), as ADR 0092 rules for credentials the engine uses itself: `api_key` and `headers` go only to the address declared with them. Each cloud built-in reads its conventional variable by default, sent only to its own address: `env:OPENAI_API_KEY`, `env:ANTHROPIC_API_KEY`, `env:GEMINI_API_KEY`, `env:AI_GATEWAY_API_KEY` (ADR 0076) and `env:OPENROUTER_API_KEY`, as Stainless SDKs read `OPENAI_API_KEY` as a default an argument replaces (ADR 0083). A built-in a program points elsewhere sends no default key, and a local built-in needs none. A missing key fails with ADR 0092's `secret_unavailable`.
- **Who sets where a key goes.** A provider's `api_key`, `headers` and `base_url` are set by the program's own code at the run layer, by configuration, or by an Operator policy, which may lock them, as ADR 0092 rules for `secrets.*`. A Recipe never sets them: it names the model it needs with `ai.model` and may expose it. A Client acting for a model, an Integration included (ADR 0056), never sets them either (`setting_locked`). So neither a third-party Recipe nor model-written code can send `env:OPENAI_API_KEY` or `env:AWS_SECRET_ACCESS_KEY` to an address of its choosing (G5).
- **A Model provider Plugin** (ADR 0033), a process Plugin the operator allowed, reaches a format beyond ADR 0012's three, so a CLI or MCP user can add one too; ADR 0033's Rust-trait form is the engine's own seam for its built-ins ([ADR 0104](0104-a-crawl-declares-its-hooks-per-stage-in-code-a-hook-returns-its-change-and-a-program-registers-its-own-plugins-by-name.md)), not a form a program uses. A Model reference names a Plugin by the provider name its manifest declares. Its models' capabilities and prices come from its manifest, which the operator sees and can override when allowing it, as ADR 0033 rules for spend outside the engine; a model it does not price is unpriced.
- **One namespace of provider names.** A Plugin or the program's own provider never takes a built-in's name or another's, and a declaration under a Plugin's or the program's own provider's name sets only `models`; either fails with `setting_invalid` where the connection is made or the scope opens.
- **The program's own provider** is ADR 0033's SDK-handler form of the Model provider kind, ADR 0012's model callback, in the form ADR 0104 gives every kind's SDK handler. TypeScript and Python register it on the connection, `connect({ modelProviders: { inhouse: handler } })` (`model_providers=` in Python, a coroutine function in the async client), as ADR 0092 registers `resolveSecret`. Rust declares its name when connecting, `ConnectOptions::model_provider("inhouse")`, and reads the calls as a stream, `gf.model_requests("inhouse")`, answering or failing each, as ADR 0092's `secret_requests`: a handler the SDK would call needs a task to run it, and Rust's async API spawns nothing (ADR 0081), while a name declared only when a stream opens would change the connection's providers after its scopes opened (ADR 0083's "no setters", G2). `gf.model_requests` returns a `Result`, as ADR 0104's `fetch_requests`: an undeclared name, or a second stream for a name whose stream is open, fails with `setting_invalid`, and a call waits for its stream until its own deadline. A Model reference then reaches it as `inhouse/<any model>`, from the Runs its own connection opened only, as ADR 0092 limits `resolveSecret`: on a Daemon, another Client's Run never reaches it, and two Clients may each name theirs `inhouse`.
- **What it sees and returns.** It receives Goodfetch's own `ModelRequest` (messages, tools and whether one must be called, the response format as JSON Schema, the maximum output tokens, the model ID and the Run asking) and returns a `ModelResponse`, a refusal included, whose input and output token counts are required, so a Limit counts every call (Stagehand leaves them optional); both types are exported, so no provider SDK is needed (G7), where Stagehand's TypeScript SDK left its callback's types to be retyped by hand. It gets the `prompt` strategy unless its models declare others under `ai.providers.<name>.models`, and it is priced like a declared provider: only configuration prices it, so under a currency Limit it needs a price. It runs where the program's own code runs (ADR 0081); the engine journals, counts and caps each call (ADR 0012), bounds it with `timeout.model` and cancels it with `$/cancel`: an async handler's task is cancelled, a sync Python handler's late answer is discarded, and a Rust call's `cancelled()` resolves. A `GoodfetchError` it raises keeps its code, so a `ModelUnavailableError` is retried as a provider's would be; any other exception, or in Rust any other error given to `fail`, is `model_handler_failed`, carrying its type and message as `handler_failed` does (ADR 0079). A Rust call dropped unanswered fails as an unreachable provider.
  > Amended by [ADR 0109](0109-a-rust-programs-own-code-returns-any-error-as-a-box-error-read-as-the-other-sdks-read-an-exception.md): a Rust call's `fail` takes a `BoxError`, as every function of the program returns its error, read by the outermost error.

### Capabilities and prices

- **Capabilities are declared, never inferred from a name.** A capability list ships with each release, covering the models ADR 0065 tests, and `ai.providers.<name>.models.<id>` declares or overrides a model's `context_window`, `max_output_tokens`, `image_input`, `tool_calls` and `strategies` (the structured output strategies it accepts, best first). Browser Use sniffs names and Midscene asks for a family; LiteLLM ships such a list, and OpenRouter and Ollama describe models through their APIs. Nothing is fetched at run time: the list is deterministic, works offline and is what the Scripted and Fake models test against (ADR 0065). A model the list does not know is text only with no tool calls, gets structured output from the top of the ladder below, and has no price. An operation that needs a capability the model lacks, such as image input, fails with `model_capability_missing`, whose fix names the key that declares it.
- **Prices come from the price table** (ADR 0012): each model's price per million tokens of each kind (input, cache read, cache write for each cache lifetime the provider sells, output), in a currency, shipped with each release and never fetched at run time (ADR 0043), unlike LiteLLM's and Browser Use's prices fetched from a URL. Configuration overrides one model's under `ai.providers.<name>.models.<id>.price`, whose fields area 9's spec names. Anthropic prices 5-minute and 1-hour cache writes at 1.25 and 2 times base input and reads at a tenth or less, so tokens alone are not a price.
- **Only configuration changes the price table:** a model's price, a metered proxy's and the fixed rates are set in user or project configuration and Operator policy, as ADR 0045 rules for the rates, and a Model provider Plugin's in its manifest under the operator's eye (ADR 0033). As ADR 0045 rules for the rates, no MCP tool, code-mode function, SDK method or `--json` CLI operation writes a price. A price set at the run layer or by a Recipe fails with `setting_locked`, and a project file sent to an Exposed Daemon has only the run layer's authority (ADR 0083). A price a Client could lower would let it escape a person's currency Limit (ADR 0041, G5). A capability, which only makes calls fail when wrong, may be declared at any layer.
- **Unpriced means unpriced.** The local built-ins at their default loopback addresses are priced zero. Every other model the table does not price is unpriced, a local built-in a program redirects included, so a proxy in front of a paid provider never counts as free: its price is reported `null`, and under a currency Limit its calls fail with `model_price_unknown`, whose fix names the configuration key that prices it (G1, G5). A priced model under a currency Limit in another currency is converted through the table's fixed rates (ADR 0045's, which now convert model prices too); with no rate between the two currencies its calls fail the same way, the fix naming the rate.
  > Amended by [ADR 0117](0117-what-coding-agents-misread-is-reshaped-an-ai-result-holds-its-answer-in-how-it-ended-resource-types-are-blocked-by-a-setting-and-a-start-names-its-run-id.md): a Run whose `ai.model` the table cannot price fails its start with `model_price_unknown` when a currency Limit applies, unless `plan.frozen`; a model given to one call is still refused at that call.

### Structured output

- **`ai.structured_output`:** `auto` (the default), `native`, `tool` or `prompt`. `auto` starts at the best strategy the capability list declares, or `native` for a model it does not know (`prompt` for the program's own provider), and steps down (native schema, a forced tool call, the schema in the prompt with JSON repair) when the provider rejects the strategy or a schema feature it uses, recording each step in the Run trace. It never steps down because an answer failed validation: that is ADR 0012's bounded retry, with the errors fed back.
- **The engine adapts the schema to each strategy's subset** (every field required and optional ones nullable for OpenAI's strict mode; the numeric and length constraints Anthropic's mode rejects left out) and **validates every answer against the program's own schema and validators** (ADR 0082), so a constraint a strategy dropped still holds. OpenAI, Anthropic, Gemini and llama.cpp each accept a different JSON Schema subset and spelling, which is why LiteLLM offers client-side validation (`enable_json_schema_validation`).
- **Failures name the model and the strategy:** `extraction_invalid`'s details (ADR 0091) carry the model and, from this ADR, the strategy; `model_output_invalid` is an `act`, `observe` or Agent step whose answer never parsed into what the step needed, with the model, the strategy, the attempts and the last problem. Stagehand's opaque "Invalid response schema" ([#689](https://github.com/browserbase/stagehand/issues/689)) is AI pain 8's example.

### Model provider failures

One code per remedy, as ADR 0080 kept one `deadline_exceeded`. Each names the Model reference, and the provider's status and request ID where one answered:

| Case | Code | Group |
|---|---|---|
| A call with no Plan entry needs a model and none is configured (ADR 0091) | `model_not_configured` | `ProgramError` |
| The provider says the model does not exist or is not available to this key | `model_not_found` | `ProgramError` |
| The operation needs a capability the model does not declare | `model_capability_missing` | `ProgramError` |
| The program's own provider raised an exception that is not a `GoodfetchError` | `model_handler_failed` | `ProgramError` |
| The provider rejected the request for another reason (a 400 or 422), such as a strategy `ai.structured_output` forces, or the last rung of `auto`'s ladder; the provider's message | `model_request_rejected` | `ProgramError` |
| The provider rejected the key (401, 403) | `model_unauthorized` | `RefusedError`, not retryable |
| The provider refused for its account's funds or a spend cap set at the provider: no credit left, an unpaid account, a used-up free tier, an organization's or workspace's spend limit, a tier's monthly cap (a 402, OpenAI's `insufficient_quota` sent as a 429, Anthropic's spend limits sent as a 400 or a 429) | `model_funds_exhausted` | `RefusedError`, not retryable |
| A currency Limit applies and the model's price cannot be stated in its currency: no price, or no fixed rate | `model_price_unknown` | `RefusedError` |
| Unreachable, a 5xx, or rate limited after the engine's retries; `reason` and `retryAfter` | `model_unavailable` | `UnavailableError`, retryable |
| The model declined to answer: a refusal or a content filter | `model_declined` | `ModelError` |
| The request does not fit the model's context window | `model_context_exceeded` | `ModelError` |
| An `act`, `observe` or Agent step's answer never parsed within the retries | `model_output_invalid` | `ModelError` |
| Every attempt of a model request outlasted `timeout.model`, within the engine's retries | `deadline_exceeded` (ADR 0080), `limit` naming `timeout.model` | `DeadlineExceededError` |

The engine classifies by the provider's error type and message, not by the status alone, since providers send a cap as a 400 or a 429. A rejected key and an empty account are not retried: the research's lesson is to fail fast on both (AI pain 8). `model_declined` avoids "refused", which names the `RefusedError` group, and `model_funds_exhausted` avoids "quota", a `GLOSSARY.md` _Avoid_ term of Limit.

> Amended by [ADR 0127](0127-a-failure-from-a-party-goodfetch-did-not-write-becomes-a-typed-error-in-one-module-per-boundary-and-no-other-code-reads-its-text.md): this classification happens once, in each Model provider adapter, its translation point; the provider's message stays a private field no other code reads.

> Note (agent decision, not read by the owner), 2026-11-23, [#3167](https://github.com/goodfetch/goodfetch/issues/3167): `model_unavailable`'s details are `ModelUnavailableDetails`: `reason`, an open set of `unreachable`, `server_error` and `rate_limited`, and `retry_after`, a duration in whole milliseconds on the wire, `null` when the provider asked for no wait. A duration, not a point in time as `blocked`'s `retry_after` is (ADR 0118): what the program does with it is wait, and a duration needs no clock shared with the engine. Each SDK's `ModelUnavailableError.retryAfter` reads it as its language's duration: milliseconds in TypeScript, a `timedelta` in Python, a `Duration` in Rust's details.

### A model request's own timeout

- **`timeout.model`, 60 s,** bounds one attempt of one model request, the program's own provider included. An attempt that outlasts it is retried as a transient failure, under ADR 0012's bounded retries; it nests inside the call that made it (ADR 0080), such as an AI verb's `timeout.ai` of 120 s (ADR 0091), so the retries share the enclosing time, and whichever ends first is the one `deadline_exceeded` names. openai-python waits 10 minutes by default and the AI SDK documents no default; ADR 0080 gives every phase a finite default (G6). A slow local model or a long reasoning answer raises both.

### Usage and its price

- **`ModelUsage` on every AI result:** `calls` (retries and Repairs included), `tokens` (input plus output, what `limits.modelTokens` counts), `inputTokens` with `cacheReadTokens` and `cacheWriteTokens` as parts of it, `outputTokens` with `reasoningTokens` as part of it, `price`, and `byModel`, the same counts and price per Model reference. Counts follow OpenTelemetry's GenAI conventions and the AI SDK, whatever the provider's (Anthropic's input count excludes its cached tokens, so its three counts are summed), so one program reads every provider alike (S2).
- **Where it is:** `StepResult.usage` (ADR 0091), the Agent's result ([The Agent in Collie's SDK API](https://github.com/goodfetch/goodfetch/issues/474)), and **every error raised by a call that made model calls**, as the error's `usage`, so a failed call's spend is never hidden (G1): Stagehand's `metrics()` skips "Calls that throw before returning a result", while the AI SDK's `NoObjectGeneratedError` keeps its usage. A step replayed from the Plan reports no call and a zero price.
- **Always on:** no switch, unlike Browser Use's `calculate_cost=True` (S2, G6).
- **The price is the price table's,** a list-price estimate and never a bill (ADR 0012): it is what a currency Limit reserves against, the same with the Fake model in tests, and needs no extra call. A charge the provider reports, such as OpenRouter's `usage.cost`, is kept in the Run trace beside it. Prices sum in the price table's currency (USD as shipped); an amount in another currency converts only through the table's fixed rates (ADR 0045). A price that would need a price or a rate the table lacks is `null`, with each priced part kept in `byModel`: never a partial sum labelled a total, as Pydantic AI's is (G1).

### A Run's totals and its Limits

- **`run.usage()`** returns a `RunUsage` while the Run is open, the figures the Usage ledger charges: `model` (a `ModelUsage`), `browserTime`, `proxyBytes`, `paidSolves`, `paidFetches`, `price` (of the Usage third parties charge for: model calls, metered proxies, paid solves and Paid fetches, `null` as above when any of it has no price or rate; browser time and an unmetered proxy carry none), `limits` (each Limit that applies to the Run, with its scope, kind, value, what remains of it and who set it, ADRs 0041 and 0045), and `uncapped`, ADR 0041's mark. The Run's report carries the final one, where [The Run in code](https://github.com/goodfetch/goodfetch/issues/478) (ADR 0102) places it. Every model call is in the Run trace with its Usage, model, strategy and price (G6).
  > Amended by [ADR 0107](0107-a-runs-model-allowance-refuses-its-model-calls-once-spent-while-the-run-goes-on.md): `RunUsage` also carries `modelAllowance`, one entry per kind of Model allowance set, with its `kind`, `value`, what remains, `reachedAt` and `source`; it is not an entry of `limits`, which lists what stops the Run.
- **Limits mirror Usage.** ADR 0080's price Limit is `limits.price`, a `Money` like `usage.price`; "cost" is a `GLOSSARY.md` _Avoid_ term of Usage. An applied Limit's period and scope ID are [The Run in code](https://github.com/goodfetch/goodfetch/issues/478)'s (ADR 0102) and area 3's.
- **Per Run, not per instance:** Stagehand's and Midscene's counters are per instance and would mix Runs (G2); a per-call usage callback, as Midscene's `onLLMUsage`, adds nothing a result does not carry.

### Golden scenario 08

Scenario 08 asks a crawl to "stop all model use once the crawl has spent a set amount", then finish without the model. Under ADRs 0041 and 0080, reaching the crawl's price Limit stops the whole crawl, `stopped` and `incomplete` with its Records kept, and a crawl cannot give its AI steps "a Run of their own" ([Crawl definition and handler context](https://github.com/goodfetch/goodfetch/issues/477) puts no Collie Run inside a crawl). That is the condition under which ADR 0080 sends a narrower cap back to the map, so the question is [Capping a crawl's model use without stopping its Run](https://github.com/goodfetch/goodfetch/issues/513)'s, which amends ADRs 0041 and 0080 if it must. Until then the price Limit stops the crawl, and `RunUsage` shows what it spent.
> Amended by [ADR 0107](0107-a-runs-model-allowance-refuses-its-model-calls-once-spent-while-the-run-goes-on.md): answered: the crawl sets a Model allowance, `ai.allowance.price`, which refuses its model calls once spent while the crawl goes on; steps its Plan learned keep replaying, and the requests a refusal ends are `skipped` with the reason `model_allowance`.

## Considered Options

- **Provider objects in each language** (the AI SDK's `openai('…')`, Browser Use's `ChatOpenAI`): rejected. A type per provider in each SDK, impossible to write in a configuration file, and Browser Use's list broke with each provider change (S1, S2).
- **`provider:model` with a colon** (Pydantic AI): rejected. The gateways, LiteLLM and Stagehand use a slash (S3, T).
- **A model object holding its key** (Stagehand's `{ modelName, apiKey, headers }`): rejected. It mixes a credential into a model choice, and its shape changed in every major.
- **A fallback list of models:** rejected by G1 and G2; a Plan would not say which model compiled a step.
- **Name sniffing or a mandatory model family:** rejected. Wrong for every renamed, fine-tuned or local model.
- **Asking the provider for capabilities and prices at run time** (OpenRouter's models API, the Gateway's `getAvailableModels`, Ollama's `/api/show`): rejected. One more call per model and per scope, values that change under a running program, a different format per provider, and a gateway's prices describe only that gateway.
- **Fetching prices from a URL** (LiteLLM, Browser Use): rejected. An unconfigured call (ADR 0043), and prices that change between two runs of one program.
- **Prices set at any layer:** rejected by G5. A Client would lower the price a person's currency Limit is held to.
- **Treating an unpriced model as free:** rejected by G1 and G5. A proxy in front of a paid provider would escape every currency Limit.
- **The provider's reported charge as the price:** rejected. Few providers report one in the answer (the Gateway needs a second call), and it cannot be known before the call a Limit must reserve for.
- **Model provider keys as Secret placeholders bound under `secrets.*`:** rejected. ADR 0092 gives credentials the engine uses itself a Secret reference directly.
- **A usage callback, a per-instance counter, or usage only on request:** rejected above (G2, S2, G6).
- **Stepping down the strategy ladder on an invalid answer:** rejected. It would hide a model that cannot follow a schema behind a weaker strategy; the retry with the errors fed back is ADR 0012's answer.

## Consequences

- **Amends ADR 0012.** The price table is changed only in configuration (a Model provider Plugin's prices in its manifest, ADR 0033), and a model the price table does not price, or cannot convert, is refused under a currency Limit with `model_price_unknown`; the table's fixed rates convert model prices too, not only Paid fetches; capabilities are a declared list shipped with each release, never inferred from a name; `ai.structured_output` steps down the strategy ladder only when a provider rejects a strategy. Notes sit under its price table, its rates and its JSON repair.
- **Amends ADR 0028.** The price table's prices (`ai.providers.<name>.models.<id>.price` among them) join the settings set only in Operator policy or user and project configuration, a note under that list; a Recipe never sets a Model provider's `api_key`, `headers` or `base_url`, and a Client acting for a model never does either, a note under its layer 4.
- **Amends ADR 0079.** An error raised by a call that made model calls carries `usage`. A note sits under its fields.
- **Amends ADR 0080.** `timeout.model`, 60 s, joins the phases. A note sits under its phase list.
- **Amends ADR 0083.** `timeout.model` joins the timeout family, and the keys `ai.model`, `ai.providers.<name>` and `ai.structured_output` join the schema; a Recipe and a Client acting for a model never set a provider's `api_key`, `headers` or `base_url`. A note sits under its timeout family.
- **Adds to ADR 0033.** The SDK-handler form of the Model provider kind is registered with `connect({ modelProviders })` in TypeScript and Python, and declared with `ConnectOptions::model_provider(name)` and read with `gf.model_requests(name)` in Rust, for the Runs its connection opened; a Model provider Plugin is named in a Model reference by its declared provider name, and its manifest prices its models; provider names form one namespace.
- **Adds to ADR 0041.** A program reads, through `run.usage()`, what remains of each Limit that applies to its Run, beside the Console and `goodfetch usage`.
  > Amended by [ADR 0137](0137-the-console-leaves-both-products-and-the-engine-and-the-owners-monitoring-tool-is-designed-apart.md): no Product carries a Console. The engine behaviour this ADR describes stands and the Console's part does not; a Client reaches it.
- **Adds to ADR 0091.** `StepResult.usage` is a `ModelUsage`, the `model` argument a Model reference, and `extraction_invalid`'s details gain the strategy.
- **Error codes.** `model_not_found`, `model_capability_missing`, `model_handler_failed` and `model_request_rejected` join `goodfetch-protocol` in the `program` group; `model_unauthorized`, `model_funds_exhausted` and `model_price_unknown` in the `refused` group; `model_unavailable` in the `unavailable` group; `model_declined`, `model_context_exceeded` and `model_output_invalid` in the `model` group, through `xtask codegen`'s naming checks (ADR 0079).
- **`GLOSSARY.md`** gains **Model reference** and **Price table**.
