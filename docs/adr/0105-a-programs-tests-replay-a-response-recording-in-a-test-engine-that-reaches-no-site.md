# A program's tests replay a Response recording in a test engine that reaches no site

A program written against the SDK API is tested offline with the testing kit each SDK already ships (ADR 0069). A Run's start may name a **Response recording**, a WARC file the program keeps: replayed, it answers every request the Run would send to a site, and refuses with a typed error naming the address any request it lacks; recorded, it receives what a live Run fetched. The kit's test engine replays an empty recording for every Run that names none, so a test reaches no site unless it records. `runHandler` runs one crawl handler on one saved page and returns how its attempt ended and what it staged; a Plan replays frozen with no model; the kit fits any test runner. The research ranks "testable callbacks and offline replay of saved responses" seventh among what users like, from Scrapy's users ("very well structured, testable, and has solved every problem"), while Crawlee has no testing harness at all, and Playwright users meet its test runner in 21% of their questions (the [synthesis](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/2026-10-14-consumer-api.md)'s seventh like and question 17; [crawl frameworks](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/crawl-frameworks.md) §2.1, §2.3, §5 L2; [browser drivers](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/browser-drivers.md) P10). Decided in [Testing a user's crawl or automation](https://github.com/goodfetch/goodfetch/issues/482), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461), every answer by the agent on the owner's delegation ([grilling record](https://github.com/goodfetch/goodfetch/issues/482#issuecomment-6187615006), [round 4 after the first review](https://github.com/goodfetch/goodfetch/issues/482#issuecomment-6188182789), [round 5 on the hand-offs of ADRs merged since](https://github.com/goodfetch/goodfetch/issues/482#issuecomment-6189719031), [round 6 after the second review](https://github.com/goodfetch/goodfetch/issues/482#issuecomment-6189923794), [round 7 after the third review](https://github.com/goodfetch/goodfetch/issues/482#issuecomment-6190120573)). It builds on ADRs 0069, 0091 (Plans), 0093 (crawl handlers) and 0100 (the Agent), under ADR 0090's names. Principles are cited by their IDs in [ADR 0077](0077-the-sdk-api-follows-eight-guarantees-and-four-ranked-shape-rules.md).

What the leaders do, read at tagged sources on 2026-10-15:
- **Scrapy 2.19.0** tests a callback by building `HtmlResponse(url, body=saved)` and calling it; its contracts (`@url`, `@returns`, `@scrapes`) run under `scrapy check` against the live URL. Its HTTP cache never expires by default, and with `HTTPCACHE_IGNORE_MISSING` a miss is dropped with a counted `IgnoreRequest` while the crawl goes on. web-poet runs saved page-object fixtures through its own pytest plugin.
- **Playwright 1.64.1** replays a HAR per page or context with `routeFromHAR`, matching URL, method and POST body strictly; a request the HAR lacks is aborted, or with `notFound: 'fallback'` sent to the network. `page.clock` and `routeWebSocket` replace the page's own `Date`, timers and `WebSocket` with injected scripts.
- **VCR libraries:** vcrpy 8.3.0's default mode `once` records whenever its cassette is missing, so a CI run without one goes live; pytest-recording 0.14.0 defaults to `none`, and its `--block-network` raises `RuntimeError: Network is disabled` without the address.
- **Testing AI code:** Pydantic AI 2.56.0 swaps in `TestModel` and blocks real model requests with a process-wide `ALLOW_MODEL_REQUESTS = False`; Stagehand's evaluations are a private package of its own, not a user's kit.
- **A test context for one unit:** Temporal's `ActivityEnvironment.run(fn, *args)` (Python 1.34.0) and `MockActivityEnvironment` (TypeScript 1.24.0) run one activity with a test context and expose its heartbeats to the test.
- **Values a program cannot build:** the AWS SDK for Rust gives each `#[non_exhaustive]` output a builder, and its mocks (`aws-smithy-mocks` 0.3.0) need the client's `test-util` feature.
- **Faithful replay:** Webrecorder's replay (wombat 3.10.8) starts a replayed page's `Date` at the capture time and seeds `Math.random`.

## Decision

### Where replay lives

- **The engine replays; each SDK's testing kit sets it up** (S2, S1). A Run's requests are sent by the engine, not the program, so there is nothing for an SDK to patch, and a browser's subresources never pass through the SDK. One implementation serves every SDK, the CLI and every fetch tier, the browser through the interception that already serves the Response cache (ADR 0046). Patching recorders is where replay breaks (ADR 0065).

### Response recordings

- **A Run's start takes `recording`**: `collie.start({ recording })` and `foxhound.startCrawl(crawl, { seeds, recording })`, with `recording: { mode: "replay" | "record", path }`; Python `recording=Recording(mode=..., path=...)`, Rust `.recording(Recording::replay(path))` or `Recording::record(path)`. The path is a WARC 1.1 file (ISO 28500:2017) on the program's machine, relative to the working directory.
- **An input of the Run, like `plan`** (ADR 0091), never a setting, so no project file, Recipe or environment can make a production Run replay (G2, G5). The SDK reads and writes the file on the program's machine, as it does a Plan file, so a Daemon or Goodfetch Cloud works the same (ADR 0001). A resume names the same recording, as it names the same Plan file ([The Run in code](https://github.com/goodfetch/goodfetch/issues/478)).
- **Replay answers every request the Run would send to an address a page can reach** (ADR 0017's first class): crawl requests, navigations, browser subresources through the engine's interception, `page.request`, discovered-API calls and robots.txt. Nothing is sent.
  - **Matching** is ADR 0046's `replay` key without its partitions: the method, the URL without its fragment, the hash of the canonical body, and the request headers the response names in `Vary`, except the credential headers a recording never keeps. The body hash is taken after Secret values are masked, when recording and when replaying, so a login form replays. A key recorded several times is answered in recorded order, then by its last response.
  - **A host the `resolve` setting maps to a loopback address** (ADR 0059), such as a test's own server, is reached as usual, once the Run allowlists loopback for tests (ADR 0017). Every other address, a private one included, is answered from the recording. The choice is made on the host name, before any lookup, so a replayed or missing request makes no DNS query.
  - **A route that fulfils a request answers before the recording**, as routes run before the network (ADR 0085).
  - **Endpoints the operator configures** (Sinks, webhooks, Model providers) are not pages' requests and are not replayed. Model calls are never recorded: a Plan replayed frozen, or the Scripted model, stands in for the model.
- **A request the recording lacks is refused, never sent** (G1, G5, G6):
  - a call the program made (`goto`, `page.request`, an AI verb's navigation) raises `response_not_recorded`, a `RefusedError`, not retryable, whose details carry the method, the URL, the recording and the recorded URLs nearest it (same host and path), and whose `fix` says to record again or to answer the request with a route;
  - a crawl request ends `failed` with that error, not retried;
  - a subresource no call awaits fails in its page as a network error, as Playwright's abort does;
  - the Run report lists every miss of the three kinds. A URL a page builds from the time, such as a cache-buster, misses on every replay; its nearest recorded URL shows why, and a route answers it.
- **`mode: "record"`** fetches as usual and, when the Run ends, whatever its outcome, replaces the file atomically with every response it received from ADR 0017's first class, subresources and robots.txt included, after a `warcinfo` record naming the engine and the Run. The responses are kept in the Run's state until then, so a resumed Run writes them all.
  > Amended by [ADR 0116](0116-a-saved-file-is-written-whole-or-not-at-all-and-a-failed-write-says-whether-its-path-or-its-storage-failed.md): a write of the recording that fails raises `path_not_writable` (a `ProgramError`) when the path cannot be written, or `file_write_failed` (an `UnavailableError`, side `program`) when its storage is full or fails, neither retryable, from the call that ends the Run, once the Run has ended (ADR 0102's note); the file is left as it was.
  > Amended by [ADR 0118](0118-every-fetch-tier-follows-redirects-as-the-browser-does-fails-a-cut-body-and-resends-only-what-a-site-never-processed.md): a response whose body was cut is recorded with `WARC-Truncated: disconnect`, and replaying it raises `response_truncated`, as the live fetch did.
  - **No credential is kept.** Secret values are masked, as everywhere the engine keeps data (ADRs 0014, 0092); the request headers `Cookie`, `Authorization` and `Proxy-Authorization` are dropped, and `Set-Cookie` values are masked. A logged-in page's content is the program's own data, which it chose to record.
  - **Only on request.** There is no "record when missing" (vcrpy's `once`), so a CI run without its file never goes live (G5), and no appending, so a file holds one capture with one age.
- **Foxhound's WARC output (CO-30) writes the same records**, so a crawl archived as WARC replays as a recording (P55). Its keys stay area 6's (ADR 0103).
- **The Response cache keeps its role.** `cache.mode: "replay"` stays the development loop (ADRs 0046, 0088): per user, partitioned, expiring, and fetching on a miss. A test needs a file it commits, that answers exactly and never reaches a site.
- **Schedules and Watches take none.** A Schedule names no Response recording (ADR 0036): replayed pages would hide every change from its Baseline, and a scheduled run has no program whose machine holds the file. A scheduled run that keeps its responses uses Foxhound's WARC output.

### What replay changes in a Run

- **Politeness.** A request the recording answers reaches no site, so it waits for no Politeness slot, delay or backoff (ADR 0086). Handler concurrency still applies.
- **robots.txt** is read from the recording alone, so a replay skips what the live Run skipped; a replaying Run neither reads nor writes the copy ADR 0086 shares across a user's runs. A robots.txt the recording lacks is a listed miss and reads as no rules, since nothing reaches the site.
- **Time and randomness.** A replayed browser page's `Date` starts at the time its document was recorded, or at the `Date` header of a document a test gives itself, and runs on; its `Math.random` is seeded from the recording, as Webrecorder's replay does, so a page that renders "today" or picks a random variant renders as recorded.
- **The Run report** carries `recording`: the mode, the file, the responses used, when they were first fetched (`recordedFrom`, `recordedTo`), the engine that wrote them, and every miss. A Run that replayed is marked so in its report, in the Console and in the CLI, as ADR 0046 marks a cached one. The recording's age is reported, never a failure: a test fails only on its own inputs, and refreshing is a `record` Run whose diff is reviewed like any committed test file's.
  > Amended by [ADR 0137](0137-the-console-leaves-both-products-and-the-engine-and-the-owners-monitoring-tool-is-designed-apart.md): no Product carries a Console. The engine behaviour this ADR describes stands and the Console's part does not; a Client reaches it.
- **Provenance** marks a Record built from a recording, with the time its page was recorded; **Usage** counts replayed responses apart from fetches (ADR 0046's rules for a cache hit).

### The testing kit

The kit is ADR 0069's, one per Product (ADRs 0090, 0095); crawl handlers and Hooks are Foxhound's (ADR 0084).

- **`TestEngine`, ADR 0069's test engine helper as a value** (G2, S2): `await using engine = await TestEngine.start(options)`, `async with AsyncTestEngine.start(...)` and `TestEngine` in Python's sync API, `TestEngine::start(options).await?` in Rust. `engine.connection` is a connection of its Product's own type (`Collie` or `Foxhound`, ADR 0090), so everything a program does works on it. Python's `TestEngine` carries `__test__ = False`, as Starlette's `TestClient` does, so pytest never collects it.
  > Amended by [ADR 0106](0106-a-program-declares-an-effect-as-a-keyed-block-whose-output-the-effect-journal-keeps-judged-by-what-the-engine-sent.md): the test engine also has `reconcile(runId, key, answer)`, standing for a person's answer about an uncertain Effect (ADR 0029), in the testing kit only.
  - **No request reaches a site unless a Run records.** Every Run started from it that names no Response recording replays an empty one, so any request to a site raises `response_not_recorded`, naming its address. A Run that names `record` reaches the site, because the test said so. Endpoints a test configures itself, such as a Sink or a Model provider, are its own choice; with nothing configured there are none.
  - **Its isolations:** ADR 0069's temporary home, removed when it closes, cleared environment, `offline` and short durations, and now no project file unless the test names one (`project`), so a project's `ai.model` or Sinks never reach a test unasked. ADR 0083's rule, found upward from the working directory, stays `connect()`'s: a test isolates its project file as it isolates its home and environment.
  - **The `resolve` setting** (ADR 0059), set in its `settings`: every host it maps to loopback is allowlisted for the engine's Runs (ADR 0017) and reached live, for a test's own server or app.
  - **What it runs on.** It finds browsers, and in Rust its Product's executable (`goodfetch-collie` or `goodfetch-foxhound`, ADR 0090), where the user's other engines do: in the browser cache of the caller's Goodfetch home (ADRs 0024, 0059), the one `GOODFETCH_HOME` names or else the operating system's usual folders, read and never written, while everything the engine keeps goes to its temporary home; or through `GOODFETCH_BROWSERS_PATH` and its Product's engine-path variable (`GOODFETCH_COLLIE_ENGINE_PATH` or `GOODFETCH_FOXHOUND_ENGINE_PATH`). It reads these three, and no other, from `connect()`'s environment map (ADRs 0062, 0083), which its `env` option replaces and which defaults to the process's own, so a test of a custom home passes a map instead of patching the environment; the engine's own environment stays cleared. With none installed, `offline` makes the first browser fail with `artifact_unavailable_offline`, whose fix names its executable's `browsers install`, the CI step ADR 0024 names.
  - **No model unless the test sets one.** With nothing configured, a call that needs a model raises `model_not_configured` (ADR 0091) before any request. Pydantic AI's process-wide flag is hidden state (G2); here the engine the test holds is what refuses.
  - An Attached engine in TypeScript and Python, the engine linked in-process in Rust (ADR 0069).
- **`engine.runHandler(crawl, label, input)` runs one handler** (G1, G6, S3, T): the handler the crawl attached to the Label, as it is wired, with the Label's settings, in a Run of its own, with the scope a crawl seeded at the input's URL would have. Nothing else runs: no Frontier, no Hooks, no commit, and one attempt with no retry.
  - **Input:** `url`; `payload`, typed by the Label and required when it has one; `response`, the document, given as `route.fulfill` gives one (`status`, `headers`, `contentType`, `body`) or read from a saved file (`path`); `recording`, a path replayed for anything else the handler reaches, and for the document when `response` is left out; `tier`; `attempt` and `depth`.
    > Amended by [ADR 0106](0106-a-program-declares-an-effect-as-a-keyed-block-whose-output-the-effect-journal-keeps-judged-by-what-the-engine-sent.md): the input also takes `effects`, the Effect journal's prior answers by Effect key (`journal` with an output, `reconciled`, or `uncertain` with its reason), and the `AttemptResult` lists the attempt's declared Effects; a command a recording answers counts as sent.
  - **The document is not fetched,** so neither robots.txt nor Politeness applies to it. ADR 0093's status rules do: a status that is a Block cause ends the attempt `blocked` with its cause, a 5xx or a 408 ends it `failed` with `response_unavailable`, and another 4xx that `crawl.handle_statuses` does not list ends it `failed` with `response_not_ok`, all before the handler runs.
  - **The tier:** `http` by default, or the tier the Label's `fetch.tier` forces, as a crawl would fetch it; a `tier` other than a forced one throws `setting_invalid` naming `fetch.tier`. No browser starts on a non-browser tier. A call only a browser serves ends the attempt `escalated`, naming the call, under `fetch.tier: auto`, and fails it with `browser_required` under a forced tier, as in a crawl (ADR 0093). `tier: "browser"` renders the document in the browser.
  - **It returns an `AttemptResult`:** `ended`, which is `returned`, `skipped` with its reason and message, `retry_requested`, `escalated` with the call rendered as the program wrote it (ADR 0079), `blocked` with its Block cause, or `failed` with its `GoodfetchError` (`handler_failed` for the handler's own exception, or the code an error kept); and everything the attempt staged, kept even when it ended early, where a crawl would discard it: `records(dataset)`, each Record `ctx.push` staged as its Dataset's schema parses it, the value `run.records()` would read back (ADR 0103), with no commit number since nothing commits and no "Record before commit" Hook applied since no Hook runs; enqueues and seeds with the answers they got, Key-value store writes, and model Usage.
  - **It throws only when it cannot run the handler:** `response_not_recorded` for the document, `payload_invalid`, `label_unknown`, `label_unhandled`, `setting_invalid` for the tier. Once the attempt started, how it ended is a value, as a crawl request's outcome is (ADR 0079).
  - **One attempt as a crawl runs it** (ADR 0093's crawl conformance cases): `skip` and `retry` end it even when the handler swallowed them, and a later call on its context fails with `attempt_ended` while `ended` keeps what ended it; a handler's own exception ends it `failed` with `handler_failed`, carrying the exception's type, message and stack, and a retryable `GoodfetchError` keeps its code; two enqueues of one URL with two POST bodies stage two requests and the same body twice is answered `duplicate`; an `enqueueLinks` Payload function's Payloads are staged, and a link it returns `null` for is reported not added as `skipped_by_payload`; a link outside the scope or past `crawl.max_depth` is answered "not added" with its reason. What spans attempts or a whole crawl (Label checks at definition and start, retries against `crawl.retry.max`, `handler_lost`, an escalation's run in the browser, sitemap seeds) is tested by starting the crawl on a recording.
    > Amended by [ADR 0109](0109-a-rust-programs-own-code-returns-any-error-as-a-box-error-read-as-the-other-sdks-read-an-exception.md): in Rust the handler's own error is any error it returns as a `BoxError`, and `handler_failed` carries the type name `BoxError` (or `panic`), the error's `Display` followed by each `source()`, and no stack.
  - Building a `CrawlContext` for the test to call the handler itself was rejected: every test would decode `skip`, `retry` and an escalation by hand, and inline handlers, every snippet's idiom, could not be reached. A context faked in each SDK without an engine would reimplement Collie's page three times (ADR 0069 rejected hand-written fakes).
- **`engine.runHook(crawl, name, input)` runs one Hook** (S1, S2, G3): one of the crawl's Hooks, by the name Hooks carry, alone, its stage's context built from the input as `runHandler` builds a handler's: the `request` every context carries (ADR 0104: id, URL, Label, typed Payload, depth, attempt), with what its stage adds, the tier, method, body, headers and `previousError` before a request, the final `response` after one, Collie's page on the document for the page stages, and the `dataset` and `record` before a Record's commit. The input names them: `label`, one the Hook is scoped to, `url`, `payload`, `attempt` (1 by default) and `depth` (0) for the request; `method` (`GET`), `body`, `headers`, `tier` (as `runHandler`'s) and `previousError` (none, a first attempt) before a request; `response` after one, which also gives the page stages their document; `dataset` and `record` before a commit; and `recording`, replayed for anything else the Hook reaches. It returns what the Hook answered (its change, or nothing), the call that ended the work (`skip`, `block` with its cause, `retry`, `drop` or `reject`, with its message or reason), or its failure as `hook_failed`. A call on the context after the Hook returned fails with `attempt_ended`, and a page stage follows the handler's tier rule above. A name the crawl does not hold raises `hook_unknown`, naming the closest.
- **AI in tests** (G5, G1, S2):
  - **A Plan replays frozen.** A test starts its Run with `plan` and `plan.frozen: true` (ADR 0091): a step the Plan holds replays with no model call, and one it lacks raises `plan_step_missing` instead of calling a model. With a recording, an AI extraction runs with no network and no model.
  - **An Agent's task replays from its Plan entry** (ADR 0100) the same way: under `plan.frozen` a replayed task makes no model call and ends `finished` with `reported` absent, a Drift raises `plan_drift` and a missing entry `plan_step_missing`, and a Success check that fails after the replay ends the task `rejected`. With a recording, a test of an Agent's task needs neither the site nor a model.
  - **The Scripted model** (ADR 0069) is a Model provider the test registers in its SDK-handler form: `modelProviders: { scripted: scriptedModel(replies) }` with `ai.model: "scripted/any"`. In Rust, `TestOptions::model_provider` registers it, and the kit answers its `model_requests` stream (ADR 0101) on the connection's own runtime, never on the program's executor (ADR 0081), so every SDK's handler path is the one tested. Each reply is a `ModelResponse` or a provider error built with `fakeError`; a retryable error is retried as a provider's would be (ADR 0101), each retry taking the next reply. It records every request; a call beyond its replies raises `scripted_model_exhausted`, and closing the test engine raises `scripted_model_unused` while a reply is left. It suits model-mode extraction, Agent turns and provider failures; a compiled step's reply follows the engine's own request, so compiled steps are tested by replaying their Plan.
    > Amended by [ADR 0117](0117-what-coding-agents-misread-is-reshaped-an-ai-result-holds-its-answer-in-how-it-ended-resource-types-are-blocked-by-a-setting-and-a-start-names-its-run-id.md): its replies also take `scriptedExtraction(data)` (`scripted_extraction` in Python, `ScriptedReply::Extraction` in Rust), which answers one `extract` call in its mode: under `model` with `data`, under `compiled` with the locators that read `data` from the page, which the kit writes by finding each value there. A value not on the page leaves its field to `extraction_incomplete`, so a compiled step is tested without a Plan too.
    > Amended by [ADR 0123](0123-a-typed-value-read-from-page-text-comes-from-an-engine-transform-under-a-stated-locale-and-time-zone.md): `scriptedExtraction(data)` answers in the model's answer form, each value as the page text and the Value transform that give it under `model`, and as the locators and the transform that read it under `compiled`; a relative time read from a Response recording is anchored at the recorded fetch time.
  - **Not offered to programs:** the Fake model, which answers from Proving ground tasks, and Model recordings, which test Goodfetch's adapters (ADR 0065); a program's Plan already holds what its model decided. No model judges a Success check either (ADR 0013).
  - **Records a test asserts** (ADR 0103): a Record that fails its schema raises `record_invalid` from `push` and is not staged, and escaping it ends the attempt `failed` with that code; a push to another crawl's Dataset raises `dataset_unknown`. A Record's committed form (its number, request ID and URL) and what Hooks drop or reject are tested by starting the crawl on a recording and reading `run.records()` and `run.rejectedRecords()`.
- **Any test runner** (S1, S2, G4, T; P31): the kit's values close with `await using`, `async with`, `with` or `close()`, so Vitest, Jest, `node:test`, pytest with AnyIO's plugin, `unittest` and `cargo test` run them alike. Failures are `GoodfetchError`s and assertions are the runner's own; `expect` stays the Success check (ADR 0091), whose failure is `success_check_failed`, never the runner's assertion error, imported under another name where a runner's `expect` is in scope. There is no runner plugin: a pytest fixture that yields a started engine is three lines, which the testing guide shows.
- **Values for a program's own unit tests** (G7, S1): results are plain interfaces in TypeScript, which a test writes as literals, and generated models in Python (ADRs 0038, 0082), which a test builds with their constructors. `fakeError(PlanDriftError, { message, details })` (`fake_error` in Python) returns an instance of that class with its group, retryable flag and typed details. In Rust, `Error::fake(code, message)` and a `fake` constructor on each `#[non_exhaustive]` result type, such as `CrawlRequestOutcome::fake` and `StepResult::fake`, sit behind `test-util`, since a struct literal cannot build them outside the crate.

### Not in the SDK API

ADR 0085 handed `page.clock`, `routeFromHAR` and `routeWebSocket` to this decision, and ADR 0091 handed `toHaveScreenshot`. None is added (S2, G5, G8):
- **`page.clock`:** a replayed page's time is already fixed. On a live site, replacing the page's `Date` and timers with an injected script is a change the site can detect (ADR 0035) and alters what it serves; Collie's users test their programs, not the sites they automate. `addInitScript` stays the way down.
- **`routeFromHAR`:** a Response recording covers every page, popup, tier and robots.txt of a Run, where a HAR covers one page or context. One mocked response is `route.fulfill` (ADR 0085).
- **`routeWebSocket`:** it replaces the page's `WebSocket` with an injected script, detectable on a live site, to mock one's own backend. The `websocket` events observe sockets (ADR 0085), and a WebSocket a replayed page opens is a recorded miss.
- **`toHaveScreenshot`:** visual comparison is a test runner's matcher, whose references repeat only in one pinned renderer, as `TESTING.md` requires for Goodfetch's own. `screenshot()` returns bytes (ADR 0085) for the runner's comparison, and a replayed page renders the same each time.

### Error codes

| Case | Code | Group |
|---|---|---|
| A replaying Run's recording lacks a request the program made; nothing was sent | `response_not_recorded` | `RefusedError` |
| The recording cannot be read, is not WARC, or is a WARC version the engine does not read (ADR 0030) | `recording_invalid` | `ProgramError` |
| A call went beyond a Scripted model's replies | `scripted_model_exhausted` | `ProgramError` |
| The test engine closed with a Scripted model's replies unused | `scripted_model_unused` | `ProgramError` |

## Considered Options

- **The SDK patching or faking the network** (vcrpy, nock, respx): rejected. The engine sends the requests, a browser's subresources never pass through the SDK, and three SDKs would each fake it differently. **Contracts run by a command** (`scrapy check`): rejected; tests belong in the program's own runner, and contracts fetch the live site.
- **The Response cache's `replay` mode as the test store** (Scrapy's cache, Scrapling's `development_mode`): rejected. It is per user and per machine, partitioned, expiring and discarded with its run, so a test cannot commit it, and a miss is fetched.
- **HAR through `routeFromHAR`:** rejected. Per page or context, outside a crawl's HTTP tiers and robots.txt; JSON with base64 bodies and no standard. **A recording format of Goodfetch's own:** rejected; WARC already records what a Run fetched, in both tiers.
- **The recording as a setting:** rejected. A project file, a Recipe or an Operator policy could then make a production Run replay stale pages without its code saying so.
- **Fetching a missing response, or dropping it silently** (a cache; Scrapy's `HTTPCACHE_IGNORE_MISSING`): rejected by G1 and G5. **Recording when the file is missing** (vcrpy's `once`): rejected; a CI run without its file would go live. **Appending missing responses** (`new_episodes`): rejected; one file would hold captures of different ages.
- **Reaching every address ADR 0017's allowlist admits while replaying:** rejected. An intranet a Run allowlists would be reached live; only a loopback host the test maps with `resolve` is.
- **Failing a test once its recording is older than a set age:** rejected. A test would fail as time passes with no change of its inputs; the age is reported, and refreshing is a reviewed `record` Run.
- **A process-wide "no network" or "no model" switch** (pytest-recording's `--block-network`, Pydantic AI's `ALLOW_MODEL_REQUESTS`): rejected by G2. The test engine the test holds refuses, and names the address.
- **A `CrawlContext` the test builds and calls the handler with,** or **a context faked in each SDK without an engine:** rejected above.
- **Answering Rust's Scripted model inside the linked engine:** rejected. The kit would then bypass the SDK-handler path that ADR 0069 has Goodfetch's own SDK suites test through it.
- **Per-runner plugins and fixtures** (web-poet's pytest plugin, Playwright Test's fixtures): rejected by S2 and P31. The kit's values work in any runner.
  > Note, 2026-11-11 (the owner, grilling of decision G-19 of the consolidated review, Q11: « Yes to all », on option (a) as put, after being told that this ADR names none of these parts; the owner did not read this note's wording): the test runner and every part of it are refused, each on its own row of ADR 0037's matrix with the reason "Goodfetch works inside the program's own runner, which already provides this": reporters, splitting a suite across machines, watch and UI mode, a dev server's start, component tests and test-writing agents (rows SDK-26 to SDK-31). It is a new decision for those parts, on the reason of lines 82, 105 and 115.
- **Model recordings or the Fake model for programs:** rejected. A Plan replays what the model decided with no call at all; the Fake model answers Proving ground tasks only.
- **`page.clock`, `routeFromHAR`, `routeWebSocket` and `toHaveScreenshot`:** rejected above.

## Consequences

- **Amends ADR 0069.** The testing kit's test engine helper is the value `TestEngine`, with `connection`, `runHandler` and `runHook`. It replays an empty recording for every Run that names none, so no request reaches a site unless a Run records; it reads no project file unless the test names one; the hosts its `resolve` setting maps to loopback are allowlisted; it finds browsers and its Product's executable where the user's other engines do, reading the caller's browser cache without writing to it. Its Scripted model raises `scripted_model_exhausted` and `scripted_model_unused`, and in Rust the kit answers it through the SDK-handler stream on the connection's runtime. The kit also holds `fakeError`, and in Rust a `fake` constructor on each `#[non_exhaustive]` result type beside `Error::fake`.
- **Amends ADR 0046.** The cache's `replay` mode stays the development loop; a program's tests replay a Response recording, which its Run's start names, instead.
