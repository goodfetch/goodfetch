# A Run's Model allowance refuses its model calls once spent, while the Run goes on

A program can cap a Run's model use without stopping the Run: a **Model allowance**, the setting family `ai.allowance.*`, is the most model Usage (a price, tokens or calls) the Run may spend. Each model call reserves its worst case against it, and once a call does not fit, every later model call of the Run is refused with `model_allowance_reached` while the Run goes on: steps its Plan already knows keep replaying with no model call, an Agent's task ends as a value, and a crawl request whose handler lets the refusal escape ends `skipped` with the reason `model_allowance`. It is not a Limit: the Limits of ADR 0041 still stop the Run and still only a person raises them, while the allowance is part of the program's own task, held in the Run's state (a Partitioned crawl's by its Lead Daemon) and set at any layer. Golden scenario 08 asks a crawl to "stop all model use once the crawl has spent a set amount (for example 0.50 USD), let the crawl finish without the model, and report which books were left unextracted and why"; under ADRs 0041 and 0080 a Limit reached stops the whole crawl, and a crawl has no Collie Run of its own for its AI steps ([ADR 0093](0093-a-crawl-declares-its-labels-and-one-handler-each-and-a-handler-reads-collies-page-on-every-fetch-tier.md)), the condition under which ADR 0080 sent the question back to the map. The gateways refuse calls past a cap and leave the caller running: LiteLLM's proxy fails a key's requests once it "crosses it's `max_budget`" with `budget_exceeded` ([budgets](https://docs.litellm.ai/docs/proxy/users)), the Vercel AI Gateway rejects a project's or key's requests with a 402 `quota_for_entity_exceeded` ([budgets](https://vercel.com/docs/ai-gateway/observability-and-spend/budgets)), and OpenRouter rejects a request past a key's `limit` with a 403 ([errors](https://openrouter.ai/docs/api-reference/errors)); only Apify, which charges per run, aborts the run at its maximum charge ([pay per event](https://docs.apify.com/platform/actors/publishing/monetize/pay-per-event)). Crawlee's `maxRequestsPerCrawl` and Scrapy's `CLOSESPIDER_*` stop the crawl, and neither caps model spend (checked 2026-10-15). It answers the scenario-08 part of pain row P42 and AI pain 13 ([AI browser automation](https://github.com/goodfetch/goodfetch/blob/research/consumer-api/rnd/research/research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md)). Decided in [Capping a crawl's model use without stopping its Run](https://github.com/goodfetch/goodfetch/issues/513), on the map [The SDK API of Collie and Foxhound](https://github.com/goodfetch/goodfetch/issues/461), under the principles of [ADR 0077](0077-the-sdk-api-follows-eight-guarantees-and-four-ranked-shape-rules.md), building on [ADR 0091](0091-collies-ai-verbs-live-on-the-page-replay-from-a-plan-file-the-run-names-and-expect-runs-a-success-check.md), [ADR 0100](0100-collies-agent-is-one-bounded-call-on-a-page-judged-by-the-programs-success-check-and-replayed-whole-from-the-plan.md) and [ADR 0101](0101-a-model-is-named-provider-slash-model-its-capabilities-and-prices-are-declared-and-every-ai-result-carries-its-priced-usage.md).

## Decision

### A Model allowance, not a Limit

- **What it is.** The most model Usage one Run may spend, past which its model calls are refused while the Run goes on. A Limit "stops runs cleanly and refuses new ones until the period ends or a person raises it" (`GLOSSARY.md`): a different meaning, so a different name (S3). A mode on a Limit, or a Limit kind that refuses instead of stopping, would leave a reader of `limits` unable to tell what stops the Run (S3, G1), and "only a person raises it" has no meaning for a figure the program picks for its own task.
- **The Limits are unchanged.** They stay the caps a person relies on, set or lowered in code and raised only by a person (ADRs 0041, 0080), and a Limit reached still stops the Run, an allowance set or not (G5). The allowance is never kept in the Usage ledger: ADR 0041's scopes, slices, Notifications and "Needs you" items are untouched.
- **The uncapped mark is unchanged.** A Run that can spend money with no Limit capping it is still marked uncapped (ADR 0041), an allowance set or not: an allowance any layer may set or raise is not a cap a person can rely on (G5).

### The setting

- **Three kinds, mirroring Limits and Usage** (S2): `ai.allowance.price` (a `Money`, as `limits.price` and `usage.price`, ADR 0101), `ai.allowance.tokens` (input plus output, as `ModelUsage.tokens`) and `ai.allowance.calls` (as `ModelUsage.calls`). None is set by default; `null` sets none. When several are set, the first reached holds.
- **Under `price`,** a model the price table does not price, or cannot convert to the allowance's currency, is refused with ADR 0101's `model_price_unknown`, as under a currency Limit, so an unpriced model never escapes it (G1, G5). A local built-in at its default address is priced zero, so only `tokens` or `calls` cap it.
  > Amended by [ADR 0117](0117-what-coding-agents-misread-is-reshaped-an-ai-result-holds-its-answer-in-how-it-ended-resource-types-are-blocked-by-a-setting-and-a-start-names-its-run-id.md): a Run whose `ai.model` the table cannot price fails its start with `model_price_unknown` when `ai.allowance.price` is set, unless `plan.frozen`.
- **Counted per Run.** It is set where a Run opens (`settings: { ai: { allowance } }` on a Run's start, ADR 0083) or above it, at the connection, in configuration, a project file, a Recipe or an Operator policy, where it is the default each Run counts on its own. A Label, a Session or a page that sets it fails with `setting_not_applicable` where it opens (G3): an allowance per Label or per page would be the "second layer of caps to explain" ADR 0080 rejected for a call scope.
- **What it counts:** every model call the Run makes, whatever makes it, the same calls as `RunUsage.model` (ADR 0101): AI verbs with their compiles, Repairs and extraction retries, an Agent's steps, the calls of a discarded attempt (ADR 0093), the program's own Model provider, and the Run's parts before a resume.
- **A Partitioned crawl counts one allowance.** Each Partition is an ordinary run (ADR 0054), but the crawl's allowance is the whole crawl's, as its Limit is: the Lead Daemon holds it with the crawl's own coordination state, outside its Usage ledger, and each Partition reserves its calls against it there in slices, as ADR 0041 reserves a Limit, so the crawl never passes it. The first refusal in any Partition reaches it for every Partition.
- **Who sets it:** any layer, a Recipe and a Client acting for a model included, since it only ever makes the Run spend less; an Operator policy, or a Recipe for what it declares, may lock it (ADR 0028). A resume may change it, as any setting that is not fixed for a Run's life ([ADR 0102](0102-a-program-names-its-run-by-an-id-that-a-start-resumes-ends-it-with-a-run-report-and-reads-what-waits-and-why.md)); raising it needs no person, because it is not a Limit.
- **A resume that raises it** opens a new cut-off: from the resume on, the raised value is in force, a reached allowance is reached no longer (`reachedAt` is `null` again until a call is refused under the new value), and the Run trace records the change with its layer, as ADR 0102 records a changed setting. A value at or below what the Run has spent stays reached. The requests skipped with `model_allowance` before the resume stay skipped: a skip is a decision, which `retryFailed` never re-admits (ADR 0102), so a program that wants those books extracted starts a Run seeded from their URLs, read from the outcomes.

### Holding it

- **Reserved before each call.** A model call reserves its worst case against the allowance in the same step as against the Limits (ADRs 0012, 0041), so the allowance is never passed, where LiteLLM's check-then-charge overshoots under concurrency ([#40095](https://github.com/BerriAI/litellm/issues/40095)) (G1). The reservation is journaled with the call, and released down to the measured Usage when the call ends.
- **Once reached, reached.** The first call whose worst case does not fit is refused, and from then on every model call of the Run is refused, a smaller one included. The crawl has one cut-off, which the Run trace records with the reservation that reached it, and which books were extracted never depends on call sizes (G1, G6).
- **A Limit wins.** A call that a used-up Limit would also refuse fails with `limit_reached` and stops the Run, as ADR 0080 says.

### What a refused call returns

- **The code.** `model_allowance_reached`, a `RefusedError` ("a policy, a Limit, a lock or a person refused", ADR 0079), not retryable within the Run. `limit_reached` is not reused, since its remedy (a person raises a Limit, the Run stops) is not this one (S3). Its `limit` names `ai.allowance.<kind>`, its value and the layer that set it, as ADR 0080's `limit` names a setting; its details carry the kind, the value, what the Run had spent and when the allowance was reached; and it carries the call's `usage`, as every error from a call that made model calls does (ADR 0101). Its `fix` names the setting (G6).
- **AI verbs.** `act`, `observe` and `extract` that need a model call (a step with no Plan entry, a compile, a Repair on Drift) raise `model_allowance_reached`, as ADR 0091 has them raise `limit_reached`. A step replayed from the Plan makes no model call and goes on, so a crawl that learned each page type's steps finishes without the model (ADR 0091), and `plan.frozen` stays the way to call no model from the start.
- **The Agent.** `page.agent` returns `ended: stopped` with the stop reason `model_allowance`, naming the setting, its value and its layer, with its `steps` and `partial` kept, as ADR 0100 has every early end of a task be a value (G1, S2). The Run goes on, as after `max_steps`. An allowance already reached when a task starts returns the same value with no step: the program set the allowance, so an Agent's task it ends is an expected outcome.
- **The Run.** It never stops for its allowance. It reports when it was reached in `RunUsage` (below), which `run.usage()` reads while it runs; its report (ADR 0102) carries the final `RunUsage` in `usage`, the requests skipped with `model_allowance` in `requests`' counts by skip reason, and the Model allowance among its Completeness reasons. Its progress gains no field: those values already say it (ADR 0102's no second channel, S2).

### The crawl requests it leaves

- **Skipped, with a reason.** A `ModelAllowanceReachedError` that escapes a handler ends its crawl request `skipped` with the reason `model_allowance` and the error's message, as ADR 0093 ends a request `skipped` when a refusal the site asked for escapes. It is the program's own choice, not a failure of the page or of the handler (G1), so it is not `failed` and is not retried.
- **A Record for it anyway.** A handler that wants one for the book catches the error and pushes a Record (such as one marking the book unextracted), since a skipped attempt discards what it staged ([ADR 0103](0103-a-handler-pushes-records-staged-with-its-attempt-into-datasets-its-crawl-declares-and-a-reader-never-slows-the-crawl.md)).
- **Reading what was left.** The books left unextracted are the Run's `skipped` outcomes with the reason `model_allowance`, which the program reads from `run.outcomes({ kinds: ["skipped"] })` (ADR 0102), picking out that reason, with their counts in the Run's report.
- **Completeness.** A Run that skipped a request for its allowance is `incomplete` when it ends, its reason naming the Model allowance and the count of requests it skipped, though its Lifecycle is `finished`: those requests were in the crawl's scope and were not done, unlike a request robots.txt kept out (ADR 0029, G1).

### Reading it

- **`RunUsage.modelAllowance`:** one entry per kind set, each with its `kind` (`price`, `tokens` or `calls`), its `value`, what remains (spent and reserved taken off), `reachedAt` (`null` until reached) and `source`, the setting, its value and its layer, as an error's `limit` names them. It is a field of its own, not an entry of `RunUsage.limits`, which lists what stops the Run (S3, G1). An empty list means no allowance is set. Every SDK keeps a kind it does not know as received (G3).

### Golden scenario 08

The crawl sets `ai.allowance.price` to 0.50 USD where its Run starts, its handler extracts each book with `extract` and lets a refusal escape, and the program reads the skipped outcomes with the reason `model_allowance` and the final `RunUsage` for the tokens and price spent. Books whose layout the Plan already learned keep being extracted after the cut-off, with no model call.

## Considered Options

- **Keeping the stop and declining "finish without the model":** rejected. It leaves the scenario's honest ending undone and keeps a pain the research ranks (AI pain 13, P42).
- **A Run of its own for a crawl's AI steps:** rejected. ADR 0093, confirmed by the owner, puts no Collie Run inside a crawl.
- **Stopping at a Limit, then resuming with `plan.frozen`:** rejected. A Run a Limit stopped resumes only once a person raises the Limit (ADR 0041), so an unattended crawl cannot finish, and the program needs two starts.
- **A call scope for Limits** (the map's fog item): rejected. It caps one call, not what a crawl has spent, and it adds the second layer of caps ADR 0080 rejected. A cap on one step alone stays a Run of its own (ADR 0080). The fog item closes.
- **A Limit with a mode** (`limits: { price, onReached: "refuse_model" }`) **or a Limit kind that refuses instead of stopping:** rejected by S3 and G1. One word with two meanings in the list a program reads to know what stops its Run, under a raising rule that does not fit a program's own figure.
- **A ledger scope for it:** rejected. It covers one Run's own task, so the Run's state holds it, and ADR 0041's ledger stays the record of the caps a person relies on.
- **Only a price:** rejected. Limits and Usage count tokens and calls too, and a local model priced zero would be uncappable (S2).
- **An allowance per Label, per Session or per page:** rejected. Nested counting per scope is a second layer of caps to explain; one Run-wide cut-off is what the scenario asks.
- **Check the spend so far, then charge** (LiteLLM): rejected. Concurrent calls pass the check together and overshoot (G1).
- **Letting smaller calls through after the first refusal:** rejected. Which books were extracted after the cut-off would depend on call sizes, and "stop all model use" would not hold (G1, G6).
- **`limit_reached` for the refusal:** rejected. Its remedy is a person raising a Limit while the Run stops; here the Run goes on and the fix is a setting (S3, G6).
- **The refusal as a value from `act`, `observe` and `extract`:** rejected. Their result would gain a second shape (S2), and ADR 0091 already has a used-up Limit raise there. The Agent's task returns a value, as ADR 0100 has every early end of a task do.
- **`failed` for the request the refusal ends:** rejected by G1. It would report the program's own choice as a failure, and be retried under ADR 0093's policy only to be refused again. **A new outcome:** rejected; ADR 0079's outcomes are closed, and `skipped` with a reason says it.
- **A `complete` Run despite those skips:** rejected by G1. The requests were in scope and were not done.
- **The allowance in `RunUsage.limits` with a kind** (ADR 0101's hand-off, "if you add one"): rejected by S3 and G1, as above.
- **An allowance clearing the uncapped mark:** rejected by G5. Any layer may raise it, so it is not a cap a person can rely on.

## Consequences

- **Amends ADR 0041.** A Run may also hold a Model allowance, which is not a Limit and is not kept in the Usage ledger: reaching it refuses the Run's model calls and does not stop the Run, and it leaves the uncapped mark as it is. A note sits under "When a Limit runs out".
- **Amends ADR 0080.** A Run's model Usage can be capped without stopping it, through the Model allowance; the call scope for Limits is declined for good, and the map's fog item closes. Notes sit under "Reaching a Limit", "No step Limit, and no per-call Limit" and its last consequence.
- **Amends ADR 0079.** `model_allowance` joins its skip reasons of a crawl request and its stop reasons of AI work. Notes sit under its outcomes of a crawl request and its `ended` field.
- **Amends ADR 0054.** A Model allowance set on a Partitioned crawl is the whole crawl's, held by the Lead Daemon outside its Usage ledger, and each Partition reserves against it in slices. A note sits under its Usage.
- **Adds to ADR 0102.** A resume that raises the Model allowance opens a new cut-off, while the requests skipped with `model_allowance` stay skipped; the report's Completeness reasons name the allowance. A note sits under its settings a resume may change.
- **Amends ADR 0101.** `RunUsage` gains `modelAllowance`; its section on golden scenario 08 is answered here. Notes sit under "A Run's totals and its Limits" and "Golden scenario 08".
- **Amends ADR 0091.** A compile or a Repair that needs a model call the Model allowance refuses fails with `model_allowance_reached`. A note sits under its failure table.
- **Amends ADR 0100.** `model_allowance` joins the stop reasons of an Agent's task, after which the Run goes on. A note sits under its stop reasons.
- **Amends ADR 0093.** `model_allowance` joins the skip reasons: a `ModelAllowanceReachedError` that escapes a handler ends its request `skipped`. A note sits under its skip reasons.
- **Adds to ADR 0029.** A Run that skipped a request for its Model allowance is `incomplete` though it `finished`. A note sits under its example of a run stopped by its Limit.
- **Adds to ADR 0083.** The keys `ai.allowance.price`, `ai.allowance.tokens` and `ai.allowance.calls` join the schema, applicable where a Run opens and above. A note sits under its timeout family.
- **Error codes.** `model_allowance_reached` joins `goodfetch-protocol` in the `refused` group, not retryable, through `xtask codegen`'s naming checks (ADR 0079); `model_allowance` joins the skip reasons of a crawl request and the stop reasons of AI work.
- **`GLOSSARY.md`** gains **Model allowance**.
- **`TESTING.md`** gains the Model allowance conformance cases.
- **Area 3 (Engine runtime)** builds the reservation against the allowance, its record in run state and its slices from the Lead Daemon for a Partitioned crawl's Partitions, and `RunUsage.modelAllowance`. **Area 9 (AI and agent)** builds the refusal in the AI verbs and the Agent. **Area 6 (Collection)** builds the skip reason and the Completeness reason. **Area 11 (Client surfaces)** builds the setting's types, `ModelAllowanceReachedError` and `RunUsage.modelAllowance` per language. Each lists this ADR.
