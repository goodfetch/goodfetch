# While the repository is private, the Release suite runs its macOS cells on the owner's machine and its hosted cells under a ceiling of included minutes

While the repository is private, each manual-dispatch Release run puts its macOS cells on the owner's machine (Apple M3 Max) as a self-hosted runner: macOS arm64 natively, and macOS x64 under Rosetta 2, labelled as translated. Only Linux x64, Linux arm64 and Windows x64 run on GitHub-hosted runners, at least 270 Linux-equivalent minutes a run, under a ceiling of 600 included minutes a month. Native macOS Intel and Windows arm64 first run once the repository is public, when their minutes are free and before the first release. The Release suite reaches the runner only from a `workflow_dispatch` on `main`, testing a commit of `main`, never a pull request or a fork. A pre-job script installed on the machine refuses every job not on its allowlist before its first step. The owner declined making the repository public earlier, for now: it stays private with no planned date before ADR 0032's first release, and this ADR assumes so.

> Note (owner's decision, 2026-11-22): this ADR's premise has ended. The owner made the repository public on 2026-11-22, before ADR 0032's first release ([ADR 0135](0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md)'s note of that day, with the owner's words and the settings in force). Its clause "Once the repository is public" is triggered and not yet done: every cell is to run on free hosted runners, native macOS Intel and Windows arm64 included, and the Release workflow is to stop naming `owner-machine`. The hosted-CI spec ([#3373](https://github.com/goodfetch/goodfetch/issues/3373)) tracks it. Since the owner's setting of that day lets no self-hosted runner, `owner-machine` included, serve the repository while it is public, the macOS cells have no runner: where they run goes to that spec, and until then `just release-ci` dispatches the hosted cells alone. The ceiling of 600 included minutes no longer counts standard hosted minutes, since standard GitHub-hosted runners in a public repository draw on no included minutes ([GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), checked 2026-11-22); the ceiling job of `release-suite.yml` still runs until that spec changes it. Larger runners still bill and stay declined (ADR 0076's note of that day).

ADR 0061 runs the Release suite on manual dispatch while the merge queue does not exist, before each milestone's owner test and before any release, and no ADR budgets its minutes. GitHub Free gives the account 2,000 included minutes a month, shared by all its private repositories. ADR 0064's ceiling holds 1,000 of them for test health, so about 1,000 remain for these runs and every other hosted job of the account: the pull-request tier and private fuzzing (ADR 0067) among them. A run of the full matrix on hosted runners, at ADR 0061's 45-minute job budget, costs about 1,350 Linux-equivalent minutes, most of it the two macOS cells. That is more than what remains.

Facts this rests on, checked on 2026-10-15:

- **Rates** ([minute multipliers](https://docs.github.com/en/billing/reference/actions-minute-multipliers)): per minute, Linux 2-core x64 $0.006, Linux 2-core arm64 $0.005, Windows 2-core x64 and arm64 $0.010, macOS 3- or 4-core (M1 or Intel) $0.062. The page no longer states how Windows and macOS minutes draw on the included minutes, which GitHub's earlier multipliers did (Windows 2, macOS 10).
- **Included minutes** ([GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)): 2,000 a month on GitHub Free, per account: the `goodfetch` organization's private repositories share them, the private fuzzing repository of ADR 0067 included. They reset at the start of each month. "GitHub Actions usage is free for self-hosted runners and for public repositories that use standard GitHub-hosted runners." "If your account does not have a valid payment method on file, usage is blocked once you use up your quota."
- **The self-hosted charge was postponed, not cancelled.** GitHub announced "a new $0.002 per minute GitHub Actions cloud platform charge" for self-hosted runners in private repositories from 2026-03-01, public repositories staying free. It then put it on hold: "We're postponing the announced billing change for self-hosted GitHub Actions to take time to re-evaluate our approach", with no new date ([changelog, 2025-12-16](https://github.blog/changelog/2025-12-16-coming-soon-simpler-pricing-and-a-better-experience-for-github-actions/)).
- **Hosted labels for private repositories** ([GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)): `ubuntu-24.04-arm`, `windows-11-arm`, `macos-15-intel` and the macOS arm64 labels are all listed.
- **`main` has no branch protection while private.** GitHub's API answers the rulesets and branch-protection endpoints with 403, "Upgrade to GitHub Pro or make this repository public to enable this feature", so anyone with write access can push to `main`.
  > Note (2026-11-22): the repository has been public since that day, so rulesets and branch protection are open to it; none is set yet, and the hosted-CI spec ([#3373](https://github.com/goodfetch/goodfetch/issues/3373)) settles them with the merge queue.
- **Intel macOS ends in 2027.** Apple: "Rosetta is available for any Mac with Apple silicon using macOS 27 or earlier"; from macOS 28, "Rosetta functionality will be available only for certain older, unmaintained games" ([Apple support](https://support.apple.com/en-us/102527)). GitHub: "GitHub will no longer support this architecture on macOS after the macOS 15 runner image is retired in Fall 2027" ([changelog, 2025-09-19](https://github.blog/changelog/2025-09-19-github-actions-macos-13-runner-image-is-closing-down/)).
- **No release is cut from the private repository.** ADR 0032 makes the repository public when the first version's release pull request merges, before that version is built.
- **Self-hosted runners** ([self-hosted runners](https://docs.github.com/en/actions/reference/runners/self-hosted-runners), [pre- and post-job scripts](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/run-scripts)): "If the job remains queued for more than 24 hours, the job will fail." A script named by `ACTIONS_RUNNER_HOOK_JOB_STARTED` runs before each job, and if it exits non-zero, "the job will not run and will be marked as failed".
- **Self-hosted runners and public repositories.** GitHub says self-hosted runners "should almost never be used for public repositories" ([secure use](https://docs.github.com/en/actions/reference/security/secure-use)), and runner groups limited to selected repositories need the paid Team plan (ADR 0084).

Decided in [Fit the private-period Release suite runs in the free Actions minutes](https://github.com/goodfetch/goodfetch/issues/535), with the agent answering on the owner's delegation. The owner settled the one point left to them on 2026-10-15: "Keep the repository private for now; fit the tests in the free minutes."

## Decision

### The matrix while the repository is private

| Cell | Where it runs | Linux-equivalent minutes, one 45-minute job per cell |
|---|---|---|
| Linux x64, glibc and musl | GitHub-hosted, `ubuntu-24.04` | 90 |
| Linux arm64, glibc and musl | GitHub-hosted, `ubuntu-24.04-arm` | 90 |
| Windows x64 | GitHub-hosted | 90 |
| macOS arm64 | the owner's machine, natively | none |
| macOS x64 | the owner's machine, under Rosetta 2 | none |
| macOS Intel, natively | not run while private | none |
| Windows arm64 | not run while private | none |

- **The owner's machine runs the macOS cells.** macOS arm64 runs natively. The x86-64 macOS build runs its macOS x64 cell under Rosetta 2, which catches the target's build, link and most of its failures. It is labelled `macos-x64 (Rosetta 2)` everywhere a cell is named. Its failures count like any other cell's, and its pass never stands in for native Intel.
- **Native macOS Intel and Windows arm64 wait for the repository to be public.** Their first run is the first Release run after the repository becomes public, on free hosted runners while GitHub still offers an Intel macOS image (fall 2027 at the latest). That run comes before the first release, since ADR 0032 makes the repository public before the first version is built. They would cost about 495 and 90 minutes a run, and no release is cut while private.
- **The owner's-machine cells run only on `main`.** A dispatch on any other branch runs the hosted cells alone and lists the macOS cells as not run. The machine also times the Performance series and the release-candidate benchmark (ADR 0076), and ADRs 0032 and 0071 keep pull-request code off the machine that does. With no branch protection while private, what reaches `main` is bounded by write access to the repository: the owner, and agents acting for the owner. No pull request and no fork reaches the machine through the Release suite.
- **The first release still runs every cell first.** The repository becomes public when the first release pull request merges (ADR 0032). From then on, the release pipeline's own Release suite run on the release commit (ADR 0061) runs the full native matrix on free hosted runners, native macOS Intel and Windows arm64 included. The build publishes nothing until that run passes. A private-period run never stands in for it.
- **A passing Release run while private is every cell above that runs, green on one commit of `main`.** It is what the milestone's owner test waits for (ADR 0058). Its cells may come from more than one dispatch of that commit. `just release-ci` takes the cells to run, all by default. On `main` it also takes a commit of `main`, its head by default; off `main` it tests the branch's pushed head, as ADR 0061 says. A dispatch on `main` runs `main`'s own workflow, which refuses a commit that is not on `main`'s history before any job checks it out, so the commit input never brings unmerged code to the machine. A cell that was held back by the ceiling, timed out in the queue or failed with no failed test step may run again. A cell with a failed test step in any attempt leaves the commit red (ADR 0064).

The accepted cost: 3 CPUs and 7 GB on arm64, and at most 5 macOS jobs at once on the Free plan. Making the macOS cells green is not part of the move ([#3322](https://github.com/goodfetch/goodfetch/issues/3322), [#2363](https://github.com/goodfetch/goodfetch/issues/2363)).

A workflow check in `just lint` takes their place and refuses a self-hosted or larger-runner label, `pull_request_target`, a `workflow_run` that checks out a pull request's head, a workflow without a top-level `permissions: {}`, and a `uses:` not pinned by commit. Once no workflow needs `owner-mac`, the owner removes it from the repository, an owner step of that spec, since the gate host's token cannot manage runners.
> - **Out of this move:** the Windows arm64 cell and the resident-memory ceilings for native macOS Intel and Windows arm64 ([#1576](https://github.com/goodfetch/goodfetch/issues/1576)), the Chromium build gate ([#445](https://github.com/goodfetch/goodfetch/issues/445)) and macOS x64 after GitHub's Intel images end ([#546](https://github.com/goodfetch/goodfetch/issues/546)).

### Counting and the ceiling

- **Minutes count in Linux-equivalent minutes.** Each hosted minute counts at its rate over Linux 2-core x64's, rounded up to a whole number: Linux x64 1, Linux arm64 1, Windows 2, macOS 11. GitHub no longer documents how Windows and macOS draw on the included minutes, so the count stays at or above both its earlier multipliers and today's rates. These are the "GitHub's minute multipliers" ADR 0064's ceiling counts with.
- **A ceiling of 600 included minutes a month covers every hosted job of manual-dispatch Release runs,** the ceiling check included. At 270 a run, that is two runs. Beside ADR 0064's 1,000, at most 400 are left for every other hosted job of the account: the pull-request tier, private fuzzing, the cache-warming job on pushes to `main` (ADR 0061) and the checks run by hand outside the Release run, such as the Live checks of ADR 0065 and the online conformance of ADR 0043. [Fit the pull-request tier, private fuzzing and other hosted jobs in the included minutes left](https://github.com/goodfetch/goodfetch/issues/545) budgets them. Jobs are counted from the durations the ingest records, as ADR 0064 counts its own.
- **270 is a floor.** ADR 0061 shards a cell over several jobs, and each shard has its own setup. So the ceiling check estimates a run from the recorded durations of the same cells' last run, and uses 270 only before any.
- **The run checks the ceiling before it starts a hosted cell.** The Release workflow's first job, a one-minute Linux job, reads the month's count and the estimate. If the run would pass 600, it starts no hosted cell. It writes the minutes it needs and the date the month turns to its job summary, and the run fails. The owner's-machine cells still run, for an early signal. A run held back by the ceiling is not a test failure, so no diagnostic run follows.
- **`main` comes first.** A dispatch off `main` starts its hosted cells only if a run on `main` still fits under the 600 after it; otherwise it is held back like a run over the ceiling. So branch runs never use up the month that a milestone's run on `main` needs.
- **A run whose own estimate passes 600 still starts as the month's first Release run on `main` whose hosted cells start,** so a milestone's owner test is never blocked for good. It opens or updates a `needs-triage` issue, as a budget breach does (ADR 0061). The fix is to merge shards or speed up the tests.
- **Running out blocks, it never bills.** The account keeps no payment method for Actions, so GitHub blocks usage past the included minutes, as quoted above. That is an owner setting, recorded in [Owner confirmations and decisions](https://github.com/goodfetch/goodfetch/issues/392).

### The owner's machine as a runner

- **It is registered on the repository, never on the organization,** with the labels `self-hosted`, `macOS`, `ARM64` and `owner-machine`.
- **A committed allowlist names every job that may reach a self-hosted runner,** with its workflow, its events and its refs. The Release suite's entry is its macOS jobs and their diagnostic jobs (ADR 0064), which run as jobs of the same Release run, on `workflow_dispatch` with `refs/heads/main` only, and each job carries the matching `if:`. The other uses of the machine join the list with the jobs their own decisions create, on the triggers those decisions set: the Performance series (ADR 0071), the release-candidate benchmark (ADR 0032), the test V8 build (ADR 0067) and the Chromium build gate ([#445](https://github.com/goodfetch/goodfetch/issues/445)). An entry whose workflow file comes from `main` or a tag (`workflow_dispatch` or `schedule` on `main`, a tag push) keeps the guarantees below. An entry triggered by a pull request runs its workflow from the pull request's branch. It joins only once its own decision squares it with ADRs 0032 and 0071, which keep pull-request code off the runner that times the benchmark, and amends them where it does not. This ADR adds no such entry.
  > Amended on 2026-10-19 (owner decision of 2026-10-19): [ADR 0135](0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md)'s list also admits `update-screenshots.yml`, dispatched from a branch other than `main`, which runs that branch's workflow file, and the diagnostic jobs of a Release run's owner's-machine cells as `diagnostic.yml#rerun-owner-machine`, a workflow of its own on `workflow_run`. The repository is private, only the owner pushes branches, and forks are refused.
  > Amended by [ADR 0135](0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md): while the repository is private, the pull-request tier's jobs join the list on the `pull_request` event, from branches of this repository only, and the cache-warming job on a `push` to `main`, each running its build and tests in a Linux VM recreated for the job.
- **Two checks hold the list.**
  - A Quick-suite check of the workflow files refuses any job whose `runs-on` names `self-hosted` or any of the runner's labels and is not on the list with the same events, refs and `if:`.
  - A pre-job script (`ACTIONS_RUNNER_HOOK_JOB_STARTED`) on the machine checks each job's repository, workflow, event and ref against its own copy of the list, which the owner installs, and fails any other job before its first step. A branch can change the committed list, but not the machine's copy. So, for every entry this ADR adds or that comes from `main` or a tag, a job pushed on a branch that names the runner never runs a step there, even before the Quick suite reports.
  - ADR 0076's rule that a self-hosted runner never runs a pull request from a fork holds in both.
- **It runs as its own standard macOS user,** not an administrator, as a launchd service. It cannot read the owner's home, keychain or `.env`. macOS puts every local user in the `staff` group, so the owner's setup checklist closes the home folder to that user (for example `chmod 700`) and checks it by trying to read it as that user. Its jobs hold no secret and a token with `contents: read` only, and clean their workspace at start and end. The Release suite needs no secret, since Live checks are in no suite (ADR 0061).
- **One runner instance runs on the machine,** so its jobs never overlap: a Release cell never runs while the same runner times the Performance series or the benchmark (ADR 0071).
  > Amended by [ADR 0135](0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md): a second instance, as its own user, serves the private fuzzing repository; the two instances' pre-job scripts share one lock, so the machine still runs one job at a time.
- **It runs only when the owner's machine is on.** Its cells wait in GitHub's queue, and fail after 24 hours there. A cell that timed out in the queue ran no test, so it may be dispatched again on the same commit. `just release-ci` says which cells are waiting for the owner's machine.
- **Its timings are labelled with the machine.** The results store records each cell's job with `owner-machine`, and flaky-test detection (ADR 0064) treats `macos-x64 (Rosetta 2)` as its own configuration. ADR 0061's time budgets are measured on GitHub-hosted runners, so they ignore these jobs, which keep the 90-minute job cap.
- **Diagnostic runs of hosted cells count against ADR 0064's 1,000,** as that ceiling already says, not against the 600.
- **Diagnostic runs of its cells run there too.** ADR 0064's diagnostic run reruns a failed test on the same runner OS. For an owner's-machine cell, it is a job of the same Release run on the owner's machine, which the allowlist entry covers, so it uses no included minutes.

### When things change

- **If GitHub brings back the self-hosted charge for private repositories:**
  - if it draws on the included minutes, the owner's-machine cells count at one third of a Linux minute ($0.002 over $0.006);
  - if it would bill money, the owner's-machine cells stop (ADR 0076), and the macOS cells wait for the repository to be public, like native Intel. Nothing is bought to keep them.
- **When Rosetta 2 or GitHub's Intel image ends** (macOS 28 on the owner's machine, or fall 2027), the macOS x64 cell has no free place to run. Whether macOS x64 stays a supported platform, and where its cell runs then, is decided in [Decide macOS x64 support once Rosetta 2 and GitHub's Intel runners end](https://github.com/goodfetch/goodfetch/issues/546), before either date.
- **Once the repository is public,** every cell runs on free hosted runners, native macOS Intel and Windows arm64 included. The Release workflow stops naming `owner-machine`, and this ceiling lapses with ADR 0064's. Whether the runner still serves builds on a public repository is decided in [Decide the free Chromium build gate](https://github.com/goodfetch/goodfetch/issues/445).
  > Note (2026-11-22): triggered by the owner's making the repository public that day, and not yet done (the note of 2026-11-22 at the top). The owner's setting of that day lets no self-hosted runner serve the repository while it is public.

## Considered Options

- **The full matrix on hosted runners:** rejected. About 1,350 minutes a run is more than the roughly 1,000 left beside test health, before a single pull request.
- **The owner's machine for macOS arm64 alone, with every other cell hosted:** rejected. Native Intel at about 495 and Windows arm64 at 90 bring a run to about 855. That fits one run a month and leaves about 145 for the pull-request tier and private fuzzing.
- **A smaller matrix alone, with macOS arm64 hosted:** rejected. About 765 a run for the same reason.
- **Native macOS Intel hosted before each owner test:** rejected. It would cost about 495 a run for what Rosetta 2 mostly catches for free, and native Intel runs free before the first release.
- **Linux arm64 in a Linux virtual machine on the owner's machine:** rejected for now. It would save 90 minutes a run at the cost of a second runner inside a VM to keep. Hosted arm64 is the cheapest rate GitHub sells.
- **Windows on the owner's machine:** rejected. It would need a paid hypervisor or a Windows licence.
- **Buying minutes, or a payment method with a spending budget:** declined while there is no revenue (ADR 0076).
- **Making the repository public earlier:** declined by the owner for now (2026-10-15), the point ADR 0076 left open. The repository stays private with no planned date before the first release, and this ADR is the plan for that whole period.
  - For it: standard hosted minutes become free, so every Release run is the full native matrix, and ADR 0064's ceiling and this one lapse. The nightly tier can turn on (ADR 0032), and the owner's machine leaves the Release suite.
  - The repository is already in the `goodfetch` organization, so going public would also bring the merge queue (ADR 0032), and with it the Release suite before every merge.
  - Against it: the code is public before the first release, which ADR 0032 chose against. GitHub advises against self-hosted runners on public repositories, which matters for [Decide the free Chromium build gate](https://github.com/goodfetch/goodfetch/issues/445).
  - Reopening it is the owner's call alone; an agent that finds the minutes do not fit says so and does not propose it as pending.
