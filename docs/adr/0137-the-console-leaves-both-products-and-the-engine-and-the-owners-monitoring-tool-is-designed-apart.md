# The Console leaves both Products and the engine, and the owner's monitoring tool is designed apart

No Product carries a Console any more. No executable embeds or serves one, and no command, setting, operation, Error code or file format exists for it. The engine keeps every feature that serves a person or a Client without the Console, and loses only what existed to serve a Console from the binary. The owner's own tool for monitoring and controlling runs while testing is outside both Products and is designed in a decision of its own.

Specs [#591](https://github.com/goodfetch/goodfetch/issues/591), [#592](https://github.com/goodfetch/goodfetch/issues/592) and [#593](https://github.com/goodfetch/goodfetch/issues/593) built a product-grade Console on ADRs 0031, 0057, 0068, 0073, 0087 and others: one Console build per Product embedded in each executable, sign-in by cookie, accounts, passkeys and OIDC, a second origin for scraped content, an encrypted offline cache, a translated and audited interface. The owner never meant to ship it. On 2026-10-28 they wrote: « it was initially for me to have a dashboard to test etc. … since then i planned and still planning in goodfetch platform repo a fully fledged cloud platform. so for this one, keep really thin: it only goal is for me to test, it stay local, isnt ship with the framework, allow me to control and monitor the runs with precise data and analytics and metrics, but no customer feature ». In the grilling of 2026-10-28 and 2026-10-29 they added that no engine feature is to be removed because the Console leaves, only what is inherent to the Console and useless to the engine, and that the Console must leave the engine in depth. On 2026-10-29 they confirmed the removal and asked for a lightweight, performant tool, written in Rust, to monitor everything that goes on, designed on its own.

## Decision

- **No Product carries a Console.** Neither executable embeds a Console build, serves Console files or has a `console` command, and no setting, Error code, operation, file format, Feature of the Feature inventory (ADR 0072), Size budget or Performance budget names the Console.
- **What leaves the engine.** Everything that served a Console from the binary: the engine's `console` module (the build's files, the Content Security Policy and headers, `/sign-in`, `/session`, `/sign-out`, `/offline-key`, `/csp-report`, the Console's `/protocol` endpoint and its Server-Sent Events fallback), the content origin, the `people` module with its sign-ins, Console key and accounts store, `sign_in.*` and `console.rotate_key`, the settings `console.*`, the Error codes `console_port_in_use`, `console_key_rotated` and `sign_in_revoked`, a run's `console_url`, `ConsoleOpened`, the browser cache's and the accounts store's formats, each executable's embedding of a Console build, `xtask console build`, the Stub gateway's serving of a Console build, the `console/` packages, and the tests, fuzz targets, conformance cases, Journey variants, budgets and CI steps of all these. The protocol's WebSocket transport stays for the Exposed Daemon (ADR 0049).
- **The engine keeps its person-facing features.** "Needs you", the Run trace's request log, `dataset.query`, the Run index, the Usage ledger, settings, the Daemon, the ops listener and its metrics stay, as their ADRs decide them. Wherever an ADR says a person acts "in the Console", the person acts through a Client: the CLI's interactive prompts, an SDK or, later, Goodfetch Cloud. The features #591 and #592 specified for a person but that are not built (`run.reconcile`, `human_pause.answer`, the Live view and its grants, accounts, roles, passkeys, OIDC and named tokens, failures grouped by cause, the Timeline) keep their ADRs and get a spec of their own.
  > Note on the owner's decision of 2026-11-01: an SDK reads and reaches the Live view, and a person's answers through an SDK wait for #1643. The Consequences' list of the CLI and later Goodfetch Cloud names where a person answers today.
- **The owner's monitoring tool is designed apart.** A local tool for the owner to monitor and control runs while testing replaces the Console's role for them. It is part of no Product, and its form, stack and features are decided in its own ADR and spec. This ADR decides only that no Product carries it.

## Considered Options

- **Keep a smaller Console inside the Products:** rejected by the owner. A Console a Product ships is a customer feature, and customer features belong to Goodfetch Cloud, built in its own repository.
- **Keep the Daemon's Console endpoint and cookie sign-in for a local tool:** rejected. It keeps a listener, a credential flow and a security policy in every executable for a tool nobody installs; a local tool reaches the Daemon as the CLI and the SDKs do.
  > Note on the owner's decision of 2026-11-01: the loopback WebSocket of [ADR 0049](0049-supported-self-hosted-targets-and-the-exposed-daemon.md)'s note of that date differs from this endpoint. It is off unless an origin is allowed or Live view is on, it serves no file and sets no cookie, and an origin's Connection goes through a Pairing.
- **Remove the engine features the Console showed along with it:** rejected by the owner. "Needs you", the request log and `dataset.query` serve the CLI, the SDKs and Goodfetch Cloud as well.

## Consequences

The Console's code and its engine parts are on `milestone/m1-core` until [#1583](https://github.com/goodfetch/goodfetch/pull/1583) merges. That pull request changes 73 ADR files, so the notes in the amended ADRs, beside the text each amends, are added by the removal spec's documentation ticket once it has merged; until then this ADR is the record. No contract changes version: nothing is published (ADR 0066).

- **Amends ADR 0031.** The Run index stays as decided, with its amendments. No Console is a served Client: no cookie, `HttpOnly` sign-in, Server-Sent Events fallback, content origin, offline cache, sign-ins or Console key. The Live view, "Needs you" and the Run trace stay engine features, reached through Clients.
- **Amends ADRs 0024, 0049 and 0055.** No executable serves Console assets and no `console` command exists; the Console's ports beside `daemon.address` and the Console key a Daemon group shares are gone. The Daemon's socket, its token and the Exposed Daemon's WebSocket stay.
- **Amends ADRs 0057, 0084, 0087, 0088, 0094 and 0096.** No executable embeds a Console build, no Size budget counts one, Foxhound's screens are no workspace package of their own, no release test walks a Console's routes, and no Daemon serves a Console. The Stub gateway stays for the cloud-readiness conformance, without a Console build.
- **Amends ADR 0098.** The Run index serves both Products; the Console a Daemon served is gone.
- **Amends ADRs 0068 and 0073.** Their Console parts end: the Console's browser tests, its served tests under the production policy, its conformance suite, its WCAG audit, its translation and its Reference screenshots. Their docs site and published-package parts stand.
- **Amends ADRs 0061, 0062, 0063, 0067, 0071, 0072 and 0075.** No suite, test layout, Journey surface, security boundary, Performance budget, Feature kind (`screen:`) or actor exists for the Console.
- **Amends ADRs 0029, 0041, 0056, 0092 and 0113.** A person reconciles an uncertain Effect, raises a Limit and answers a Human pause through the CLI's interactive prompts, or later Goodfetch Cloud, and logs in through a headful window locally or the Live view once it is built. These rules otherwise stand.
- **Amends ADRs 0037 and 0058.** The local Console leaves V1's Product scope and M1's contents. The person-facing capabilities ADR 0037's matrix gives the Console (run status, the Live view, replay) stay in scope through Clients; the hosted dashboard is Goodfetch Cloud's.
- **Every other mention.** Where an ADR says what the Console shows or offers (ADRs 0001, 0002, 0006, 0009, 0011, 0015, 0017, 0018, 0026, 0027, 0028, 0030, 0032, 0033, 0035, 0036, 0042, 0043, 0045, 0046, 0048, 0052, 0053, 0054, 0059, 0066, 0069, 0070, 0077, 0079, 0080, 0081, 0085, 0091, 0095, 0097, 0099 to 0103, 0105, 0106, 0122, 0130 and 0134), the engine behaviour stands and the Console's part does not; a Client reaches it.
- **Specs.** A removal spec replaces #591, #592 and #593. The person-facing features listed above get their own spec, and the owner's monitoring tool its own; their open tickets move under them.
- **Glossary.** **Console** leaves the glossary and the list of Clients, **Stub gateway** no longer serves one, and the Console leaves **Performance budget**'s and **Pre-merge suite**'s definitions. The terms only the served Console used leave with its code. These edits land with the removal spec's documentation ticket, after #1583, which adds glossary entries beside the Console's.
