# Every shared per-unit path has one owner module, a cost contract of counted work and a benchmark

Most features of Collie, Foxhound and the engine do their work on one of nineteen **Shared paths**: the route that every page, request, Record, CDP command, action, navigation, protocol message, Audit entry, charge, governor sample, trace entry, Politeness permit, Hook stage or Sink batch takes. Each Shared path has one owner module that every feature's work on it goes through. Each has a **Cost contract**: the **Counted work** that one unit of the path may cost, counted by deterministic counters and never timed. Each is measured by a named benchmark of the whole composition. The limits live in the **Quality register** of `TESTING.md`, which starts at today's figures and only ratchets down. Every known gap between today's code and its contract is an Exception that expires. Decided with the owner in the `system-qualities` Setup grilling of 2026-11-01, which the owner asked for on that date, retroactively, for the whole repository. The same day's sweep of the open tickets found three more paths and errors in this text; they are corrected here under the owner's instruction to decide every reversible choice (« fait tout ce que tu peux faire suel »), and stay open to the owner's review.

## Context

On 2026-10-30, Foxhound crawled about 80 pages a second against Spider's 11,145, and 337 against 12,983 like for like, at 165–181 MiB of resident memory against 25 MiB (#1577). The profile of that crawl (Hetzner CCX43, tip `0fd15a3a7`, the Proving ground's 1,000-page site at 16 requests at once) found the cause in structure, not in any one feature:

- **8 HTML parses** and about 614 CSS selectors compiled twice per page;
- **135 SQL statement preparations**, about 8 run-state commits and 7.5 fsyncs (in `full`) per page;
- **329 system calls** per page against Spider's 12, among them `provenance.jsonl` opened twice per page, `configuration.toml` and `operator-policy.toml` read 650 times and `/proc/meminfo` opened 177 times during the crawl.

ADR 0138 decides the page path's fix. A read of the code at `203f17f42`, checked again at `779a2ffa0` (strand E of [the 2026-10-31 research](../../rnd/research/2026-10-31-llm-planning-cross-cutting-failures/strands/e-codebase-scan.md)), found the same pattern on twelve more paths, in 17 confirmed and 5 suspected cases:

- every CDP command opens, writes and closes `trace/cdp-commands.jsonl`;
- every page read creates its isolated world again, and every guard check sends the 9,631-byte `check.js` source again;
- every Audit entry reads both TOML files, opens its store twice and runs a schema set-up transaction;
- every usage charge reads every Limit back from the Usage ledger;
- every governor sample reads both TOML files and opens `/proc/meminfo` three times;
- every links batch rebuilds the crawl's Scope from the run file and compiles its globs;
- every incoming JSON-RPC message is walked about five times and deep-copied once.

Each spec added its own per-unit work: its own parse, open, commit or settings read. Each piece was correct on its own. No decision owned any path's total cost, so no review could see the sum. ADR 0071's +5 % comparison sees one change against its base, never the slow accretion of many. ADR 0134 made the absolute ceilings informative until the optimization pass, and they measured 234 times against 2.

How proven projects own these paths. Each was read at a pinned version on 2026-11-01, in [the per-unit path research](../../rnd/research/2026-11-01-per-unit-path-architecture/):

- **One owner per path, built once, walked per unit.** Scrapy's middleware and pipeline managers precompute their method chains at start. Crawlee keeps hook arrays and a `Router`. Spider has one `Website` coordinator. Playwright sends every command through one connection object.
- **"Off" is free by construction.** Scrapy removes a disabled component from its chain (`NotConfigured`), and Spider compiles a feature out. Neither tests an `if` per unit inside shared code.
- **Run invariants are compiled once, in a bounded cache keyed by the source text.** parsel keeps a 256-entry CSS translation cache and a 2,048-entry XPath cache; Spider uses `OnceLock`. Counter-examples: Crawlee builds a `Minimatch` per page, and Playwright compiles a glob into a `RegExp` on every request (`urlMatches`, v1.64.1).
- **A browser's utility world is registered once and injected code is called by handle.** Playwright and Puppeteer register the world once per session with `Page.addScriptToEvaluateOnNewDocument(worldName)`, keep its context id from Chromium's events, evaluate their injected script once per context and call it by handle afterwards. Stagehand v3 recreates the world on every read and sends its whole script on every call, as Collie does today. Chromium's source (`InspectorPageAgent::createIsolatedWorld`, `main` at `fc2ff626`) answers a second `createIsolatedWorld` with the same world name with the same context, so the cost is a round trip, not a leak. Collie cannot copy how they learn the id: those events need the `Runtime` domain, which ADR 0019 never enables.
- **One writer per log file, holding one buffered handle.** Spider's WARC writer keeps a 256 KiB `BufWriter`, and Playwright's tracing flushes at 64 KiB or at action boundaries. No surveyed project opens a file per unit.
- **Per-unit cost guards.** Only Scrapy gates per-unit cost in CI (CodSpeed, instruction counts on every pull request touching `scrapy/**`). No project counts structural events per unit, such as parses, compilations, prepared statements, commits or syncs.

## Decision

### The Shared paths

Every Shared path names one unit, one owner module, one Cost contract and one benchmark. **Counted work** is work that repeats exactly from run to run: parses; selector, glob, regex and schema compilations; statement preparations; connections and files opened; transactions; syncs; configuration reads; tasks spawned; CDP commands; encodes and decodes. Durations and resident memory stay Performance targets (ADR 0134).

### What every path keeps

- **The plug-in rule.** A feature on a Shared path adds its work through the path's owner module: either the owner itself, or a stage the owner builds once and calls. The feature declares what it reads and what it adds. It builds per unit nothing that depends only on the engine's, the Run's, the Session's or the document's inputs. A second loop, handler or queue for the same unit beside the owner is a second entry point, and is refused.
- **What is built once, and at which scope:**
  - **The engine:**
    - one snapshot of the machine's settings (the Operator policy and user configuration), resolved when the engine starts, refreshed when the engine writes its own configuration (`config set`) and resolved again when a Run is admitted. A hand edit of either file while the engine runs is seen at the next Run or the next write by the engine.
    - each SQLite store (the Audit log, the Usage ledger, known certificates, the Run index), opened and set up once with its connections kept and every statement prepared through `prepare_cached`. The writer is an actor of `tasks` and the readers run on its blocking threads, as `run_state` does (ADR 0060).
    - the bounded cache of compiled selectors of ADR 0138, which also holds compiled globs and regular expressions, keyed by their text.
  - **The Run:** the Run invariants (the Scope, Payload rules and Fragments with their compiled patterns and validators), the Datasets and their validators (ADR 0138), the Hook chains, each origin's parsed robots.txt in a bounded cache, and the Run-trace writer and its file handles.
  - **The Session:** its Page check matchers.
  - **The document:** the utility world's context id and the handle of `check.js` in it. ADR 0019 never enables `Runtime`, so no context event arrives: the registry makes the world on a frame's first read in a document, as the guard's turn does today, and drops the id and the handle at that frame's `Page.frameNavigated` or detach. `check.js` is evaluated once in that world (`Runtime.evaluate`, keeping its remote object) and called by `objectId`.
- **A feature switched off removes its work, not only its effect** (ADR 0138's rule, for every path). For example, with no route and no Filter list, interception sends no `Fetch` message. With the CDP command log off, nothing is sent to its writer.
- **Each benchmark runs the whole composition with its default features on, plus one run with each feature on the path that can be switched off turned off.** Each benchmark checks that the work it counts happened, as Scrapy's benchmarks assert that their selectors still match. Its own tests also plant one extra unit of each counted work and expect it to fail.

### How work is counted

- **Each count sits at the primitive that does the work, beneath every owner,** so that work added beside an owner is counted too: a counter only inside the owner module would miss exactly what it exists to catch. A parse, a selector or validator build and a file open each go through one function that counts, and the `disallowed-methods` lints of ADR 0138 and `STYLE.md` keep other code off the raw call. CDP commands and protocol messages are counted at C1's and E1's seams.
- **What no wrapper can see is read from outside it:** statement preparations from Callgrind's call count of SQLite's own `sqlite3_prepare_v3`, whose C symbol does not inline or change with Goodfetch's code; transactions from a commit hook on each connection; syncs through a counting SQLite VFS, as the crash VFS of ADR 0060 sits there. A merge-gate cell cross-checks the counts of opens, directories and syncs against `strace` on B1 and B2, so a bypass of the wrappers fails.
- **The counts are one metric of the ops listener** (ADR 0050, as ADR 0138 decides for the page path), `goodfetch.counted_work` with the bounded labels `path` and `work`, not a metric per row. A count shared between threads lives in its crate's `sync` module and is checked under loom (ADR 0060).
- **A benchmark reads the counters on the paused runtime** and divides each count by the units of the outcome that did the work (per click, per fill, per read, per navigation with and without a Page check, per page served, blocked or redirected, per charge within a Slice, per Slice taken), never by the sample's mix of outcomes.
- **Instructions, allocations and bytes stay gungraun's** (ADR 0071), measured beside the counts.
- **System calls are not counted as such** (ADR 0138): futex and epoll waits depend on scheduling. Their causes (files opened, syncs, configuration reads) are counted.

### The benchmarks

- **B1, the whole crawl:** `goodfetch-foxhound`'s in-memory crawl of #1572 (`crawl::in_memory_pages`), with a counts cell beside its existing heap cell. Its fixture is extended so that the crawl meets every outcome its paths have: a redirect, a blocked page, a payload under a Label's schema, a Record under a Dataset's schema, a Page check, a Limit, a Politeness permit, a Hook, a handler on a document tier and the SQLite Sink. Work no code does yet joins the fixture in the ticket that adds it.
- **B2, a Collie Session:** a new `goodfetch-page` scenario over the in-memory CDP end that `check_and_arm` already uses, with a scripted browser that answers each command at once. It opens a page, navigates with and without a Page check, clicks, fills, presses, reads, and sends requests, some of them blocked, with a navigation in the middle so that the world and `check.js` are set up again exactly once. Stealth cells count human-like input and typing, and a scripted Playwright-driver end counts C1's second transport. Goodfetch's counts do not depend on Chrome, so a real browser's time stays a Performance target.
- **B3, the engine:** `goodfetch-engine`'s `dispatch`, extended from `engine.info` to large params (a `crawl.request_handled` Record, a `route.fulfill` body), a Plugin's messages and events, beside new scenarios for Audit entries, charges and governor samples, the last over the stand-in `/proc` folder the governor's tests already use.

### Interface changes this decides

- **The CDP command log (spec #577) becomes a setting of the Run trace, off by default,** which the tests and the conformance cases that read `trace/cdp-commands.jsonl` turn on. Its name is set by the spec that builds it. Off, it does no work, as Playwright's protocol log (`DEBUG=pw:protocol`) is off by default.
- **The egress relay answers its 407 on `Fetch.authRequired` with no request patterns where it can,** so a Session whose egress the relay enforces, with no route, Filter list, placeholder or gate, pauses nothing. ADR 0014's and ADR 0017's checks stay on wherever the relay does not enforce them.
- **The Audit log prunes when the engine starts and then once a day,** on a task of `tasks`, not before every entry. An entry past `audit.retention` may then stay up to a day longer.
- **The Run-trace writer flushes its buffer** (a `write`, with no sync) when a group of outcomes commits (F2), when a Call that wrote an entry returns (Collie has no group commit, and Playwright flushes at action boundaries too), when its buffer passes 64 KiB, and when the Run ends. A process crash then loses at most the entries of the work in flight, so the Run trace stays in step with what the engine has told.

- **The Merge host (E7) is a child process of the Daemon.** Merging an update runs in a process of its own, started on first use, because an import can abort in a way `catch_unwind` cannot catch, and one update must not end a Daemon's Runs. If it dies, that update is refused and the next call restarts it. Its command is hidden and writes nothing to stdout.

### The Quality register

- **`TESTING.md`'s "Quality register" holds every limit of these contracts**, in `system-qualities`' register format: the Floor, the Enforced and Measured tables, and the Exceptions. The project has no `CONSTRAINTS.md`.
- **Every Cost contract's count has a row.** It is Measured until the gate's spec builds its command, and Enforced from that pull request on, failing the merge gate. Promotion is a tightening and needs no approval. It does not wait for ADR 0134's `GATING` switch, which keeps governing ADR 0071's +5 % comparison until #1577's pull request.
- **Retroactive adoption.** Every row starts at its figure measured on its benchmark, which is taken once the gate's spec builds it after [#1583](https://github.com/goodfetch/goodfetch/pull/1583) merges. Every gap between today's code and a contract is an Exception with the owner and an expiry date (2027-01-30, 90 days). Each Exception names the spec that removes it: #1577 for ADR 0138's counts, or the Shared paths spec for the others. No row is set at a value the current code fails on its first gate. A gap the first measure finds that no Exception names is recorded as one in the gate spec's pull request, with the same expiry: that is this adoption, not a later loosening. A row of work no code does yet starts at this ADR's value.
- **Runs at.** The rows of counted work run at implementer done, at most 60 seconds per benchmark family (`TESTING.md`'s guidance for the Quick suite). The rows read under Valgrind (instructions, allocations, bytes) run at the merge gate through `xtask perf`.
- **Coverage is a Measured row,** "must not fall" within 0.5 %. ADR 0072's weekly coverage job compares it and opens an issue when it falls, as `xtask budgets` does, and no merge fails on it.
- **The register is the source of the numbers.** The register check compares `xtask perf`'s ceilings with the register and fails on a difference. It also fails when a path in this ADR has no row, when a count in a Cost contract has no row, or when a row allows more than its contract.

### Drift, waivers and the competitor ratio

Adopted from recommendations R3, R4 and R9 of the 2026-10-31 research, as amendments of ADRs 0071 and 0134:

- **A fixed-baseline drift gate (R3).** `xtask perf` also compares the head with a pinned reference build: #1577's tuned build, then each release tag. No counted figure passes 1.10 times its reference without an ADR amendment the owner approves. A +5 % change that passes ADR 0071's comparison still adds up against this.
- **No gate is informational without an owner and an expiry (R4).** A waiver names its figures, its owner and a date or a named merge, and the gate blocks again by itself when it ends. `GATING` being `Informational` is such a waiver: it is an Exception of the register, on ADR 0071's comparison and the ceilings, ending at #1577's merge or on 2027-01-30, whichever comes first. Meanwhile the rows of this ADR gate from their pull request.
- **The instruction ratio against Spider is counted, and blocks once tuned (R9).** Foxhound's instructions per page against Spider's, both under Callgrind on scenario 1 of ADR 0138's matrix, is a Measured row; it was 32 times on the 2026-10-30 profile. Its ceiling is set from #1577's tuned figure, and it gates from that pull request. The matrix's wall-time cells stay Performance targets.

### Open questions

These are recorded here, and each blocks only the tickets that would extend its path:

1. **F1's crate.** The Page analysis's crate is set by #1577's spec.
2. **C3's cap on CDP commands per action kind.** Set from the first measure of B2, plain and human-like kinds apart. Playwright's `locator.click()` sends about 15 messages, and Collie's click sends at least 5.
   _Still open, with B2's first figures (#1881, 2026-11-02):_ the plain kinds read click 5, fill 2 and press 4 CDP commands an attempt, each held to its figure as `C3.commands`' Today. The human-like kinds have no figure: human-like input (#1018) and typing (#1022) are not built, so B2 has no cell for them. The caps are set together once those kinds are measured, plain and human-like apart.
3. **C4's one detection read, one check left.** The Consent detection runs inside `recovery`'s one composed read, and only its clicks follow as guarded actions (C3). The cap becomes 2, with the owner's approval, only if B2's first measure shows that the runner's start per document cannot join that read.

   _Answered by B2's first measure (#1866's note below; #1881):_ 4 detection reads per navigation, in every cell. The runner's start per document cannot join the composed read, as it runs from the document's first script, before the navigation's wait ends; its first-pass read can. So the cap becomes 2 with the owner's approval; until then `C4.detection_reads`' Contract stays `≤ 1` and X12 holds its figure of 4.
4. **The SDKs' framing per message** (TypeScript's `collie-client/src/framing.ts`, and Python's generated layer). It becomes a Shared path only once its CPU cost per message is measured. Until then, the engine's decode of `_meta` counts in E1, and the protocol count snapshots cover the SDKs' bytes.

> - **A folder's creation is the call that made it or found it there:** `create_dir_all`'s first try at a folder whose parent is missing, refused with `ENOENT`, is not one, nor is a sync of a folder, which SQLite does inside a counted file sync.
> - **The benchmark runs as `--strace`, with nothing beside its cells** (no run under Callgrind), and the counting VFS names the files it opened, so `strace`'s `-y` descriptors can be matched to them. B2 has no sync counter, so its syncs are not held. Its first run found 6 syncs of the Usage ledger no counter saw: B1's own setup of its Limit, through SQLite's default VFS, on the file the engine then opens through the counting one. The setup now writes through a counting VFS of its own, whose syncs the cell adds as the fixture's, never as `F2.syncs`.
> - **A bypass is planted, not a row:** `--bypass open|directory|sync` has the default cell do one raw unit a page (B1) or a command (B2) beside the counted function, in a Run trace or on a file of the counting VFS of its own, made first through what counts; `--strace --prove` expects each to fail the cell.
> - **The CI image pins `strace` at the base's Debian version (`6.13+ds-1`),** in a layer of its own at the end.

## Considered Options

- **A review rule only, with no counted contracts:** rejected. Strand E's 17 cases each passed review, because no reviewer could see the sum.
- **Ceilings on time or throughput per path:** rejected. A shared runner varies by about 2.7 % (ADR 0071), and pages per second stays a Performance target. The counts gate the causes, which repeat exactly.
- **Gating on every system call with strace, or on Rust functions' call counts under Callgrind:** rejected. Futex and epoll waits depend on scheduling (ADR 0138), and a Rust function's name or inlining changes without any change of cost. Opens, directories and syncs repeat exactly, and SQLite's C symbol is stable, so those alone are read that way.
- **Counters only inside the owner modules:** rejected. A second parse added beside the owner would not move them, which is the drift this ADR exists to stop.
- **One owner for the whole engine (a cost registry with a budget per feature):** rejected. A path with two owners has none, and a registry beside the code would drift from it. The owner module that every unit crosses already sees every feature's work.
- **Each feature caching its own result:** rejected, as ADR 0138 rejects it for the page. The next feature's module would add its own work again.
- **The driver's `Browser` as C1's owner:** rejected. Most commands pass its `try_send_within` and `send_unleased`, which record the CDP command log, but the launch's `Browser.close` (`launch.rs`) goes straight to the connection. `goodfetch-cdp`'s connection is the one seam every command crosses, so its counts see them all. The CDP command log becomes a stage the connection is given once and calls, not work beside it.
- **Registering the world once per session with `Page.addScriptToEvaluateOnNewDocument`, as Playwright and Puppeteer do:** rejected. They learn its context id from `Runtime.executionContextCreated`, and ADR 0019 never enables `Runtime`. One `Page.createIsolatedWorld` per document costs one round trip, and only on a document that is read.
- **A new request per page to tell a cut document apart, everywhere:** rejected. A second GET runs only on the charset path, where nothing else can tell (#1783).
- **Keeping one page read per detector on a navigation, under a ratchet:** rejected for now. It would leave three round trips per navigation, where one composed read gives each detector the same view. Open question 3 keeps the fallback.
- **Re-reading the settings files on each change, through a stat of their modification time or a file watcher:** rejected. A stat is counted work per unit. A watcher needs its own thread and code per platform (ADR 0060). No ADR promises that a hand edit is seen before the next Run.
- **A write per Run-trace entry with a kept handle:** rejected. It still costs a system call per entry, which no surveyed project pays.
- **Coverage gated at the merge gate:** rejected. ADR 0072 decides that coverage means every Feature is tested, not a percentage, and an instrumented build of the whole workspace on every gate would take hours.
- **Separate ADRs for Foxhound's, Collie's and the engine's paths:** rejected. The register check reads one inventory, and the built-once rules (the settings snapshot, the stores, the compile cache, the Run-trace writer) serve paths in all three.
