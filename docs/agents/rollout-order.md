**What a step is.** Each `/implement-spec` run is one whole spec, and milestones never scope a run (ADR 0136):

- **A step that names a spec** is one `/implement-spec` run of it: every open ticket of that spec, whatever its milestone. A ticket that another spec's open ticket blocks stays off its frontier until that ticket closes.
- **A step that names tickets** (steps 1, 2, 7, 9 and 15, and the tickets step 3 names after its spec) is a relay of `/implement` on those tickets alone. It is no `/implement-spec` run, so it cuts no spec into scoped runs. Each of its tickets is built on a branch from `main` and reaches `main` through a pull request that closes it; tickets that are ready together are combined into one branch for one gate (`AGENTS.md`, Merging). None lands on a spec's integration branch. A relay's pull request merges on the quick gate, whatever a test reads: only the pull request that finishes a spec takes the full gate (the owner's rule of 2026-11-14, « FULL GATE seulement en fermant une spec entière », which ended the tenth change's full gate of 2026-11-10 and 2026-11-11; `AGENTS.md`, Merging).
