# Order of work

The order the owner adopted on 2026-11-01 for the specs after [#1583](https://github.com/goodfetch/goodfetch/pull/1583), with Foxhound's refactor placed first on 2026-11-06 in [How are the browser pool spec's bookkeeping choices settled?](https://github.com/goodfetch/goodfetch/issues/2149). Each refactor spec runs right after the tickets its performance criterion is measured with, so that criterion can pass on its own pull request to `main`.

**What a step is.** Each `/implement-spec` run is one whole spec, and milestones never scope a run (ADR 0136):

- **A step that names a spec** is one `/implement-spec` run of it: every open ticket of that spec that no open ticket blocks.
- **A step that names tickets** (steps 2, 4 and 10) is a relay of `/implement` on those tickets alone. It is no `/implement-spec` run, so it cuts no spec into scoped runs.
- **#1838 is named three times and runs as a spec once.** Steps 2 and 4 take the seven tickets of it that another spec's ticket waits for, and step 9 is its `/implement-spec` run, with every ticket still open then.

**Where the order is held.** This file picks the next run. The tracker's native dependencies hold each "before" that code or a measurement requires, and each step names them, so a run started out of turn still takes no ticket too early. When this file and the tracker differ, correct the wrong one in the same change.

1. **[#1577](https://github.com/goodfetch/goodfetch/issues/1577),** ADR 0138's optimization pass, which removes the page path's Exceptions: merged on 2026-11-07 ([#2074](https://github.com/goodfetch/goodfetch/pull/2074)). Only its figures, ceilings and `GATING` tickets remain open, and they run at step 10.
2. **The tickets the raw HTTP cell is measured with,** in this order:
   - **First, the Spider arm ticket [#2213](https://github.com/goodfetch/goodfetch/issues/2213),** alone, of [Spec: just compare measures Spider honestly](https://github.com/goodfetch/goodfetch/issues/2212). It has no blocker, and it blocks every refactor spec's performance acceptance (#2176, #2183, #2191 and #2205) and #1931. It changes Spider's side of `foxhound.spider_instruction_ratio`, so a figure read before it lands cannot be compared with one read after. The spec's five new arms (crawlee-rs, pagesift, OpenSpider, fastCRW, crawlberg) are blocked by #2213 and nothing waits for them: `/implement-spec #2212` takes them at any later point.
   - **Then the Shared paths spec's HTTP path tickets** (#1838): [#2133](https://github.com/goodfetch/goodfetch/issues/2133), [#2134](https://github.com/goodfetch/goodfetch/issues/2134), [#2135](https://github.com/goodfetch/goodfetch/issues/2135) and [#1896](https://github.com/goodfetch/goodfetch/issues/1896). #1896 blocks the memory-first Run state's admission ticket (#2167). #2133, #2134 and #2135 block its acceptance (#2176), and #2133 blocks the peak memory acceptance (#2205).
3. **[Spec: memory-first Run state](https://github.com/goodfetch/goodfetch/issues/2138)** (ADR 0142), the largest gap: raw HTTP. Its admission ticket (#2167) closes #2069, a ticket of #1838 that is blocked by it.
4. **The Shared paths spec's CDP tickets** (#1838): [#1892](https://github.com/goodfetch/goodfetch/issues/1892), then [#1894](https://github.com/goodfetch/goodfetch/issues/1894) and [#2071](https://github.com/goodfetch/goodfetch/issues/2071), which it blocks.
5. **[Spec: browser pool grows with concurrency](https://github.com/goodfetch/goodfetch/issues/2139)** (ADR 0143). It starts once step 3 has merged: its Session pool ticket (#2178) is blocked by #2167, because both rewrite the code that leases work items and draws their Sessions in the crawl's delivery loop. Its page reuse ticket (#2182) is blocked by #1892 and #1894, which change the per-page code it changes, and its acceptance (#2183) by #1894 and #2071.
6. **[Spec: the extraction path](https://github.com/goodfetch/goodfetch/issues/2164)** tests a clean-up rule only where it can match, builds rules once per version and host, and reads the body as it arrives.
7. **[Spec: analysis backpressure and host fairness](https://github.com/goodfetch/goodfetch/issues/2194).** Its tickets are blocked by the Run state's admission ticket (#2167) and the extraction path's streaming ticket (#2187).
8. **[Spec: Foxhound's peak memory](https://github.com/goodfetch/goodfetch/issues/2165):**
   - What it changes: huge pages off, a profile-guided, hot-ordered static-PIE, and lazy start-up.
   - When it can run: it needs only #2133 from the steps above, so it may run earlier.
   - The research that extended it: [#2198](https://github.com/goodfetch/goodfetch/issues/2198), closed on 2026-11-07, on the ~10 MiB left at 100 and 1,000 pages. Its cuts are the spec's tickets #2200 and #2208.
9. **[The Shared paths spec](https://github.com/goodfetch/goodfetch/issues/1838),** its one `/implement-spec` run: every ticket still open then, the other paths' Exceptions. Two of them wait for tickets of step 3: #1899 is blocked by #2171 and #2172, and #1890 by #2168.
10. **#1577's closing tickets:** [#1931](https://github.com/goodfetch/goodfetch/issues/1931), [#1932](https://github.com/goodfetch/goodfetch/issues/1932) and [#1933](https://github.com/goodfetch/goodfetch/issues/1933) read the figures, the owner approves the ceilings, and `GATING` is enforced. They run last, once every refactor spec has landed: #1931 is blocked by the four performance acceptances (#2176, #2183, #2191 and #2205) and by the three tickets of #2194, which has no acceptance ticket.
11. **Features,** each spec with the path check of `system-qualities`. A ticket that extends a Shared path waits for its path's gate ticket.
