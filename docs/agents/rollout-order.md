**What a step is.** Each `/implement-spec` run is one whole spec, and milestones never scope a run (ADR 0136):

- **A step that names a spec** is one `/implement-spec` run of it: every open ticket of that spec, whatever its milestone. A ticket that another spec's open ticket blocks stays off its frontier until that ticket closes.
- **A step that names tickets** (steps 2, 5, 7 and 13) is a relay of `/implement` on those tickets alone. It is no `/implement-spec` run, so it cuts no spec into scoped runs. Each of its tickets is built on a branch from `main` and reaches `main` through a pull request that closes it; tickets that are ready together are combined into one branch for one gate (`AGENTS.md`, Merging). None lands on a spec's integration branch.
- **#1838 is named three times and has one `/implement-spec` run.** Steps 2 and 7 take, as relays, the nine tickets of it that another spec's ticket waits for. Step 12 is its run, with every ticket still open then. That run started on 2026-11-06: `spec/1838` holds 12 commits that are not on `main`, the work of #2066 and #2106, and has no pull request yet, so step 12 resumes it.
