## Free tiers and local secrets

Decided in [ADR 0076](../adr/0076-tests-and-ci-run-on-free-tiers-and-ai-calls-go-through-the-vercel-ai-gateway.md); the owner's machine in the private-period Release suite in [ADR 0108](../adr/0108-while-the-repository-is-private-the-release-suite-runs-its-macos-cells-on-the-owners-machine-and-its-hosted-cells-under-a-ceiling.md), and in the private-period pull-request tier and private fuzzing in [ADR 0135](../adr/0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md).

- **Spend nothing until the owner declares revenue.** No job, build, account or service that bills is created or switched on. Where a paid option would be better, choose the free one and record the paid one as declined.
- **Run CI on GitHub's free standard runners.** Since the repository became public on 2026-11-22 ([ADR 0135](../adr/0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md)'s note of that day), its standard hosted minutes are free and draw on none of GitHub Free's 2,000 included minutes a month, which the account's private repositories share and every minute budget here was set for (GitHub Pro bills, so it is declined). Larger runners bill, in public repositories too, and are declined. No self-hosted runner serves the repository while it is public. Until the hosted-CI spec ([#3373](https://github.com/goodfetch/goodfetch/issues/3373)) moves CI, the pull-request tier is the local gate ([Suites, commands and time budgets](suites-commands-and-time-budgets.md)), and fuzzing runs nightly on the rented gate host ([Fuzzing](security.md#fuzzing), #2454, `ci/fuzz-nightly.crontab`). A self-hosted runner never runs a pull request from a fork.
- **Run every job on one standard hosted label.** `xtask workflow-policy`, a `just lint` step, refuses a job whose `runs-on` is a self-hosted or larger-runner label, a runner group or an expression it cannot resolve; `pull_request_target`, and a `workflow_run` job that checks out a pull request's code; a workflow whose top-level `permissions:` is not `{}`; and a `uses:` pinned by neither a full commit nor an image digest ([ADR 0108](../adr/0108-while-the-repository-is-private-the-release-suite-runs-its-macos-cells-on-the-owners-machine-and-its-hosted-cells-under-a-ceiling.md)'s amendment of 2026-11-22, [#3385](https://github.com/goodfetch/goodfetch/issues/3385)). Other uses of the owner's machine (the Performance series, the release-candidate benchmark, the test V8 build, the Chromium build gate) run outside GitHub Actions until a decision of their own brings a runner back. The owner removes the `owner-mac` runner from the repository ([#3386](https://github.com/goodfetch/goodfetch/issues/3386)).
  _Why:_ a self-hosted runner executes whatever a branch's workflow asks, and larger runners bill.
- **Let usage stop at its budgets.** Since the owner's approval of 2026-11-21, the GitHub organization holds a payment method, under budgets that stop usage when reached: $20 a month for Actions beyond its included minutes, and $0 for every other metered product (Codespaces, Packages, Git LFS, Copilot and the rest) ([ADR 0076](../adr/0076-tests-and-ci-run-on-free-tiers-and-ai-calls-go-through-the-vercel-ai-gateway.md)'s note of 2026-11-21). So GitHub blocks Actions usage once the included minutes and the $20 are spent. Raising a budget, or removing a stop, is the owner's. A self-hosted runner costs nothing today, but GitHub postponed, without cancelling, a $0.002-a-minute charge for self-hosted runners in private repositories. If it returns and would bill money, the owner's-machine cells stop. Once GitHub announces a date for it, open a `needs-triage` issue that links ADR 0135, so the pull-request tier's and fuzzing's design is revisited before that date.
- **Time on the owner's machine, never publish it as the reference class.** The Performance series and the release-candidate benchmark run on the owner's machine (Apple M3 Max) when it is on, labelled with that machine; the rented reference host and the benchmark's paid services (proxies, CAPTCHA solving, model spend) are declined, and published reference-class runs wait for revenue. A comparison report is published labelled with its machine, never as the reference class, under ADR 0025's notes of 2026-11-10.
- **Use free tiers for outside accounts.** Real SaaS Sink accounts and Integration platform accounts use free plans only; a Sink with no free tier keeps its emulator suite and its Live check waits. LocalStack runs on its free open-source licence; if that is refused, the affected Sinks use free emulators such as MinIO, or wait.
- **Keep local secrets in `.env`, written by `scripts/env-setup.sh`.** It is git-ignored and mode 600; `.env.example` lists every name, what it is for, the milestone that needs it and the page that creates it. Add a new secret to `.env.example` in the pull request that first needs it.
- **Never read `.env` from a test.** Test support clears the environment (ADR 0059); only the recipes that run Live checks load `.env`, each on its own, so the `justfile` never uses a global `set dotenv-load`. CI reads the same names from GitHub Actions secrets.
- **Never print, log or commit a secret's value,** including in a failure message or a recording; Secret canaries and `gitleaks` check it (ADR 0067).
