## Security

Decided in [ADR 0067](../adr/0067-security-is-tested-per-trust-boundary-with-secret-canaries-and-private-fuzzing.md). The Quick, Pre-merge and Release suites are those of [Suites, commands and time budgets](suites-commands-and-time-budgets.md): the Pre-merge suite runs on Linux, and the Release suite on the full matrix in the merge queue once it exists, and until then on manual dispatch before each milestone's owner test and before any release, on the private-period matrix of [Suites, commands and time budgets](suites-commands-and-time-budgets.md). Live checks are those of [Flaky tests and Live checks](flaky-tests-and-live-checks.md#live-checks), in no suite.

### Fuzzing

- **Every decoder of input Goodfetch did not write itself has a `cargo-fuzz` target.** Today: JSON-RPC, plugin-protocol, peer-protocol and Script sandbox pipe framing; catalog-call arguments; CDP messages; HTML and Markdown; sitemaps, robots.txt and Site preference files; run-state import; Checkpoint and session-export bundles; Plugin manifests, OCI image indexes and bundle unpacking; Recipes and settings files; Secret references; certificate and key files; Filter lists; Session source formats, `Cookies.binarycookies` included; extraction schemas; URL canonicalisation and the resolved-IP classification.
- **Write each target's body as a plain function**, and replay its seeds and every past crasher from a `#[test]` on every OS.
  _Why:_ cargo-fuzz does not build on Windows, and path handling differs most there.
- **Replay a target only with `goodfetch_test_support::fuzz_replay!(body, "fuzz/<target>")`**, once per target, in its own module of the crate's unit tests, so it runs in the Quick suite. It writes a `#[test]` that runs `body`, the target's `Fn(&[u8])`, over every file of `fuzz/<target>/seeds/` and then of `fuzz/<target>/crashers/` (relative to the crate's manifest folder), and fails naming each file the body panicked on; it prints each file as `goodfetch-fuzz-replay=<path>` before running it, so an input that aborts the process is named too. A missing or empty `crashers/` passes; a missing or empty `seeds/` fails. Commit each minimised crasher in `crashers/`.
- **Check more than crashes where a pair exists:** round-trip for encoders and decoders, and the resolved-IP classification against the reference table built from the IANA registries.
- **Commit seeds and a dictionary per target.** The grown corpus stays private.
- **Never fuzz in a pull request or in a gate.** Fuzzing is a Live check. While the repository is private and the owner rents the gate host, it runs there nightly from cron, against `main`'s head, by a script of the repository that runs every target with `cargo fuzz run` on the pinned sanitizer toolchain and prunes each corpus with `cargo fuzz cmin`; no merge fails on it; ClusterFuzzLite, push fuzzing and continuous builds do not run while the repository is private (owner, 2026-11-10, grilling of G-09, Q3 and Q6; [ADR 0135](../adr/0135-while-the-repository-is-private-the-owners-machine-runs-the-pull-request-tier-in-a-throwaway-linux-vm-and-private-fuzzing-nightly.md)). That job is **`just fuzz-nightly [ref]`** (`ci/fuzz-nightly.sh`, #2454), started by the entry in `ci/fuzz-nightly.crontab`, in a worktree of its own. The run is one hour in all, on 4 cores at the lowest priority, each target the same share of it: the hour divided by the rounds the 4 cores take, one round per 4 targets (720 s each for 17 to 20 targets); it skips its night while a gate, the backstop or a test-health run holds its lock, and stops, with everything it started, when a gate starts: the gate signals it and waits only for that stop (`ci/merge-pr.sh`), so no gate waits for the fuzzing itself (the grilling session's choices, shown to the owner as a list on 2026-11-10 and not changed). Each target's corpus is kept between nights in `~/fuzz-nightly/corpus/` (`GOODFETCH_FUZZ_LOG`), listed before the committed seeds so a run never grows them, and pushed to the private fuzzing repository after its `cmin`; without a clone of that repository on the host (#2456), the corpora and any crash's input stay on the volume, and the night's line in `~/fuzz-nightly/results.txt` says so.
  _Why:_ a random check inside a gate can fail a pull request for a crash that was already on `main`, and a public job's logs and artifacts would disclose such a crash before its fix.
- **Keep fuzzing's results in the private repository.** They never go to the results store or its published report.
- **The job that builds and runs fuzz targets holds no secret** and a token with no permissions; a later job stores its results.
- **Run ClusterFuzzLite's images by digest** from Goodfetch's workflow, never through its action's `:v1` tag.
- **Send every new crash to a private security advisory draft** on the main repository, never a public issue. Until the main repository is public, which advisories need, open an issue in the private fuzz repository instead; the nightly job files it, with the input shrunk by `cargo fuzz tmin`, and the ticket below, marked `ready-for-agent`; while a target's ticket is open, a new crash of that target gets its own issue and a comment on that ticket in place of a second ticket. The issue holds the input. A ticket in the main tracker names the target and links the issue, without the input; the relay takes it before its other tickets, and it fails no gate. When a spec of the order is about to rewrite the decoder, the ticket is attached to that spec's ticket instead, which must pass the input (owner, 2026-11-10, grilling of G-09, Q7 and Q8). A crash that also crashes the previous continuous build joins its advisory, or opens one. Fix it from the advisory's private fork (before publication, an ordinary pull request), and commit the crasher, minimised with `cargo fuzz tmin`, as a regression input with the fix.
- **An open fuzz crash blocks the promotion of the next minor** until it is fixed or triage closes it as not a vulnerability. Patches are not held. Never post a private result (the Private component run or fuzzing) on a public commit. The release pipeline reads them from the private repositories when each step starts, with the read-only private gates App: the Private component run for candidates and patches, and also open fuzz crashes for promotion to `x.y.0`. A promotion held while every public gate is green does reveal that a fuzz crash is open; this is accepted, since it shows neither the target nor the input (ADR 0067).
- **Fuzz, and run the ASan tests, on one nightly toolchain pinned in its own file**, apart from `rust-toolchain.toml`: [`ci/sanitizer-toolchain.toml`](../../ci/sanitizer-toolchain.toml), with the cargo-fuzz version. **`just fuzz-check`** runs `cargo fuzz check` of every target with it, in the Pre-merge suite's `supply-chain` job; a fuzz crate's `Cargo.lock` must be current.
- **Run the tests of every crate that opts into `unsafe` under AddressSanitizer** in the Release suite, on Linux glibc: **`just asan`**, the standard library rebuilt with the sanitizer. It runs the crate's unit tests and its integration tests in a module named after a module on the opted-in file's path; the others drive the crate's own sanitized executables and compare their output byte for byte.

### Confinement

- **Generate Plugin confinement cases from the policy.** One probe per rule of each generated seccomp, Landlock, Seatbelt, AppContainer and broker policy, at each network level. A rule without a probe, or a probe without a rule, fails.
- **Assert the exact error** ADR 0033 gives for a call the seccomp, Landlock or Seatbelt policy refuses: a kill or an allowed call fails the test. Resource-limit probes expect the limit's own Error code.
- **Pair every refusal with a positive control:** the same probe first succeeds unconfined, in the same test.
  _Why:_ a probe that fails for an unrelated reason would otherwise pass as a refusal.
- **Assert the mechanism each runner uses** (Landlock ABI, user namespaces, mount-namespace fallback), so a silent fallback fails. A container under Docker's default seccomp profile on a kernel before 6.12 must refuse with `confinement_unavailable`.
- **Test the Script sandbox worker as if V8 were broken:** run the probes under the worker's own generated policy, and inspect a live worker (`Seccomp:` and `NoNewPrivs:` on Linux, an AppContainer token on Windows, the spec's method on macOS). In the Release suite, on Linux x64, run corruption scripts on a V8 build with `v8_enable_memory_corruption_api`; each must end as `script_crashed`.
- **Build the test V8 once per V8 version**, in its own required check on the pull request that changes the version, outside the Pre-merge suite's "all green" check. The job skips when that version's build is already published. A later job attests it and publishes it as a release asset, as the Goodfetch Chromium is. The author commits its digest, which a check matches against the attested asset. A fork's pull request cannot attest, so a V8 change from a fork is rebuilt from a branch of the main repository. The Release suite fetches the build by digest before the outbound deny and never builds it.
- **Check that every renderer is sandboxed** for each browser Goodfetch launches: `Seccomp: 2` and `NoNewPrivs: 1` on Linux (Ubuntu 24.04 with its AppArmor restriction on), `chrome://sandbox` on Windows, Seatbelt on macOS. Test ADR 0049's startup probe in its refuse and record cases.

### Egress and hostile input

- **Keep SSRF cases in one table, as data, and run it at every layer:** the resolved-IP classification in-process, the HTTP tiers, the egress proxy, browser Sessions for every request type of ADR 0014, raw CDP, a Lent page whose client also tries a browser context with its own proxy and an extension (ADR 0089), the relays of ADRs 0042 and 0044, a Borrowed browser, Plugin traffic, and Sinks and webhooks under "no private endpoints".
  - Collie's layers are data, in [`test-support/fixtures/ssrf/layers.toml`](../../test-support/fixtures/ssrf/layers.toml): each layer, the runners that apply the table to it and the families each runs, and why a layer never meets a family every layer meets (encodings, IPv6 forms, the IANA blocks, mixed answers, redirects, rebinding, the upstream proxy path); a layer not built yet is `pending`, naming the ticket that builds it. The Quick suite fails on a built layer with no runner, a family a layer skips without a reason, a family of the table no layer runs, and a runner its test file does not hold (`goodfetch-test-support`'s `ssrf_table::every_layer_collie_carries_has_runners_for_every_family_of_the_ssrf_table`). A new layer joins the file with its ticket.
  - Foxhound's HTTP tier runs it on reqwest and `wreq` (`goodfetch-fetch-tier`'s `tests/it/addresses.rs`), directly and through the Proving ground's open proxy, resolving through the DNS fixture in process on every OS: a case's lookups become the fixture's name that answers them (`mixed.dns.test` for one lookup, `alternating.dns.test` for one answer per lookup), a domain-policy case keeping its own host. The discovered-API tier is not built yet; it takes the same transports and joins the runner with its ticket.
- **Cover every family:** encodings; IPv6 forms (IPv4-mapped, NAT64, 6to4, Teredo, zone IDs); every IANA special-purpose block that is not globally reachable; names with mixed answers; redirects of every kind and to non-HTTP schemes; rebinding; the upstream proxy path.
- **Assert that no connection reached the target**, from the Proving ground's connection-recording fixture, and the typed refusal.
- **Test rebinding against the Proving ground's DNS fixture**: end to end on Linux in a network and mount namespace whose resolver points at it (`DnsNamespace`, in a module compiled for Linux only, so no other OS runs it and Linux never skips it); in-process on every OS with a scripted sequence of answers. Never use a public rebinding service.
- **Keep the IANA special-purpose registries committed with their date**, in `crates/goodfetch-engine/iana/`, beside the classification table `xtask codegen` writes from them, so `xtask codegen --check` fails when the two drift. The classification's differential test reads the same files through `goodfetch-test-support`'s own parser. A nightly watch job, which runs none of the product, opens an issue when they change.
- **Test the hostile-input set where each case can happen:** CR, LF or NUL in header values (Recipes, Sinks, webhooks, CDP); a domain-bound Secret across a cross-origin redirect; path traversal into every file Goodfetch writes from outside input, with each OS's cases; external `$ref` in extraction schemas; no process spawned to compare page content (checked under a seccomp filter that refuses `execve`); decompression bombs, endless bodies, deep nesting and oversized messages ending in their typed limit errors.
  - A layer refuses through `goodfetch-engine`'s one check of each kind, whose unit tests run the whole table: `hostile_input::check_headers` before a header leaves, `hostile_input::check_path` before a name from outside input names a file, and `response_limits` (`Decoding` or `parse_json`) as a body is read. A layer's own test drives it end to end against the Proving ground's pages (`bombs/*`, `body-limits/*`) with a positive control, and asserts the memory bound from the Proving ground's record of the bytes it sent.

### Endpoints

- **Run the endpoint table against every listener:** the Daemon's socket and WebSocket, the HTTP listener, the ops listener, MCP over HTTP, the Live view, raw CDP, the Attached engine's private endpoint, an Exposed Daemon and the peer link.
  - A Session's proxy relay (`goodfetch-page`'s `proxy::relay`), a listener outside `transport`, binds a port of its own on `127.0.0.1` for its Session's life and relays its client's connections to the Session's proxy, adding the proxy's credentials. It is an HTTP proxy that tunnels only for its per-Session credentials (`Endpoint::HttpProxy`: user `goodfetch`, the token as the password of a `CONNECT`'s `Proxy-Authorization: Basic`), which the engine answers the browser's `Fetch.authRequired` with and the egress relay sends. Its column (`proxy_relay`) runs in process in `proxy::relay`'s tests, against a fake SOCKS5 proxy, with the Run's Audit log on a test home as the verifier, since its token never leaves the engine. A request without credentials is answered with the `407` challenge every client meets first (`{ expect = "challenge" }`, no Audit log entry); a wrong token, another Session's relay's among them, is refused with a `407` and recorded.
  - The committed table, [`test-support/fixtures/endpoint-table.toml`](../../test-support/fixtures/endpoint-table.toml), is the one source of its rows and columns; nothing else lists them. A listener joins as a column with its ticket, and a rule as a row with the first listener it applies to. The Quick suite fails on a row that applies to no listener, a listener with no row, and a cell its listener's transport cannot try.
  - A listener's tests call `EndpointRunner::new(verifier).run(&listener)` from `goodfetch-test-support`, with the listener's kind, address, token and the token of another listener as a value, and the product's reader of its Audit log as the verifier. The runner first sends the valid `hello` or request, which must be accepted, then every row of the listener's column, never skipping one, and fails each row whose answer or Audit log entry is missing.
  - The rows presenting a token of their own take it from the listener's description (`with_other_listener_token`, `with_expired_token`, `with_revoked_token`, `with_scoped_elsewhere_token`), and a row whose token the test does not give fails. The Collie listeners' tests read their refusals from the Audit log through `tests/it/endpoint.rs`'s `audit_verifier`.
  - A regression test of an advisory calls `run_advisory(&listener, "CVE-…")`, which runs only the rows whose `advisories` cite it, after the positive control, and fails when no row of the listener's column does. The token comparison's timing is a property of `goodfetch-engine`'s `endpoint` interface: guesses sharing no prefix and all but the last letter, timed in a seeded interleaving, show no difference Welch's t finds.
- **Cover every row:** missing, wrong, expired, revoked, out-of-scope and other-listener tokens, and tokens in a query string; a foreign `Host`; a foreign or missing `Origin` on the request and the WebSocket handshake; plain HTTP where TLS is configured; `X-Forwarded-*` from an unconfigured address; each listener's own rules (ADRs 0031, 0049, 0050, 0055, and MCP's audience and no passthrough). Check each refusal in the Audit log.
- **Fuzz the protocol from the committed JSON Schema bundle** with `proptest` and `proptest-state-machine`, over every transport. Every invalid call gets a typed error and changes no state.
  - A listener's test calls `ProtocolFuzz::new(ProtocolSchema::committed()?).with_valid_calls(&[…]).run(config, connect, state)` from `goodfetch-test-support`. It reads the bundle and the catalog file as files, so a change to the contract changes the calls with no hand edit. `connect` opens a new Connection, past its `hello`, for each sequence; the transport is the caller's `ProtocolTransport`, which returns the reply carrying a call's id. `state` reads the state the calls may change, such as the files of the engine's Goodfetch home.
  - Each sequence mixes invalid calls of every operation, one breach each (an unknown operation, params that are no object, a missing or unknown property, a value its schema refuses), with valid calls of the operations `with_valid_calls` names, which must answer at once. An invalid call fails the property unless it gets a typed error that is not internal and leaves `state` unchanged; a valid call fails it on an internal or untyped error or a result its schema refuses, and its state becomes the one the next calls are checked against. A failure is reported as the sequence proptest shrank it to.
  - Run it at `proptest_config()`'s size with the test's seed and with `source_file` set to `file!()`, so proptest writes its regression file under the crate's `tests/proptest-regressions/`, which is committed.
- **Run the MCP conformance suite against MCP over HTTP**, in the suites and on the platforms [ADR 0070](../adr/0070-mcp-adapters-and-integrations-are-tested-through-their-platforms-own-clients-against-a-real-engine.md) gives it.

### Secrets

- **Plant a Secret canary for every kind of secret** (typed password, TOTP seed, emailed or texted one-time code, proxy password, HTTP authentication password, a header or JSON value sent by `page.request` or a route, a value a `caller:` resolver returns, model API key, webhook signing secret, Sink credential, Session cookie, endpoint token, run data key), through the Proving ground's login flows and every Secret provider (ADR 0092).
- **Search every output for every Secret canary**, raw and JSON-escaped, URL-encoded, base64 and hex, and inside the Basic `Authorization` and `Proxy-Authorization` headers the engine builds. The outputs are:
  - logs, Run traces, HAR files and console captures, and screenshots and recordings where masking applies;
  - the OTLP export, read through an in-process OTLP collector (ADR 0132);
  - the Audit log, the Effect journal, and Checkpoints outside their encrypted fields;
  - Exports and Notifications;
  - JSON-RPC errors, error messages in run state, and model requests;
  - `doctor`'s file, and the SDKs' `repr`, `toString` and errors;
  - what a call returns and an event carries: reads such as `inputValue`, page function results, extracted values, Records, response bodies, and page and network events, for every canary but a one-time code, masked only where it was typed, and a Session cookie, which `cookies()` and network events return by design;
  - Plans (ADR 0092).

  _Why:_ redaction is best effort against arbitrary transforms, but Goodfetch's own encodings are known.
- **Property-test redaction** with generated values that are hard to redact (quotes, backslashes, newlines, `%`, Unicode, very long, empty, common words, values that contain one another), through every formatter and serializer. Commit `proptest-regressions/`.
- **Scan each CI job's logs, test reports, snapshots and artifacts with the `gitleaks` binary** (pinned by checksum, Secret canaries added as a rule) before they upload. A hit fails the job. Each job that uploads runs `ci/leaks.sh` over every path it uploads, with `if: always()`, and each upload waits for that step's success; `xtask output-scans` refuses an upload without it. The scan runs gitleaks' own rules ([`ci/gitleaks.toml`](../../ci/gitleaks.toml)) and the canaries' rule; `just leaks <path>…` runs it locally. A job's live log reaches GitHub as each step runs, so no step scans it first: the canary searches of the tests that write it stand there.
- **Scan commits,** Model recordings included: with GitHub secret scanning and push protection once the repository is public ([`.github/security-settings.md`](../../.github/security-settings.md)); until then with `gitleaks` over each pull request's commits in the Pre-merge suite (`just commit-leaks`).

### Other rules

- **Property-test the Audit log's hash chain:** an edit, deletion, reordering or truncation of entries or of the tail fails verification, a Daemon group's single chain included.
- **Add one regression test per bypass** at the layer it slipped through, Goodfetch's own or a class a comparable project disclosed. Cite the advisory in a comment. A nightly watch job lists new advisories of comparable projects and opens an issue.
- **Never skip a security test where it is scheduled.** The OSes in the boundary table are the schedule, and a test's absence from an OS its row does not give is not a skip. On a scheduled host, never `#[ignore]` it, return early or gate it at run time; where the host lacks a mechanism, assert the refusal (`confinement_unavailable`, `local_address_unavailable`). A missing tool fails the job.
- **Pin every container image a workflow runs by digest.** `xtask image-pins`, in `just lint`, reads each job's and service's container, each `docker://` step and action, each Containerfile's `FROM`, each `image.toml` pin file under `ci/` and each literal image a `run:` script or `ci/` script names.
- **Run CodeQL** on Rust, TypeScript, Python and the workflows in the Pre-merge suite once the repository is public. A high or critical alert blocks the merge. `.github/workflows/codeql.yml` skips its jobs while the repository is private; the owner's checklist turns the merge protection on.

### Manual security tests

Only these stay manual. They are not Journeys: none has an automated step, and each runs on a release candidate rather than at a milestone's owner test. They are named by title.

| Manual test | When | What a person does | Recorded on |
|---|---|---|---|
| Threat-model review | each minor's release candidate | Walks the trust-boundary table against the minor's changes and confirms each new decoder, listener, Plugin kind, widening setting, Secret kind and output has its test | the release pull request |
| Vulnerability triage | each new fuzz crash, external report and advisory-watch issue | Judges it against `SECURITY.md`'s vulnerability definition; opens the private advisory or closes with a reason | the advisory or issue |
| Independent security assessment | before 1.0 and each later major; declined while there is no revenue (ADR 0076), the manual threat-model review stands in | An outside tester attacks the boundaries; each finding gets a fix and a regression test | a report linked from the release notes |
| Confinement where CI cannot run | each minor's release candidate | WSL1's refusal; Bridge Sinks under Docker Desktop and Podman machine on macOS and Windows; the documented host-firewall recipes for `direct` | the release pull request |
| Passkeys on real authenticators | each minor's release candidate | Sign-in, step-up and recovery on a platform authenticator and a hardware key | the release pull request |
