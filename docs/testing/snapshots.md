## Snapshots

- **Tools:** insta in Rust, Vitest's snapshots in TypeScript, inline-snapshot in Python.
- **Inline for short values** (about 20 lines); a file for longer ones: insta's `.snap` files, Vitest's `toMatchFileSnapshot` or `toMatchSnapshot`, inline-snapshot's `external()`.
- **What snapshots cover:** structured outputs (JSON-RPC responses, CLI output, generated surfaces, extraction output). Never instead of a precise assertion on one value.
- **Every varying value is redacted or filtered** (IDs, times, durations, temporary paths), with the shared settings of test support.
  - The rules are committed once, `test-support/fixtures/snapshot-filters.json`: the test's folder, the executable's Product version and commit, matched literally, then ULIDs and Schedule IDs, RFC 3339 instants, durations and port numbers on loopback hosts. A value no rule names stays, so a change to it fails the snapshot.
  - Rust binds `snapshot_settings(&SnapshotValues::of(&env).with_executable(version, commit))` around its insta assertions; TypeScript and Python snapshot `redact(output, values)` (`{ folder, productVersion, commit }`; `folder=`, `product_version=`, `commit=`).
  - A path the output prints that no rule names, such as an executable's in a `fix`, is named with `.with_path(path, "[COLLIE]")`, never a filter of its own: it is matched in the folder's forms, its canonical path among them, since an executable names itself by the path the OS gives it, canonical on Linux, and a build folder reached through a link (`CARGO_TARGET_DIR` on another disk) prints in another form than the test's path. Rust's `redact(text, &values)` applies the same rules to a value a test compares without a snapshot.
  - On Windows, Rust's rules also match the separators under each named path written as `/`, so `[FOLDER]\home\0.0` prints as `[FOLDER]/home/0.0` and one snapshot serves every OS (issue 2900); TypeScript's and Python's `redact` do not yet.
- **CI never writes a snapshot and fails on a mismatched, missing or orphaned one:** `cargo insta test --check --unreferenced reject`; Vitest in CI; inline-snapshot, which raises on an empty `snapshot()` there. While the quarantine list skips a nextest test, its snapshots look orphaned, so `just test` lets unreferenced insta snapshots warn instead, and says so, until the test leaves the list.
- **Snapshots change only through the tool's update or review command, never by hand:** `just snapshots [packages]` runs the tests and reviews insta's changes (`cargo insta test --review`), updates the changed pnpm packages' Vitest snapshots (`-u`), and reviews inline-snapshot's (`--inline-snapshot=review`); `just snapshots accept` writes them all without review. inline-snapshot updates run single-process (`-n0`), since under xdist it can neither create nor fix one. CI runs neither.
- **A snapshot change is reviewed as a change of expected behaviour.**
- **A file a Rust test writes and another language's test reads is an insta binary snapshot** (`assert_binary_snapshot!`), so the Rust test fails when the file's bytes change and the commands above update it. Pitfall D07's XLSX Export is one (issue 1679): the D07 acceptance test of `goodfetch-foxhound`'s `tests/it/exports.rs`, in the Pre-merge suite, keeps the workbook as `tests/it/snapshots/it__exports__d07_books.snap.xlsx`, and `sdks/python/foxhound/tests/unit/test_export_xlsx.py`, in the Quick suite, opens it with openpyxl and reads every Record back.
  _Why:_ no Rust spreadsheet library fits the workspace's one build: calamine turns on another deflate backend for every crate built with it, which changes the Proving ground's compressed bodies.
