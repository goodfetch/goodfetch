# Features

The Feature inventory and its sources (ADRs 0072 and 0075; `TESTING.md`, Feature coverage):

- `inventory.json`: every Feature, generated by `xtask codegen` from the files below, ADR 0037's matrix, `goodfetch-protocol`'s catalog (Block causes included, as the shared type `block_cause`'s values), both executables' clap command lines and each Console package's committed route list (`console/<package>/routes.json`), with the Products that carry each. Never edit it by hand; `xtask codegen --check` fails on drift.
- `stories/<area>.toml`: each area's user stories, with ADR 0075's `journey` and `not_journey`, and `product = "foxhound"` on a story of Foxhound's part (area 4's 94 to 122, areas 6's and 8's from 201, area 11's from 1001, and area 3's 40 and 41, a work item's lease and its delivery), which Collie's view then leaves out (ADR 0094). `rows.toml` takes the same field on a row of Foxhound's alone.
- `rows.toml`: each matrix row's milestone.
- `areas.toml`: the owning area of each generated Feature, by kind and ID prefix.
- `exceptions.toml`: the Features no pinned test can prove.

Each file's JSON Schema sits beside it as `<name>.schema.json`, written by `xtask codegen` (`stories.schema.json` for every stories file). `xtask features check`, in `just lint`, is the Feature check over the Rust `Covers:` lines and the Journeys' and conformance cases' `covers` lists; `just features-tests`, in the Pre-merge suite, runs it with the runners' listings too, so Vitest tags, Playwright annotations and pytest markers count. `just features` prints what the changed packages declare and the check's findings. `xtask features audit` (`just features-audit`, after `just test pre-merge` or `release`) is the exercise audit: it fails a Rust test that declares an `operation:`, `error:`, `event:`, `command:` or `exit:` Feature its exercise record, in `target/test-records/`, never shows it reached; the Pre-merge and Release suites run it with the justfile's `exercise_audit` verdict, `gate`, so a finding fails them. `xtask features report` reads these files with the declarations, `quarantine.toml` and the results store, and writes each Feature's status at a milestone's gate as JSON and HTML, which the daily test-health job attaches to its run (`TESTING.md`, The report). `vitest.config.ts` and `playwright.config.ts` read `inventory.json`, checked against its schema.
