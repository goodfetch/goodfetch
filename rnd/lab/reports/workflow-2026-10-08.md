# Durable workflow and shared SQLite — October 8, 2026

The lab now has the prototype **acquisition → extraction → validation → bounded queue → batched writer → commit → ack**, with idempotent recovery. The write track adds synchronous Rust and Go, compared with Node using **the same SQLite 3.53.4 artifact**.

**Retained results: 153/153 cells verified, 606,528 SQLite rows read back, 1,344 workflow jobs acknowledged and verified, i.e. 19,776 extracted records.** The full suite passed 28 tests, then the new real Crawlee pool test passed after its fix: **29 distinct qualified tests**. TypeScript, the backends doctor and the Rust/Go format checks pass. [Detailed verification](verification-2026-10-08.json).

These are exploratory measurements on a shared Mac, not proof of an architecture or of universal superiority. The tables concern specific local workloads; Rust/Tokio remains a candidate for the portable core.

## Writing: runtime and binding under a shared SQL engine

The three synchronous bindings load a single C library, with a reused statement and one call to the shared shim per insert: Node N-API, Rust FFI, Go/cgo. Node **25.5.0**, Rust **1.93.0**, Go **1.27.1**, Apple M3 Max, macOS 27 arm64. The SHA-256 of the library actually checked is `d2d6f564187c2a0e2dd4f83e11316c50beca8023ff1bb4a5083b840d9c5dd170`. Version, source ID, compile options, loaded path and PRAGMAs are checked for each connection. The build sources and the campaign sources are frozen.

Bindings, allocations, JSON encoders and protocols remain different: the figures compare these implementations, without isolating a property of the language. The historical embedded Node SQLite and Rust SQLx remain in their separate tracks; they do not use this shared artifact.

Verified row throughput: sum of rows / sum of write durations of the two blocks. Each cell has 48 batches, a 512-byte ASCII payload, eight producers; W denotes real processes on the same database. Startup, final close/checkpoint and oracle are separated. B1 cells sometimes last only a few milliseconds: their figures are particularly sensitive to noise.

## Engineering result: Crawlee pool wake-up

The workflow exposed an interaction between writer backpressure and the pool: the Crawlee queue can become empty between two admissions. The pool then checks for tasks periodically, with a default of 500 ms observed in Crawlee 3.18.2. The public `notify()` API triggers an immediate check. A separate series compares the two integrations, without changing the record guarantees. [AutoscaledPool API](https://crawlee.dev/js/api/core/class/AutoscaledPool).

A first integration called `notify()` before native initialization had finished. The test detected the timeout; the experimental campaign was stopped and excluded. The fix waits until a first handler has actually started before allowing the notification. The real test and the 20 subsequent cells pass. The diagnostics and sources of the interrupted experiment are kept.

The A/B series uses **12 jobs per cell**, two randomized blocks and the same fixtures as above. Compare the modes within this series; do not confuse its small batches with the 24-job ones in the previous table. Each p95 aggregates 24 jobs.

| C | Jobs/batch | Poll, jobs/s | Notify, jobs/s | p95 ack poll, ms | p95 ack notify, ms |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 1.9 | 17.3 | 525.6 | 213.5 |
| 4 | 1 | 8.2 | 16.6 | 515.8 | 295.5 |
| 4 | 4 | 7.0 | 17.0 | 514.5 | 246.6 |
| 8 | 1 | 17.3 | 15.9 | 292.4 | 399.1 |
| 8 | 4 | 10.0 | 16.9 | 458.7 | 335.2 |

At C1, throughput improves by about **9×**. At C8/B1, notify does not win in this series. The response depends on admission, lifecycle and batch size; a single setting is not enough to become a general winner. This result shows why the acquisition/sink integration must be tested before drawing conclusions about a language.

## Recovery: contract actually verified

Twelve cells inject a SIGKILL into the writer: before COMMIT, after inserts in the transaction; or after COMMIT, before the response. Each restarts once. The **144 jobs / 576 records** end up acknowledged and exact, with no duplicates. Before commit, the transaction is rolled back and the lease is waited out, then replaced. After commit, the persisted receipts are validated and reconciled; the other interrupted jobs are resumed after their lease expires. The aborted attempts remain in the raw data, and recovery is counted in the workflow duration.

Two functional tests also stop a coordinator with its workers, then start a **new coordinator process**, after claim or between commit and ack. The fixture server and the external oracle stay alive. Recovery is exact; its latency across this full stop is not yet measured. The other tests cover fencing of stale tokens, identical replay, data conflict, queue bound, batching and rejection of a false success before writing.

This prototype has no migration, heartbeat, continuous backlog admission or exactly-once guarantee on an external effect. The qualified recoveries concern idempotent HTTP reads. No crash during click/payment, distributed reader, full disk or power loss is qualified. [Detailed contract and commands](../docs/workflow.md).
