# Goodfetch — crawl, resource and worker capability matrix

State of the sources as of **October 7, 2026**. The Goodfetch contracts are **proposed**, they do not describe an existing implementation. Scope: Crawlee TS/Python, Spider, Scrapy, Colly, Crawl4AI, Firecrawl, Scrapling, Katana, Apache StormCrawler and relevant browser transports/clients. It does not claim to cover every project in the world or every option of every repository.

Supplementary research: **`sources_reviewed = 10`**, two Exa calls of five results for Katana and StormCrawler, followed by primary inspection of the sources. Reuse of previous research ([engines](2026-10-07-crawl-engines.md), [Crawlee/Spider contracts](2026-10-07-crawlee-spider-contracts-followup.md), [engines/workers/browsers](2026-10-07-engines-workers-browsers.md)) without recounting their results. The archives and files were read; no benchmark or run of these projects was performed for this matrix.

## 1. Reading the matrix and pinned references

**Present** means that a mechanism is observable in the sources; **option** that a backend, plugin, feature or parameter must enable it; **not established** that the audit does not allow the property to be promised, without proving that it is impossible. "Durable" must always specify what is persisted, when and with which backend. "Pool", "adaptive" and "worker" are not single capabilities.

## 2. Families: do not adopt the wrong level of abstraction

| Tool | Core role | Runtime / acquisition | Browser | Observed native distribution | Useful position for Goodfetch |
|---|---|---|---|---|---|
| Crawlee TS | URL processing, handlers, queue, sessions, autoscale, storage | Node/TS, replaceable HTTP clients; optional Impit | Playwright/Puppeteer; separate Stagehand adapter | A local async pool is not a distributed fleet; multi-client queue depending on the backend | Functional reference and ecosystem bridge. |
| Crawlee Python | Same family, distinct storage clients | Async Python, HTTP and parsing | Playwright; Stagehand REST + Playwright/CDP | SQL/Redis coordinate claims; worker deployment remains to be provided | Reference for queues independent of the browser engine. |
| Spider | Rust HTTP/rendering/budget collection, smart and hooks | Rust/Tokio, reqwest | Chromey → Chrome/Chromium CDP; optional features | `decentralized` + `spider_worker` HTTP Rust/Warp/Hyper | Adapter and specialized components; durable frontier owned by Foxhound. |
| Scrapy | Scheduler/downloader/middlewares/pipelines | Python; engine/downloader/scraper boundaries | Plugins such as scrapy-playwright | Distribution via extensions, not a universal base fleet | Contracts for middlewares, pipelines and local resume. |
| Colly | Callback-based Go HTTP collector | Go/net/http, customizable transport | No integrated JS rendering equivalent to Playwright | Goroutine queue; injectable storage | Simple HTTP baseline, per-domain limits and callbacks. |
| Crawl4AI | Content/corpus/extraction for AI, deep crawling | Python, HTTP/browser strategies | Playwright, managed browser/CDP, sessions | Local dispatcher; Docker/API service distinct from a durable distributed queue | Extraction, cache, sessions and memory control. |
| Scrapling | Adaptive parsing + fetchers + spiders | Python, curl_cffi | Dynamic/Stealthy sessions, Patchright | Local scheduler/checkpoints; no durable fleet demonstrated | Parsing recipes, transport and explicit checkpoints. |
| Katana | Discovery/scope/forms/JS/XHR, reconnaissance pipelines | Go HTTP with retryablehttp/fastdialer | Rod, distinct hybrid and full headless modes | Parallelism of inputs and fetchers; no fleet leases demonstrated | Enriched discovery and scope controls. |
| StormCrawler | Distributed continuous crawling and URL status | Java, Apache Storm, protocols including OkHttp | Optional Playwright module/CDP/remote server | Storm topology + spouts/bolts/configured persistent frontier | Reference for partitioning, politeness, recrawl and feedback. |
| Firecrawl OSS snapshot | Multi-format extraction/crawl API/service | Selected services/queues/workers/engines | Scraper service, wrappers of other engines | NuQ PG, optional FDB route, workers/services | Product and service-queue reference; AGPL cost and no presumed cloud parity. |

## 3. Frontier, discovery and scheduling matrix

| Capability | Crawlee verified | Spider verified | Supplementary references / limit | Proposed Goodfetch contract |
|---|---|---|---|---|

| Canonical URL and dedup | Configurable unique key; queue already distinguishes present/handled | Visited sets, normalization and signatures depending on features | SC fingerprints; CO request IDs; SL fingerprints | Transport URL preserved; work key includes method/body and task context; entity dedup separate from URL dedup. |
| Order / priority | FIFO/forefront; Python SQL sequences and Redis lists | Frontier set and budgets; do not promise a stable total order | SC configured priority queues/LIFO or FIFO; C4 BFS and scoring; ST next fetch | Priority + `ready_after`, fair scheduling; documented stability, no result dependent on implicit order. |
| HTML links and scopes | `enqueueLinks`, selectors, filters/strategies | Streaming parse, domains/subdomains/TLD, allow/deny/depth | KA fields/regex/scope; ST URL filters and parse filters | Composable discovery; traced rejection reason; prevention of crawl traps and query explosion. |

| Pagination / infinite scroll | Handler must provide actions, end criterion and enqueue | Link crawl + scripting/agent depending on feature | ST bounded `ScrollToBottomAction`; KA browser exploration; C4 deep crawling | `paginate`/`scroll_collect` operators: verifiable stop, entity dedup, page/item/time cap. |
| Count/depth/time caps | Configured max requests, retries and timeouts | wildcard/path budget, `with_limit(0)` unlimited, depth, crawl timeout | KA depth/duration/response cap; C4 max_pages | Multidimensional budget reserved **before admission**: URLs, attempts, bytes, browser time, tokens, cost; valid results counted separately. |
| Rate limit / politeness | Delays, concurrency options and sessions; separate autoscale | Delays/semaphore; optional auto-throttle | CO domain LimitRule; SC latency-based AutoThrottle; KA host rate + backoff 429/503; ST host/IP/domain queues | Global + per-domain + per-identity/proxy concurrency; token buckets and `Retry-After`; a slow host does not block the whole fleet. |
| Recrawl / freshness | Reuse of queues and tasks to be scheduled | cron and cache features; permanent crawl to be designed on top | ST `nextFetchDate` via Scheduler/StatusUpdater; SC jobs | Frontier owns revisit policy, last proof and version; distinguishes new/changed/unchanged/error. |
| Cache / conditional | Clients/HTTP hooks/storage; define the chosen transport | cache/hybrid, ETag cache, namespace/policy, cache shortcircuit depending on features | CO GET file cache; C4 result/content cache; SL cache; ST protocol/cache | Separate cache for raw response/rendered DOM/extraction/recipe; key partitioned by identity and method; TTL/ETag/invalidation/hit reason. |
| Sink backpressure | Asynchronous dataset/handler; source locks | Page broadcast + time guard, `balance` spool | SC engine/scraper backpressure; C4 streaming dispatcher | Bounded end-to-end flow: fetch → parse → validate → durable sink; no unbounded memory consumption nor acknowledgment merely on in-memory receipt. |

## 4. Pool matrix: four different resources

| Resource/capability | Crawlee | Spider | Other verified lessons | Proposed Goodfetch contract |
|---|---|---|---|---|
| HTTP connections | Replaceable client; transport lifecycle outside BrowserPool | reqwest reused; compression/stream/H2 in manifest | CO reusable net/http transport; Impit/curl_cffi profiling | Connection pool partitioned by endpoint/proxy/TLS profile/identity; socket/byte budgets; keep-alive and DNS measured. |
| Browser processes | BrowserPool selects/relaunches/retires browsers | BrowserController/OnceBrowser; lazy smart upgrade, reuse during the crawl | C4 managed/CDP cache; KA Rod pool; ST configurable Playwright | Local/remote `BrowserHost` pool with health checks, warm capacity, resource limits, draining, crash recovery. |
| Contexts | Playwright/Puppeteer backend; incognito depends on options | Contexts and Chrome configuration depending on paths; do not presume an isolated identity per URL | C4 context/session TTL; KA incognito/profile/no-incognito; ST new context/config | `IdentityContext` owns cookies/storage/fingerprint/proxy; exclusive write lease and explicit backend capability. |
| Pages / tabs | BrowserPool default **20 open pages per browser**, creation/closing options | Worker + tab semaphores, closing/cancellation guards | KA `GetPageFromPool`/`PutBrowserToPool`, replacement slot; C4 active pages | Page lease tied to run/step/identity; page/frame confinement; guaranteed cleanup even after timeout/cancel. |
| Rotation / retirement | Default **retires after 100 pages**, operation timeout 15s, idle retirement 10s, inactive close 300s | Dispose at the end of the crawl; parameters and context on the Chrome side | Reuse is not persistence after reboot | Counters for retirement reasons/leaks/RSS; retire without cutting active steps; distinguish a crash from an intended rotation. |
| Network sessions | SessionPool score/markGood/markBad, bounded rotation, cookies/proxy | Jar/profile config/proxy/retry strategy; interfaces distinct from a business session | SL SessionManager with explicit sid, protected lazy startup; C4 session_id | Stable and explicit `NetworkIdentity`; cookies/proxy/profile consistent between HTTP and browser under a transfer policy. |
| Auth/session state | Persistable cookies; save timing before the handler in BrowserCrawler | Browser state/jar depending on mode, no universal auth journal | C4 storage_state/profile/session reuse; KA existing profile/CDP | Compatible cookies + storage snapshot, origin and version; auth checks; no blind copy of all stores to all origins. |
| Proxy pool / stickiness | ProxyConfiguration tied to the session; rotation/tiers depending on setup | RequestProxy/proxy routing and retry directives | CO custom proxy funcs; distinct impersonation transports | Proxy pool with capabilities/cost/health, sticky identity, cooldown and trace of changes; external providers as adapters. |
| Fingerprints | BrowserPool generation/injection/cache; adapter restrictions | Chrome fingerprint/config and optional components | SL Patchright/challenge logic; Impit HTTP/TLS | Consistent headers/TLS/browser/locale/timezone bundle, versioned config; measure success, do not promise undetectability. |
| Pool hooks | pre/post launch, create page, close page | Specific hooks/script/fetchers | Hooks themselves can create deadlock/latency | Async extensions with a deadline; declared capabilities, safe context; hook order and scope tested. |
| Browser borrow / remote | Backend plugin and launcher; CDP via adapter | Retained controller provided to `fetch_chrome_persisted` | C4 CDP cache refcount; KA ChromeWSURL; ST CDP or remote Playwright | Explicit owned versus borrowed; close the resources created by Goodfetch; the user browser's lifecycle is preserved. |
| Concurrent acquisition | Page pool and AutoscaledPool are distinct | Static semaphore by default, opt-in adaptive handle | C4 memory adaptive dispatcher; SC downloader slots | Multidimensional resource scheduler; preserve context/page/LLM/sink reservations, avoid double counters and lost permits. |

### Stagehand clause

`@crawlee/stagehand` 3.18.2 declares **Stagehand TS `^3.0.0`**, not v4. The plugin launches Stagehand and then connects Playwright to the same browser; `_newPage` uses `contexts()[0]` and ignores the context options. `act`/`observe`/`extract` bind the page, **`page.agent` does not inject this page**. Python 1.10.4 uses the REST SDK `>=3.19.5,<4.0.0`, a different API, and binds `execute` to its page; its integration documents **incognito and full fingerprint as not supported**. General BrowserPool parity therefore does not automatically apply to all adapters. [TS package](https://github.com/apify/crawlee/blob/v3.18.2/packages/stagehand-crawler/package.json), [controller](https://github.com/apify/crawlee/blob/v3.18.2/packages/stagehand-crawler/src/internals/stagehand-controller.ts), [TS wrapper](https://github.com/apify/crawlee/blob/v3.18.2/packages/stagehand-crawler/src/internals/utils/stagehand-utils.ts), [Python wrapper](https://github.com/apify/crawlee-python/blob/v1.10.4/src/crawlee/browsers/_stagehand_types.py).

## 5. Durability, resume and retry scope matrix

| Mechanism | What is actually present | What this does not establish | Proposed Goodfetch contract |
|---|---|---|---|
| C-TS RequestQueueV2 | Claim with lock, extension, reclaim, handled; local storage backend or configured service | Transaction with dataset/business effects; unchanged resume boundary after a crash | Lease token + epoch fencing; attempt separate from the job; atomic commit of result/state when they share the store. |
| C-PY SQL | Block expiry/client_key; `FOR UPDATE SKIP LOCKED` for PG/MySQL/MariaDB, another claim path for other dialects | Same behavior/performance for all dialects; global cloud guarantee | Backend contract tests per dialect; multi-worker capability announced only after concurrency/kill tests. |
| C-PY Redis | Lua scripts for atomic claim and stale recovery; sets or Bloom depending on strategy | Durability independent of the Redis config; dataset/job atomicity; absence of false positives in Bloom mode | Explicit durable store; exact dedup by default for completeness; Bloom only as an accelerator or an accepted-loss mode. |
| C-TS storage defaults | `persistStorage=true` and **`purgeOnStart=true`** | Automatic resume of the same run with default queues | Stable Run ID, resume explicitly tied to the run; no implicit purge of durable state in production mode. |
| SP SQLite disk | Tables `resources(id,url)` and `signatures`: visited/signatures; persist=false by default, opt-in retention | Pending frontier, leases, step checkpoints and atomic sink | The Spider adapter publishes discoveries; the Foxhound durable frontier remains the source of truth. |
| SP queue and pages | In-memory Tokio broadcast; `ChannelGuard` with a 250ms timeout; optional spool | Durable job/result journal; absence of loss due to consumer lag | Backpressured IPC/streams + referenced durable spool; acknowledge after commit, handle late messages explicitly. |
| SC JOBDIR | Disk priority queue + persisted dupefilter; non-serializable requests may stay in memory | Each external callback being atomic; browser snapshots | Serializable Request schema independent of the SDK; refuse or isolate non-persistable callbacks in a durable run. |
| CO queue/storage | Goroutine queue; Storage `GetRequest()` pop; memory by default; separate visited/cookies Storage | Claim/ack/lease API in the base interface; exactly-once | Do not adapt a simple pop while claiming to preserve durable semantics; the adapter must declare its guarantees. |
| SL checkpoint | Snapshot of pending + inflight kept in the scheduler, seen; temp pickle then rename; default interval 300s | Per-operation persistence, full browser/sink state; established crash/power-loss fsync | Periodic snapshot only as an accelerator; durable transition journal; controlled/versioned checkpoint import. |
| KA resume | `RunnerState.InFlightUrls` of the **root inputs**; JSON written on SIGINT/SIGTERM | Capture of the entire discovered frontier; recovery after SIGKILL before the snapshot | Resume at URL/step/lease level; seed restart distinguished from a frontier resume. |
| ST status frontier | URL status/metadata/nextFetchDate; SQL/OpenSearch/URLFrontier depending on topology; Storm ack/fail; SQL batch ack after executeBatch | A universal index/results/status transaction; snapshot of a browser workflow | Recrawl frontier and document status; idempotent output sink; possible redelivery documented. |
| FC NuQ PG snapshot | queued/active/completed/failed, `SKIP LOCKED` claim, UUID lock, heartbeat, finish conditioned on the lock; optional FDB route | Business extraction success; legally and performance-wise free copy-paste; SaaS parity | Single-owner queue service; visible heartbeat/fencing/deadletter and reconciliation; not two silently diverging queue engines. |
| Crawlee URL retry | Full handler replayed; default 3 retries, 10 rotations; `SessionError` handled specially | Retry of only the failed action; global bound of 4 attempts; "handled" = successful result | Explicit retry scope transport/page/task/step; side effects under idempotency rules, unknown outcome distinct from failed. |
| Spider retry | Default 0; status/truncated/should_retry/proxy 401; RetryStrategy max and directives; conditional smart bootstrap fallback | N valid results for budget N; all 4xx statuses retryable; documented 15s timeout applied by default | Taxonomy transient/permanent/blocked/auth/schema/action-unknown; explicit deadlines — Spider's `Configuration::new()` sets 120s. |

## 6. Workers and autoscaling matrix

| Capability | Verified market state | Proposed Goodfetch contract / dependency |
|---|---|---|
| Local async | Crawlee AutoscaledPool, Spider Tokio, Colly goroutines, C4 dispatcher, Scrapling AnyIO, Katana fetchers/input parallelism | Local worker = job executor, not a new definition of the job. Identical primitives locally/remotely. |
| Process isolation | Browsers have their own processes; control/runtime can be another process | Rust sidecar; browser crash isolated from the control plane; limits/process group/kill and cleanup tested. |
| Distributed fleet | ST Apache Storm topology + frontier; FC workers/services; SP optional HTTP worker | Worker announces backend/capabilities/versions/capacity; routing by task and identity; no rendering claim if the worker is HTTP-only. |
| Spider worker | Rust Warp/Hyper/Tokio, Page streaming/raw HTTP; worker manifest without the Chrome feature | Reusable for HTTP collection if the adapter contract respects the guarantees; do not announce a browser fleet with the provided binary. |
| Load autoscale | C-TS memory/CPU/event loop/client; C4 memory 90%/critical 95%/recovery 85% by default; SP static semaphore unless external handle; SC latency-based AutoThrottle | Adjust admission according to RSS/CPU/queue lag/transport 429/sink backlog and browser/LLM capacity; hysteresis and observable throttling reasons. |
| Per-host limits | CO LimitRule; KA host rate + backoff; SC downloader slots; ST host partition and politeness | Distributed/coordinated local budgets; a per-worker limit multiplied by the fleet is not a global limit. |

## 10. Goodfetch target contract: sources of truth and invariants

### Proposed objects and owners

| Object | Canonical owner | Essential fields/relations | Invariant |
|---|---|---|---|
| `Run` / `WorkflowSpec` / `CrawlSpec` | Rust control plane | Spec version, seeds, identity requirements, budgets, validators, adapters | An SDK reimplements neither leases nor commit logic. |
| `WorkItem` | Frontier/workflow scheduler | run_id, work_id, URL/action input, unique_key, priority, ready_after, desired capabilities | The identity of a work item is separate from the attempts and from the final URL after a redirect. |
| `Attempt` | Worker executor + journal | attempt_id, owner, lease token/epoch, started/deadline, transport/profile/proxy, costs | A worker whose lease has expired cannot publish a late authoritative commit. |
| `IdentityContext` | Session manager | Account/proxy/fingerprint/storage_state/version, owner/exclusive lease, capabilities | Two workflows with effects do not concurrently mutate the same auth state without an explicit policy. |
| `BrowserHost` / `PageLease` | Browser pool | Owned/borrowed, backend version, pages/contexts, memory, health, drain status | No orphan page/future/permit after cancel or crash; page/frame bound to each AI/action call. |
| `Observation` / `ResultEnvelope` | Executor + validator | Origin status, redirects, MIME, raw/artifact refs, DOM/screenshot, extraction/schema, completeness | HTTP 200 or LLM done is not enough for the succeeded state. |
| `Commit` / `OutboxEvent` | Durable store | Idempotent results, state transition, validated discoveries, output revision, sink delivery | Durable commit before ack; external sink delivered/replayed idempotently from the outbox. |
| `CrawlDocument` | Recrawl frontier | Canonical key, last fetch/result/error, ETag/date, next_fetch_at, provenance | Visited means neither a valid result nor forever-complete. |

### Proposed states and guarantees

Job lifecycle: **queued → leased → running → validating → committed**, or **retry_wait / failed_terminal / cancelled / unknown_effect**. `unknown_effect` concerns an action whose external effect may have occurred before a timeout/connection loss; it must not be arbitrarily reclassified as a replayable failure.

For collection without business effects, aim for **at-least-once execution + idempotent results**. When job/outputs/discovered URLs share the same transactional store, one transaction can cover their internal commit. It does not make an external site transactional. For workflows with effects, combine check-before/check-after, available idempotency keys, receipts and reconciliation rules; promising "exactly once on the Web" would be unjustified.

HTTP and browser transports receive the same budget/deadline/identity policy. The escalation mechanism changes the fetch/render attempt, not the owner of the run. Plugins declare capabilities and effective guarantees — `http`, `browser`, `context_isolation`, `remote_connect`, `durable_claim`, `stream_backpressure`, `auth_snapshot`, `actionability`, formats — and must refuse the requirements they do not satisfy.

## 12. Proof protocol and build/reuse choice

The benchmark compares **validated work**, not merely "visited" URLs. Publish site fixtures, payloads/goldsets, versions, hardware, concurrency, cold/warm browser/connection/cache, proxy/IP, model/temperature, tokens and features. Measure p50/p95, wall time, CPU/RSS, socket/browser/page peak, bytes, tokens/cost, completeness and final failure rate; include slow queues/sinks and interruption. Parsing or transport microbenchmarks remain useful, but are not converted into a promise of an "unrivaled" workflow. See the [benchmark audit](2026-10-07-benchmark-audit-followup.md).

Proposed decision: **own protocol/journal/frontier/identity/result-policy; reuse transports, drivers and parsers via versioned adapters**. Crawlee serves as the reference for the depth of pools and queues; Spider as the Rust reference for acquisition/rendering/features; StormCrawler as the reference for distributed frontier/recrawl; the others provide extraction, middleware, discovery and regression corpora. Reuse of a narrow component or an upstream contribution comes before a global fork. No language choice exempts from tests on real Chrome, storage guarantees and a maintenance/license matrix.

### Limits of this matrix

- Facts from pinned sources, without full validation of installation or network/DB/Chrome stress.
- The Firecrawl snapshot and the stable code of the other projects are not interchangeable; private SaaS infrastructure is not extrapolated.
- The "Goodfetch" rows are contract proposals; they require an implementation and their acceptance tests.
- Several capabilities require flags/features/plugins/backends; the cited defaults and restrictions take precedence over README slogans.
- Detailed agent/perception/repair capabilities belong to the supplementary browser/agent report; this matrix focuses on their safe integration with crawl/pools/workers.
