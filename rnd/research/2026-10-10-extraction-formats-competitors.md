# Extraction chains and output formats actually adopted by competitors

Research of **October 10, 2026**. Question: for each competitor, which main-content extractor, HTML→Markdown converter and HTML parser are actually wired in, which output formats are offered, and which extraction-quality benchmark is cited. Also: the state of the Rust main-content extractors (rs-trafilatura, dom_smoothie, htmd, lol-html and the 2026 newcomers).

**Method.** Source code read at pinned tags/commits (shallow clones, published npm archive for Stagehand), registry metadata read from crates.io, npm and PyPI on the day, and first-party documentation fetched for closed services (Browserbase, Exa, Tavily, Apify actor input schema via the Apify API). Exa search was unavailable (credit limit), so discovery used the standard web search and GitHub/crates.io searches. No extractor was run locally; every quality figure below is the publisher's own number. Hosted services can differ from their public repositories: a feature absent from a repository is not presumed absent from the cloud product, and conversely.

## 1. Conclusions that matter for Automan

1. **Nobody among the crawl frameworks ships a scored main-content extractor in its core.** Crawlee (JS and Python), Scrapy and the Stagehand client have none. Spider puts Readability in a separate crate (`spider_transformations`). Firecrawl's `onlyMainContent` is a fixed CSS denylist (42 selectors), not a scoring algorithm. Only the "content" products (Jina Reader, Apify Website Content Crawler, Crawl4AI) wire a real extractor, and they chose **Mozilla Readability** (Jina, Apify) or an **in-house pruning/BM25 filter** (Crawl4AI). **No competitor examined wires trafilatura.**
2. **HTML→Markdown is fragmented and often home-made**: turndown (Firecrawl fallback), a Firecrawl fork of the Go `html-to-markdown`, a vendored html2text fork (Crawl4AI), the original html2text (ScrapeGraphAI), Jina's in-house `MarkifyService` (turndown-style options, turndown no longer a dependency), `fast_html2md` on lol-html (Spider). Apify does not document its converter.
3. **The "LLM" tier is now standard**: schema-driven JSON (Firecrawl `json`, Crawl4AI `LLMExtractionStrategy`, Jina `readerlm-v2`, Stagehand `extract`, Browserbase Fetch `json`, Exa `summary.schema`, Crawlee Python `PydanticAiCrawler`), LLM cleanup of Markdown (Firecrawl `onlyCleanContent`, Crawl4AI `LLMContentFilter`), and **LLM-generated selectors** (Crawlee Python `PydanticAiSelectorExtractor`, ScrapeGraphAI `code_generator_graph`).
4. **WARC is almost absent**: among the tools examined, only Spider writes WARC 1.1, and it is compiled into its default feature set. Crawlee, Scrapy core, Crawl4AI, Firecrawl, Jina and ScrapeGraphAI have no WARC writer in the inspected code.
5. **lol-html cannot do main-content extraction alone**: it is a streaming rewriter with a restricted selector set (no `:has()`, no sibling combinators, no tree). Firecrawl, which already ships lol-html in its Rust addon, uses a full DOM (kuchikiki) for main-content removal; Spider uses lol-html for links and Markdown, and html5ever (via `llm_readability`) for Readability.
6. **The Rust extractor scene is young and self-benchmarked.** dom_smoothie (Readability.js port) is the most adopted (≈436k recent downloads, 38 dependents) and actively maintained; htmd is the de facto HTML→Markdown crate (≈4.7M recent downloads, 112 dependents). rs-trafilatura is a one-maintainer, 24-commit project, silent since April 2026 with 11 open issues, whose headline benchmark (WCXB) was built by the same author.

## 4. Per-competitor evidence

### Crawlee JS 3.18.2 and 4.0.0-rc.1

- Parser: `cheerio` (`1.0.0-rc.12` in 3.18.2, `^1.0.0` in 4.0.0-rc.1) and `htmlparser2`; 3.18.2 also has JSDOM and LinkeDOM crawlers. [3.18.2 cheerio-crawler package.json](https://github.com/apify/crawlee/blob/v3.18.2/packages/cheerio-crawler/package.json), [4.0.0-rc.1 package](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/packages/cheerio-crawler/package.json). The rc.1 `packages/` directory contains no `jsdom-crawler` or `linkedom-crawler`, while the [v4 upgrade guide](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/docs/upgrading/upgrading_v4.md) still names `JSDOMCrawler`/`LinkeDOMCrawler`; their v4 location was not resolved here.
- No Markdown, Readability or turndown anywhere in `packages/*/src` at either tag (repository grep).
- Text: `htmlToText` turns the whole document into text; it became `async` with a dynamic cheerio import in v4. [3.18.2 cheerio.ts#L44](https://github.com/apify/crawlee/blob/v3.18.2/packages/utils/src/internals/cheerio.ts#L44), [4.0.0-rc.1 cheerio.ts#L41](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/packages/utils/src/internals/cheerio.ts#L41).
- Contacts: `parseHandlesFromHtml` returns emails, phones, uncertain phones and LinkedIn, Twitter, Instagram, Facebook, YouTube, TikTok, Pinterest, Discord handles. [social.ts#L664](https://github.com/apify/crawlee/blob/v3.18.2/packages/utils/src/internals/social.ts#L664), [SocialHandles at rc.1](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/packages/utils/src/internals/social.ts#L203).
- Metadata: `parseOpenGraph`. [open_graph_parser.ts#L398](https://github.com/apify/crawlee/blob/v3.18.2/packages/utils/src/internals/open_graph_parser.ts#L398). **New in v4:** `extractMicrodata` (schema.org microdata per the WHATWG processing model; not JSON-LD). [extract-microdata.ts](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/packages/utils/src/internals/extract-microdata.ts). Neither tag contains a JSON-LD helper (grep for `ld+json` returned nothing).
- Snapshots: `saveSnapshot` stores screenshot and HTML in the key-value store. [playwright-utils.ts#L534](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/packages/playwright-crawler/src/internals/utils/playwright-utils.ts#L534). v4 adds `extractLinks()` (links without enqueueing). [upgrade guide](https://github.com/apify/crawlee/blob/v4.0.0-rc.1/docs/upgrading/upgrading_v4.md).

### Crawlee Python 1.10.4

- Parsers: optional extras `beautifulsoup4[lxml]`+`html5lib`, `parsel`. [pyproject.toml](https://github.com/apify/crawlee-python/blob/v1.10.4/pyproject.toml). Text via `html_to_text` per parser. [BeautifulSoup utils](https://github.com/apify/crawlee-python/blob/v1.10.4/src/crawlee/crawlers/_beautifulsoup/_utils.py), [Parsel utils](https://github.com/apify/crawlee-python/blob/v1.10.4/src/crawlee/crawlers/_parsel/_utils.py). No Markdown, no social/contact helpers.
- **`PydanticAiCrawler` (added in 1.8.0, July 2026)**: `PydanticAiDirectExtractor` sends distilled HTML to the model and validates a Pydantic schema; `PydanticAiSelectorExtractor` asks the model for a tree of Parsel CSS selectors from a DOM skeleton that "never renames or re-parents elements", so selectors stay valid on the original page; `PydanticAiCleanHtmlDistiller` uses `lxml_html_clean`. [crawler](https://github.com/apify/crawlee-python/blob/v1.10.4/src/crawlee/crawlers/_pydantic_ai/_pydantic_ai_crawler.py), [selector extractor](https://github.com/apify/crawlee-python/blob/v1.10.4/src/crawlee/crawlers/_pydantic_ai/_selector_extractor.py), [skeleton distiller](https://github.com/apify/crawlee-python/blob/v1.10.4/src/crawlee/crawlers/_pydantic_ai/_skeleton_distiller.py), [CHANGELOG](https://github.com/apify/crawlee-python/blob/v1.10.4/CHANGELOG.md). This is the closest public design to "LLM writes a deterministic extractor once".

### Spider 2.53.9 and spider_transformations 2.39.13

- Core (commit [`e4b53c5`](https://github.com/spider-rs/spider/tree/e4b53c5b582357e46433fa9ba3d91f930fb67cb4), the published crate's VCS SHA): `lol_html = "2"` (latest is 3.0.1), used in `page.rs`, `website.rs`, CSS selector utilities. [Cargo.toml](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider/Cargo.toml). `Metadata` keeps only title, description and `og:image`; a fuller Open Graph struct is commented out. [page.rs#L2225](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider/src/page.rs#L2225).
- **WARC 1.1 writer** written directly (no WARC dependency), lock-free MPSC to a single writer, `response` records, soft backpressure via `SPIDER_WARC_QUEUE_BYTES`. Feature `warc` is in `__basic` ⊂ `basic` ⊂ `default`. [warc.rs](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider/src/utils/warc.rs), [configuration.rs#L692](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider/src/configuration.rs#L692).
- `prefer_native_markdown` asks the browser engine for Markdown via the vendor CDP `Content.getMarkdown` (chromey ≥ 2.54) and falls back to HTML when unsupported. [configuration.rs#L560](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider/src/configuration.rs#L560).
- Selector extraction: `css_query_select_map` lives in the separate `spider_utils` crate. [spider_utils](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider_utils/src/lib.rs).
- LLM extraction: `openai`/`gemini` features with `json_schema`, optional screenshot per step. [openai_common.rs#L103](https://github.com/spider-rs/spider/blob/e4b53c5b582357e46433fa9ba3d91f930fb67cb4/spider/src/features/openai_common.rs#L103).
- `spider_transformations` (commit [`5da9b2e`](https://github.com/spider-rs/spider_transformations/tree/5da9b2e203a5691793e1fe12fdbc1b45133848d4)): `ReturnFormat` = Raw, Bytes, Text, Html2Text, Screenshot, Markdown, CommonMark, XML, Empty; `TransformConfig` = `readability`, `clean_html`, `filter_images`, `filter_svg`, `main_content`. [content.rs#L31](https://github.com/spider-rs/spider_transformations/blob/5da9b2e203a5691793e1fe12fdbc1b45133848d4/src/transformation/content.rs#L31). `main_content` only adds `nav`, `header:first-of-type`, `footer`, `body > aside:not(:first-of-type)` to the ignore list. [content.rs#L260](https://github.com/spider-rs/spider_transformations/blob/5da9b2e203a5691793e1fe12fdbc1b45133848d4/src/transformation/content.rs#L260). Readability: `llm_readability` "a rewrite of `readability-rs`" on a forked html5ever. [llm-readability](https://github.com/spider-rs/llm-readability). Markdown: `fast_html2md` 0.0.63, default feature `rewriter = lol_html`, alternative `scraper` (html5ever). [fast_html2md Cargo.toml](https://github.com/spider-rs/html2md/blob/main/fast_html2md/Cargo.toml). Note: the transformations crate is at 2.39.13 (April 30, 2026), behind core 2.53.9.

### Stagehand 4.2.0 and Browserbase Fetch

- npm 4.2.0 ships a thin client (deps: `@browserbasehq/sdk`, OpenTelemetry, `zod`) plus a Chrome extension; tag `@browserbasehq/stagehand@4.2.0` → commit [`2d605b0`](https://github.com/browserbase/stagehand/tree/2d605b099996e10c3e3ab0dcf293db8d482a2c97).
- `extract` builds "an accessibility snapshot" (hybrid DOM + AX tree) and optionally a viewport PNG, then calls the LLM with a schema. [extractService.ts](https://github.com/browserbase/stagehand/blob/2d605b099996e10c3e3ab0dcf293db8d482a2c97/packages/extension/services/extractService.ts), [snapshot capture](https://github.com/browserbase/stagehand/blob/2d605b099996e10c3e3ab0dcf293db8d482a2c97/packages/extension/understudy/a11y/snapshot/capture.ts). `page.snapshot()` returns `formattedTree`, `xpathMap`, `urlMap`; `page.screenshot()`, `page.pdf()` exist (from `dist/index.d.mts` of the npm archive). No Markdown or main-content extractor in the client.
- `browserbase.fetch()` options: `format` ∈ `raw | json | markdown`, `schema`, `proxies`. Docs: no JavaScript execution, 5 MB / 60 s limits, no PDF conversion, Markdown/JSON ("Fetch Extract") priced separately, conversion algorithm not documented. [Browserbase Fetch docs](https://docs.browserbase.com/features/fetch).

### Firecrawl (main @ [`6f892bc`](https://github.com/firecrawl/firecrawl/tree/6f892bc5026efc6355d017ec38dfffb84c228100), 2026-10-09; JS SDK 4.46.0, Python SDK 4.50.0)

- Formats (v2 schema): `markdown` (default), `html`, `rawHtml`, `rawBase64`, `links`, `images`, `summary`, `json`, `deterministicJson`, `changeTracking` (requires `markdown`), `screenshot`, `attributes`, `branding`, `product`, `menu`, `question`, `highlights`, `query`, `audio`, `video`; options `onlyMainContent` (default **true**), `onlyCleanContent` (default false), `includeTags`/`excludeTags`, `removeBase64Images`, `blockAds`, `parsers`. [native/src/html.rs#L335](https://github.com/firecrawl/firecrawl/blob/6f892bc5026efc6355d017ec38dfffb84c228100/apps/api/native/src/html.rs#L335), [removeUnwantedElements.ts](https://github.com/firecrawl/firecrawl/blob/6f892bc5026efc6355d017ec38dfffb84c228100/apps/api/src/scraper/scrapeURL/lib/removeUnwantedElements.ts). `onlyCleanContent` is an LLM pass on the Markdown (trimmed to 120k tokens, disabled under zero data retention). [llmExtract.ts#L1192](https://github.com/firecrawl/firecrawl/blob/6f892bc5026efc6355d017ec38dfffb84c228100/apps/api/src/scraper/scrapeURL/transformers/llmExtract.ts#L1192).
- Markdown chain: optional HTTP service → Go shared library (a `firecrawl/html-to-markdown` fork replacing `JohannesKaufmann/html-to-markdown`) when `USE_GO_MARKDOWN_PARSER` → **turndown** + `joplin-turndown-plugin-gfm`. Rust addon deps: `lol_html 2.6`, `kuchikiki`, `pdf-inspector`. [native/Cargo.toml](https://github.com/firecrawl/firecrawl/blob/6f892bc5026efc6355d017ec38dfffb84c228100/apps/api/native/Cargo.toml).
- Benchmark: **scrape-evals**, 1,000 URLs with human-annotated core snippets, Coverage and word F1 ("quality"). Vendor-authored, single run; Firecrawl's comparison pages cite a different internal run. [launch post](https://www.firecrawl.dev/blog/introducing-scrape-evals).

## 6. WARC in three lines

WARC (Web ARChive, ISO 28500; current spec 1.1 by the IIPC) is a container that concatenates HTTP request/response records with their headers, payload digests and metadata, so a crawl can be replayed and re-extracted later byte-for-byte. It is the storage format of Common Crawl, the Internet Archive (Heritrix/Wayback), national libraries in the IIPC and Webrecorder tools (Browsertrix, pywb), and `wget --warc-file` writes it. For a scraper it is the "keep the raw evidence" format: re-run a new extractor over old captures without re-fetching. [WARC 1.1 spec](https://iipc.github.io/warc-specifications/specifications/warc-format/warc-1.1/).

## 7. Surprises and open points

- `firecrawl/scrape-evals`, the most-cited multi-vendor extraction benchmark, is no longer reachable on GitHub (HTTP 404 on 2026-10-10).
- Spider's WARC writer is on by default, while no other crawl framework here offers WARC.
- Firecrawl's "main content" is a hard-coded selector list including 12 `.swoogo-*` classes for one event platform; a learned per-domain signature mode (OMCE) is in progress behind an experimental flag.
- Jina Reader's public repository has not moved since May 2026; the hosted r.jina.ai may differ.
- Crawlee Python 1.8.0+ ships LLM-written Parsel selectors validated by Pydantic: a direct precedent for Automan's "compile once, replay deterministically" idea.
- readabilityrs publishes numbers where Readability.js beats it; Rust is not automatically faster for this workload.
- rs-trafilatura's README and its benchmark site disagree on the held-out F1 (0.893 vs 0.903).
- JSON-LD: in Firecrawl the only `ld+json` read found is inside the cloud `fire-engine` branding script, not in `metadata`; Apify's readme example shows `openGraph` but no JSON-LD field.
- Not verified: Apify's Markdown converter; Exa/Tavily algorithms; Spider Cloud's hosted formats.
