# Rust model-provider libraries: aisdk, Rig, genai and others

Survey of October 10, 2026, for [issue 94](https://github.com/Jbmanllr/automan/issues/94), which feeds Q18 of [Adopt AI and agent decisions](https://github.com/Jbmanllr/automan/issues/72). It compares every maintained Rust library that could serve as, or underpin, Automan's model-provider layer, then lays out the options for Q18. It states facts and options; it does not decide.

**Method.** Package data comes from the crates.io API on 2026-10-10 (`recent` = crates.io's 90-day download count). Repository data comes from the GitHub API. For the deep profiles, the source was read at a pinned commit (given in each profile) and line links point at that commit; nothing was built or run, so runtime behaviour is inferred from the code unless a test in the repository shows it. Items that could not be checked are marked **unverified**. Exa and lib.rs were unavailable (lib.rs timed out), so discovery relied on crates.io keyword and search listings, GitHub organisation listings, vendor SDK pages and awesome lists.

**Correction of an earlier claim.** "Rust has no equivalent of the Vercel AI SDK" is false. [aisdk](https://crates.io/crates/aisdk) describes itself as "inspired by the Vercel AI SDK", and Rig, genai, liter-llm and adk-rust are multi-provider layers of similar scope. What Rust does lack is an **official** SDK from Anthropic, OpenAI or Google GenAI (section 1).

## What Automan needs from this layer

From the owner's answers on issue 72 ([round 2](https://github.com/Jbmanllr/automan/issues/72#issuecomment-6100442057)):

- **Q17:** the engine owns its model calls. Each call is journaled, counted in Usage and capped by Limits. An SDK can register a model callback that the engine still journals, counts and caps.
- **Q19:** Limits on tokens, calls and money, with a **worst-case reservation before each call**.
- **Q22:** vision opt-in, with the three vendors' **computer-use tools**.
- **Q30:** web search through a provider, i.e. **provider-native search tools**.
- **Q18 (open):** an in-house provider layer with structured-output repair: constrained decoding where the provider offers it, otherwise JSON repair plus a bounded validation retry.
- Providers named in the brief: Anthropic, OpenAI, Google Gemini and Vertex AI, AWS Bedrock, Azure OpenAI, and any OpenAI-compatible endpoint. The engine is Rust on Tokio ([issue 70](https://github.com/Jbmanllr/automan/issues/70); R&D proposal [rnd/adr/0001-runtime-language.md](../adr/0001-runtime-language.md)). The adopted ADR 0002 in `docs/adr` is about run state, not the runtime, so the Rust/Tokio premise is taken from the brief rather than from an ADR.

The test that matters most for Q17/Q19 is therefore: **can the host see every individual model call (ideally every HTTP attempt, retries included) before it is sent, refuse it, and read its exact usage afterwards?**

## 3. Deep profiles

### 3.1 aisdk (lazy-hq)

Read at `c5905120` (`main`, 2026-08-08); links below are to that commit. Base: `https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/`.

- **Release vs `main`.** `main` is 95 commits ahead of tag v0.5.2 and still says version 0.5.2. The unreleased work contains breaking changes (async `ToolExecute`, renamed stream chunks) ([CHANGELOG L18-L41](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/CHANGELOG.md#L18-L41)). [Issue #117](https://github.com/lazy-hq/aisdk/issues/117) asking for a release has no maintainer reply. The changelog lists the rustls switch under 0.5.2, but that commit postdates the tag; the published 0.5.2 uses reqwest's default native-tls ([0.5.2 dependencies](https://crates.io/api/v1/crates/aisdk/0.5.2/dependencies)).
- **Providers.** Native Anthropic Messages, OpenAI **Responses only**, and Gemini via API key. Bedrock is reached only through its OpenAI-compatible endpoint with a bearer key, no SigV4 ([amazon_bedrock/mod.rs L1-L15](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/providers/amazon_bedrock/mod.rs#L1-L15)). No Vertex, no Azure (grep). Any OpenAI-compatible base URL works ([openai_compatible/settings.rs L14-L36](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/providers/openai_compatible/settings.rs#L14-L36)).
- **Structured output.** Schemas come from `schemars`. OpenAI Responses is sent with `strict: false`, so it is not constrained ([openai/conversions.rs L203-L217](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/providers/openai/conversions.rs#L203-L217), re-checked for this note). Chat Completions providers get `strict: true`; Gemini gets `response_schema`. **Anthropic never receives the schema** ([anthropic/conversions.rs L19-L24](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/providers/anthropic/conversions.rs#L19-L24)), and a `DynamicModel` accepts it silently ([capabilities.rs L136-L148](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/capabilities.rs#L136-L148)). Parsing is plain `serde_json`: no repair, validation or retry ([generate_text.rs L204-L210](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/language_model/generate_text.rs#L204-L210)).
- **Tools, streaming, media.** A multi-step tool loop with no default step cap ([generate_text.rs L84-L172](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/language_model/generate_text.rs#L84-L172)); open [issue #114](https://github.com/lazy-hq/aisdk/issues/114) reports tools run twice when streaming on OpenAI-compatible providers. Typed stream parts. **User messages are text only** ([messages.rs L109-L112](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/messages.rs#L109-L112)): no vision. No computer use and no provider search; Gemini search is hard-coded off ([google/conversions.rs L40-L48](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/providers/google/conversions.rs#L40-L48)).
- **Usage.** `input`, `output`, `reasoning`, `cached` tokens; Anthropic merges cache reads and writes, Gemini reports neither cached nor reasoning tokens ([anthropic/conversions.rs L161-L170](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/providers/anthropic/conversions.rs#L161-L170)). Usage is per step, not per HTTP attempt.
- **Cancellation, timeouts, retries.** Streaming runs in a detached `tokio::spawn` that ignores send failures, so dropping the stream does not stop further model calls ([stream_text.rs L92, L168](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/language_model/stream_text.rs#L92)). Timeouts are hard-coded in two private static clients (180 s non-streaming, none streaming) ([client.rs L48-L90](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/client.rs#L48-L90)). Internal retries on 429/5xx with integer `Retry-After`; the public `max_retries` option is never read (grep).
- **Extensibility.** `LanguageModel` trait with `generate_text`/`stream_text` ([mod.rs L50-L81](https://github.com/lazy-hq/aisdk/blob/c5905120f1164853b6d29538aa33a1c240ad637c/src/core/language_model/mod.rs#L50-L81)); in 0.5.2 its stream type is crate-private, fixed only on `main` ([PR #120](https://github.com/lazy-hq/aisdk/pull/120)). ## 5. Options for Q18

The four options from the ticket, with what each costs and which library fits best. These are facts and trade-offs; the choice stays with the owner.

### Option A: adopt a library as a direct dependency

The engine calls the library's types directly.

- **Best fits:** Rig (broadest native coverage, a pre-call hook that can deny, rich usage, OTel) or liter-llm (Tower hooks and a budget ledger built for exactly this purpose, every listed provider including Vertex and Azure).
- **Costs:** smallest initial code. Automan still writes repair, validation retry, the reservation logic, journaling and retry policy.
- **Risks:**
  - *Churn.* Rig breaks on every minor, about every two weeks, and rewrote its core traits in 0.43; liter-llm reached major 2 within six months. Library types would leak into the journal format and the SDK callback surface, so each upgrade touches engine code.
  - *Abandonment.* liter-llm is 82% one author and six months old. Rig is broadly staffed but its funding is unverified.
  - *Supply chain.* Rig's MSRV 1.95 becomes Automan's floor. Neither Rig nor most others run cargo-deny; liter-llm does, but drags in a large optional surface.
  - *Gaps remain:* Rig lacks typed Anthropic and Gemini computer use and retries; hooks exist only in rig-agent, and Bedrock/Vertex bypass its HTTP client. liter-llm keeps its `Provider` trait crate-private, so an SDK model callback cannot be plugged in as a provider.

### Option B: adopt behind Automan's own provider trait, with adapters

Automan defines its own `ModelProvider` trait and request/response/usage types (owned by the journal), and implements it with adapters over one or more libraries.

- **Best fits:**
  - genai as the main codec layer: it has the cleanest request/response model, the richest usage normalisation, Vertex with Claude, Bedrock SigV4, rustls, `forbid(unsafe)`, and dual licence. Its missing hooks matter less here because Automan's trait is the hook. Gaps to fill: Azure, computer use, repair, retries.
  - Or Rig's `Model::call` level (below rig-agent), which gives native structured output on five providers.
  - Per-provider composition is also possible: async-openai for OpenAI and Azure (with its retry layer replaced by Automan's Tower layer), the official aws-sdk-bedrockruntime for Bedrock, the official google-cloud-aiplatform-v1 for Vertex. Anthropic and the Gemini Developer API have no strong single-provider crate, so they would come from genai or Rig or be written in-house.
- **Costs:** one trait plus one adapter per library, plus the shared repair/validation/reservation/journaling code. Upgrades are contained in adapters. A model callback registered from an SDK becomes just another implementation of the same trait.
- **Risks:** the adapter must map the library's lossy points (e.g. dropped schemas, merged cache counts) and cannot see retries the library performs internally; each wrapped library keeps its own supply-chain and bus-factor risk; features the library does not model (computer use in genai) still need a raw-JSON escape hatch or in-house code.

### Option C: fork

- **Best fits:** genai (MIT OR Apache-2.0, a coherent ~30k-line codebase, single maintainer so upstream coordination is simple, `Adapter` trait only needs to be made public) or aisdk (Vercel-like API, but its gaps are the largest: no vision, no computer use, no search, no Vertex or Azure).
- **Costs:** Automan takes over the codebase, including the parts it does not need (genai has ~34 provider kinds). Size proxy: genai's Anthropic, OpenAI Chat, OpenAI Responses, Gemini, Vertex and Bedrock adapters total about 12,300 non-blank lines at `fd1b949b` (counted for this note, tests within those folders included).
- **Risks:** losing upstream fixes for provider API drift (the main ongoing cost of this layer), or paying to rebase continuously. Forking Rig is impractical given its change rate.

### Option D: write in-house

Automan implements the wire codecs for the providers it names, on its own HTTP stack.

- **Scope:** Anthropic Messages; OpenAI Responses and Chat Completions (Chat also covers Azure OpenAI and every OpenAI-compatible endpoint); Gemini `generateContent` for both the Developer API and Vertex (Vertex also serves Claude, as genai's Vertex adapter shows: [vertex/adapter_impl.rs L172-L187](https://github.com/jeremychone/rust-genai/blob/fd1b949bd635237a594f9c422c85f059a8e5a535/src/adapter/adapters/vertex/adapter_impl.rs#L172-L187)); Bedrock Converse, either via the official aws-sdk-bedrockruntime or by signing requests with SigV4. Plus streaming parsers, usage normalisation, provider-native tools (computer use, web search) and structured output mapping.
- **Costs:** the largest initial effort; the genai line count above (~12k non-blank lines for six adapters) gives an order of magnitude for the codecs alone. The continuing cost is tracking provider API changes (new tool versions, beta headers, usage fields), which libraries otherwise absorb. Existing libraries' code (MIT/Apache) can be read as a reference.
- **Benefits:** the journal, Usage, Limits and reservation see each HTTP attempt by construction; no third-party churn in engine types; dependencies limited to Automan's own reqwest/rustls stack and, optionally, the two official cloud SDKs; computer use and provider search are first-class from the start.
- **Risks:** bus factor and maintenance move into Automan's team; provider coverage beyond the named six would have to come from the generic OpenAI-compatible path.

### Summary

| Option | Best-fit library | Initial cost | Ongoing cost | Main risk |
|---|---|---|---|---|
| A. Dependency | Rig, or liter-llm | Lowest | Upgrade churn leaks into engine | Breaking changes every few weeks; young or concentrated maintainership |
| B. Own trait + adapters | genai (or Rig `Model` level); async-openai + official Bedrock and Vertex crates per provider | Medium | Contained in adapters | Library-internal retries and lossy mappings stay invisible |
| C. Fork | genai | Medium | Rebasing or losing upstream provider fixes | Owning ~30k lines, half unneeded |
| D. In-house | (reference: genai, Rig, liter-llm) | Highest | Tracking provider API drift | Maintenance and bus factor move in-house |

In every option, Automan writes the same three pieces itself: JSON repair with bounded, error-fed validation retry; the worst-case reservation and journaling around each call; and its own retry policy so each attempt is counted.

## 6. Caveats

- Feature claims for the five deep profiles come from reading pinned source, not from running it. Rows in section 2 beyond those profiles and the two late finds rest on README and grep checks; treat them as indicative.
- Download figures include CI traffic; aisdk's recent jump looks like rebuilds by one dependent (**inferred**).
- lib.rs was unreachable and Exa unavailable, so a maintained crate with low visibility on crates.io search could be missing. edgequake-llm and octolib were found but not inspected.
- Some library behaviours are **unverified**: aisdk's SSE reconnection on POST and its streaming 429 loops; genai with Azure via overrides and Bedrock with `JsonSpec`; Rig's raw computer-use passthrough and OpenAI's acceptance of its `computer_use` type; liter-llm's retry position relative to hooks; Google Cloud Rust's `unstable-streams` gating of streaming generation.
