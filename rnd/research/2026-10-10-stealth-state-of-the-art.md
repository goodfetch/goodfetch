# State of the art in stealth and challenge solving (October 2026)

**Desk research of October 10, 2026, for ticket #64 (map #61).** R&D material for inspiration only: nothing here is an adopted term or decision. Context: [ADR-002](../adr/0002-access-identity-stealth.md) (profiles `identified` / `standard` / `stealth`, CAPTCHA tiers), the lab's [identity report](../lab/reports/identity-2026-10-08.md) and [TLS fingerprint report](../lab/reports/tls-fingerprint-2026-10-08.md), and the [pain ranking](market/pains-ranking.md), where `access-antibot-ip` is the first pain.

**Method.** Primary sources only where possible: project repositories and READMEs, vendor documentation, standards and the researchers' own write-ups. Repository metadata (license, last commit, last release) was read from the GitHub API on 2026-10-10; PyPI release dates from the PyPI JSON API the same day. Current browser versions: Chrome Stable **156** ([chromiumdash](https://chromiumdash.appspot.com/fetch_releases?channel=Stable&platform=Windows&num=1), read 2026-10-10) and Firefox **157.0.1** ([Mozilla product-details](https://product-details.mozilla.org/1.0/firefox_versions.json), read 2026-10-10). Nothing was run against live targets. Success claims made by vendors or project authors about their own products are marked *(self-reported)*. Techniques are described at the level of architecture and capability, not as procedures.

## Summary

- **Detection is layered and consistency-driven.** Vendors combine network fingerprints (JA4 TLS, HTTP/2 frames, header order), JavaScript fingerprints, automation artifacts, behavior, IP reputation and, increasingly, per-site behavioral baselines. A request fails less because one value is wrong than because values disagree: across layers (TLS says Chrome, headers say otherwise), across time (fingerprint changes mid-session), or across the population (an OS share that real traffic does not have).
- **The 2024–2026 shift in counter-techniques is downward in the stack.** JavaScript-injected stealth plugins are obsolete and themselves detectable; `puppeteer-extra` has had no commit since March 2023. The current state of the art is (a) drivers that avoid the CDP side effects detectors probe (Patchright, nodriver/zendriver), and (b) browsers whose fingerprint is changed in engine C++ (Camoufox for Firefox; CloakBrowser, BotBrowser, fingerprint-chromium, Clearcote for Chromium).
- **The best Chromium stealth builds are mostly closed.** CloakBrowser and BotBrowser publish MIT wrappers around proprietary binaries; the newest CloakBrowser builds require a subscription. The fully open options are Camoufox (MPL-2.0, Firefox, self-described "under development"), fingerprint-chromium (BSD-3) and Clearcote (BSD-3, newest versions released to paying users first).
- **HTTP impersonation clients lag the browser.** The newest profiles available on 2026-10-10 were Chrome 149 (wreq-util), Chrome 150 (curl-impersonate) and Chrome 151 (impit), against Chrome 156 Stable. The lab already observed that impit's Chrome profile does not match a current Chromium and that only the session's own browser keeps a coherent identity.
- **Challenges are now mostly invisible.** Cloudflare Turnstile, DataDome Device Check, AWS WAF Challenge, Kasada and Vercel BotID run environment interrogation, often with proof-of-work, without a puzzle; visible steps (checkbox, slider, press-and-hold) exist to collect behavior. Image CAPTCHAs are broken by vision models (100% on reCAPTCHA v2 images in 2024; 60.7% on 26 unseen visual types with a VLM in 2025), so the defense moved to reputation, cookies and environment, not puzzles.
- **The solving market has three tiers:** token services (CapSolver, 2Captcha, CapMonster: reCAPTCHA, Turnstile, AWS WAF, DataDome, GeeTest; hCaptcha is largely dropped), payload-generation APIs that reverse-engineer vendor sensors so plain HTTP clients pass (Hyper Solutions: Akamai, Imperva, DataDome, Kasada), and full unblockers that charge only for successful responses (Bright Data, Zyte, ZenRows, Scrapfly) or hosted browsers with built-in stealth (Browserbase, Browser Use, Anchor, Kernel, Steel).
- **The identity route is no longer Cloudflare-only.** Web Bot Auth signatures are verified by Cloudflare, AWS WAF (November 2025), Akamai, DataDome and HUMAN. This strengthens ADR-002's `identified` default.
- **Residential IP supply is a legal and ethical exposure.** Google disrupted IPIDEA (January 2026) and NetNut (July 2026), stating that many residential proxy brands whitelabel NetNut's botnet of at least 2 million hijacked home devices.
- **Measurement must check content, not status, and run on fixtures one owns.** Public benchmarks are either vendor-run (Browser Use), private-URL (Scrapeway, Proxyway) or small. The reproducible path is a ladder: hermetic network and fingerprint fixtures, then vendor protections deployed on Automan-owned domains (where the vendor's own verdict can be read back), then separate, dated live campaigns.

## 2. Counter-techniques and open-source implementations

### 2.1 Generations

1. **JavaScript patches** (puppeteer-extra-plugin-stealth, fingerprint-injector). Override `navigator.*`, WebGL and so on from page scripts. Detectable through the overrides themselves and through inconsistencies ([Castle, June 2025](https://blog.castle.io/from-puppeteer-stealth-to-nodriver-how-anti-detect-frameworks-evolved-to-evade-bot-detection/)).
2. **Patched automation drivers** (rebrowser-patches, Patchright). Keep Playwright/Puppeteer but remove driver leaks: no `Runtime.enable` (JavaScript runs in isolated execution contexts), `Console.enable` disabled, automation flags adjusted, init scripts injected through routes. Patchright documents that its init-script method is open to timing attacks ([Patchright README](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright)).
3. **CDP-minimal drivers** (nodriver, zendriver, Selenium-Driverless, pydoll, SeleniumBase CDP mode). Talk to Chrome without WebDriver and avoid high-risk CDP domains ([Castle, June 2025](https://blog.castle.io/from-puppeteer-stealth-to-nodriver-how-anti-detect-frameworks-evolved-to-evade-bot-detection/)).
4. **Engine-level browsers.** Fingerprint values are set in the browser's C++ so nothing is visible to JavaScript inspection. Camoufox also isolates Playwright's Juggler agent from the page and routes input through Firefox's native handlers ([Camoufox README](https://github.com/daijro/camoufox)). Chromium builds patch canvas, WebGL, audio, fonts, GPU, screen, WebRTC, network timing and "CDP input behavior" ([CloakBrowser README](https://github.com/CloakHQ/CloakBrowser)).
5. **Network impersonation clients.** Reproduce a browser's TLS ClientHello, HTTP/2 frames and header order without a browser (curl-impersonate, curl_cffi, wreq, impit, tls-client, uTLS). A variant routes ordinary HTTP clients through a real Chrome so JA4 and JA4H match byte for byte (thermoptic).
6. **Fingerprint generation.** Bayesian networks trained on real traffic draw coherent device profiles with realistic market shares (fingerprint-suite, BrowserForge, Scrapfly's fpgen, which Camoufox now uses with a coherence check).
7. **Behavior.** Recorded human trajectories replayed and morphed onto targets (Cursory, used by Camoufox's `humanize`) or synthetic curves (ghost-cursor).
8. **Challenge wrappers.** Run a browser until the challenge clears, then hand cookies to an HTTP client (FlareSolverr, Byparr), or solve inside a session (Scrapling `solve_cloudflare`, thermoptic hooks).

### 2.3 What the projects say about their own limits

- Camoufox: fingerprints "must also be internally consistent", and anti-bot providers "test Camoufox over and over again to find even 1 unique inconsistency"; some WAFs test SpiderMonkey behavior, so Chromium fingerprints cannot be injected; humanized cursor "may still be detected" ([README](https://github.com/daijro/camoufox)).
- CloakBrowser: headful recommended because "some sites detect headless even with C++ patches"; a Linux persona without real Windows fonts is "itself a bot tell"; on detection eventually catching up: "Possibly" ([README](https://github.com/CloakHQ/CloakBrowser), [PyPI](https://pypi.org/project/cloakbrowser)).
- Patchright: console disabled entirely; init scripts detectable by timing ([README](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright)).
- The lab ([identity report](../lab/reports/identity-2026-10-08.md), [TLS report](../lab/reports/tls-fingerprint-2026-10-08.md)): impit in Chrome emulation sent two fewer TLS extensions than the session's Chromium and an HTTP/2 header table of 4,096 instead of 65,536, plus Chrome 124 client hints; wreq without emulation showed a generic BoringSSL fingerprint; got-scraping switched cipher lists mid-session.

Payload-generation and token services, the layer most unblockers and open-source wrappers call underneath:

- **Token solvers.** [CapSolver](https://docs.capsolver.com/guide/api-support) (list updated June 9, 2026): recognition (image, reCAPTCHA v2, AWS WAF) and token tasks (GeeTest, reCAPTCHA v2/v3, MTCaptcha, DataDome, AWS WAF, Cloudflare Turnstile, Cloudflare Challenge); published prices include $0.5 per 1,000 for reCAPTCHA v3, $3 per 1,000 for v3 Enterprise and Turnstile ([pricing](https://docs.capsolver.com/en)). [2Captcha](https://2captcha.com/api-docs/recent-changes) moved to API v2 in 2023 and added CaptchaFox, Prosopo and VK in 2024–2025. hCaptcha is absent from CapSolver's list, a 2Captcha client issue reports support was dropped ([issue](https://github.com/Furry/2captcha/issues/55)), and a competitor states NopeCHA dropped it on Oct. 2, 2026 ([NoneCap](https://nonecap.com/vs/), secondary).
- **Sensor and payload generation.** [Hyper Solutions](https://docs.hypersolutions.co/start-here/overview) generates Akamai sensor data, SBSD and SEC-CPT proof-of-work, Imperva reese84 and utmvc, DataDome interstitial and slider payloads, Kasada tokens and Vercel BotID headers, so a plain HTTP client passes. Its stated requirements are the same consistency rules as above: browser-grade TLS, exact header order including HTTP/2 pseudo-headers, the same UA/TLS/IP/header order for the whole flow, and sticky proxies whose IP matches the one declared. It sponsors curl_cffi and Scrapling.

### 4.1 Solving approaches, from most to least robust

1. **Not being challenged.** A coherent identity (engine, network fingerprint, headers, OS share, geo matching the IP), a reputable IP and a warm session. Every vendor above scores before it challenges.
2. **Passing invisible challenges inside a genuine engine.** Turnstile non-interactive, DataDome Device Check, AWS Challenge, Kasada and BotID are proof-of-work plus interrogation, which a real browser passes if nothing in it contradicts itself.
3. **Interactive steps with human-like input.** Checkbox, slider, press-and-hold. These collect behavior, so input realism matters more than the click.
4. **Vision models on puzzles.** YOLO solved 100% of reCAPTCHA v2 image challenges ([COMPSAC 2024](https://www.computer.org/csdl/proceedings-article/compsac/2024/769600b047/1ZIUJ5qE5gc)); the Halligan VLM solver reached 60.7% on 2,600 challenges of 26 visual types and 70.6% on unseen challenges in the wild over 30 days ([USENIX Security 2025](https://dl.acm.org/doi/10.5555/3766078.3766271)); [Open CaptchaWorld](https://arxiv.org/abs/2505.24878) (NeurIPS 2025) benchmarks multi-step interactive CAPTCHAs for MLLM agents.
5. **Token outsourcing.** A solver returns a token that is injected into the session; it only works when the rest of the session is consistent with the solver's context.
6. **Browser-to-HTTP handoff.** Clear in a browser, continue over HTTP with the cookies. Requires the HTTP client to keep the browser's TLS, HTTP/2, headers and IP; the lab found only the browser tier did.
7. **Payload generation.** Reverse-engineered sensors for plain HTTP. Cheapest at scale, breaks on every script update, and the most exposed legally: ADR-002 already notes the §1201 *trafficking* theory in Reddit v. SerpApi targets tool providers.
8. **Human handoff and declared identity.** Operator solves in the live session; or the site's vendor verifies a Web Bot Auth signature and the challenge is not served.

## 5. Measuring stealth reproducibly

### 5.1 What existing benchmarks do

| Benchmark | Design | Reproducibility |
| --- | --- | --- |
| [Scrapeway](https://scrapeway.com/methodology) | Self-serve scraping APIs; fixed live URLs per target, same for all providers; ~1,000 requests per provider per target over two weeks; success = expected content present, not status code; cost per 1,000 successes; published twice a month (latest run Aug. 14–28, 2026) | URL list private by design |
| [Proxyway Web Scraping API Report 2025](https://proxyway.com/research/web-scraping-api-report-2025) | 11 APIs, 15 protected sites, mainly October 2025; 2 and 10 req/s; site list withheld from participants | Snapshot; Shein averaged 21.88% success, YouTube and Walmart 93.05% |
| [Browser Use stealth benchmark](https://browser-use.com/posts/stealth-benchmark) ([code](https://github.com/browser-use/benchmark), v2.1.1, 2026-09-25) | 71 sites drawn from 300,000 production security-check events, grouped by vendor (Cloudflare 23, PerimeterX 18, DataDome 13, Akamai 8, reCAPTCHA 6, other 3); 3-step tasks; LLM judge only decides "blocked or not"; controls: headless 2%, headful 50% | Code public; run by a competitor of the providers it ranks (Browser Use 81%, Anchor 77%, Kernel 67%, Steel 47%, Browserbase 42%, Hyperbrowser 40%) |
| [BrowserBench (Halluminate)](https://www.halluminate.ai/blog/browserbench) | 296 tasks; agent and model held constant; "stealth failure rate" scored by a calibrated LLM judge (90.4% agreement with humans) | Harness open ([repo](https://github.com/Halluminate/browserbench)) |
| [FP-Inconsistent](https://arxiv.org/abs/2406.07647v3) | Honey site with DataDome and BotD, traffic bought from 20 bot services | Ground truth by construction; the method transfers to Automan |

Test pages (CreepJS, Sannysoft, BrowserScan, Pixelscan, brotector) are useful regression checks but are not the vendors; passing them says little about DataDome or Akamai. Turnstile's dummy sitekeys always pass or always fail, and Cloudflare notes that Selenium, Cypress and Playwright suites "are detected as bots by Turnstile" ([testing docs, May 5, 2026](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)), so they test integration, never stealth.

### 5.2 A measurement ladder for Automan

1. **Hermetic conformance (CI).** Extend the lab's relay: JA4 (BSD-3), HTTP/2 SETTINGS/WINDOW_UPDATE/PRIORITY and pseudo-header order, header order, client hints, cookies, per session and across the HTTP to browser transition. Add self-hosted fingerprint probes ([CreepJS](https://github.com/abrahamjuliot/creepjs), MIT; [BotD](https://github.com/fingerprintjs/BotD), MIT; [brotector](https://github.com/ttlns/brotector), MIT, idle since Dec. 2024) and CDP side-effect probes, plus FP-Inconsistent-style space and time consistency rules. Gate: a profile is "fresh" only if it matches a capture of the browser version it claims.
2. **Vendor fixtures on Automan-owned domains (scheduled, outside CI).** Deploy real protections and read the vendor's own verdict: Turnstile with a real sitekey and Siteverify; a Cloudflare zone with Bot Fight Mode or Bot Management (bot score, detection IDs in logs); AWS WAF Bot Control with Challenge and CAPTCHA on a CloudFront distribution (labels); a reCAPTCHA key in an Automan GCP project (the score itself, within the free tier); Vercel BotID on an Automan Vercel project (Kasada Deep Analysis); hCaptcha; Anubis, Cap and ALTCHA for proof-of-work. Ground truth and legal clarity together; DataDome, Akamai, HUMAN and Kasada direct need trials or partnerships.
3. **Live campaign on third-party sites (separate, authorized, dated).** Scrapeway-style content oracle, fixed URL set, block-randomized order, IP class held constant, controls (stock headless, stock headful), results never merged with hermetic scores, as ADR-002 already requires.

**Metrics per (vendor, access profile, engine build, network profile, IP class, date):** content-verified success rate; challenge rate; solve rate and solve latency; requests survived before the first block; consistency violations; cost per 1,000 verified successes; score distributions where the vendor exposes one (reCAPTCHA, Cloudflare bot score). Report profile age (days and Chrome majors behind Stable) next to every result, since anti-bot vendors update weekly.

## 6. Implications and open questions for Automan

- **The CDP driver is part of the stealth surface.** [ADR-0001](../adr/0001-runtime-language.md) proposes Rust with CDP. The leaks detectors probe come from the driver's protocol use (`Runtime.enable`, `Console.enable`, injected bindings, input events), so leak-free CDP usage (isolated worlds, no Runtime/Console domains, native input) belongs in the driver contract, not in a plugin. Patchright and nodriver show it is feasible.
- **Engine-level patching is the bar, and its maintenance is the product.** Options: build on an open Chromium patch set (fingerprint-chromium or Clearcote, BSD-3), maintain an Automan fork, or support closed builds (CloakBrowser, BotBrowser) only as BYO plugins, since their licenses forbid redistribution or serving third parties without an OEM license. This matches ADR-002's split: open mechanisms, cloud-maintained builds.
- **Firefox is a separate driver.** Camoufox is driven through Playwright's Juggler protocol, not CDP; supporting it means a second protocol adapter for an engine whose own README calls it unstable.
- **HTTP transport: impersonate or delegate.** wreq (BoringSSL, most profiles) and impit (rustls, HTTP/3) are the Rust candidates, both Apache-2.0, both several Chrome majors behind. The lab's finding that only the browser keeps identity argues for "browser-as-transport" in `stealth` sessions (thermoptic pattern) and for generating impersonation profiles from Automan's own captures of real builds rather than trusting library presets.
- **Fingerprint generation needs a population model and a coherence check,** tied to the proxy exit (timezone, locale, geolocation, WebRTC) and to realistic OS shares; Browserbase's non-Verified sessions run Linux, which one competitor calls a giveaway. fingerprint-suite and fpgen are Apache-2.0 bases; Cursory's LGPL-3.0 needs attention if bundled.
- **Challenge solver architecture.** ADR-002's tiers fit the field: (1) vendor-aware challenge detection (Cloudflare, DataDome, PerimeterX, Akamai, Kasada, AWS WAF, decoy content) with typed errors; (2) in-session human handoff; (3) a solver adapter for token services that injects into the same session; (4) managed solving in the cloud. Payload generation (Hyper class) is the most fragile and the most legally exposed; it looks out of scope for the open-source framework.
- **Identity route is widening.** Web Bot Auth verification at Cloudflare, AWS WAF, Akamai, DataDome and HUMAN makes `identified` reach more of the protected web than when ADR-002 was drafted; Browserbase's "Verified" shows a hybrid where the vendor partnership, not evasion, earns access.
- **Proxy sourcing needs due diligence.** Google's 2026 actions against IPIDEA and NetNut, with whitelabeling across "many popular residential proxy brands", mean a managed pool needs provider vetting and per-tenant isolation; BYO stays the open-source default.
- **JA4+ licensing.** Computing JA4 is free; monetized use of JA4H, JA4T and the rest needs a FoxIO OEM license.

**Open questions**

1. Which Chromium base for maintained stealth builds: adopt fingerprint-chromium or Clearcote, fork, or plugins only?
2. Is `stealth` HTTP done by a library (wreq or impit, with Automan-captured profiles) or always by the session's browser?
3. Is a Juggler or WebDriver BiDi adapter for Camoufox worth it next to CDP?
4. Which vendor fixtures can Automan own (Cloudflare, AWS WAF, reCAPTCHA, BotID, hCaptcha are self-serve), and which need trials (DataDome, Akamai, HUMAN, Kasada direct)?
5. What profile-age threshold makes a build "outdated" (ADR-002 asks for dated profiles; Chrome ships every four weeks)?
6. Do token-service adapters ship in the open-source tier given the §1201 trafficking theory raised in ADR-002, pending legal review?

## Limitations

- No product or project was run for this note; all success figures come from the cited parties and many are self-reported.
- Anti-bot vendors document their detection only partially; the table in §4 is limited to what they publish plus what solving services expose.
- The March 2026 CDP variant and the NopeCHA hCaptcha change rest on secondary sources.
- Repository status is a snapshot of 2026-10-10; this field changes monthly.
