Patterns: Mintlify dominates the agent/cloud vendors (Stagehand, Browser Use, Firecrawl, LangChain). ## 3. Generated API references per language

- **TypeScript**: TypeDoc (Apache-2.0, v0.28.x) converts TS comments to HTML or a JSON model. `typedoc-plugin-markdown` emits Markdown and has Docusaurus/VitePress themes and `docusaurus-plugin-typedoc`. `docusaurus-plugin-typedoc-api` renders `/api/*` React pages and versions them with `api:version`. https://typedoc.org/ ; https://github.com/typedoc2md/typedoc-plugin-markdown ; https://github.com/milesj/docusaurus-plugin-typedoc-api/blob/master/packages/plugin/README.md
- **Rust**: docs.rs builds docs for every crate released on crates.io in a sandbox with nightly rustc; `cfg(docsrs)`; `cargo docs-rs` to test builds in CI. Builds can fail (example: spider 2.48.8 "failed to build", fallback to last successful). https://docs.rs/about/builds ; https://docs.rs/crate/spider/2.48.8
- **Python**: mkdocstrings + Griffe (static extraction; `griffe2md` outputs Markdown; Griffe also detects API breaking changes). Sphinx autodoc. pdoc (MIT-0). Fumadocs has a Python content source. https://github.com/mkdocstrings ; https://github.com/mitmproxy/pdoc ; https://www.fumadocs.dev/llms.txt
- **One schema → all languages**:
  - Playwright: API is written once in `docs/src/api/*.md`; `utils/doclint` (api_parser, generateApiJson, generateDotnetApi) produces API JSON; Python port generates its sync/async API with `scripts/generate_api.py` and tracks `expected_api_mismatch.txt`. https://github.com/microsoft/playwright/tree/main/docs ; https://github.com/microsoft/playwright-python/tree/main/scripts (contents listed via gh API)
  - Pulumi: "Pulumi Package schema … drive[s] code generation for SDKs in each supported Pulumi language, as well as generation of language-agnostic package documentation"; `resourcedocsgen` generates Registry API docs from `schema.json` with golden-file tests. https://www.pulumi.com/docs/iac/guides/building-extending/packages/schema ; https://pkg.go.dev/github.com/pulumi/registry/tools/resourcedocsgen/pkg/docs
  - Stainless: docs platform (Astro-based, public beta Mar 2026) generates API + SDK reference from the same "SDKJSON" used to generate SDKs; language tabs show real SDK method signatures; can also inject `x-codeSamples` into OpenAPI for third-party docs hosts. Stagehand Python SDK is Stainless-generated. https://www.stainless.com/blog/stainless-docs-public-beta ; https://www.stainless.com/docs/docs-platform/advanced/custom-sdk-json ; https://www.stainless.com/docs/docs-integrations ; https://docs.stagehand.dev/v3/migrations/python
  - Stripe: single API reference; curl by default, user selects a client library to see examples. https://docs.stripe.com/api
  - Biome: rule pages code-generated from the Rust analyzer source. https://github.com/biomejs/website
- **CLI references**: `clap_mangen` renders ROFF man pages from a `clap::Command` (recommends `cargo xtask` over build.rs). `clap-markdown` generates a `CommandLineHelp.md` (`--markdown-help`). Playwright has `generate_cli_help.js --readme`. https://github.com/clap-rs/clap/blob/master/clap_mangen/README.md ; https://docs.rs/crate/clap-markdown/latest ; https://github.com/microsoft/playwright (package.json `playwright-cli-readme`)
- **MCP tool docs**: MCP spec: each tool has a name plus schema metadata (spec 2026-07-28). Playwright MCP keeps its README tool list generated by `update-readme.js` (run as `npm run lint`). Next.js `next-devtools-mcp` documents tools in a README table. https://modelcontextprotocol.io/specification/2026-07-28/server/tools ; https://github.com/microsoft/playwright-mcp (package.json) ; https://github.com/vercel/next-devtools-mcp/blob/main/README.md

## 4. Agent-facing documentation

**llms.txt adoption vs evidence of use**
- Proposed by Jeremy Howard, Sept 2024. Adoption grew 8.8x (4,088 → 36,120 sites, Jun 2025 → May 2026, Originality.ai tracker). https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests
- Ahrefs (137,210 domains, May 2026 logs): 97% of llms.txt files got zero requests; of bot requests that did arrive, 1.1% from AI retrieval bots, 10.5% from AI agents/agentic tools. https://mentionbeat.com/blog/does-llms-txt-work (summarizing Ahrefs, 2026-06-15)
- Google's John Mueller (June 2025): "no AI system currently uses llms.txt". https://www.seroundtable.com/google-ai-llms-txt-39607.html
- Dries Buytaert (Mar 2026, Cloudflare logs): llms.txt requests all from SEO tools; across Acquia fleet ~5,000 of 400M requests; AI crawlers "rarely request Markdown". https://dri.es/markdown-llms-txt-and-ai-crawlers
- Server-log study (~900 domains): 0 of 1,227 llms.txt requests from frontier-lab crawlers. https://www.digitalapplied.com/blog/llms-txt-in-practice-adoption-evidence-2026
- Interpretation from the evidence: the real audience is coding agents/tools fetching on demand, not crawlers.

**Copy-as-markdown / `.md` endpoints** (now common): Temporal ("append .md"), Prisma, Mintlify sites, Crawlee (`/js.md`), uv (`index.md`), Bun (`rel=alternate type=text/markdown`), AI SDK (`/agents.md`, `/sitemap.md`), Stainless ("Open in Claude/ChatGPT/Cursor"). Sources: https://docs.temporal.io/references/api-reference ; https://www.prisma.io/docs/guides ; https://docs.astral.sh/uv/llms.txt ; https://ai-sdk.dev/docs/getting-started ; https://www.stainless.com/docs/sdks/python

**Docs MCP servers**: Context7 (Upstash) serves version-specific library docs via MCP or `ctx7` CLI + skill; pin versions with `/owner/repo/<version>`. https://context7.com/docs/api-guide ; https://github.com/upstash/context7/blob/master/README.md. Mintlify hosts `/mcp` per site. Fumadocs CLI generates one. Next.js: `next-devtools-mcp` now only a "gateway" pointing agents to bundled docs ("Docs and migration workflows no longer live in this server"). https://github.com/vercel/next-devtools-mcp/blob/main/README.md. Quality complaints about Context7: not verified.

**Docs bundled in packages (verified)**: Next.js 16.2+ ships version-matched docs at `node_modules/next/dist/docs/`; 16.3+ `next dev` auto-generates AGENTS.md/CLAUDE.md pointing to them; older versions use `npx @next/codemod@canary agents-md` (downloads to `.next-docs/`). Next.js skills moved into the Next.js repo "so they stay version-matched". https://nextjs.org/docs/app/guides/ai-agents ; https://github.com/vercel-labs/next-skills
- Vercel eval (Jan 2026): 8KB compressed docs index in AGENTS.md got 100% on Next.js 16 API evals; skills max 79%, and without explicit instructions skills were no better than no docs. https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals ; HN discussion https://news.ycombinator.com/item?id=46809708

**Skills shipped with packages**: Agent Skills spec (agentskills.io): folder with `SKILL.md` (YAML `name`, `description` ≤1024 chars, optional `license`, `compatibility`, `metadata`, `allowed-tools`) plus `scripts/`, `references/`, `assets/`. https://agentskills.io/specification. Playwright: `playwright-cli install --skills` copies the skill into `.claude/skills` or `.agents/skills`; also "skills-less" mode via `--help`. https://playwright.dev/agent-cli/skills. Skill source lives inside the package: https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/tools/skills/playwright-cli/SKILL.md. Vercel `npx skills add` CLI + skills.sh directory. https://www.skills.sh/docs/cli. Browser Use ships `cloud` and `open-source` skills via `npx skills add`. https://docs.browser-use.com/open-source/examples/skills/cloud. Mintlify advertises `/.well-known/agent-skills/index.json`. https://www.mintlify.com/docs/ai/llmstxt

**Docs inside the CLI**: Playwright recommends pointing agents at `playwright-cli --help` when skills aren't installed. https://playwright.dev/agent-cli/skills. Docs-inside-CLI patterns beyond `--help` (e.g. `tool docs` subcommands): not verified for the target projects in this pass.

## 6. Docs testing

- **Rust doctests**: rustdoc compiles and runs examples as tests; 2024 edition merges compatible doctests for speed; README can be included as doctests via `#[cfg(doctest)]`. https://doc.rust-lang.org/rustdoc/write-documentation/documentation-tests.html ; https://doc.rust-lang.org/1.97.1/rustdoc/documentation-tests.html
- **Playwright**: `utils/doclint/linting-code-snippets/{python,java,csharp}` + `--js-only` mode lints code snippets in docs for every language; `npm run doc` (doclint) is part of `lint`. https://github.com/microsoft/playwright (package.json, utils/doclint)
- **TypeScript**: Twoslash renders code samples using the TypeScript compiler's information (type errors surface at build). https://twoslash.netlify.app/. Fumadocs supports Twoslash. https://www.fumadocs.dev/llms.txt
- **Python**: pytest-examples (Pydantic) lints with ruff/black, runs examples, checks `#>` print output, can update in place. https://github.com/pydantic/pytest-examples ; https://pypi.org/project/pytest-examples/0.0.17. Sybil parses and evaluates examples in docs as part of test runs. https://sybil.readthedocs.io/en/latest/
- **Snippet sync**: Temporal uses `snipsync` (config in repo) to pull code from tested sample repos; also Vale and Playwright tests. https://github.com/temporalio/documentation
- **Links**: lychee (Rust, MIT/Apache) + lychee-action. https://github.com/lycheeverse/lychee-action/blob/master/README.md. Prisma `lint:links`, `lint:code`. Fumadocs "Validate Links" integration. https://www.fumadocs.dev/llms.txt
- **Generated-docs golden tests**: Pulumi resourcedocsgen golden files (`PULUMI_ACCEPT`). https://pkg.go.dev/github.com/pulumi/registry/tools/resourcedocsgen/pkg/docs

## Patterns (summary)

1. Multi-language libraries keep one site with per-language sections and generate the per-language API from one source (Playwright api.md → doclint → ports; Pulumi schema; Stainless SDKJSON). Per-language drift still produces most of the Python-parity bugs users file.
2. Versioning: the trend is fewer kept versions. Playwright keeps only stable + next; others keep per-minor dropdowns (Crawlee, Pydantic) or separate per-major deployments (Biome, Tauri, LangChain). Deploying docs from main without a version split is a recurring complaint.
3. Agent-facing docs converged on: `.md` per page, llms.txt (cheap but weak evidence of crawler use; real consumers are coding agents), a docs MCP or an MCP gateway, skills installed from the package, and, at the leading edge, version-matched docs inside the installed package plus an AGENTS.md index (Next.js; backed by Vercel's eval).
4. Tool landscape shifted in 2025-2026: MkDocs Material in maintenance mode; Zensical early (0.0.x) with versioning only via a transitional mike fork; Starlight versioning still a community plugin in "early development"; Docusaurus has the most mature built-in versioning and is heading to v4; Mintlify gives the most agent features out of the box but its llms.txt only covers the default version.
5. Docs testing that works is language-native: rustdoc doctests, Twoslash, pytest-examples/Sybil, cross-language snippet linting (Playwright), plus lychee for links.
