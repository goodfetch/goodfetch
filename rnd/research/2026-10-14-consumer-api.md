# Consumer API of browser-automation and crawl frameworks: patterns, what users like, what hurts

State observed on **2026-10-14**. Input for the developer-facing API of Goodfetch Collie (one browser page with AI primitives) and Goodfetch Foxhound (crawling and collection at scale), on the products map [#447](https://github.com/goodfetch/automan/issues/447). It covers what developers write and call, not engine internals. This note is a synthesis; every claim is sourced in one of three detailed notes:

- [AI browser automation](research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md): Stagehand 4.2 (and v1–v3), Browser Use 0.13, Midscene 1.15, Vercel agent-browser 0.39, Skyvern 1.0.56, Playwright MCP 0.0.83 and playwright-cli, Notte 1.9.7; LaVague, HyperAgent and Magnitude as dormant references.
- [Browser drivers](research_notes/Consumer%20API%20of%20competitors/browser-drivers.md): Playwright 1.64 (all four languages, and how its multi-language API is produced), Puppeteer 25.13, Selenium 4.51 and WebDriver BiDi, the Rust crates (chromiumoxide, headless_chrome, fantoccini, thirtyfour, playwright-rs, rustwright), Cypress and WebdriverIO for ideas, nodriver, Patchright and rebrowser for why users switch.
- [Crawl frameworks](research_notes/Consumer%20API%20of%20competitors/crawl-frameworks.md) and its [forum evidence table](research_notes/Consumer%20API%20of%20competitors/forum-evidence.md): Crawlee JS 3.18 (and the 4.0 RC), Crawlee Python 1.10, Scrapy 2.19 (with scrapy-playwright and web-poet), Spider 2.53 and its bindings, Colly, Crawl4AI, Firecrawl SDK v2, Scrapling, Katana, Apify SDK.

## Method and limits

- Primary sources: official docs and source at pinned tags, release notes, and the issue trackers themselves (ranked by reactions and comments through the GitHub API, plus top closed and declined issues with the maintainers' reasons). User sentiment: Hacker News (Algolia API), Stack Overflow (Stack Exchange API, top-voted questions per tag), migration posts and independent blogs. Vendor and competitor write-ups are cited only as support, never counted as user evidence.
- **Reddit could not be read** (login wall, 403 and refused by the search tool), nor Lobsters or the vendors' Discords. The "likes" rankings therefore over-weight Hacker News and GitHub. Every detailed note ends with an explicit **unverified** list; no code sample was executed.
- Counts such as "8 independent reports" mean distinct non-vendor authors found in this pass, not a census.

## 1. The three API families at a glance

| Family | Shape users write | Where they converge | Where they still split |
|---|---|---|---|
| **Browser drivers** (Playwright, Puppeteer, Selenium, Rust crates) | Browser → Context → Page → Locator; `await page.getByRole(...).click()` | Lazy re-resolving locators; strict matching (ambiguity is an error); auto-wait before actions; pages and frames as values, not a "current" pointer; scoped close (`await using`, `with`); the protocol hidden behind the API | Whether waiting lives in every action or only in explicit waits; what "actionable" means; timeouts (4 s to 30 s); where callbacks run (host or page); cancellation (JS-only `AbortSignal` at best) |
| **AI browser automation** (Stagehand, Browser Use, Skyvern, Midscene, Notte, agent-browser, Playwright MCP) | `act(instruction)`, `observe()`, `extract(instruction, schema)`, sometimes `assert`/`validate`, sometimes an agent loop | The same three verbs; a Playwright-grade page within reach; AI steps that return something replayable; selector first, AI as fallback; compact accessibility snapshots with short refs; the in-library agent moving outside | Verbs on the page (`page.act`) or on a runtime object (`stagehand.act(x, { page })`); schema as native types or JSON Schema; failures as values or exceptions; cache local or on the vendor's server |
| **Crawl frameworks** (Crawlee, Scrapy, Spider, Colly, Crawl4AI, Firecrawl, Scrapling) | A crawler object or `Spider` class, a handler per page type (labels and a router, or `callback=`), `enqueueLinks`, `pushData` / `yield item` | Discover → fetch → handle → emit; labels or callbacks as the page-type router; an enqueue helper with a same-host default scope; per-request user data; fetch tier moving from "pick a class" to a per-request or learned choice; AI extraction moving into the handler with "learn selectors once, replay without the model" | Who owns the event loop (Scrapy) or the user (Crawlee); push into storage or pull a stream; typed items (Scrapy) or plain dicts (Crawlee); runtime options or compile-time features (Spider); purge or continue on the second run |

## 2. Patterns common to all three families

1. **Small surface with honest, typed results wins.** Liked everywhere: Playwright's "just promises" API, Stagehand's three verbs ("super clean", [HN](https://news.ycombinator.com/item?id=42644964)), Firecrawl's one call. Disliked everywhere: Browser Use's ~60-kwarg `Agent` that silently ignores unknown options ([#3535](https://github.com/browser-use/browser-use/issues/3535)), Crawl4AI's `arun()` whose return type depends on the config ([#1898](https://github.com/unclecode/crawl4ai/issues/1898)), Skyvern's `timeout` in minutes, seconds or milliseconds depending on the call.
2. **The deterministic artifact is the product.** Drivers: Playwright's codegen and trace viewer are its most-loved tools after auto-wait. AI tools: the most requested feature in every tracker is "replay without the model / export the script" (Stagehand [#389](https://github.com/browserbase/stagehand/issues/389), Browser Use [#763](https://github.com/browser-use/browser-use/issues/763) and [#943](https://github.com/browser-use/browser-use/issues/943), Playwright MCP [#123](https://github.com/microsoft/playwright-mcp/issues/123), at least 12 independent forum voices). Crawlers: Scrapy's HTTP cache and contracts make crawls replayable offline, and Crawlee Python's `PydanticAiSelectorExtractor` caches model-learned selectors.
3. **Escape hatches are expected, but secondary.** Raw CDP sessions (Puppeteer, Playwright `CDPSession`), `evaluate`, Playwright MCP's `run_code` (its top issue, +25). Users leave a library whose hatch is too narrow (browser-use left Playwright for raw CDP in 2025-08). Every family keeps the hatch outside the main path.
4. **The hidden-state models lost.** Selenium's `switch_to` pointer, Cypress's command queue ([#1417](https://github.com/cypress-io/cypress/issues/1417), 492 reactions, open since 2018), Stagehand's implicit "active page", Crawlee v3's implicit storage purge, Scrapy's process-global reactor. Each is now either removed or the top complaint.
5. **Unsafe defaults fall on the tool's reputation.** Seven of eight crawlers ignore robots.txt by default (only Firecrawl obeys; Scrapy only in its generated template); Scrapy's tracker has site owners calling it "a malicious denial-of-service tool in its default configuration" ([#6597](https://github.com/scrapy/scrapy/issues/6597)). On the AI side: telemetry on by default with task text and URLs (Browser Use, Notte), secret values sent to a vendor cache by default (Stagehand v4), domain policies bypassed (Stagehand [#2945](https://github.com/browserbase/stagehand/issues/2945), Skyvern [#8577](https://github.com/Skyvern-AI/skyvern/issues/8577)).
6. **Language ports drift unless generated and tested together.** Spider's Python binding was last published 2025-01-28; Crawlee Python keeps parity through mirror issues; Stagehand's Python SDK took three unrelated shapes; Selenium wrote a behavioural contract because its five bindings disagreed on network handlers. Playwright is the counter-example (behaviour lives once in its server), and Stagehand v4 fixed its parity only by generating its SDKs.
7. **Churn is measured, and users stay behind.** Two months after Stagehand v4, only 28.8% of its npm downloads are v4; Browser Use issue volume rose 52% after the 0.3.3 break; Playwright MCP is still 0.0.x after about 15 renames; Scrapy removed `start_requests()` 12 months after deprecating it and still gets confused reports. Midscene's aliases-with-warnings and Playwright's "no major since 1.0" are the praised models.
8. **Logging to stdout breaks agent hosts.** Crawl4AI ([#1968](https://github.com/unclecode/crawl4ai/issues/1968)), Scrapling ([#50](https://github.com/D4Vinci/Scrapling/issues/50)) and Browser Use ([#2748](https://github.com/browser-use/browser-use/issues/2748)) broke MCP stdio; Stagehand v4's top issue is logs forced to stderr ([#3035](https://github.com/browserbase/stagehand/issues/3035)); Playwright's bindings cannot route logs into the host logger ([#6465](https://github.com/microsoft/playwright/issues/6465), +82, not planned).

## 3. What users like (merged ranking)

| # | Liked quality | Strongest evidence | Families |
|---|---|---|---|
| 1 | **Auto-waiting, guarded actions** | 8+ distinct HN authors 2021–2026, 4 migration posts; Selenium's top pain is its absence ([browser drivers §5](research_notes/Consumer%20API%20of%20competitors/browser-drivers.md#5-what-users-like-ranked)) | drivers |
| 2 | **Generate with AI once, then own deterministic, reviewable code** | ≥12 independent voices across Stagehand, Browser Use, agent-browser, playwright-cli ([AI §5](research_notes/Consumer%20API%20of%20competitors/ai-browser-automation.md#5-what-users-like-ranked)) | AI |
| 3 | **One API across HTTP and browser fetching, browser only where needed** | 8 independent reports; "unified API for browser and HTML scraping" ([HN](https://news.ycombinator.com/item?id=32561840)) ([crawl §5](research_notes/Consumer%20API%20of%20competitors/crawl-frameworks.md#5-what-users-like-ranked)) | crawl |
| 4 | **Plain async/await, no hidden queue; small clean primitives mixed with ordinary code** | 7 HN authors on drivers; 6 on Stagehand's verbs | drivers, AI |
| 5 | **Seeing what happened: trace viewer, replay reports, per-action code** | 6 HN authors plus 4 migration posts (Playwright); Skyvern and Midscene reports | all |
| 6 | **One official API in several languages** | 8 HN authors; pyppeteer's abandonment pushed users to Playwright | drivers, crawl |
| 7 | **Testable callbacks and offline replay of saved responses** | 5 reports for Scrapy ("solved every problem", [HN](https://news.ycombinator.com/item?id=32570837)) | crawl |
| 8 | **Any model, including local ones** | Browser Use 3, Stagehand 2, Midscene 1 | AI |
| 9 | **Time to first result** ("just works", one install command, browsers fetched for you) | 5 for crawlers, 4 for Playwright's installer, 4 for Browser Use | all |
| 10 | **Token-efficient observations** (refs, compact snapshots, CLI over MCP) | agent-browser 10, playwright-cli 5 | AI |
| 11 | **Locators that read like the user's view** (role, text, label) next to CSS and test IDs | 6 authors, with pushback when CSS is discouraged | drivers |
| 12 | **Middleware and fine-grained control when off the happy path** | 5 reports for Scrapy; Crawlee Python's launch thread asked for it | crawl |

## 4. Pain points (merged, ranked by evidence weight)

Weight combines independent reports, reactions and votes, how many libraries show the problem, and whether it is still open. The lesson column is analysis for Collie and Foxhound; the "Goodfetch today" column says whether an adopted ADR already answers it.

| # | Pain | Evidence (abridged; full rows in the detailed notes) | Lesson | Goodfetch today |
|---|---|---|---|---|
| 1 | **Timing: "element ready" is not "app ready"** | 53 of 375 top Playwright/Puppeteer SO questions (1,686 votes); Selenium wait questions 356 and 304 votes; strict mode failing at once instead of waiting ([#36045](https://github.com/microsoft/playwright/issues/36045)) | First-class, composable waits for app state (URL, response, count, load state, predicate) under one deadline; every timeout error says what was waited for, the last observed state and where the limit came from | Guard covers element readiness (ADR 0019); app-state waits and error contents not yet specified |

## 5. Bearing on Goodfetch's adopted design

- **Already aligned with the evidence:** one engine with generated SDKs (ADRs 0011, 0024, 0038), the guard's checks beyond Playwright's (uniqueness, hit target, cancel-and-replay; ADR 0019), Plans and replay without a model (ADR 0009), journaled AI effects (ADR 0010), leases and staged outputs, typed errors and `$/cancel` (ADR 0038), capabilities as settings, no Node runtime, no stdout writes outside the transport.
- **Playwright's multi-language method is the closest precedent and differs in one respect.** Playwright keeps two definitions: the wire protocol in 19 YAML files and the public API in Markdown with 461 per-language annotations, with each client's implementation hand-written. Since 2026-10-12 its Python client generates from those docs, and Python-only facts live in a rules file ([browser drivers §4.3](research_notes/Consumer%20API%20of%20competitors/browser-drivers.md#43-how-one-api-is-ported-across-languages)). Goodfetch's single catalog avoids the drift but needs somewhere to put per-language aliases, reserved words, language-only overloads (Python context-manager waiters, Rust `Stream`s, TypeScript `AbortSignal`) and typed defaults (`timedelta`, `Duration`). Playwright's server also renders locators in the caller's language inside errors, which is cheap in the same architecture.
- **The in-library agent is being withdrawn by the largest vendors.** Stagehand v4 removed `agent()` (2026-08); Playwright 1.58 shipped a hidden `page.agent()` with `perform`, `expect`, `extract` and a code cache, then deleted it on 2026-03-11 with no public reason. The owner's direction lists `agent` among Collie's primitives; the evidence argues for deciding its form explicitly (none, a thin journaled loop over the same verbs, or first-class).
- **One adopted decision runs against the user evidence:** crawl politeness (ADRs 0016 and 0021; pain 9). The ADRs chose parity with Crawlee and Spider; the trackers show the cost of that choice falling on the tool's reputation.
- **Not covered by any ticket yet:** the public SDK shapes themselves (entry points, object lifecycle, the handler context, the replay artifact, result and outcome types, waits, the payload model, the Python sync client). See the questions below.

## 6. Design questions this research raises (for grilling, not decisions)

**Both products**
1. Lifecycle: scoped disposal in every SDK (`await using`, `async with`, a Rust scope helper) plus explicit ownership of launched versus attached browsers; one object or two (browser and AI runtime)?
2. Failure model: values with an explicit raise switch (Notte's `raise_on_failure`) or exceptions with stable codes, never both by accident (Stagehand v4)?
3. Python: a separate blocking client over the same JSON-RPC, or async only?
4. Events: emitters, async iterators or streams per language; do host-language predicates run in the host on streamed events (Playwright) or as declarative filters in the engine (cheaper for crawls)?
5. How does the catalog carry per-language aliases, reserved words, language-only overloads and typed defaults?

**Collie**
6. Where do the AI verbs live: on the Playwright-shaped page (`page.act`, as Skyvern and HyperAgent; Stagehand v2) or on a runtime object (`collie.act(x, { page })`, Stagehand v3/v4)?
7. Is `observe` → typed action → `act(action)` the replay contract, and what does the action carry beyond an absolute XPath (a selector ladder, a target fingerprint, frame identity)?
8. A deterministic `check`/`assert` verb next to `act`/`observe`/`extract`, and results that separate stopped, agent-reported and verified?
9. Schema input: JSON Schema on the wire with native types per language (Standard Schema/Zod, Pydantic, serde), without depending on a schema library's internals (Stagehand's Zod 3→4 break lasted about three months)?
10. `agent`: none, a thin journaled loop, or first-class?
11. Strict-mode ambiguity: wait for uniqueness within the action deadline (the guard can) or fail at once (Playwright)?

**Foxhound**
12. Page types: a router with labels (Crawlee) or per-request callbacks (Scrapy, Scrapling), given handlers run behind JSON-RPC?
13. Results: push into a Dataset from the handler, pull a stream (`for await item of run.items()`), or both (Scrapling)?
14. Typed items with a schema per Dataset, or plain dicts?
15. Tier: per request with learned escalation, and what happens when an HTTP-tier handler touches `page` (escalate or error)?
16. Run identity: continue by default and explain when nothing is processed (Crawlee v4), or explicit resume?
17. Test story: recorded responses replayed offline and page-object fixtures, as an engine feature, an SDK feature or both?
18. Politeness: do ADR 0016 (robots.txt not obeyed by default) and ADR 0021 (8 per domain, no delay) stand against the Scrapy abuse reports, or does Foxhound's API add safer defaults (a delay, an operator-identifying user agent, a logged opt-out)? Scrapy's experience is that defaults placed only in a project template do not reach users who call the library from a script.
