# Agent-loop APIs: how a program calls a model-driven loop

Research as of **October 15, 2026**. It answers one question: how the leading agent-loop APIs shape a loop that a program calls, on fixed points: the step cap and its default, what happens at the cap, streaming, tools, structured output and the result object. Nothing here is a Goodfetch decision.

**Method.** Versions come from the npm and PyPI registries on October 15, 2026. Every claim is read from the source or the documentation **at the tagged release** named in each section; the links pin that tag. Where only a documentation page was read, the section says so. "Unverified" marks a point that was not established from a primary source; it does not mean the feature is absent. No code was run.

## Surprising findings

1. **Most loops return at the step cap; five of the twelve rows throw.** OpenAI Agents (both languages), Pydantic AI, Midscene and Playwright raise; the AI SDK, Stagehand, Notte (steps), Browser Use, Skyvern and both provider tool runners return a result that records the stop. The OpenAI Agents SDK is the only one with a documented switch between the two: `error_handlers["max_turns"]` turns the exception into a returned `final_output`.
2. **The AI SDK returns at the cap but its typed output may not exist.** `generate()` resolves normally at `isStepCount(20)`, yet `result.output` throws `NoOutputGeneratedError` when the final step finished with tool calls. A caller reading only `output` meets a throw at a different point than the loop.
3. **The OpenAI Agents SDK stopped showing tool exceptions to the model.** In Python 0.22.3 the default failure message ended with the exception text; from 0.23.0 it is a fixed "An error occurred while running the tool. Please try again." The JS SDK 0.20.0 does the same. Details reach the model only through a custom `failure_error_function` / `errorFunction`.
4. **Pydantic AI does the opposite by default:** an ordinary exception in a tool **ends the run**; only `ModelRetry` (counts against the retry budget, default 1) or the newer `ToolFailed` (does not) is shown to the model.
5. **Defaults differ by mode inside one library.** Stagehand v3 documents `maxSteps` 20, but its three CUA clients use 10. Midscene's cap depends on the model family (20, 40 or 100). Browser Use's classic agent allows 500 steps, its beta agent 100. Skyvern's server default is 10 steps for engine `skyvern-1.0` and 25 for `skyvern-2.0`.
6. **AI SDK v7 renamed the stop helpers.** `stepCountIs` survives only as a deprecated alias of `isStepCount`; `fullStream` is deprecated in favour of `stream`. The default cap moved from silent (v6, `stepCountIs(20)`) to logging a warning when it stops a loop.
7. **Judges and validators differ in authority.** Notte's `CompletionValidator` can reject the agent's "done" and make it continue. Browser Use's judge (`use_judge=True` by default) only attaches a verdict to the result and does not override the agent's own success flag.
8. **Playwright's hidden agent shipped in one minor release only.** `page.agent()` appears in 1.58.0 (January 23, 2026) and is gone from 1.59.0 (April 1, 2026) onwards; its loop came from the bundled `@lowire/loop` 0.0.25.

## 1. OpenAI Agents SDK

**Versions.** Python `openai-agents` 0.23.1 (PyPI, October 2, 2026); JS `@openai/agents` 0.20.0 (npm, October 8, 2026).

**Turn cap.**

- Python: `DEFAULT_MAX_TURNS = 10` ([run_config.py#L45](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/run_config.py#L45)); `Runner.run`, `run_sync` and `run_streamed` take `max_turns: int | None = DEFAULT_MAX_TURNS`, and `None` disables the limit ([run.py#L261-L330](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/run.py#L261-L330)). A turn is one model invocation, including its tool calls.
- JS: `DEFAULT_MAX_TURNS = 10` ([runner/constants.ts](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/runner/constants.ts)); option `maxTurns?: number | null`, where `null` disables it ([running-agents guide](https://openai.github.io/openai-agents-js/guides/running-agents/)).

**At the cap.** Python raises `MaxTurnsExceeded` ("Max turns (N) exceeded", [run.py#L1507-L1531](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/run.py#L1507-L1531)); JS throws `MaxTurnsExceededError` ([errors.ts#L38](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/errors.ts#L38)). Both accept **error handlers** that return a value instead:

- Python: `error_handlers: RunErrorHandlers`, a dict with keys `max_turns`, `model_refusal`, `invalid_final_output`. A handler receives `RunErrorHandlerInput(error, context, run_data)` and returns `RunErrorHandlerResult(final_output, include_in_history=True)`, a dict, or a raw value; `None` declines ([run_error_handlers.py](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/run_error_handlers.py); [Error handlers docs](https://openai.github.io/openai-agents-python/running_agents/#error-handlers)).
- JS: `errorHandlers` keyed `maxTurns`, `modelRefusal`, `invalidFinalOutput`, plus a `default` fallback; a handler returns `{ finalOutput, includeInHistory? }` or `undefined` ([runner/errorHandlers.ts#L31-L78](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/runner/errorHandlers.ts#L31-L78)). The returned `finalOutput` is validated against the agent's `outputType`.

**Streaming.**

- Python: `Runner.run_streamed(...)` is a plain (non-async) class method that returns a `RunResultStreaming` immediately ([run.py#L469](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/run.py#L469)). Iterate `async for event in result.stream_events()`; event types are `raw_response_event`, `run_item_stream_event`, `agent_updated_stream_event` ([stream_events.py](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/stream_events.py)). `stream_events()` raises `MaxTurnsExceeded` and guardrail tripwires ([result.py#L942-L951](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/result.py#L942-L951)). After the iterator ends, read `result.final_output` (it stays `None` until then) and `result.is_complete` ([Streaming docs](https://openai.github.io/openai-agents-python/streaming/); [Results docs](https://openai.github.io/openai-agents-python/results/)).
- JS: `run(agent, input, { stream: true })` resolves to a `StreamedRunResult` that implements `[Symbol.asyncIterator]` (`for await (const event of result)`), plus `toStream()`, `toTextStream()`, the `completed` promise, `cancelled` and `error` ([result.ts#L303-L625](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/result.ts#L303-L625)). Event types: `raw_model_stream_event`, `run_item_stream_event`, `agent_updated_stream_event` ([events.ts](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/events.ts)). The docs say to await `completed` before reading `finalOutput` ([Streaming guide](https://openai.github.io/openai-agents-js/guides/streaming/)).

**`output_type`.** Python `Agent.output_type: type | AgentOutputSchemaBase | None = None`; without it the output is `str`; non-strict schemas through `AgentOutputSchema(MyClass, strict_json_schema=False)` ([agent.py#L383-L390](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/agent.py#L383-L390)). JS: `outputType` (a Zod schema, JSON schema or `'text'`) ([Agents guide](https://openai.github.io/openai-agents-js/guides/agents/)).

**Function tools and errors.**

- Python `@function_tool(name_override, description_override, failure_error_function, strict_mode=True, needs_approval=False, timeout=None, timeout_behavior="error_as_result", ...)` ([tool.py#L2569-L2690](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/tool.py#L2569-L2690)). When the tool raises, the default `default_tool_error_function` returns the fixed text "An error occurred while running the tool. Please try again." without the exception ([tool.py#L1975-L1980](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/tool.py#L1975-L1980)); in 0.22.3 the same function appended `Error: {str(error)}` ([v0.22.3 tool.py](https://github.com/openai/openai-agents-python/blob/v0.22.3/src/agents/tool.py)). Passing `failure_error_function=None` re-raises and fails the run. Timeouts with `"raise_exception"` raise `ToolTimeoutError`.
- JS `tool({ name, description, parameters, execute, errorFunction, strict, needsApproval, timeoutMs, timeoutBehavior })`, `parameters` being a Zod object or JSON schema. The default error function returns the same fixed message; `errorFunction: null` propagates the error; tools with an output schema rethrow by default ([tool.ts#L1736](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/tool.ts#L1736) and the `errorFunction` comment above [L1824](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/tool.ts#L1824)). Run option `toolErrorFormatter` customizes the message.

**Result fields.** Python `RunResultBase`: `input`, `new_items`, `raw_responses`, `final_output`, `input_guardrail_results`, `output_guardrail_results`, tool guardrail results, `context_wrapper`, `last_agent`, `final_output_as(cls)`, `to_input_list()`; `RunResult` adds `max_turns` and `interruptions` ([result.py#L312-L519](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/result.py#L312-L519)). There is no `usage` field on the result: usage is `result.context_wrapper.usage` (`requests`, `input_tokens`, `output_tokens`, `total_tokens`, `request_usage_entries`) ([Usage docs](https://openai.github.io/openai-agents-python/usage/)). JS: `finalOutput`, `newItems`, `history`, `output`, `rawResponses`, `lastAgent`, `interruptions`, `state`, and usage at `result.state.usage` or `result.runContext.usage` ([result.ts#L134-L290](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/result.ts#L134-L290); [usage example](https://github.com/openai/openai-agents-js/blob/v0.20.0/examples/docs/results/usage.ts)).

**Output guardrails.** Run only on the agent that produces the final output, after it, never in parallel. A guardrail function returns `GuardrailFunctionOutput(output_info, tripwire_triggered)`; a tripwire raises `OutputGuardrailTripwireTriggered`, and the session keeps completed tool items but not the rejected final output ([guardrail.py#L134-L143](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/guardrail.py#L134-L143); [Guardrails docs](https://openai.github.io/openai-agents-python/guardrails/)). `error_handlers` do not cover tripwires (their kinds are only the three above). JS is the same (`OutputGuardrailTripwireTriggered`, [Guardrails guide](https://openai.github.io/openai-agents-js/guides/guardrails/)); its `outputGuardrailBlockedMessage` run option only changes the placeholder kept for a rejected terminal tool output.

**`tool_use_behavior`.** Default `"run_llm_again"`; also `"stop_on_first_tool"`, `StopAtTools(stop_at_tool_names=[...])`, or a function returning `ToolsToFinalOutputResult`. It applies to function tools only; hosted tools always go back to the model. `reset_tool_choice=True` by default ([agent.py#L396-L420](https://github.com/openai/openai-agents-python/blob/v0.23.1/src/agents/agent.py#L396-L420)). JS: `toolUseBehavior`, default `'run_llm_again'`, with `{ stopAtToolNames }` ([agent.ts#L617](https://github.com/openai/openai-agents-js/blob/v0.20.0/packages/agents-core/src/agent.ts#L617)).

## 2. Vercel AI SDK

**Version.** `ai` 7.0.140 (npm `latest`, October 14, 2026). v7.0.0 shipped on June 25, 2026; the v6 line continues as 6.0.306 (dist-tag `ai-v6`), v5 as 5.0.276. **v7 is current**, not v5 or v6.

**Class.** `ToolLoopAgent` implements the `Agent` interface (`version: 'agent-v1'`, `id`, `tools`, `generate()`, `stream()`) ([agent.ts#L191-L218](https://github.com/vercel/ai/blob/ai%407.0.140/packages/ai/src/agent/agent.ts#L191-L218)). The docs also describe a `WorkflowAgent` that has **no** default step limit ([loop-control.mdx#L23](https://github.com/vercel/ai/blob/ai%407.0.140/content/docs/03-agents/04-loop-control.mdx#L23)).

**Default stop condition.** `stopWhen: this.settings.stopWhen ?? createDefaultStopCondition(20)` ([tool-loop-agent.ts#L132](https://github.com/vercel/ai/blob/ai%407.0.140/packages/ai/src/agent/tool-loop-agent.ts#L132)). **`steps`.** `GenerateTextResult.steps: Array<StepResult>` ("details for all steps"), plus `finalStep`, `text`, `toolCalls`, `toolResults`, `usage` (last step) and `totalUsage` (all steps) ([generate-text-result.ts#L40-L181](https://github.com/vercel/ai/blob/ai%407.0.140/packages/ai/src/generate-text/generate-text-result.ts#L40-L181)).

**Structured output.** Declared on the agent with `output: Output.object({ schema: z.object({...}) })` and read as `const { output } = await agent.generate(...)` ([building-agents.mdx#L296-L318](https://github.com/vercel/ai/blob/ai%407.0.140/content/docs/03-agents/02-building-agents.mdx#L296-L318)).

**Tools and errors.** `tool({ description, inputSchema, execute, outputSchema, needsApproval, strict, toModelOutput })` ([provider-utils tool.ts](https://github.com/vercel/ai/blob/ai%407.0.140/packages/provider-utils/src/types/tool.ts)). Errors thrown by `execute` become `tool-error` content parts and are sent back to the model in multi-step runs ([tools-and-tool-calling.mdx#L1188-L1261](https://github.com/vercel/ai/blob/ai%407.0.140/content/docs/03-ai-sdk-core/15-tools-and-tool-calling.mdx#L1188-L1261)).

## 3. Pydantic AI

**Version.** `pydantic-ai` 2.56.0 (PyPI, October 13, 2026). Docs now live at `pydantic.dev/docs/ai/…`.

**`Agent.run`.** `await agent.run(user_prompt, *, output_type=None, message_history=None, deps=None, model_settings=None, usage_limits=None, retries=None, toolsets=None, event_stream_handler=None, ...)` → `AgentRunResult`; siblings `run_sync`, `run_stream`, `run_stream_events`, `iter` ([agent/abstract.py#L477-L600](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/agent/abstract.py#L477-L600); [Agent docs](https://pydantic.dev/docs/ai/core-concepts/agent/)).

**`output_type`.** Constructor and per-run argument, default `str` ([agent/__init__.py#L573](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/agent/__init__.py#L573)); accepts types, unions, output functions and the markers `ToolOutput`, `NativeOutput`, `PromptedOutput`, `TextOutput` ([output.md](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/docs/output.md)).

**`UsageLimits`.** Fields `request_limit: int | None = 50`, `tool_calls_limit`, `input_tokens_limit`, `output_tokens_limit`, `total_tokens_limit`, `per_request_input_tokens_limit` (all `None`), `cost_limit = None`, `count_tokens_before_request = False` ([usage.py#L485-L537](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/usage.py#L485-L537)). When `usage_limits` is omitted, the run uses `UsageLimits()`, so the 50-request cap always applies unless set to `None` ([agent/__init__.py#L1731](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/agent/__init__.py#L1731)). The request count bounds turns of the loop, not provider retries.

**At the limit.** Raises `UsageLimitExceeded` (an `AgentRunError`), checked before each step: "The next request would exceed the request_limit of 50", with a docs hint appended ([usage.py#L570-L572](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/usage.py#L570-L572); [exceptions.py#L451](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/exceptions.py#L451)). No option returning a value at the limit was found (unverified absence).

**`agent.iter()`.** `async with agent.iter(prompt) as agent_run:` gives an `AgentRun`; `async for node in agent_run` yields graph nodes (`UserPromptNode`, `ModelRequestNode`, `CallToolsNode`, then `End`), or drive it with `await agent_run.next(node)`. `agent_run.usage` is live; `agent_run.result` becomes the `AgentRunResult` at the end ([agent.md "Iterating Over an Agent's Graph"](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/docs/agent.md#L451-L598); [run.py#L170-L284](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/pydantic_ai_slim/pydantic_ai/run.py#L170-L284)). `run_stream_events()` is now an async context manager whose iterator ends with an `AgentRunResultEvent` carrying the result ([agent.md#L79](https://github.com/pydantic/pydantic-ai/blob/v2.56.0/docs/agent.md#L79)).

**Output validators.** `@agent.output_validator` on `(ctx, output) -> output`; raising `ModelRetry(message)` sends a retry prompt to the model and consumes one unit of the output retry budget, default 1 (`retries={'output': N}` on the agent or run, or `ToolOutput(max_retries=N)`). ## 10. Playwright 1.58 hidden `page.agent()`

**Version.** Shipped in 1.58.0 (January 23, 2026; patches to 1.58.2) as a hidden, JS-only API; absent from 1.59.0 (April 1, 2026) through the current 1.64.1 (`client/pageAgent.ts` and the `Page.agent` doc entry are gone at those tags).

**Options** (`await page.agent(options)`, [class-page.md#L712-L765](https://github.com/microsoft/playwright/blob/v1.58.0/docs/src/api/class-page.md#L712-L765); [client/page.ts#L851-L873](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/client/page.ts#L851-L873)):

- `provider: { api: 'openai' | 'openai-compatible' | 'anthropic' | 'google', apiEndpoint?, apiKey, apiTimeout?, model }`.
- `limits: { maxTokens?, maxActions?, maxActionRetries? }`: `maxTokens` unlimited by default; `maxActions` "defaults to 10"; `maxActionRetries` "defaults to 3". The same three plus `cacheKey` and `timeout` can be passed per call (`PageAgentOptions`, [protocol.yml#L4377-L4384](https://github.com/microsoft/playwright/blob/v1.58.0/packages/protocol/src/protocol.yml#L4377-L4384)).
- `cache: { cacheFile?, cacheOutFile? }`: generated code for performed actions; no cache unless `cacheFile` is set. Per-call `cacheKey` defaults to the task text.
- `expect: { timeout? }` (5,000 ms default), `secrets` (hidden from the LLM), `systemPrompt`.

**Loop and cap.** The server builds a `@lowire/loop` `Loop` with `maxToolCalls: maxActions ?? 10`, `maxToolCallRetries: maxActionRetries ?? 3` ([server/agent/pageAgent.ts#L106-L122](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/server/agent/pageAgent.ts#L106-L122)); the bundle pins `@lowire/loop ^0.0.25` ([bundles/mcp/package.json](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/bundles/mcp/package.json)), whose loop also has `maxTurns` defaulting to 100, unset by Playwright ([lowire loop.ts at 0.0.25](https://github.com/pavelfeldman/lowire/blob/b59051f7ee/packages/loop/src/loop.ts#L100-L156)). Exceeding `maxToolCalls` returns an error from the loop, which Playwright **throws** as "Agentic loop failed: Failed to perform step, max tool calls (10) reached"; a refusal throws "Agent refused to perform action" ([server/agent/pageAgent.ts#L143-L159](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/server/agent/pageAgent.ts#L143-L159)).

**Methods** ([client/pageAgent.ts](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/client/pageAgent.ts); [class-pageagent.md](https://github.com/microsoft/playwright/blob/v1.58.0/docs/src/api/class-pageagent.md)): `perform(task, options)` → `{ usage }`; `expect(expectation, options)` → resolves or throws; `extract(query, zodSchema, options)` → `{ result, usage }`; `usage()` → `{ turns, inputTokens, outputTokens }`; `dispose()` / `Symbol.asyncDispose`; event `turn` with `{ role, message, usage? }`. There is no caller-defined tool parameter: `perform` and `expect` use fixed toolsets ([performTools.ts](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/server/agent/performTools.ts), [expectTools.ts](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/server/agent/expectTools.ts)). Unverified: the docs give 5,000 ms as the `perform`/`extract` timeout default, but the client passes the page's action-timeout setting; which value applies was not checked.

## Limits of this note

- Defaults were read from source at the tag; documentation pages that only render client-side were not used as evidence for values.
- Cloud services (Skyvern Cloud, Notte cloud agents, Browser Use Cloud, Browserbase) may apply other defaults server-side; those were not verified.
- Streaming and custom tools for Notte, and an event stream for Browser Use, were not examined in depth.
