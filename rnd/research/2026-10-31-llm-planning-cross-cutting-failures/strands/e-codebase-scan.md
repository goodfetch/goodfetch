# Strand E: the per-unit cost pattern beyond Foxhound's crawl path

Read-only scan of `/Users/jb/Dev/goodfetch` at `203f17f42` (branch `milestone/m1-core`), 2026-10-31.

**Method.** I used grep and file reads only. No cargo command, build, test or rust-analyzer index ran, because the machine was busy with a merge gate and an index is too heavy for it right now. Call chains were followed by hand. Here **confirmed** means I read the chain from the unit's entry point to the repeated work. **Suspected** means I read the code, but the unit's frequency or the cost per call is my estimate, not a measurement. No finding was measured.

**The pattern looked for.** Several features each add work to one per-unit path (per message, action, request, record, URL or sample). Each redoes base work: an open, a parse, a compile, a settings read, a connection, a commit. No module owns the path's total cost. These findings are new. The profile's crawl-path findings are not repeated. Where a finding shares code with one of them, it is listed once under "Shared roots" with the other units that pay for it.

## Owners missing

Each confirmed finding is a feature that adds its own base work to a path no module budgets. The CDP log, Provenance, the request log and the Audit log each open their own file per write. The Audit log, the ledger and known certificates each open a connection per call. The governor, the Audit log and admission each re-read the machine's settings. The Scope, Payload rules, Fragments and the validators are each rebuilt from the run file per call. The guard, live hiding, Block markers, the Page check and consent each make their own isolated-world call. A module that owns each path's total cost could fix all of a row at once:
- a Run-trace writer that keeps one handle per file;
- a store opener that sets up each store once per engine;
- a machine-settings snapshot;
- Run invariants built once;
- one cached isolated world per document.
