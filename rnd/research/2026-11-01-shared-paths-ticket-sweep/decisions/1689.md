# Decision log: spec from #1689

## Reversible choices

- **CRDT: Loro,** because it alone has a native list move and a written format promise; alternative Yrs or Automerge with a fractional position per step, a merge rule of our own. Evidence and gaps are in the spec's table.
- **How the sources were reached:** docs.rs, automerge.org and docs.yjs.dev were read directly. loro.dev answered 403, so Loro's docs were read in its `loro-docs` repository through `gh`. Licences come from each crate's Cargo manifest. Nothing was built, benchmarked or reproduced, and Python packages for Yrs and Automerge were not checked.
- **Reversible until the first publish** (ADR 0066); the `document` ticket holds the stop condition; alternative: treat the library as final now, which the evidence doesn't support.
- **A replica model on the wire (`working_copy.sync`) as well as typed edits;** the owner's "CRDT" and the issue's "as a CRDT document does"; alternative typed edits only, with the CRDT private to the engine, which removes hostile bytes but makes every Client's local echo a rebase of its own, and no merge format exists to publish.
- **The Merge host, a child process,** because #1046 reports an abort that `catch_unwind` can't catch; alternative in-process with `catch_unwind` and fuzzing, which risks every Run on a Daemon. See `OWNER`.
- **Single-valued fields use last-writer-wins, with the loser in the history;** Loro's map rule; alternative multi-value conflicts shown to people, which a step's fields don't need and a Client would have to render. Story 16 and 17 state what a person sees.
- **`working_copy.enabled` defaults on,** because nothing happens until a person opens one and the store and process start on first use; alternative off by default, which adds a step for the feature's only users. An operator locks it off.
- **Retention 30 days, update cap 1 MiB, copy cap 64 MiB:** starting values, each a setting; nothing measured them.
- **Writes have SDK reach, not `Reach::PersonOnly`,** as #1696's draft spec does, since a passkey per keystroke is unusable; alternative a new `Reach` value for the CLI, out of scope and additive later.
- **Daemon only,** since the state must outlive a Client (ADR 0024); alternative an Attached engine sharing the store, which would hold two live documents for one file.
- **The Lead Daemon keeps them in a group,** as the Schedule store; alternative replication between members, unneeded.
- **No sync per edit:** every replica resends after a machine crash; a save syncs; alternative one sync per update, costly for typing and a typed-edit-only Client's last moments are the only thing it protects.
- **Engine-issued peer IDs, checked from the update's header,** so "who" can't be forged; alternative trusting the Client's, rejected by story 28.
- **`working_copy.read`, `.list` and `.history` reach all surfaces but no default MCP profile,** so #1707's profile can add them; alternative SDK only, which would need a second read for that profile.
- **The store left when the setting goes off stays untouched;** alternative deleting it, which destroys work on a config change.
- **Milestone M4 for every ticket,** since these tickets block #1697's spec, which is M4 through #829; #1663, #1664, #1667, #1685, #1645 and #1641 have no milestone yet, and must be at most M4 when set.

## OWNER

- **A new Shared path, E7, one Working-copy update, with a new process on it (the Merge host).** The triage said no Shared path; I disagree now that four features feed the unit. Recommendation: **yes**, amend ADR 0140 with E7 (owner `working_copy`; per update 1 Merge host round trip, 0 whole-document loads or encodes, 0 store opens, 0 preparations, 1 transaction, 0 syncs, 1 encode), on a new B3 scenario, and accept the child process, because one update must not end a Daemon's Runs. The spec assumes yes. On no to the path, the counts stay the tracer's plain criteria. On no to the process, merging stays in the Daemon's process, and a reported abort can end its Runs.
- **Conditional: Size budget.** Loro's size in each Product's executable is unmeasured. If the `document` ticket finds a Size budget (ADR 0087) exceeded, raising it is the owner's. Recommendation then: raise Collie's by the measured amount rather than drop the feature. Nothing to answer yet.
- **At the first publish, not now:** the Merge format becomes a one-way public contract tied to Loro's 1.x bytes. Recommendation: confirm the library when publishing is planned, with the `document` and `format` tickets' results in hand.

## CLOSE

None. #1689 becomes the tracer; #1803 builds on this and stays open.
