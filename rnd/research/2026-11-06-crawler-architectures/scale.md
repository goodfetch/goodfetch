## Heritrix 3.18.0

### 1. Threads and hand-offs

- **One thread per page, end to end.** `ToeThread.run` takes a URI with `frontier.next()`, runs the fetch chain, calls `beginDisposition`, runs the disposition chain, then `frontier.finished()` and loops ([`ToeThread.java:121-189`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/framework/ToeThread.java#L121-L189)).
- **The frontier work is done in the calling thread.** `next()` takes a read lock and calls `findEligibleURI()` in the ToeThread ([`AbstractFrontier.java:452-461`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/frontier/AbstractFrontier.java#L452-L461)). `WorkQueueFrontier.schedule` runs the uniqueness test "in calling thread, rather than deferring operations via in-queue to managerThread" ([`WorkQueueFrontier.java:340-359`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/frontier/WorkQueueFrontier.java#L340-L359)). Outlinks go through the candidate chain and `frontier.schedule(candidate)` from the same thread ([`CandidatesProcessor.java:178-209`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/postprocessor/CandidatesProcessor.java#L178-L209), [`:257`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/postprocessor/CandidatesProcessor.java#L257)).
- **The chains** (profile): fetch chain preselector, preconditions (robots, DNS), FetchDNS, FetchHTTP, bot-block detector, extractors HTTP, robots, sitemap, HTML, CSS, JS, SWF; disposition chain WARC writer, candidates, disposition ([`profile-crawler-beans.cxml:337-429`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/resources/org/archive/crawler/restlet/profile-crawler-beans.cxml#L337-L429)).
- **Concurrency:** `maxToeThreads` `@Value("25")`, resizable at run time ([`CrawlController.java:182-191`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/framework/CrawlController.java#L182-L191)). Locks are per queue (`synchronized(wq)`) plus the outbound read-write lock; no memory-adaptive control.

### 2. Fetch client

- **`FetchHTTP` builds a new `FetchHTTPRequest` per URI** ([`FetchHTTP.java:672`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/fetcher/FetchHTTP.java#L672)), and each builds its own `BasicHttpClientConnectionManager` ([`FetchHTTPRequest.java:596-597`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/fetcher/FetchHTTPRequest.java#L596-L597), [`:662-670`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/fetcher/FetchHTTPRequest.java#L662-L670)). So connections are not reused across URIs. The connection is wrapped to record raw bytes for WARC ([`:672-747`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/fetcher/FetchHTTPRequest.java#L672-L747)). With one URI in flight per host and a 3 s minimum delay, reuse would rarely help.
- **`FetchHTTP2`** (opt-in) uses Jetty `HttpClient`: HTTP/2 by ALPN, HTTP/1.1, and HTTP/3 at lowest priority; 6 connections per destination, 5 min idle ([`FetchHTTP2.java:80-157`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/fetcher/FetchHTTP2.java#L80-L157)). It records "a simplified HTTP/1.1 representation", not the wire bytes.

### 3. Frontier and duplicate check

- **The seen set is a BerkeleyDB JE database of 64-bit fingerprints.** The key concatenates a 24-bit fingerprint of scheme and authority with a 40-bit fingerprint of the URL, so one host's URLs sit together in the B-tree; the comment says this halved lookup times ([`BdbUriUniqFilter.java:51-64`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/util/BdbUriUniqFilter.java#L51-L64), [`:302-312`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/util/BdbUriUniqFilter.java#L302-L312)). A check is one `putNoOverwrite` with an empty value ([`:317-327`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/util/BdbUriUniqFilter.java#L317-L327)).
- **The disk is avoided by the JE cache**, sized by `cachePercent` or `cacheSize` in `BdbModule` ([`BdbModule.java:152-165`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/commons/src/main/java/org/archive/bdb/BdbModule.java#L152-L165)); the databases are deferred-write (persistence survey).
- **Alternatives:** `BloomUriUniqFilter` (in memory, about 1 in 4 million false positives by default, [`BloomUriUniqFilter.java:38-56`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/util/BloomUriUniqFilter.java#L38-L56)), `MemUriUniqFilter`, and FP-merge filters (same folder).

### 4. Politeness

- **One queue per host (class key), and a queue is "in process" while one of its URIs is out:** `inProcessQueues.add(readyQ)` in `findEligibleURI` ([`WorkQueueFrontier.java:581-620`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/frontier/WorkQueueFrontier.java#L581-L620)). So by default one URI per host is in flight.
- **Delay:** `DispositionProcessor` computes `delayFactor × fetch duration`, clamped to `minDelayMs` and `maxDelayMs`, raised to robots' `Crawl-delay` up to `respectCrawlDelayUpToSeconds` ([`DispositionProcessor.java:230-293`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/postprocessor/DispositionProcessor.java#L230-L293)). Defaults: 5.0, 3,000 ms, 30,000 ms, 300 s ([`:72`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/postprocessor/DispositionProcessor.java#L72), [`:86`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/postprocessor/DispositionProcessor.java#L86), [`:114`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/postprocessor/DispositionProcessor.java#L114)).
- **Cost per page:** `processFinish` puts the queue in a `DelayQueue` of snoozed queues, in memory up to `MAX_SNOOZED_IN_MEMORY` = 10,000, otherwise in an overflow map ([`WorkQueueFrontier.java:1014-1073`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/frontier/WorkQueueFrontier.java#L1014-L1073), [`:203`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/frontier/WorkQueueFrontier.java#L203)). No transaction: an object insert under the queue's monitor.

### 5. Parsing and link extraction

- **No tree.** `ExtractorHTML` runs one regular expression (`RELEVANT_TAG_EXTRACTOR`: script, style, any tag with attributes, comments) over a `ReplayCharSequence` of the recorded body ([`ExtractorHTML.java:148-152`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/extractor/ExtractorHTML.java#L148-L152), [`:916-919`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/extractor/ExtractorHTML.java#L916-L919), [`:984-1000`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/modules/src/main/java/org/archive/modules/extractor/ExtractorHTML.java#L984-L1000)). A Jericho-based extractor exists as an alternative (`JerichoExtractorHTML.java`).
- **It runs after the body is recorded**, not while streaming. The recorder keeps 512 KiB in memory per thread, then spills to a scratch file ([`CrawlController.java:216-233`](https://github.com/internetarchive/heritrix3/blob/eac2c96daf06ee74aba938cc4754d798192544e4/engine/src/main/java/org/archive/crawler/framework/CrawlController.java#L216-L233)).

### 6. Main text

None: Heritrix is an archival crawler.

## Apache StormCrawler 3.7.0

### 1. Threads and hand-offs

- **The archetype topology:** spout → `URLPartitionerBolt` (shuffle) → `FetcherBolt` (fields grouping on the host key) → `SiteMapParserBolt` → `FeedParserBolt` → `JSoupParserBolt` → `RedirectionBolt` → Tika or indexer, all `LOCAL_OR_SHUFFLE`; the fetcher and parsers also emit to the status updater ([`crawler.flux:13-95`](https://github.com/apache/stormcrawler/blob/604a97328f83073b98f1b707b38293d832fe2b81/archetype/src/main/resources/archetype-resources/crawler.flux#L13-L95)). Each bolt is a Storm executor with its own receive queue, so a page crosses about 7 queues. Whether tuples between executors of one worker are passed without serialisation is **unverified** here (Storm internals not read).

- A Python `set` per deep crawl; each discovered link is normalised and checked, and the level is capped by `max_pages` ([`bfs_strategy.py:138-204`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/deep_crawling/bfs_strategy.py#L138-L204)). No persistent frontier.

### 4. Politeness

- `RateLimiter.wait_if_needed` keeps per-domain state: wait until `current_delay` after the last request; the first delay is drawn from `base_delay` ([`async_dispatcher.py:28-66`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/async_dispatcher.py#L28-L66)); 429 and 503 double the delay up to `max_delay` 60 s ([`:66-87`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/async_dispatcher.py#L66-L87)).
- Tasks that read the same `last_request_time` all sleep the same amount and leave together, so it limits the rate only loosely (read from the code; not measured).

### 5. Parsing and link extraction

- `LXMLWebScrapingStrategy` (the default, [`async_configs.py:1991`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/async_configs.py#L1991)): `lhtml.document_fromstring` per page, XPath for base, links, images, media and forms, then clean-up and `lhtml.tostring` into `cleaned_html` ([`content_scraping_strategy.py:131-152`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/content_scraping_strategy.py#L131-L152), [`:276-398`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/content_scraping_strategy.py#L276-L398), [`:649-919`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/content_scraping_strategy.py#L649-L919)). Several passes over the tree (`iterdescendants` for empty-element removal, one XPath per excluded tag).

### 6. Main text

- **Markdown by default:** `DefaultMarkdownGenerator` runs `CustomHTML2Text` (a pure-Python HTML parser) over `cleaned_html`, then converts links to citations ([`markdown_generation_strategy.py:148-249`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/markdown_generation_strategy.py#L148-L249)). - **"Fit" Markdown** only with a content filter: `PruningContentFilter` (BeautifulSoup tree, text and link density with tag weights, threshold 0.48) or BM25 ([`content_filter_strategy.py:382-640`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/content_filter_strategy.py#L382-L640)). The BeautifulSoup version is deprecated for `PruningContentFilterLXML`, "~10x faster with identical output" ([`:588-600`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/content_filter_strategy.py#L588-L600)); that figure is the project's claim, not measured here. A filter adds a third parse and a second html2text pass ([`markdown_generation_strategy.py:230-249`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/markdown_generation_strategy.py#L230-L249)).

### 7. What is written per page

- **Protocol calls per page with defaults** (`wait_until` `domcontentloaded`, `scan_full_page` false, [`async_configs.py:1892-1913`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/async_configs.py#L1892-L1913)): `new_page`, `goto`, `wait_for_selector("body")`, a visibility poll by `evaluate` (up to `body_visibility_timeout` 30 s), `wait_for_load_state` and the `update_image_dimensions` script unless `text_mode`, `page.content()`, `page.close()` ([`async_crawler_strategy.py:568-1120`](https://github.com/unclecode/crawl4ai/blob/838869bdda93f25e6d50b3f50ae9577d9b19a586/crawl4ai/async_crawler_strategy.py#L568-L1120)). ## Firecrawl v2.11.0 (self-hosted path)

### 1. Workers and hand-offs

- **A page is a NuQ job**, a PostgreSQL row. A `SystemMonitor` refuses work above `MAX_CPU` or `MAX_RAM` 0.8 ([`system-monitor.ts:212-216`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/services/system-monitor.ts#L212-L216), [`config.ts:292-293`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/config.ts#L292-L293)).
- **Hand-offs per page:** API → PostgreSQL queue → worker process → (browser) HTTP call to the Playwright service → back → transformers → Redis pipeline and PostgreSQL `UPDATE`. Each discovered link becomes a new job row.

### 2. Fetch client

- **Engines without fire-engine:** `playwright` if `PLAYWRIGHT_MICROSERVICE_URL` is set, then `fetch` ([`engines/index.ts:50-80`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/scraper/scrapeURL/engines/index.ts#L50-L80)).

### 3. Frontier and duplicate check

- After a crawl page, links are extracted from the raw HTML and filtered in Rust (`filterLinks`), then **for each link, one after the other**: `await lockURL(...)`, then `getJobPriority`, then `addScrapeJob` ([`scrape-worker.ts:433-500`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/services/worker/scrape-worker.ts#L433-L500)).

- `goto` with `waitUntil` `load` by default, an optional fixed wait and selector wait, then `page.content()` ([`api.ts:281-313`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/playwright-service-ts/api.ts#L281-L313)). No init scripts, no recycling; the container is capped at 2 CPUs and 4 GB ([`docker-compose.yaml:79-82`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/docker-compose.yaml#L79-L82)).

Per URL, the Redis sets `visited`, `visited_unique`, the jobs-done set and ordered list grow, all with a 24 h TTL ([`crawl-redis.ts:476-492`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/lib/crawl-redis.ts#L476-L492)).

- A Prometheus timer per job ([`nuq-worker-runner.ts:152`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/services/worker/nuq-worker-runner.ts#L152)); crawl status is computed when asked, from Redis counts (`getDoneJobsOrderedLength`, [`crawl-logic.ts:141`](https://github.com/firecrawl/firecrawl/blob/ef12eb36b2f3382838dfe0a0c1a5add3d5df7fe5/apps/api/src/services/worker/crawl-logic.ts#L141)). ## 11. What Foxhound could adopt, and what would be a loss

Foxhound's measured causes (from the inputs): three single-threaded hops per page (Politeness actor, analysis pool, run-state writer), SQLite on every page at `durability: off`, R1's throw-away `CountedWork`, R7's in-flight progress serialised 32 times a page, a clean-up that tests every rule against every element, and in the browser cell 100 contexts, 43 browser launches and 57–60 CDP commands a page with the 583 KB Consent bundle on every page. Each proposal below is a setting with an off state, or an internal change with no behaviour change.

| # | Idea | Seen in | Fits which Foxhound cause | Form | Loss if adopted? |
|---|---|---|---|---|---|
| A1 | **Run the page in the task that fetched it, frontier calls included, with per-queue locks instead of actors.** | Heritrix's ToeThread and in-thread `schedule`; crawl4ai's one task per URL | The three single-threaded hops and their futex chain | Internal (implementation); with `durability: off` the dedup and leases can be in-memory structures behind a lock | None if the run file is written at clean stop or Checkpoint; needs ADR 0138's commit design to change (owner decision, already raised by the Spider-gap note) |
| A2 | **A memory dedup cache in front of the persistent store** (in-memory set, or a Caffeine-like bounded cache, or a Bloom filter), with host-local keys if a disk set stays | StormCrawler's DISCOVERED cache; Heritrix's 24+40-bit fingerprint keys and JE cache; Heritrix's `BloomUriUniqFilter` | R2 and the SQLite admission per links batch | Setting `frontier.dedup_cache` (on by default, off = today's path) | A Bloom filter alone would drop a small share of new URLs as false positives: offer it only as an opt-in for huge crawls |
| A3 | **Politeness that costs nothing when it cannot bind:** a per-host `nextFetchTime` and `inProgress` counter, checked under a lock | StormCrawler's and Nutch's `FetchItemQueue` | R4 (in-memory SQLite, ~9 statements a permit) | Internal for a run-private store; the shared store keeps SQLite | None: caps and delays still hold (ADR 0053, 0086). Avoid their 100–500 ms sleep-polling: wake on the next due time instead |
| A4 | **Lazy work: build what only a consumer needs.** | StormCrawler builds the W3C DOM only if a filter `needsDOM()`; Firecrawl extracts `links` only for the links format | R1 (a `CountedWork` built and dropped per batch); the extraction path | Internal | None |
| A5 | **One parse per page, shared by every consumer.** | The counter-example: Firecrawl parses one page 3+ times, crawl4ai twice (lxml then html2text) | Foxhound already does one streaming pass in raw (ADR 0138); keep the tree shared in extraction between clean-up, readability and Markdown | Internal | None |
| A6 | **Bounded hand-off between frontier and fetchers** (fill to `threads × k`, then block) | Nutch's QueueFeeder (`threads × 50`); StormCrawler's `max.spout.pending` | Memory bound and back-pressure; replaces lease bookkeeping per page | Setting for the buffer depth | None |
| A7 | **Memory-pressure admission:** stop starting pages above a high-water mark, resume below a low one, requeue above a critical one | crawl4ai's MemoryAdaptiveDispatcher (90/85/95%, 1 s sampling); Firecrawl's 0.8 CPU and RAM gate | Complements ADR 0040's governor | Setting with off state; thresholds as settings | Sampling system memory is coarse: keep the governor's own accounting as the authority |
| A8 | **Browser recycling by pages served, with old browsers drained** | crawl4ai's `max_pages_before_recycle` (off by default, 500–1000 suggested), version bump, at most 3 draining | The browser-gap note's 43 launches for 1,000 pages from the "twice the warm-up" memory cap | Setting `browser.recycle.after_pages`; memory-based recycling stays as the other trigger | None if memory recycling stays available |
| A9 | **One context per configuration, a new page per URL** | crawl4ai (contexts keyed by config signature, LRU 20); StormCrawler and scrapy-playwright (one context) | The 100 contexts and 2.6 renderers per page | Default of the Session pool, still a setting: pages that need isolation (logins, Sessions with state) keep their own context | Cookie and storage isolation between unrelated pages of one Session; keep per-Session contexts where Sessions carry state |
| A10 | **Init scripts only when a feature needs them** | crawl4ai adds navigator and shadow-DOM scripts only for their options; Firecrawl and StormCrawler add none | The 583 KB Consent bundle on every page | Inject the Consent runner only when Consent is on for that host, or inject a small loader | None; Consent stays a setting |
| A11 | **Progress computed on read** | Firecrawl (status from Redis counts when asked); Heritrix (atomic counters, a 20 s snapshot) | R7 | Internal | None |
| A12 | **Clean-up in native code with selectors grouped** | Firecrawl's 42 main-content selectors in Rust | The clean-up's 4.73 M instructions a page | Internal: index rules by id, class and tag (the Spider-gap note's proposal) | None: ADR 0047's rules unchanged |

**What would be a loss if copied as is:**

- **Heritrix's and Nutch's default fetch path** (a new connection per URI, `Connection: close`) and Nutch's 5 s, Heritrix's 3 s minimum delay: right for archives and politeness to strangers, far slower than Foxhound's defaults.
- **Nutch's batch dedup** (`updatedb`): no per-page lookup, but no live crawl either; Foxhound's Runs are live.
- **Heritrix's regular-expression link extractor:** cheap, but less exact than Foxhound's streaming HTML parser (ADR 0138).
- **Firecrawl's process-per-page model** and per-link Redis round trips: process isolation is robust, but the cost per page is far higher than in-process tasks, and its politeness is crawl-wide, not per host.
- **StormCrawler's and Playwright-Java's one page at a time per protocol instance**, and per-request routing through a script handler (Firecrawl, StormCrawler, scrapy-playwright): a CDP round trip per sub-request. Foxhound should keep interception off unless a feature needs it.
- **crawl4ai's level-synchronous deep crawl** and the O(n) state copy per URL for resume; and its synchronous parse on the event loop.
- **Firecrawl's default Turndown Markdown** and crawl4ai's pure-Python html2text: slower than a native converter.
