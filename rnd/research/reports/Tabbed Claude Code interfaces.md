# Nobody ships interactive sub-agent tabs yet

No plugin, mod, extension or third-party tool found as of 13 October 2026 gives each Claude Code sub-agent its own tab with a full interactive session. The Codex-style workspace of a session plus browser, file and diff tabs does exist, in three forms: natively in the Claude desktop app's Code tab, in third-party GUIs such as Superset and Agentastic, and in agent-aware terminals such as cmux. The barrier to interactive sub-agent tabs is structural. The new mods API, launched on 1 October 2026, can draw tabbed panes, diffs and file trees, but it **cannot embed a webview, a terminal or another live Claude session**. Task-tool sub-agents are also built to report a summary back to their parent, not to be driven as peers. Every community mod for sub-agents is therefore a read-only status board, and every protocol-level design (ACP child sessions, the VS Code agent map) is read-only too. The Codex desktop app itself, the user's reference point, does not give sub-agents interactive tabs either: its tabs hold a browser and a terminal, and its sub-agent threads are inspect-only. The one way to get a full interactive session per agent today is Claude Code's experimental **agent teams** in split-pane mode, where each teammate runs as its own Claude process in its own tmux or iTerm2 pane. The best setup now pairs that with either the desktop app's native panes or cmux's browser split.

## The mods API caps sub-agent tabs at read-only views

Mods arrived in Claude Code v2.1.287 on 1 October 2026 and run in both the CLI and the desktop app's Code tab. They do not run in the VS Code extension's chat panel, in `claude -p`, in the Agent SDK or in cloud sessions ([Mods overview](https://code.claude.com/docs/en/plugins/mods)). A mod opens **panes**: a docked sidebar, or a framed region above the prompt. When several panes are open, "each gets a tab that shows its title" ([Draw in the interface](https://code.claude.com/docs/en/plugins/mods/interface)). That makes tabs real, but only as one tab per mod pane. Tabs inside a single pane are not a widget, and Anthropic's own `hello-tabs` example fakes them with a row of buttons. In the terminal, a pane the mod opens on its own appears only at **144 or more columns** ([Reference, Limits](https://code.claude.com/docs/en/plugins/mods/reference)).

Inside a pane, a mod draws from a fixed set of elements: text, buttons, inputs, Markdown, syntax-highlighted code, SVG (desktop only) and pixel images (terminal only) ([Reference, Elements](https://code.claude.com/docs/en/plugins/mods/reference)). **Diffs are first-class**. `Code` with `format: 'diff'` draws line numbers, red and green shading and word-level highlights, and the built-in `/diff` command is itself a mod whose source is public ([Interface gallery](https://code.claude.com/docs/en/plugins/mods/gallery); [anthropics/claude-code/mods/diff](https://github.com/anthropics/claude-code/tree/main/mods/diff)). There is no element that accepts HTML, a URL or a webview. The 517 KB type file holds no "webview" or "iframe" ([claude-code.d.ts](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts)). The types do hint at a future browser route: `$.ui.blit` swaps a keyed image up to 120 times a second from a shared-memory buffer, and its documented example uses `requestId: 'browser'`. A mod could therefore stream frames from a headless browser into a terminal pane, but real pixels show only in kitty 0.28+ and Ghostty, and nobody has built one yet.

For sub-agents, a mod can start them (`$.agent.spawn`), list them with their status (`$.agent.list`), attribute every tool call to an `agentId`, and send text to any of them with `$.session.send` ([Use the mods API](https://code.claude.com/docs/en/plugins/mods/api)). What it cannot do is show another agent's transcript through Claude Code's own renderer: `$.session.messages()` returns only the current session's messages. The nearest a mod gets to a sub-agent tab is a pane that rebuilds a read-only transcript from events or from the JSONL files on disk, plus an input box that sends text. That is a crude chat, not a session interface.

## Two weeks of community mods produced boards, not sessions

The community output fits that ceiling exactly. Anthropic's official directory holds no tab, sub-agent or browser plugin ([claude-plugins-official](https://github.com/anthropics/claude-plugins-official/tree/main/plugins)). The community mods that matter are sub-agent observers. **agent-flow** draws the main loop and a tree of sub-agents, showing for each one the context passed down, its tokens and recent tools, and its final answer ([aitmpl agent-flow](https://www.aitmpl.com/component/mods/ui/agent-flow)). **claude-mod-agent-board** shows a card per sub-agent with status, model, elapsed time, last tool call and the start of its answer ([GitHub](https://github.com/tjanuki/claude-mod-agent-board)). Smaller variants come from named-subagents-mod, pulse-progress and akaz01's agent-board ([named-subagents-mod](https://github.com/Bobby-cell-commits/named-subagents-mod); [pulse-mods](https://github.com/MrValraven/pulse-mods); [akaz01/claude-mods](https://github.com/akaz01/claude-mods)). For files, **data-goblin/claude-code-filetree** (about 169 stars, the most popular mod found) adds an IDE-style tree with git status that highlights the files Claude reads and writes. The desktop app docks it on its own ([GitHub](https://github.com/data-goblin/claude-code-filetree)). YeonwooSung's `time-machine` adds a branching timeline of tool calls with a file view at each step ([GitHub](https://github.com/YeonwooSung/my-claude-code-mods)).

None of these embeds a browser, gives a sub-agent an interactive session, or offers a multi-tab file and diff workspace. All are days old, have few stars and run unsandboxed, so treat them as unvetted. Mod UI in the desktop app is also still rough: open bugs report that mod panes and bands render only in the primary pane of split view ([#101748](https://github.com/anthropics/claude-code/issues/101748); [#99868](https://github.com/anthropics/claude-code/issues/99868)), and that the pane cannot be resized when the window is maximized ([#100716](https://github.com/anthropics/claude-code/issues/100716)).

## The desktop app already has most of the Codex layout

The gap is narrower than the question assumes, because Anthropic's desktop app already has native panes for **chat, diff, a tabbed browser, terminal tabs, a file editor, plan, tasks, a sub-agent view and the iOS Simulator**. Panes can be dragged, resized and popped out ([Desktop docs](https://code.claude.com/docs/en/desktop)). The browser is "a tabbed browser, so you can open documentation, issue trackers, or any other site next to your running app". Clicking a task shows its output in the sub-agent pane. The docs describe seeing and stopping that output, but not typing into the sub-agent, so whether that pane is interactive is unconfirmed. Split view has its own gaps: "+ New", Ctrl+N and deep links all overwrite the leftmost pane, with "no way to open a new session in a new pane" ([#100080](https://github.com/anthropics/claude-code/issues/100080)).

The CLI goes further on interaction than either GUI. Background sub-agents and forks appear as rows below the prompt, and **`Enter` opens the selected transcript and lets you send follow-ups**. `Ctrl+Enter` sends a message mid-task, and `x` stops an agent ([Sub-agents docs](https://code.claude.com/docs/en/sub-agents)). This is a switchable view inside one terminal, not a tab strip, and it has its own open bugs. For example, `/compact` run in the sub-agent view compacts the main session ([#97857](https://github.com/anthropics/claude-code/issues/97857)). The research preview `claude agents` lists background sessions across projects and attaches to any of them full screen, but it gives sub-agents no rows of their own ([Agent view docs](https://code.claude.com/docs/en/agent-view)). The only open request for CLI tabs asks for project-bound session tabs, not sub-agent tabs ([#94920](https://github.com/anthropics/claude-code/issues/94920)).

It also helps to know what Codex actually offers. The Codex app, now documented as the "ChatGPT desktop app", shows tabs beside the chat, and its confirmed tab types are a **Browser** and a per-chat **Terminal**. Diffs live in a separate review pane, and sub-agents appear as inspectable Active and Done threads that you steer by asking in the main chat ([Browser docs](https://learn.chatgpt.com/docs/browser); [Integrated terminal](https://learn.chatgpt.com/docs/integrated-terminal); [Subagents docs](https://learn.chatgpt.com/docs/agent-configuration/subagents)). So "a full interactive session in a tab for each sub-agent" goes beyond Codex as well. The industry-wide pattern is read-only sub-agent inspection.

## Agent teams in split panes are the only fully interactive per-agent tabs

The one way to get a real, full Claude TUI per agent is **agent teams** with `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` and `teammateMode` set to `tmux` or `iterm2`. In that mode "each teammate gets its own pane… click into a pane to interact directly" ([Agent teams docs](https://code.claude.com/docs/en/agent-teams)). With teams on, a sub-agent that Claude names launches as a teammate, so named delegations get a pane. The cost is real. Teammates are separate processes that burn more tokens. `/resume` does not restore in-process teammates, teams cannot nest, and split panes are officially unsupported in VS Code's terminal, Windows Terminal and Ghostty. Open bugs include a lead's messages arriving only once a teammate goes idle ([#98998](https://github.com/anthropics/claude-code/issues/98998)). An open request asks for workflow sub-agents to get tmux panes too ([#66686](https://github.com/anthropics/claude-code/issues/66686)).

Terminal tools build on this. **cmux** (about 28k stars, macOS only, Ghostty-based) has vertical tabs per workspace, a blue ring on panes that are waiting for input, and an **in-app browser split** that Claude can drive (accessibility snapshot, click, fill, evaluate JS) ([cmux](https://github.com/manaflow-ai/cmux)). Its `cmux claude-teams` command puts a tmux shim on the PATH so teammates appear as native cmux splits. That shim is fragile: it supports a fixed list of tmux commands, and a teammate can land as a hidden tab instead of a split ([cmux docs](https://cmux.com/docs/agent-integrations/claude-code-teams)). **herdr** (about 44k stars) is a cross-platform Rust runtime that owns agent terminals, marks each pane working, blocked or idle, and survives detach ([herdr](https://github.com/herdrdev/herdr)). For diff review, **workmux** has a dashboard with per-agent diff stats, a hunk-staging diff view, live previews and an `i` key that types straight into an agent ([workmux dashboard](https://workmux.raine.dev/guide/dashboard)), and **Claude Squad** toggles between a preview tab and a diff tab per session ([Claude Squad](https://github.com/smtg-ai/claude-squad)). All of these work at the level of whole sessions or teammates. None turns Task-tool sub-agents into panes.

## Third-party GUIs and IDEs offer tabs per session, never per sub-agent

Among the dozen GUIs that wrap Claude Code, the closest matches to the Codex layout are **Superset**, with a browser pane that detects each workspace's ports, a diff viewer with PR review, and terminals with "tabs, infinite splits, presets, and persistent sessions" ([Superset](https://github.com/superset-sh/superset)), and **Agentastic**, with an agent-drivable Chromium browser, a native code editor, unified or side-by-side diffs and a real terminal. Agentastic is macOS-only and still in closed development ([agentastic.dev](https://www.agentastic.dev)). **Nimbalyst** (MIT, the successor to Crystal) leads on editing and is the only GUI with a confirmed teammate panel, where agent-team teammates appear in a sidebar and can receive messages ([Nimbalyst teammate docs](https://github.com/nimbalyst/nimbalyst/blob/main/docs/TEAMMATE_IMPLEMENTATION.md)). **CloudCLI** is the best web-first option: it has a file tree with live editing, git diffs, a shell and a plugin system for "custom tabs with their own frontend UI" ([CloudCLI](https://github.com/siteboon/claudecodeui)). Two well-known names are out: opcode (formerly Claudia) has had no code commits since October 2025, and 1Code is archived ([opcode](https://github.com/winfunc/opcode); [1Code](https://github.com/21st-dev/1code)).

How a GUI runs Claude Code matters for subscription users. Anthropic allows an end user to sign in to the **unmodified Claude Code binary** with their own subscription, including where another platform hosts it. It tells developers building products on the Agent SDK to use API keys, and forbids routing Pro or Max credentials on users' behalf ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). GUIs that wrap the terminal (Superset's terminal path, Conductor, Emdash) are therefore on the safest footing. SDK-based GUIs get structured sub-agent events (`parent_tool_use_id`) but sit in a grey zone when they use your own login.

In editors, the official **VS Code extension** opens each conversation as its own editor tab, with status dots, groups and `Cmd+Shift+T` to reopen a closed one. Edits open in the native diff editor. Sub-agents appear in an **agent map** tree where you can open a read-only transcript or stop an agent ([VS Code docs](https://code.claude.com/docs/en/vs-code)). Cursor, Kiro and Devin Desktop install the same extension, and Cursor adds a built-in browser pane ([Cursor Browser](https://cursor.com/docs/agent/browser)), though no source confirms that the Claude extension can use it. The JetBrains plugin is a thin bridge to the CLI with native diffs ([JetBrains docs](https://code.claude.com/docs/en/jetbrains)). **Zed**, through the `claude-agent-acp` adapter, can expose each sub-agent as an ACP child session. Clients "can't yet prompt, cancel, or otherwise change a child" ([claude-agent-acp](https://github.com/agentclientprotocol/claude-agent-acp)).

| If you want | Best option today | What you give up |
|---|---|---|
| Codex-like browser, diff, files and terminal beside the chat, no new tools | Claude desktop app's Code tab with native panes, plus the filetree and agent-board mods | Sub-agent pane may be output-only; split view and mod bugs |
| A full interactive session per agent | Agent teams with `teammateMode: tmux`, run inside cmux (macOS) or tmux/herdr | Experimental; costs more tokens; only teammates, not Task sub-agents |
| The same plus an in-terminal browser | cmux with `cmux claude-teams` and its browser split | macOS only; tmux shim breaks easily |
| A third-party desktop GUI | Superset (cross-platform), or Agentastic on macOS | Session tabs only; no sub-agent tabs |
| Everything inside an editor | VS Code or Cursor with the official extension | Read-only sub-agent transcripts |

## Conclusion

Interactive sub-agent tabs are missing because of how sub-agents are designed, not for lack of tooling. Task-tool sub-agents exist to hand a summary back to their parent, and every surface (Anthropic's agent map, ACP child sessions, Codex's sub-agent threads, the mods API) has settled on inspect, message and stop rather than drive. When users want a peer they can type into, the working answer is to promote the sub-agent to a teammate. That is why agent teams in split panes, not any plugin, are the real route today. Building a mod to bridge the gap would mean reconstructing a transcript and faking a prompt box. It would be a useful read-only board, but not a session.

For this user, the recommended setup today is the desktop Code tab for browser, diff and file panes, with the filetree and agent-board mods for visibility. Turn on agent teams in tmux mode (inside cmux on a Mac, for its browser split) whenever an agent needs its own interactive session. Two things to watch: the mods API's shared-memory `blit` route, which could bring a browser into the terminal, and the protocol work to let ACP clients prompt child sessions. Either would close most of the remaining gap, and a mod or GUI built on that would likely be the first real "sub-agent tab".
