## 2. Paradigm

**Runtime and concurrency.** Tokio multi-thread. Each crawl method builds its own `JoinSet` and a `Semaphore`, spawns one task per URL through a thin wrapper `spawn_set` ([utils/mod.rs:L10002-L10035](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/utils/mod.rs#L10002-L10035)) whose `_task_name` argument is ignored, and pushes each `Page` to subscribers over a `tokio::sync::broadcast` channel ([website.rs:L14696-L14710](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L14696-L14710)). In `spider/src` (non-comment lines, tests included): 29 `JoinSet` mentions, 52 `Semaphore`, 26 `broadcast::`, 30 `mpsc::`, 30 `oneshot`, 52 `select!`, 213 atomics, 35 `DashMap`, and no `Mutex`/`RwLock` outside one test. Pause/resume/shutdown go through one process-wide `watch` channel keyed by the string `"{crawl_id}-{url}"` ([utils/mod.rs:L9561-L9605](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/utils/mod.rs#L9561-L9605)). The library also starts hidden process-global executors on first crawl: a second Tokio multi-thread runtime with `num_cpus` workers on its own OS thread ([utils/connect.rs:L14-L60](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/utils/connect.rs#L14-L60)), started from `setup_base` ([website.rs:L4095](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L4095)), plus io_uring worker threads and a spool-cleanup thread ([utils/html_spool.rs:L64-L78](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/utils/html_spool.rs#L64-L78)).

**Programming style.** Struct + giant `impl`, not traits. `Website` has 48 fields, 13 of them `#[cfg]`-gated ([website.rs:L1402-L1571](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L1402-L1571)), and one `impl Website` block runs from L1656 to L15090 (13,435 lines) with 361 `fn` definitions under 300 distinct names (310 `pub`, 17 `pub(crate)`, 34 private); the 61 extra definitions are `#[cfg]` variants of the same method. `Configuration` has 99 fields with 45 `#[cfg]` attributes inside the struct ([configuration.rs:L334-L719](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/configuration.rs#L334-L719)). `Page` is defined twice, 43 fields without `decentralized` and 38 with it ([page.rs:L2421-L2446](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/page.rs#L2421-L2446), [page.rs:L2583-L2585](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/page.rs#L2583-L2585)). Traits appear only at a few seams (section 6). The longest functions are approximately: `crawl_concurrent_raw` ≈1,027 lines, `crawl_concurrent` (chrome) ≈809, `crawl_concurrent_send` ≈553; in the agent, `RemoteMultimodalEngine::run_with_memory` ≈1,482 lines. Nesting reaches 26 indentation levels ([website.rs:L9885-L9892](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L9885-L9892)); 1,929 prod lines of `website.rs` sit at 12 levels or deeper.

**Public API style.** Build, subscribe, crawl, read:

```rust
let mut website = Website::new("https://example.com").with_limit(10).build().unwrap();
let mut rx = website.subscribe(16);                 // broadcast::Receiver<Page>
tokio::spawn(async move { while let Ok(p) = rx.recv().await { /* … */ } });
website.crawl().await;                              // or crawl_raw / crawl_smart / crawl_sitemap / scrape …
```

([lib.rs:L47-L157](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/lib.rs#L47-L157)). The rendering engine is chosen by both the method name (14 `pub` `crawl*` and 4 `scrape*` methods) and the Cargo features compiled in: `crawl()` renders with Chrome when `chrome` is on, `crawl_raw()` forces HTTP ([website.rs:L7368-L7680](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L7368-L7680)). `build(&self) -> Result<Self, Self>` clones the whole `Website` and returns it as the error, which is why `Website` implements `std::error::Error` ([website.rs:L14626-L14633](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L14626-L14633), [website.rs:L15309](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L15309)).

| Lock-free shared state | atomics, `DashMap`, `ArcSwap`, channels; no `Mutex` | Deliberate; makes ownership harder to read in 1,000-line functions |

**Typing strictness.** Mixed. Enums for states (`CrawlStatus`, `ProxyKind`, `SpiderCloudMode`), a few newtypes (`SerializableHeaderMap(pub HeaderMap)`, `CaseInsensitiveString` from an external crate), `CompactString` for URLs. Stringly-typed spots: cron expressions stored as `String` and parsed late (`with_cron(&str, …)`), budgets as `HashMap<&str, u32>` with a `"*"` wildcard path ([website.rs:L13702](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L13702)), control targets as concatenated strings, 40 distinct environment variables read inside the library (`SPIDER_MAX_SIZE_BYTES`, `CHROME_URL`, `SEMAPHORE_MULTIPLIER`, `LINKS_VISITED_MEMORY_LIMIT`, …), several into `lazy_static`s ([utils/mod.rs:L450-L460](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/utils/mod.rs#L450-L460)). Fetch failures are not typed: they become synthetic HTTP status codes (section 6). Most important: many public types and signatures change shape with Cargo features (section 6).

## 3. Organization

**Layout and dependency direction** (read from each `Cargo.toml`; an arrow points from a dependent up to its dependency):

```
spider_agent_types  (leaf: serde, aho-corasick, memchr, llm_models_spider)
   ↑            ↑
spider_agent_html   │
   ↑            │
spider_agent ───┘   (+ chromey, thirtyfour, reqwest, rustpython/boa, aws-sdk-s3 … all optional)
   ↑ optional (`agent*` features)          ↑ always (types only)
spider  ───────────────────────────────────┘  (+ chromey optional, reqwest, tokio, lol_html, sqlx optional …)
   ↑                     ↑                 ↑
spider_cli          spider_mcp        spider_worker        spider_utils (independent: spider_scraper, sxd-xpath)
   └── spider_transformations (crates.io, depends on spider) ──┘   unified by [patch.crates-io] spider = { path = "spider" }
```

- The core crawler depends on the agent, not the other way round: `spider` re-exports `spider_agent` types under `agent_*` features ([spider/Cargo.toml:L145-L153](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/Cargo.toml#L145-L153), [lib.rs:L323-L387](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/lib.rs#L323-L387)) and always depends on `spider_agent_types` for two result types ([features/automation.rs:L152-L160](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/features/automation.rs#L152-L160)). `spider_agent` talks to Chrome through `chromey` directly, beside `spider`'s own Chrome path.
- External crates that depend on `spider` (`spider_transformations`) are pulled back into the workspace with a `[patch.crates-io]` to avoid compiling two `spider`s ([Cargo.toml:L14-L20](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/Cargo.toml#L14-L20)).
- The repo's agent guide states the order `… -> spider -> spider_cli / spider_utils / spider_worker / spider_mcp` ([CLAUDE.md:L497-L499](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/CLAUDE.md#L497-L499)); `spider_utils` does not depend on `spider` at this commit, so that line is stale.
- No `[workspace.package]`, `[workspace.dependencies]` or `[workspace.lints]`: zero `workspace = true` keys. Versions are kept in lockstep by `sed` in `release.sh` ([release.sh:L12-L19](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/release.sh#L12-L19)); `serde_json = "1"` is repeated in 9 manifests. **Module boundaries inside `spider`.** Flat: `website.rs`, `page.rs`, `configuration.rs`, `client.rs`, `traits.rs`, `fetcher.rs`, `fetch_engine.rs`, `retry_strategy.rs`, `proxy_strategy.rs`, plus `utils/` (33 modules) and `features/` (18 modules, roughly one per Cargo feature: `chrome.rs`, `chrome_common.rs`, `chrome_args.rs`, `webdriver*.rs`, `openai*.rs`, `gemini*.rs`, `disk.rs`, `glob.rs`, `solvers.rs`, `search_providers/`). The `*_common.rs` files hold what is shared between the feature-on and feature-off builds. Domain logic does not have its own modules: the frontier, robots handling, sitemap crawl, HTTP client construction, Chrome orchestration, WARC, SQLite, cron, control and subscriptions all live as methods of `Website`.

**Public vs internal.** Everything is public by default in the core. `spider/src` prod: 1,739 `pub` items, 178 `pub(crate)` items, about 445 private `fn`s; `utils/mod.rs` declares 32 of its 33 submodules `pub`, `features/mod.rs` 16 of 18 ([utils/mod.rs:L1-L87](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/utils/mod.rs#L1-L87)); `website.rs` alone has 338 `pub` items against 26 `pub(crate)`. Structs expose fields (673 `pub` fields in `spider` prod; `Website.configuration` is a `pub Box<Configuration>`). The crate re-exports its dependencies wholesale: `pub extern crate tokio, reqwest, url, hashbrown, bytes, quick_xml, …` and `pub use chromiumoxide` ([lib.rs:L281-L321](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/lib.rs#L281-L321), [lib.rs:L430-L431](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/lib.rs#L430-L431)). `spider_agent` is the counter-example: private modules (`mod agent; mod config; mod error; mod llm; mod memory;`) and a curated `pub use` list ([spider_agent/src/lib.rs:L145-L330](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider_agent/src/lib.rs#L145-L330)).

**Naming.** Feature-variant twins carry suffixes (`crawl_concurrent_raw` / `crawl_concurrent_raw_send`, `crawl_concurrent` / `crawl_concurrent_send`): the `_send` versions exist so the future can cross threads for subscriptions ([website.rs:L10005-L10011](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L10005-L10011)). Leading-underscore methods (`_crawl_establish`, `_fetch_chrome`) mark internal helpers instead of visibility. Comments narrate version history: 40 comment lines in `spider/src` and `spider_agent/src` cite a specific `2.x.y` release.

**Tests, benches, examples, docs.** Unit tests live at the end of the giant files, partly in `#[cfg(test)] mod tests`, partly as top-level `#[tokio::test]` functions each gated by `#[cfg(all(test, feature = …, not(feature = "decentralized")))]` ([website.rs:L15311-L15324](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L15311-L15324), [page.rs:L9837](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/page.rs#L9837)). `spider/tests/` has 21 files, several named after a customer site or version (`fleetio_smart_repro.rs`, `doi_smart_repro.rs`, `smart_smoke_v117.rs`), plus a `crawler_test_com/` suite against a public test site. Benchmarks: `spider/benches` (criterion) and a top-level `benches` crate comparing with Go colly and node-crawler. Examples: a separate unpublished crate with 74 files. Docs: rustdoc on docs.rs with a curated feature list, because `all-features` does not build there ([spider/Cargo.toml:L442-L480](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/Cargo.toml#L442-L480)).

## 4. Design patterns catalog

| Pattern | Where | Problem it solves | Assessment |
|---|---|---|---|
| Mutable chained builder + clone-on-build | [configuration.rs:L1769-L1773](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/configuration.rs#L1769-L1773), [website.rs:L13712-L13716](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L13712-L13716), [website.rs:L14626-L14633](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L14626-L14633) | Fluent configuration of ~100 options | Mixed: readable call sites, but `with_*(&mut self) -> &mut Self` on the product itself, `build()` clones everything, the error is the whole object, and 94 of `Website`'s 115 `with_*` names repeat a `Configuration` method (those read simply forward, like `with_depth`) |
| Strategy objects behind `Arc<dyn Trait>` aliases | [retry_strategy.rs:L192-L206](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/retry_strategy.rs#L192-L206), [proxy_strategy.rs:L88-L99](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/proxy_strategy.rs#L88-L99) | Per-attempt retry and per-request proxy routing without new features | Good: small `Send + Sync + 'static` traits, `Shared*` aliases, own unit tests; the recent seams are the cleanest code in the repo |
| Pluggable transport (port/adapter) | [fetch_engine.rs:L208-L238](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/fetch_engine.rs#L208-L238), [fetcher.rs:L92-L106](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/fetcher.rs#L92-L106) | Replace reqwest per URL while keeping retry/cache/hedge wrappers | Good shape, but two overlapping hooks (`RemoteFetcher` replaces the loop's fetch, `HttpFetchEngine` the inner body fetch) and both fire on HTTP paths only, not Chrome/WebDriver |
| Read-only trait facade | [traits.rs:L14-L80](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/traits.rs#L14-L80) | Mocking and generic code over `Page`/`Website` | Mixed: tidy (RPITIT `impl Future + Send`), but 7 `Crawler` methods next to 310 inherent `pub` methods, so generic code can do little through it |

## 5. Separation of concerns and DRY

**How they avoid duplication.** Mostly by `#[cfg]` toggles inside shared functions and by `*_common.rs` modules; a few `Arc<dyn Trait>` seams (section 4); generic `ListBucket<K>` and `links_stream<A: …>` helpers; only 5 `macro_rules!` in `spider` prod. There is no trait over "fetch one page" that the HTTP, Chrome, WebDriver and Smart loops share.

**Where it fails, with counts.**
- **Feature conditionals everywhere.** `spider` declares 129 `[features]` entries (128 plus `default`) ([spider/Cargo.toml:L214-L440](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/Cargo.toml#L214-L440)); the workspace declares 169 named features. The code holds 2,470 `cfg`/`cfg_attr`/`cfg!` predicates that mention a feature, naming 105 distinct features. Densest: `website.rs` 533 (29 per 1,000 lines), `page.rs` 430, `utils/mod.rs` 320, `configuration.rs` 285 (72 per 1,000 lines), `client.rs` 17 in 49 lines. Most-referenced: `chrome` 566, `decentralized` 471, `balance` 192, `serde` 185, `cache_request` 111.

- **God object.** `Website` mixes crawl orchestration, HTTP-client construction (it calls `reqwest::ClientBuilder` itself), robots, sitemaps, Chrome and WebDriver lifecycles, SQLite, WARC, cron (`impl Job for Website`, [website.rs:L15273](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L15273)), control and subscriptions. `Page` both carries data and parses links, detects anti-bot pages and streams HTML from disk.

## 6. Contracts and extension points

**Extension APIs.** Callbacks (`on_link_find_callback`, `on_should_crawl_callback`, `on_link_blocked_callback`), strategies (`RetryStrategy`, `ProxyStrategy`), transports (`RemoteFetcher`, `HttpFetchEngine`, async via `#[async_trait]`), the `Crawler`/`PageData` traits, and in the agent a `CustomToolRegistry` for LLM tools. The dominant extension mechanism is a new Cargo feature: the PR template asks contributors to put optional functionality behind a flag ([.github/PULL_REQUEST_TEMPLATE.md](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/.github/PULL_REQUEST_TEMPLATE.md), [CONTRIBUTING.md:L83-L90](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/CONTRIBUTING.md#L83-L90)).

**Configuration system.** One `Configuration` struct with public fields, ~175 `with_*` definitions in `configuration.rs`, optional serde with `#[serde(default)]`, plus 40 environment variables read deep in the library and `lazy_static` globals (37 `lazy_static!` blocks next to 60 lines using `LazyLock`/`OnceLock`: both styles coexist). The serialized format depends on the features compiled in, because fields appear and disappear with `#[cfg]`.

**Contracts that change with features (non-additive features).** Cargo unifies features across a dependency graph, so any of these can break a crate that never asked for the feature:
- `Page::error_status` is `Option<String>` normally and `Option<Arc<reqwest::Error>>` with `page_error_status_details` ([page.rs:L2441-L2446](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/page.rs#L2441-L2446)); added for [#244](https://github.com/spider-rs/spider/issues/244).
- `Configuration` derives `PartialEq` only when `regex`, `openai`, `cache_openai`, `gemini` and `cache_gemini` are all off ([configuration.rs:L334-L344](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/configuration.rs#L334-L344)).
- `black_list::contains` takes `&RegexSet` with `regex`, `&[CompactString]` without ([lib.rs:L438-L456](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/lib.rs#L438-L456)); the maintainer names this type split as one cause of [#348](https://github.com/spider-rs/spider/issues/348).
- `Website::queue` returns `Option<broadcast::Sender<String>>` with `sync`, `Option<Arc<(Sender<Page>, Receiver<Page>)>>` without ([website.rs:L14712-L14730](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L14712-L14730)); `configure_http_client` switches between `&self` and `&mut self`; `features::automation::EngineError` is a different type with and without `agent`; `Page` is two different structs with and without `decentralized`.

**Error types.** The crawl itself reports no `Result`: a failed fetch is a `Page` whose `status_code` is a synthetic code (table in section 4). Typed errors exist only at the seams (`EngineError` in `fetch_engine.rs`, `SearchError`) and in the agent (`AgentError`, a hand-written enum with `#[cfg]`-gated variants, [spider_agent/src/error.rs:L7-L42](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider_agent/src/error.rs#L7-L42)). `thiserror = "2"` is declared in `spider_agent` ([spider_agent/Cargo.toml:L26](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider_agent/Cargo.toml#L26)) but no `.rs` file references it; no crate uses `anyhow`.

**Panics and `unsafe`.** Prod counts: `spider` 25 `.unwrap()`, 46 `.expect(`, 1 `panic!`-family macro; whole workspace 27 `unwrap`, 72 `expect`. Worse than `unwrap`: 8 prod `unwrap_unchecked()` calls, 7 on the fallible `reqwest::ClientBuilder::build()` in `website.rs` and 1 on `Regex::new` in `features/glob.rs`, for example `unsafe { client.build().unwrap_unchecked() }` inside the public `configure_http_client` ([website.rs:L3612-L3618](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/website.rs#L3612-L3618)). If the TLS backend or a proxy setting makes `build()` fail, that is undefined behaviour reachable from safe public code `[inferred: Result::unwrap_unchecked is UB on Err per std docs]`. 53 `unsafe` blocks and 3 `unsafe impl` in `spider` prod (`uring_fs.rs` 27, `bloom.rs` 10, `website.rs` 7, `page.rs` 6); a `// SAFETY` comment within six lines above appears for 10 of 27 sites in `uring_fs.rs`, 9 of 12 in `bloom.rs`, and none of the 9 in `website.rs` (tests included). `page.rs` turns spooled bytes read back from disk into `String` with `from_utf8_unchecked`, trusting a flag computed before the write ([page.rs:L6954-L6973](https://github.com/spider-rs/spider/blob/fb0f270d77e19442de59350d9dbbacf52f1804b4/spider/src/page.rs#L6954-L6973)).

**Logging and tracing.** The library uses the `log` facade (267 `log::*!` calls in `spider/src`: 124 `warn`, 63 `info`, 44 `error`, 35 `debug`) and, behind the `tracing` feature, 48 `#[cfg_attr(feature = "tracing", tracing::instrument(skip_all))]` plus scattered `#[cfg(feature = "tracing")] tracing::error!`: two facades chosen per call site. **Deprecation and semver.** 3 `#[deprecated]` attributes in the whole repo, all in `spider_agent`. In #349 the reporter asks for documentation of allowed feature combinations and suggests `cargo hack`; the maintainer welcomes the tool. In #348 the maintainer lists four cross-feature defects fixed together.
- **Warnings are not a priority.** Asked about compile warnings, the maintainer says they are generally not cleaned up and are fixed only as needed ([#276](https://github.com/spider-rs/spider/issues/276)).

## 10. Lessons for Goodfetch

Against Goodfetch's existing bans:
- **Capabilities as Cargo features (ban confirmed).** Spider is the case study for the rule: 128 features in one crate, 2,470 feature predicates, non-additive types and signatures (section 6), silent no-op stubs (`with_stealth` without `chrome`), and a steady stream of "feature X does not compile" issues. Keep capabilities as runtime settings; if a Cargo feature is ever unavoidable (TLS backend, allocator), require it to be additive and run `cargo hack --feature-powerset check` in CI.
- **`unwrap()` outside tests (ban confirmed, extend it).** Spider has few plain `unwrap`s in prod (25 in core), but 8 `unwrap_unchecked()` calls on fallible builders. Ban `unwrap_unchecked`/`expect` too unless justified, and enable `clippy::unwrap_used`, `clippy::expect_used`, `clippy::undocumented_unsafe_blocks` (Spider's `website.rs` has 0 SAFETY comments for 9 unsafe sites) and `unsafe_code = "deny"` outside an allow-listed crate.
- **`#[allow]` (ban confirmed).** Spider shows the drift: 25 crate-wide clippy allows including all of `clippy::perf`, 80 local allows, 0 `#[expect]`; the `dead_code`/`unused_*` allows are the scar tissue of `cfg` combinatorics. Put lints in `[workspace.lints]` and add `clippy::allow_attributes` and `clippy::allow_attributes_without_reason` so the `#[expect(…, reason)]` rule is machine-checked.
- **Bare `tokio::spawn` outside a tracker (ban confirmed).** Spider's per-crawl `JoinSet` is the right instinct, but its `spawn_set` wrapper ignores the task name, 17 prod `tokio::spawn` sites remain in the core, and the library starts a hidden second runtime and OS threads it never joins. Use one owner-scoped tracker (`TaskTracker` + `CancellationToken`) and never create runtimes inside a library.
- **stdout/stderr discipline (Spider complies).** No prints in library code, `log` everywhere, and the MCP server pins logs to stderr; copy that and enforce it with `clippy::print_stdout`/`print_stderr`/`dbg_macro` rather than convention.

Further lessons:
- **Avoid: one god struct per concept.** Split crawl orchestration, frontier, fetcher, renderer, storage and event sink into types with private fields and narrow `pub` surfaces; Spider's `impl Website` (361 fns, 310 `pub`) shows where "add a method" ends. Set file and function size budgets and check them in CI.
- **Adopt: one crawl loop over a fetch trait.** Spider wrote ≥10 loops because HTTP, Chrome, WebDriver, Smart and `Send` variants were separate code paths; define the engine boundary (`async fn fetch(&self, …) -> Result<…>`) first, make futures `Send` from day one, and keep a stack-size or future-size test (Spider's v2.51.188 overflow).
- **Adopt: typed failures in results.** Never encode transport errors as fake HTTP statuses (Spider's 525/524/599/310/503); carry a protocol-level error enum with the cause chain, so SDKs generated by `xtask codegen` get a stable, documented error contract.
- **Adopt: the types-crate split and the actor pattern.** `spider_agent_types` (no heavy deps) mirrors Goodfetch's protocol crate; the dedicated-thread actor for `!Send` engines (handle over channels, ends on last drop) is a good template for CDP-adjacent `!Send` state.
- **Adopt: private modules + curated re-exports, not `pub extern crate`.** `spider_agent`'s private-module/`pub use` façade is the better model; re-exporting `tokio`, `reqwest` and `chromiumoxide` from `spider` ties Spider's semver to theirs.
- **Avoid: CI that skips the core.** Run the core crate's offline tests on every PR, keep live-network tests in a separate gated job, share one live-test helper, and add `cargo-semver-checks` so a "breaking" change cannot ship as a minor version.
- **Avoid: side effects in build scripts and hidden env configuration.** No `build.rs` that installs tools; no 40 environment variables read deep in the library. One typed settings surface, validated once.
