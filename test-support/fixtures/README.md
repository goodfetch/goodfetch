# Shared fixtures

Data that several languages' tests read, each file at most 256 KiB (ADR 0062). The Test infrastructure spec fills this folder.

`endpoint-table.toml` is the endpoint table (ADR 0067): one row per refusal rule, one cell per listener it applies to. `goodfetch-test-support`'s `EndpointRunner` reads it, and the Quick suite checks it.

`ssrf/` holds the SSRF case table (`cases.toml`, ADR 0067), which every layer's runner applies through `goodfetch-test-support`'s `SsrfTable::committed()` and `run_cases`, which covers IANA's IPv4 and IPv6 special-purpose registries, committed with their date beside the table `xtask codegen` generates from them (`crates/goodfetch-engine/iana/`). The Quick suite fails when a registry block that is not globally reachable has no case. `ssrf/layers.toml` lists the layers Collie carries the table to, each with its runners and the families each runs (`Runner::committed`), and the Quick suite fails on a layer with no runner or a family a layer skips without a reason.

`hostile/` holds the hostile-input case tables (ADR 0067), one per family: `header_values.toml` (CR, LF or NUL in a header value), `secret_redirects.toml` (a domain-bound Secret across a cross-origin redirect), `paths.toml` (path traversal, each case with the OSes it runs on), `schema_refs.toml` (a JSON Schema's external reference) and `limits.toml` (decompression bombs, endless bodies, deep nesting and oversized messages). Each case gives its input, the typed error every layer gives, and what serves it end to end: a Proving ground page by its task ID, a page waiting on the owner or not built yet, or the program's own input. Every layer's runner reads them through `goodfetch-test-support`'s `HostileTables::committed()`; a case with no expected error fails the parse, and a Pre-merge test fails when a case names a page the Proving ground has no task for.

`snapshot-filters.json` holds the shared snapshot rules (ADR 0062): the run's values to replace literally, then the patterns, in order. A pattern keeps to the syntax Rust's `regex`, JavaScript and Python's `re` read alike, its word boundary ASCII's in all three (Rust's patterns run under `(?-u)`, Python's under `re.ASCII`), and a replacement is literal text, with neither `$` nor `\`. The test's folder is replaced as written, as its canonical path and as each sits inside a JSON string. insta applies them through `snapshot_settings()`, Vitest and inline-snapshot through each package's `redact()`. `snapshot-filter-cases.json` holds hand-written outputs and what each redacts to, a Run ID in the engine's lowercase among them, and a ULID matches only as a whole word, so a longer token whose tail reads as one, such as the Daemon's hex token, stays whole; all three languages' tests pass them.

`locales.json` is ADR 0073's table of locales and time zones; the DST days are 2026's under the IANA rules (the European Union's last Sundays of March and October, the United States' second Sunday of March and first Sunday of November). `unicode-record.json` is ADR 0073's Unicode record, written with JSON escapes so every invisible character shows. Rust, TypeScript and Python read both files.

`canaries/` holds the Secret canaries' files (ADR 0067). `search.json` is the fixture set Rust's `Canaries::search`, TypeScript's `searchCanaries` and Python's `search_canaries` all pass: canaries, outputs that hold them raw, JSON-escaped, URL-encoded, in base64 (standard, URL-safe and inside a Basic header) and in hex, and the hit each search must give, with its output, byte offset and whether it is a planted copy; its values are not canary-shaped, so no secret scan flags them. `gitleaks.toml` is the `gitleaks` rule, one per kind, which `xtask codegen` writes from the kinds and `--check` keeps current; never edit it by hand. `artifacts/` holds canary-shaped values on purpose: `ci/canary-rule.sh` (`just lint`) shows each file of `leaked/` failing a scan with the rule and `clean/` passing, and the rule's allowlist passes over the folder, so a scan of commits does too.

`schemas/` holds the JSON Schemas of `goodfetch-test-support`'s file types, such as `goodfetch-test-env`'s description and the test tool manifest. `xtask codegen` writes them from the crate's Rust types and `xtask codegen --check` fails when they drift; never edit them by hand.

`proving-ground/routes.json` holds the paths of the Proving ground's own routes (the task list, the oracle, the time step, the observations and the client certificate and key), and `schemas/proving-ground-*.schema.json` the line `serve` prints, an oracle submission and the observations document. `xtask codegen` writes all of them from the Proving ground's `src/interface.rs`, which `goodfetch-test-support` compiles in, so the Proving ground, its Rust harness and the TypeScript and Python test support read one described format; never edit them by hand.

`outcome-vectors/` holds the hand-written outcome vectors of the result document (ADR 0063): what a `journey` or `conformance` document holds and the outcome it must get, which `goodfetch-protocol`'s constructors and the TypeScript and Python helpers pass, and which `journey` documents the reader refuses for not holding exactly their Journey's steps, checks and tasks.

`engine-scripts/` holds the Scripted engine's scripts (ADR 0069), grouped by capability: `self-test/` holds the scripts every player (`goodfetch-scripted-engine` and the TypeScript `playScript`) plays to a tiny Client in its own tests, `hello/` the refused `hello`, `attached-engine/` the faults of an Attached engine (a crash mid-call, garbage on stdout), `connect/` and `run/` what the TypeScript SDK's own tests play (a `hello` accepted by either Product or refused, a line that is not JSON-RPC or an exit during a call, a Run started and finished or closed while running; each `hello` carrying the SDK's Product version, `0.0.0`), and `daemon/` the scripts a Client plays to the Scripted engine found as a Daemon, each `hello` carrying the token `scripted-daemon-token` (a refused `hello`, a dead PID in the runtime file, a connection dropped mid-call). `goodfetch-test-support`'s Quick suite validates every message step against the committed JSON Schema bundle and catalog. `script.schema.json` is the script format's schema, which `xtask codegen` writes from `goodfetch-test-support`'s `Script` type; never edit it by hand.
